这个专题拆解 DeepSeek 的 **Mega MoE**：把 **EP dispatch → linear1 → SwiGLU → linear2 → EP combine**
融合进**单个 mega-kernel**、并让 **NVLink 通信与 Tensor Core 计算重叠**的设计；
以及 MoE 的**反向**（weight-gradient / input-gradient 的 grouped GEMM）实现。

参考实现是 **DeepGEMM** 与 **DeepEP**。Mega MoE 主实现是 **SM100（Blackwell）专属**，
本机 H100 跑不了端到端，因此以源码精读 + 线上资料为主线，能跑的部分（grouped GEMM / backward）给实测。

- 配套代码：[`code/mega-moe/`](https://github.com/BlueSkyyyyyy/tech_record/tree/main/code/mega-moe)

[MoE dispatch / combine 的反向语义：伴随恒等式与路由权重梯度]({{< relref "mega-moe-95-ep-backward-adjoint" >}}) —— 第 4 篇推了 MoE 反向的数学、第 12/13/14 篇拆了反向 grouped GEMM、第 43 篇拆了 EPLB 权重预取/梯度归约、第 7/51/58/61/71 篇拆了 dispatch/combine 设备 kernel，但把前向通信接回反向的那层——**「dispatch 的反向是 combine、combine 的反向是 dispatch」为什么成立、路由权重 `w` 的梯度怎么走**——一直只在第 7 篇 §8 与 README 里一句话带过。本篇把它单独拆透：把 dispatch 看成**复制/置换**算子 `D:ℝ^{T×H}→ℝ^{N×H}`、combine 的 token 求和看成 `Dᵀ`，两个原语互为转置，于是**反向不需要任何新通信 kernel**——`dispatch_backward`（`README.md:204-220`）就是 `combine(grad_recv_x, topk_weights=grad_recv_w)`、`combine_backward`（`:242-258`）就是 `dispatch(grad_combined_x)`。**一个只在复制语义下成立的巧妙设计**：非 expand 按**目的 rank**复制（`refs.py:67`），一个 token 的整行 `w` 会被复制 `d` 份，朴素求和得 `d·w`——所以 `combined_topk_weights` 必须**选择而非求和**（`combine_reduce_epilogue.cuh:128-139` 的 `master_lane_idx`），才能满足 `test_ep.py:514` 的 `== topk_weights`。训练图把权重乘法融进专家计算（`README.md:279`），反向 `∂L/∂y=w·g`（复制=dispatch）、`∂L/∂w=<y,g>`（沿 k 归约=combine）。**纯语义/纯张量，H100 真机 ALL PASS**（`harness/exp_ep_backward_adjoint.{sh,py,out.txt}`）：单进程四条伴随恒等式 `<D(x),g>==<x,Dᵀ(g)>`、`<G(w),gw>==<w,Gᵀ(gw)>`、`<C(y),v>==<y,D(v)>` 与路由权重梯度对拍 autograd（fp64 ≤1e-12）；**8×H100 真机 NCCL 用真实 `refs.dispatch`** 跨 rank 验 `<D(x),g>==<x,Dᵀ(g)>`（100.3833==100.3833）与权重伴随（−18.4716==−18.4716）、复制语义 `Σrecv_w==degree·w`（平均 degree 3.328）。端到端 `EPBuffer` 反向 helper 依赖 NCCL ≥2.31 → 仅分析。
