这个专题拆解 DeepSeek 的 **Mega MoE**：把 **EP dispatch → linear1 → SwiGLU → linear2 → EP combine**
融合进**单个 mega-kernel**、并让 **NVLink 通信与 Tensor Core 计算重叠**的设计；
以及 MoE 的**反向**（weight-gradient / input-gradient 的 grouped GEMM）实现。

参考实现是 **DeepGEMM** 与 **DeepEP**。Mega MoE 主实现是 **SM100（Blackwell）专属**，
本机 H100 跑不了端到端，因此以源码精读 + 线上资料为主线，能跑的部分（grouped GEMM / backward）给实测。

- 配套代码：[`code/mega-moe/`](https://github.com/BlueSkyyyyyy/tech_record/tree/main/code/mega-moe)

[Mega Gate 的端到端验收测试与路由 oracle]({{< relref "mega-moe-57-mega-gate-test-oracle" >}}) —— 第 13 篇拆了 Mega Gate 的**实现**、第 51 篇拆了 Mega MoE 的测试，本篇补上 Mega Gate **自己的**验收测试 `tests/test_mega_gate.py`：它定义了「Mega Gate 的输出算什么对」。主体 kernel `sm100_bf16_mega_gate` 是 SM100 专属（`csrc/apis/mega_gate.hpp:159` 断言 `arch_major==10`），H100 跑不了；但它的**路由 oracle**全是纯 torch、架构无关。拆透判据：打分 `sqrt_softplus`（threshold-20 折衷，与 `F.softplus(·).sqrt()` 数值完全一致）、排名带 bias 而出权重用无 bias 的 `scores` 归一化（`scores/(sum+1e-20)*1.5`）、image token 的 bias 是**替换**不是叠加、top-k 选择用**结构无关的 crossing 不等式**验收（选中最小分 ≥ 未选中最大分，容差 `1e-5+1e-5·|ranking|max`）、判据是 `calc_diff<1e-11` 而非逐位（因参考 logits 走 `cublaslt_gemm_nt`）、logical→physical 逆映射 `p<E?p:p-E` 依赖 `make_physical_map` 的编号约定（副本槽=`E+logical`）、kernel 侧副本分散 `(rank+t·23333)%n_dup`、`force_random` 无放回采样、确定性模式从不 split K（逐位重复 10 次的根据）。**H100 真机 47 PASS/0 FAIL**：直接 import 真实 test 复用它的 helper，用一个完全正确的 torch 代理 gate 让判据 `weight_diff=0`，再用六类扰动反例（权重偏 1e-3 / 换专家 / 重复专家 / 忽略 image_bias / 漏归一化）证明判据真能抓错

[DeepEP combine 的归约 epilogue：top-k 去重、rank/topk 双布局与 bf16 直加旁路]({{< relref "mega-moe-58-deepep-combine-reduce" >}}) —— 补上第 7 篇只一笔带过的 combine 归约侧：EP 在「专家算完后把结果加回源 token」这一步的真实实现。两阶段设计——主 combine kernel 做通信搬运 + 本地归约，`combine_reduce_epilogue` 延迟到 compute stream 做跨 rank 求和（靠 **PDL** 与主 kernel 建立顺序，故 epilogue 里读 metadata **不能用 `__ldg`**）；两张布局由 `use_rank_layout = allow_multiple_reduction && num_ranks <= num_topk` 决定（rank 当外层维 vs topk 当外层维，主 kernel 与 epilogue 共用同一 constexpr）；top-k 去重用 `ptx::deduplicate`（`__match_any_sync` + `bfind.u32` 取组内最高 lane）+ `compute_topk_slots`（`__ffs` 从低位挤到前、`-1` 占位、`ldg_with_ge_pred` 谓词跳过越界）；`combine_reduce` 的两条路径——无 bias 且有效槽 ≤2 时 **bf16 直加旁路**（省两次类型转换），否则 **fp32 累加一次舍入**（`ptx::accumulate` 在 sm100 是融合 `add.rn.f32.bf16`、sm90 回退）。**H100 真机 16 PASS/0 FAIL**：直接 include 真实头文件、用真实对称 recv_buffer 跑真实 `combine_reduce_epilogue_impl`，rank/topk 两套布局的输出与 top-k 权重 vs 独立 oracle **逐位 0 不符**（含同 rank 重复 token 的去重）；并用 20 万随机样本坐实「≤2 槽时 bypass 与通用逐位一致、≥3 槽链式 bf16 有 22.1% 会偏」——这正是旁路卡在上界 2 的原因

[DeepEP 的设备端公共层：mbarrier、TMA、multimem、谓词化访存与内存序]({{< relref "mega-moe-59-deepep-ptx-primitives" >}}) —— 把 DeepEP **所有 kernel 共同踩的那层地板** `deep_ep/include/deep_ep/common/ptx.cuh`（612 行）及其同目录 `math.cuh`/`utils.cuh`/`layout/common/barrier.cuh` 系统讲透：前面第 7/11/53/58 篇里每一行 `mbarrier`/`cp.async`/`TMA`/`red.release.sys`/`__match_any_sync` 都源于此，却从没单独拆过。八组原语——① **mbarrier 五原语**与 DeepEP 特有的计数模型：`cp.async.mbarrier.arrive` **发射时 +1、完成时 −1**（净零但会「卡住」mbarrier 到拷贝完成），故 dispatch 的 mbarrier init count 是 **1** 而非线程数（`dispatch.cuh:273/309/353`）；② **三条搬运路径**：`tma_load_1d`（`shared::cluster` + `evict_first`）、`tma_store_1d`（`bulk_group` + `evict_normal`）、`tma_store_reduce_add_f32`（`cp.reduce.async.bulk…add.f32` 元素级归约，`reduce_grads`/`all_reduce` 靠它累加）；③ **NVLink 多播 `multimem.*`**（`ld_reduce.add`/`st`/`cp.async.bulk`）——`bucket/all_reduce/nvlink.cuh:44-50` 用它把每 rank 的 NVLink 流量从 O(N) 降到 O(1)；④ **谓词化访存**（`*_with_{ge,gt}_pred` + `ld.global.nc` + `L1::no_allocate` + L2 cache hint）+ 宿主 `iterate_ld_st` 的网格步进 + 尾部裁剪；⑤ **内存序阶梯**（`red`/`ld_acquire_sys`/`st_release_sys`/`st_relaxed_*`/`ld_volatile`）与「跨卡为什么必须 `sys`」；⑥ **`warpgroup_reg_realloc`**（`setmaxnreg`，sm90a 起）；⑦ **warp 内建**（`exchange`/`gather`/`match`/`deduplicate`/`get_master_lane_idx`=`bfind.u32`/`warp_*_sum`）；⑧ **浮点打包**（`fadd4`/`fmul4`/`accumulate` 的 SM100 packed 快路与 sm90 回退、`cvt_rs_bf16x2` 随机舍入）。另拆 `math.cuh` 的 `encode_decode_positive`（`-x-1` 对合，让「未就绪=0、已就绪=负数」，dispatch 跨 rank 计数就靠它）与 `BarrierSignals`（计数 + 双相位的免复位屏障布局）。**架构无关部分 H100 真机直接 include 真实头文件、跑真实设备代码 41 PASS / 0 FAIL**：mbarrier 相位翻转、TMA 载入/归约写、`cp.async` 计数模型、谓词裁剪、2000 轮 release-acquire 生产者-消费者坏数据=0、warp 内建逐项对拍、`setmaxnreg` 实跑；`multimem`/`cvt.rs` 只做语义 oracle（并实证 `cvt.rs` 在 `sm_90a` 被 ptxas 拒绝、`sm_100a` 通过）
