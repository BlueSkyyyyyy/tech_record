前七篇把五个方向拆开讲了。这一篇合起来，回答三个问题：

1. 哪些设计已经**收敛**（可以当默认值用）？
2. 哪些还在**分叉**（现在下注有风险）？
3. 2027 年最可能发生什么？

为了不让结论停留在「我感觉」，我先把 2026 年 8-11 月的 arXiv 结构类论文扫了一遍：20 组查询、去重后 2,756 篇语言模型相关论文，其中结构类 1,401 篇。这个数字后面还会用到——它说明**结构研究是个小体量、高杠杆的赛道**（约占 cs.CL + cs.LG 三个月投稿的 4.7%），但它的每一个收敛都会改变所有模型的成本结构。

## 0. 先记住一个画面

2023 年的结构研究像**重新发明发动机**：注意力能不能换掉、FFN 能不能换掉、残差能不能换掉。

2026 年的结构研究像**给同一台发动机换配件**：缸体（Transformer 骨架）不动，换的是涡轮（稀疏注意力）、喷油嘴（MoE 路由）、曲轴（残差流）、以及加一套新的进气系统（Engram）。

这不是贬义。**配件替换才是工程成熟的标志**——它意味着大家终于同意「哪些东西不能动」，然后把精力放在「哪些东西值得调」上。

> **类比的边界**：发动机的配件可以单独换、单独测；模型结构不行。换稀疏注意力会改变最优学习率，换优化器（Muon）会改变最优 batch size 甚至让 warmup 变得不必要。**结构、优化器、硬件是一个联合设计问题**，这也是 2026 年最重要的一条方法论变化。

## 1. 五个收敛

### 收敛一：注意力 = 少量全注意力 + 大量稀疏/压缩

四代注意力走完，2026 年的默认配方是：

- **全局层**：MLA 或共享 KV latent + 稀疏选择（top-k 512-2048）+ 压缩（$m=2$~128）+ 跨层共享；
- **局部层**：128 窗口的 SWA，负责精确的局部顺序；
- **索引器**：低精度（FP4）、少量头（32）、层次化候选。

关键数字：V4.1 的全局 KV 到 **890 B/token**，1M 上下文 933 MB；对比 Llama-3.1-405B 的 541 GB，**580 倍**。

这条已经收敛到「没有争议」：2026 年的旗舰里，没有一个是纯稠密全注意力的。

### 收敛二：序列混合 = 3:1 或 4:1 的线性 : 全注意力

Qwen3-Next、Qwen3.5/3.6/3.8、Kimi Linear/K3、Nemotron-H、Turing——全部是混合，比例集中在 3:1 到 4:1。

背后的算术很简单：**3:1 恰好等于 KV 只剩 1/4**。而消融显示收益很快饱和（Mamba-2 350M：0 层 8.60 → 6 层 8.26 → 24 层 8.50），所以「刚好够用」就是最优。

**纯线性已经退场**：三个月内没有任何纯 SSM 的 LLM 技术报告，全语料里 "attention-free / 纯 SSM" 只有 5 次命中。它不是被否定，是被混合吸收了。

### 收敛三：MoE = 细粒度 + sigmoid + bias 均衡 + 有界激活

- 打分：softmax → **sigmoid**（V3 起）→ sqrtsoftplus（V4）→ 分位数均衡（K3 的 QB）；
- 均衡：aux loss → **aux-loss-free bias**（但保留 $10^{-4}$ 兜底）；
- 结构：细粒度 + 共享专家 + **LatentMoE**（专家在 $d/2$ 的潜空间工作）；
- 激活：SwiGLU → **有界激活**（K3 的 SiTU-GLU，$\beta_1\beta_2=100$），因为 2.8T 参数下无界激活会爆。

专家数：256（V3）→ 384（K2/V4-Pro）→ **896（K3）**，top-k 8 → 6 → 16。

### 收敛四：残差流 = 加宽 + 约束

HC → mHC（双随机约束）→ Single-Pass mHC（访存砍半）→ AttnRes（深度注意力）→ MSAR/HiRes（多头、宽度解耦）。

这条收敛得最快：**2026 年下半年的新模型里，加宽残差流已经是标配**（Qwen3.8-Next 的 Gated Residual、Motif 3 的 modified mHC）。原因是它太便宜——参数 +0.03%、FLOPs +0.2%，只要把访存优化好就能白拿。

### 收敛五：位置 = 分层稀释

不再是「一个全局 base」，而是：

| 层型 | 位置方案 |
|---|---|
| SWA | RoPE base=1e4 |
| 压缩/全局 | RoPE base=1.6e5，只 64 维 |
| 线性层 | 无（decay 隐式） |
| 全局 MLA（K3） | **完全 NoPE** |

位置编码论文的数量在**下降**（三个月 50 篇，且大多被并入稀疏化/效率工作）。它不是不重要了，是**不再需要单独设计了**——位置需求被拆给最便宜的组件。

## 2. 三个分叉

### 分叉一：循环深度（looped depth）——最强的「后 Transformer」候选

这是 2026 年下半年**升温最快**的方向：提及量 8 月 9 篇 → 9 月 31 篇 → 10 月 51 篇（5.7 倍）。

证据很硬：

| 工作 | 规模 | 结果 |
|---|---|---|
| SMELT | **54B** | FLOP/参数/KV 三重匹配下省 6.8-18% 训练 FLOPs |
| Loop Scaling Laws | 万亿 token | 稀疏给 ~3× 激活效率、循环给 ~2× 总参数效率 |
| LOOM | 1.7B / 60B token | 9 loops：ppl 9.62 → 7.77 |
| Looped Done Right | 8BA0.8B | 比 112 层前馈 MoE 少 75% 常驻参数 |

但**收敛形态不是「深循环」**，而是「中段 loop 两次」这种温和版（SMELT 只 loop 中间一半层）。原因很实际：全循环会让残差方差爆炸、路由器跨 loop 选同一批专家（「专家选择坍缩」），要额外加残差缩放、每 loop 重注入输入、per-loop 路由器——**「loop 几次、loop 哪里」目前是配方，不是定律。**

### 分叉二：条件记忆（Engram）——容量故事成立，推理故事不成立

Engram 已经是**生产规模组件**（V4.1 的 196B 参数，移除它掉 36.8 PopQA）。但 2026 年下半年出现了三篇「拆台/补台」论文，结论是分裂的：

| 问题 | 证据 | 结论 |
|---|---|---|
| 能扩容吗 | 196B 参数、198 GB、12 KiB/token | ✅ 成立 |
| 能编辑吗 | EngramEdit 编辑成功率近满分，CoT 多跳 ~3× 基线 | ✅ 成立 |
| 能组合推理吗 | 写入覆盖率 98%（50 条事实）→ **12.7%**（1000 条）；两跳组合 26% vs 独立单跳期望 25% | ❌ **不成立** |

所以正确的说法是：**Engram 写入的是「可检索的原子」，不是「可组合的知识」。** 把容量故事和推理故事合并叙述，是 2026 年最容易被审稿人抓的错误。

### 分叉三：头粒度混合（head-wise hybrid）

2026 年出现了一类新做法：不再按**层**分配注意力类型，而是按**头**分配。

HwH 用两个干预指标（RFIS/RPD）把头分成「检索头」和「位置头」，然后让检索头用 NoPE 全注意力、位置头用线性注意力，FA:LA < 1:3，同时改善检索和零样本外推。NAMOH 更激进：把「头」当专家，每 token 只激活 $H$ 个头中的 $K$ 个。

**分叉点在于**：头功能分类是从 RoPE 频率推出来的，而旗舰正在往 NoPE/稀疏索引迁移——**分类前提可能随基座换代失效**。而且头粒度路由对 kernel 不友好，实际吞吐收益还没和理论对上。

## 3. 三个赌注（2027）

### 赌注一：索引器经济学

2026 年的竞争已经从 core attention 转到**索引器**：DSA 在 1M 时索引器占注意力 FLOPs 的 97%，于是有三条解法同时出现：

- **跨层共享**（CSA2、LatentIndex：索引缓存 −61.1%）；
- **层级/树状索引**（ZHA 亚二次、PISA $O(N\log N)$、LSA 聚类）；
- **索引器低精度**（FP4，68 B/条目）。

我的判断：**2027 年会出「索引器专用 kernel + 索引精度分级」的标准件**，就像 2023 年的 FlashAttention。理由：索引器现在是唯一还随 $N$ 线性增长的项，而它比 core attention 简单得多，最适合做硬件特化。

### 赌注二：记忆的 serving 栈

Engram 的 198 GB 表 + 12 KiB/token 随机读，和现有 serving 栈（连续批处理 + PagedAttention + prefix cache）**根本不兼容**：

- 表要跨卡切分，随机读要走 NVLink 或 CXL；
- 预取窗口有限（第 1 层只留一个 block），batch 越大越盖不住延迟；
- 表可以被编辑，于是有了「版本管理」问题。

我的判断：**2027 年会出现专门为「大表 + 稀疏查」设计的推理栈**（类似当年为 MoE 做的 EP），而且大概率从 DeepSeek 或 Kimi 的工程博客里先出来。

### 赌注三：循环深度会成为「第四根轴」

现在结构设计的三个轴是序列、宽度、深度。循环深度如果成立，会变成**第四根轴**（时间维：同一个 block 用几次）。

但我的下注是**温和版**：不是「无限循环」，而是「中段 loop 2 次 + per-loop 路由」。理由是 SMELT 的 54B 证据说明它在大规模上 work，而全循环的稳定性问题（方差爆炸、专家坍缩）在 2026 年还没被干净解决。

## 4. 一个不舒服的事实：谁在真正验证？

我把 1,401 篇结构论文里 822 篇的摘要规模统计了一遍：

| 最大验证规模 | 占比（有规模的 239 篇） |
|---|---|
| ≤1B | 18.8% |
| 1-3B | 14.6% |
| 3-8B | 34.3% |
| 8-30B | 15.9% |
| **≥30B** | **16.3%** |

三个结论：

1. **71% 的结构论文在摘要里根本不报规模**——这是「验证不可比」的根源；
2. 分布是**双峰**的：学术侧 ≤3B，工业侧 ≥30B，中间的 8-30B 最薄；
3. 更关键的是分界线在「新结构」和「改造旧模型」之间：本次选出的 12 篇「结构上真正有新东西」的论文里，**8 篇最大验证 ≤1.7B**；而所有 ≥30B 的结构证据**全部来自工业技术报告，且几乎都是「在既有架构上换配件」**。

配套数字：结构论文中 12.0% 是 training-free/post-hoc，9.0% 走蒸馏改造，只有 **6.3% 自称从头训练**。

**这意味着：2026 年你在 arXiv 上看到的「新结构」，绝大多数只在 1B 级验证过；真正上 30B 的，是工业界在成熟架构上换配件。** 这不是丑闻，是成本结构的必然——但它意味着「读论文选结构」时必须看规模，否则会把「1B 上的增益」当成「30B 上的增益」。

还有一条更隐蔽的：**结构结论和优化器耦合**。Qwen3.8-Next 的报告明确写：架构 + Muon 一起把最优学习率与 batch size 往上推，甚至让 batch-size warmup 变得不必要。也就是说，「结构 A 比 B 好」的结论，换优化器后可能翻转。

## 5. 选型决策树

如果你现在要从零设计一个模型，或者给现有模型换结构，按这个顺序问：

```
1. 上下文多长？
   ├─ < 32K：稠密 GQA + 标准 MoE 就够，别上稀疏注意力（索引器是净亏）
   └─ > 32K：
      ├─ decode 主导（服务）：3:1 线性混合，或 MLA + DSA
      └─ 1M + 高吞吐：CSA2 式跨层共享 + FP4 KV + 层次化索引器
2. 知识密集吗？
   └─ 是：加 Engram（但要接受 198 GB 常驻 + 12 KiB/token 随机读）
3. 训练预算紧、想加深度？
   └─ mHC / AttnRes（参数 +0.03%，先做访存优化）
4. 追求极致稀疏？
   └─ LatentMoE（专家在 d/2 潜空间），但必须配有界激活
```

**五个「别做」**：

1. 别做纯线性（检索塌方，NIAH 从 92 掉到 30）；
2. 别做纯 SSM（三个月零技术报告，已被混合吸收）；
3. 别上无索引器的稀疏注意力（top-k 需要索引器，索引器是 $O(N)$）；
4. 别在 <32K 上下文用稀疏注意力（索引器开销是净亏）；
5. 别把 Engram 当推理基底（它只保证「可检索」，不保证「可组合」）。

## 6. 结语

回到导读里的七个判断，逐条结账：

| 判断 | 结论 |
|---|---|
| 注意力竞争转到索引器 | ✅ 成立（DSA 1M 时索引器占 97%） |
| 纯线性不会回来，全注意力更少 | ✅ 成立（3:1 收敛，纯线性退场） |
| MoE 下一步是更小专家 + 更低精度 | ⚠️ 部分成立（LatentMoE 对，但 expert FFN 反而涨到 3072） |
| 残差加宽成标配 | ✅ 成立（Qwen3.8/Motif 3 已用） |
| 位置退化成少数层少数维 | ✅ 成立（K3 全 NoPE，V4.1 64 维） |
| 记忆成为第二条稀疏轴 | ⚠️ 分叉（容量成立，推理不成立） |
| 结构论文验证规模变小 | ✅ 成立（71% 不报规模，8/12 篇 ≤1.7B） |

七个里五个成立、两个要修正——这个命中率对一份写于 2026 年 11 月的预测来说，还算诚实。

最后说一句方法论。这九篇里，每一个数字都尽量能追溯到一个来源：论文的哪张表、config 的哪一行、代码的哪一行。**结构研究最容易犯的错，是把「论文里的一个漂亮数字」当成「生产上的一个可靠结论」。** 两者之间隔着规模、优化器、kernel 实现和 serving 栈——这个专题能做的，只是把账算清楚，让你知道每一步的代价记在哪个科目上。
