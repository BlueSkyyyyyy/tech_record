# 贪心：每一步都选「当前最好」

贪心（greedy）是一种很符合直觉的解题思路：**在每一步都做出当下看起来最优的选择，
并且做完就不再回头**。它不像动态规划那样保存所有中间状态、也不像回溯那样穷举所有分支，
而是沿着一条路一步走到底。写起来通常很短，往往是「排序 + 一次遍历」或「边走边维护几个变量」。

但贪心有个致命前提：**局部最优必须能推出全局最优**。这句话不是自动成立的，许多题用贪心
看似合理却会得到错误答案（例如「零钱兑换」若面额是 `[1, 3, 4]`、目标 6，贪心取 4 后还要
再凑 2，得到 3 枚，而最优是 3 + 3 共 2 枚）。所以在用贪心之前，必须能说清「为什么这么选
不会错过最优解」——常见的手段是**交换论证**：假设有一个最优解，如果它和贪心的选择不同，
就把它改造成贪心的样子，且不使答案变差，从而证明贪心解也是最优的。

本篇先用三道最基础的小题建立这种「选择 + 论证」的感觉：一道排序配对、一道边走边找零、
一道实时维护极值。

| 模式 | 题目 | 难度 |
|---|---|---|
| 模式一：排序 + 双指针配对 | 455. 分发饼干 | 简单 |
| 模式二：边走边做局部选择 | 860. 柠檬水找零 | 简单 |
| 模式三：一次遍历维护极值 | 121. 买卖股票的最佳时机 | 简单 |

三题的共同点是：**只扫一遍、只留几个变量、不做任何回溯**。区别在于每一步「选什么」不同。
读的时候请特别留意每题的「为什么贪心是对的」——那才是这道题真正的考点。

## 模式一：排序 + 双指针配对

**适用信号**：要把两堆东西配成尽可能多的对，配对条件是「一个够大、一个够小」，且每样东西
只能用一次。

**核心动作**：两堆都从小到大排序，然后双指针各扫各的：能用当前最小的去满足当前最小的需求
就配对成功，否则说明当前这个太小、对谁都无用，直接跳过。

### 455. 分发饼干（简单）

**题目**：有一群孩子和一堆饼干。数组 `g[i]` 是第 `i` 个孩子的胃口值，数组 `s[j]` 是第 `j`
块饼干的尺寸。只有当 `s[j] >= g[i]` 时，这块饼干才能喂饱这个孩子。求最多能满足多少个孩子。
每个孩子最多给一块饼干，每块饼干最多给一个孩子。

**思路**：

先把 `g` 和 `s` 都升序排序。然后用两个指针从前往后扫：

- 若当前饼干 `s[j] >= 当前孩子 g[i]`，就把它分给这个孩子，两个指针都前进；
- 否则这块饼干连当前胃口最小的孩子都喂不饱，对后面胃口更大的孩子更没用，直接舍弃，
  只让饼干指针前进。

循环结束时，成功配对的次数就是被满足的孩子数。

**为什么贪心是对的（交换论证）**：看任意一个最优分配方案。把两个人按胃口从小到大看，
最优方案一定可以整理成「让胃口最小的若干个孩子被满足，并且分给他们的饼干也按尺寸从小到大
配对」。假设有一块更小的饼干 `s[j]` 已经够喂饱当前最不挑食的孩子 `g[i]`，而某个方案却把一块
更大的饼干分给了他，那么我们把这大小两块饼干**对调**——小的那块照样喂饱这个孩子，大的那块
留给后面胃口更大的孩子只会更宽裕。对调后满足的人数不变，说明「能用小饼干就先用小饼干」
不会比最优解差。

**为什么排序之后一趟扫就够**：排序后，最不挑食的孩子和最小的饼干都排在最前面；随着配对推进，
两个指针都只朝一个方向移动，因此每个元素最多被看一次，不需要回头或嵌套循环。

**代码**（完整可运行版见 `src/greedy/assign_cookies.py` / `.cpp`）：

```python
def find_content_children(g, s):
    g.sort()
    s.sort()
    i = 0
    j = 0
    while i < len(g) and j < len(s):
        if s[j] >= g[i]:
            i += 1
            j += 1
        else:
            j += 1
    return i
```

```cpp
int findContentChildren(std::vector<int> g, std::vector<int> s) {
    std::sort(g.begin(), g.end());
    std::sort(s.begin(), s.end());
    int i = 0, j = 0;
    while (i < static_cast<int>(g.size()) && j < static_cast<int>(s.size())) {
        if (s[j] >= g[i]) {
            ++i;
            ++j;
        } else {
            ++j;
        }
    }
    return i;
}
```

- **复杂度**：时间 O(n log n + m log m)（`n`、`m` 分别是孩子数与饼干数，主要在排序），
  空间 O(1)（排序之外只用常数变量）。
- **易错点**：两个指针的含义要分清楚——`i` 指向当前最不挑食的孩子、`j` 指向当前最小的饼干，
  饼干不够大时只能 `j++`，别顺手把 `i` 也加了；循环条件要同时判 `i`、`j` 是否越界；
  Python 的 `list.sort()` 是原地排序、返回 `None`，不能写 `g = g.sort()`；
  C++ 传值是特意为之（避免改动调用方数组），若要省拷贝可传引用但在函数内自行复制。
- **相似题**：135. 分发糖果（每个孩子还要和邻居比较，靠两次遍历满足双向约束）；
  2410. 运动员和训练师的最大匹配数（同一套「排序 + 双指针配对」模板）；
  881. 救生艇（排序后从两端往中间配对，见数组与双指针篇）。

## 模式二：边走边做局部选择

**适用信号**：按某种顺序逐个处理，每一步都要做一个「怎么花掉手里的资源」的决定，且当场的
决定会影响后续。

**核心动作**：每一步都优先保留**更通用、更灵活**的资源，把**用途更单一**的资源先花掉。
这样后续遇到约束时选择余地最大。

### 860. 柠檬水找零（简单）

**题目**：每杯柠檬水售价 5 元，顾客只会递给你 5、10 或 20 元的钞票，你必须当场找零。
一开始你手头没有零钱。给定顾客付款顺序 `bills`，判断能否给每一位顾客都正确找零。

**思路**：

维护手头 5 元、10 元钞票的数量，逐个顾客处理：

- 收到 5 元：不需要找零，直接收下，`five++`；
- 收到 10 元：必须找回 5 元，所以 `five` 至少要有 1，然后 `five--`、`ten++`；
- 收到 20 元：需要找 15 元，有两种凑法——「一张 10 + 一张 5」或「三张 5」。贪心策略是
  **优先用 10 + 5**：只有 `ten` 和 `five` 都够时先用这种；否则再试 `five >= 3`；两种都
  做不到就返回失败。

**为什么优先花掉 10 元是对的（交换论证）**：面对一个 20 元顾客，如果「10+5」和「5+5+5」
两种找法都可行，用什么顺序花不影响当前顾客。但 5 元比 10 元更**灵活**：一张 5 元既能找给
10 元顾客，也能参与 20 元的找零；而一张 10 元只能用于 20 元顾客。所以用掉一张 10 元、
把 5 元留到后面，后续可选择的空间不会变小。反过来，如果明明能用 10+5 却硬花掉三张 5 元，
后面遇到 10 元顾客就可能无钱可找。因此「优先花 10 元」是安全的。

**为什么不需要考虑更大的面额**：题目里顾客只会付 5、10、20，找零最大也就 15 元，所以只需
关心 5 元和 10 元两种零钱的存量，20 元钞票收进来也无法用于找零（找给不了 20），不必计数。

**代码**（`src/greedy/lemonade_change.py` / `.cpp`）：

```python
def lemonade_change(bills):
    five = 0
    ten = 0
    for bill in bills:
        if bill == 5:
            five += 1
        elif bill == 10:
            if five == 0:
                return False
            five -= 1
            ten += 1
        else:
            if ten >= 1 and five >= 1:
                ten -= 1
                five -= 1
            elif five >= 3:
                five -= 3
            else:
                return False
    return True
```

```cpp
bool lemonadeChange(const std::vector<int> &bills) {
    int five = 0, ten = 0;
    for (int bill : bills) {
        if (bill == 5) {
            ++five;
        } else if (bill == 10) {
            if (five == 0) return false;
            --five;
            ++ten;
        } else {
            if (ten >= 1 && five >= 1) {
                --ten;
                --five;
            } else if (five >= 3) {
                five -= 3;
            } else {
                return false;
            }
        }
    }
    return true;
}
```

- **复杂度**：时间 O(n)（一次遍历），空间 O(1)（只数两种零钱的张数）。
- **易错点**：处理 20 元时**先试 10+5、再试 5+5+5**，顺序反过来就可能在不该失败的地方失败；
  收到 10 元却一张 5 元都没有时立即返回 `False`；不要给 20 元钞票计数（它不能用于找零，
  计了也没用）；Python 里判断用 `is True` / `is False` 只是为了更严格，实际返回布尔值即可。
- **相似题**：122. 买卖股票的最佳时机 II（把每天的正收益都吃掉，见动态规划篇）；
  452. 用最少数量的箭引爆气球（排序后贪心，见本分类后续）；
  406. 根据身高重建队列（贪心选择的顺序本身需要精心设计，见本分类后续）。

## 模式三：一次遍历维护极值

**适用信号**：答案和「某个位置的最优前缀信息」有关，且前缀信息可以用一个变量边走边更新。

**核心动作**：从左往右扫，用常数个变量记录「到当前为止的某种极值 / 最优解」，每读一个新元素
就用它更新这两个量。关键是**更新顺序**要与问题的因果方向一致。

### 121. 买卖股票的最佳时机（简单）

**题目**：给定数组 `prices`，`prices[i]` 表示第 `i` 天的股票价格。你只能选择某一天买入、
并在未来某一天卖出，最多完成一笔交易，求能获得的最大利润；若无法获利则返回 0。

**思路**：

只允许「先买后卖」，那么在第 `i` 天卖出能拿到的最大利润，就是 `prices[i]` 减去**第 `i` 天
之前出现过的最低价**。于是从左往右扫一遍，维护两个量：

- `min_price`：到目前为止见过的最低价格（即当前最佳买点）；
- `best`：到目前为止的最大利润。

每读到一天价格 `p`，先用 `p - min_price` 更新 `best`（把今天当作卖出日），再用 `p` 更新
`min_price`（今天也可以成为将来的买点）。**顺序不能反**：必须先用旧的最低价算利润、再更新
最低价，否则会把「今天买、今天卖」算进去，得到 0 而不是真实利润。

**为什么贪心是对的**：固定「卖出日」`i` 之后，能和它配对的最优买入日就是 `i` 之前价格最低
的那天——卖出价固定，买入价越低利润越大。所以枚举所有可能的卖出日、每个都配上它之前的历史
最低价，取最大值，就必然是全局最优。这本质上等价于「把每一天都当作买点试一遍」，只是用
`min_price` 把平方级的枚举压成了线性。

**与动态规划的关系**：本题也可以用状态机 DP 求解——用 `hold` / `cash` 两个状态边走边转移
（见动态规划篇）。两种做法都是 O(n) / O(1)，贪心版更直白，只维护一个最低价，是「一次遍历 +
维护极值」的典型模板；DP 版则更容易推广到「多笔交易」「含冷冻期」等变体。

**代码**（`src/greedy/best_time_to_buy_and_sell_stock.py` / `.cpp`）：

```python
def max_profit(prices):
    min_price = float("inf")
    best = 0
    for p in prices:
        best = max(best, p - min_price)
        min_price = min(min_price, p)
    return best
```

```cpp
int maxProfit(const std::vector<int> &prices) {
    int minPrice = INT_MAX;
    int best = 0;
    for (int p : prices) {
        best = std::max(best, p - minPrice);
        minPrice = std::min(minPrice, p);
    }
    return best;
}
```

- **复杂度**：时间 O(n)（一次遍历），空间 O(1)。
- **易错点**：**先算利润、再更新最低价**，两步顺序写反会得到错误的 0；初值 `best = 0`
  正好处理「全程下跌、无法获利返回 0」的情况，不必额外判断；最低价初值用无穷大
  （C++ 用 `INT_MAX`，需 `<climits>`）；`p - min_price` 是「今天卖出」的利润，别忘了。
- **相似题**：122 / 123 / 188 买卖股票系列（多次交易 / 限定笔数，见动态规划篇）；
  53. 最大子数组和（同样是「一次遍历维护局部最优 + 全局最优」，见分治与动态规划篇）；
  309 / 714（含冷冻期 / 含手续费的变体，见动态规划篇）。

## 规律总结

1. **贪心的两个动作**：定义一个「当前最优选择」的规则，再证明它不会让答案变差。规则通常是
   「排序后按序处理」「优先花掉不灵活的资源」「实时维护极值」；证明手段几乎都是**交换论证**
   ——假设最优解与贪心选择不同，把它改造成贪心的样子且不更差。

2. **贪心题常见的三种骨架**：
   - **排序 + 双指针**（455）：先排序，让「最优选择」排在最前面，然后一趟扫描配对；
   - **边走边做局部选择**（860）：逐个元素处理，每步优先保留用途更广的资源；
   - **一次遍历维护极值**（121）：用一个或几个变量记录前缀信息，边读边更新。

3. **「为什么不用贪心」和「为什么能用贪心」一样重要**：先想清楚局部最优是否能推出全局
   最优；不能时不要硬套。经典反例是零钱兑换（面额不规整时贪心会错），那类问题要用动态
   规划。**能用贪心时优先用**——它通常比 DP、回溯更简单、更快。

4. **贪心与排序的关系**：多数贪心题的「选谁先处理」需要一个合理的顺序，而排序常常就是
   产生这个顺序的手段（455 按胃口/尺寸排序，后续的区间题按右端点、按身高排序）。顺序选错，
   贪心就会失效。

5. **贪心常常是某个 DP 的简化版**：121 的贪心解和它的 DP 解复杂度相同，只是省去了状态
   定义；一旦问题增加约束（多笔交易、有冷冻期），贪心往往不再适用，得退回 DP。遇到「贪心
   想不到证明」时，退回 DP 或回溯也常能拿到正确答案。

6. **本专题的贪心才刚起步**：区间类的「按右端点排序选最早结束」、跳跃游戏的「最远可达
   位置」、加油站/划分字母区间等，都是同一套「选择 + 论证」的延伸，将在后续子篇里补齐。
