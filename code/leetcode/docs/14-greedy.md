# 贪心：每一步都选「当前最好」

贪心（greedy）是一种很符合直觉的解题思路：**在每一步都做出当下看起来最优的选择，
并且做完就不再回头**。它不像动态规划那样保存所有中间状态、也不像回溯那样穷举所有分支，
而是沿着一条路一步走到底。写起来通常很短，往往是「排序 + 一次遍历」或「边走边维护几个变量」。

但贪心有个致命前提：**局部最优必须能推出全局最优**。这句话不是自动成立的，许多题用贪心
看似合理却会得到错误答案（例如「零钱兑换」若面额是 `[1, 3, 4]`、目标 6，贪心取 4 后还要
再凑 2，得到 3 枚，而最优是 3 + 3 共 2 枚）。所以在用贪心之前，必须能说清「为什么这么选
不会错过最优解」——常见的手段是**交换论证**：假设有一个最优解，如果它和贪心的选择不同，
就把它改造成贪心的样子，且不使答案变差，从而证明贪心解也是最优的。

本篇用十道题，从最基础的三道开始，逐步走到区间调度、跳跃游戏、环形加油站和按身高重建队列，
建立这种「选择 + 论证」的感觉，并覆盖贪心题最常见的几种骨架。

这些题共同点是：**只扫一遍（最多加一次排序）、只留几个变量、不做任何回溯**，区别在于每一步
「选什么」以及「按什么顺序处理」。读的时候请特别留意每题的「为什么贪心是对的」——那才是这道题
真正的考点。

## 模式一：排序 + 双指针配对

**适用信号**：要把两堆东西配成尽可能多的对，配对条件是「一个够大、一个够小」，且每样东西
只能用一次。

**核心动作**：两堆都从小到大排序，然后双指针各扫各的：能用当前最小的去满足当前最小的需求
就配对成功，否则说明当前这个太小、对谁都无用，直接跳过。

### 455. 分发饼干（简单）

**题目**：有一群孩子和一堆饼干。数组 `g[i]` 是第 `i` 个孩子的胃口值，数组 `s[j]` 是第 `j`
块饼干的尺寸。只有当 `s[j] >= g[i]` 时，这块饼干才能喂饱这个孩子。求最多能满足多少个孩子。
每个孩子最多给一块饼干，每块饼干最多给一个孩子。

**思路**：

先把 `g` 和 `s` 都升序排序。然后用两个指针从前往后扫：

- 若当前饼干 `s[j] >= 当前孩子 g[i]`，就把它分给这个孩子，两个指针都前进；
- 否则这块饼干连当前胃口最小的孩子都喂不饱，对后面胃口更大的孩子更没用，直接舍弃，
  只让饼干指针前进。

循环结束时，成功配对的次数就是被满足的孩子数。

**为什么贪心是对的（交换论证）**：看任意一个最优分配方案。把两个人按胃口从小到大看，
最优方案一定可以整理成「让胃口最小的若干个孩子被满足，并且分给他们的饼干也按尺寸从小到大
配对」。假设有一块更小的饼干 `s[j]` 已经够喂饱当前最不挑食的孩子 `g[i]`，而某个方案却把一块
更大的饼干分给了他，那么我们把这大小两块饼干**对调**——小的那块照样喂饱这个孩子，大的那块
留给后面胃口更大的孩子只会更宽裕。对调后满足的人数不变，说明「能用小饼干就先用小饼干」
不会比最优解差。

**为什么排序之后一趟扫就够**：排序后，最不挑食的孩子和最小的饼干都排在最前面；随着配对推进，
两个指针都只朝一个方向移动，因此每个元素最多被看一次，不需要回头或嵌套循环。

**代码**（完整可运行版见 `src/greedy/assign_cookies.py` / `.cpp`）：

```python
def find_content_children(g, s):
    g.sort()
    s.sort()
    i = 0
    j = 0
    while i < len(g) and j < len(s):
        if s[j] >= g[i]:
            i += 1
            j += 1
        else:
            j += 1
    return i
```

```cpp
int findContentChildren(std::vector<int> g, std::vector<int> s) {
    std::sort(g.begin(), g.end());
    std::sort(s.begin(), s.end());
    int i = 0, j = 0;
    while (i < static_cast<int>(g.size()) && j < static_cast<int>(s.size())) {
        if (s[j] >= g[i]) {
            ++i;
            ++j;
        } else {
            ++j;
        }
    }
    return i;
}
```

- **复杂度**：时间 O(n log n + m log m)（`n`、`m` 分别是孩子数与饼干数，主要在排序），
  空间 O(1)（排序之外只用常数变量）。
- **易错点**：两个指针的含义要分清楚——`i` 指向当前最不挑食的孩子、`j` 指向当前最小的饼干，
  饼干不够大时只能 `j++`，别顺手把 `i` 也加了；循环条件要同时判 `i`、`j` 是否越界；
  Python 的 `list.sort()` 是原地排序、返回 `None`，不能写 `g = g.sort()`；
  C++ 传值是特意为之（避免改动调用方数组），若要省拷贝可传引用但在函数内自行复制。
- **相似题**：135. 分发糖果（每个孩子还要和邻居比较，靠两次遍历满足双向约束）；
  2410. 运动员和训练师的最大匹配数（同一套「排序 + 双指针配对」模板）；
  881. 救生艇（排序后从两端往中间配对，见数组与双指针篇）。

## 模式二：边走边做局部选择

**适用信号**：按某种顺序逐个处理，每一步都要做一个「怎么花掉手里的资源」的决定，且当场的
决定会影响后续。

**核心动作**：每一步都优先保留**更通用、更灵活**的资源，把**用途更单一**的资源先花掉。
这样后续遇到约束时选择余地最大。

### 860. 柠檬水找零（简单）

**题目**：每杯柠檬水售价 5 元，顾客只会递给你 5、10 或 20 元的钞票，你必须当场找零。
一开始你手头没有零钱。给定顾客付款顺序 `bills`，判断能否给每一位顾客都正确找零。

**思路**：

维护手头 5 元、10 元钞票的数量，逐个顾客处理：

- 收到 5 元：不需要找零，直接收下，`five++`；
- 收到 10 元：必须找回 5 元，所以 `five` 至少要有 1，然后 `five--`、`ten++`；
- 收到 20 元：需要找 15 元，有两种凑法——「一张 10 + 一张 5」或「三张 5」。贪心策略是
  **优先用 10 + 5**：只有 `ten` 和 `five` 都够时先用这种；否则再试 `five >= 3`；两种都
  做不到就返回失败。

**为什么优先花掉 10 元是对的（交换论证）**：面对一个 20 元顾客，如果「10+5」和「5+5+5」
两种找法都可行，用什么顺序花不影响当前顾客。但 5 元比 10 元更**灵活**：一张 5 元既能找给
10 元顾客，也能参与 20 元的找零；而一张 10 元只能用于 20 元顾客。所以用掉一张 10 元、
把 5 元留到后面，后续可选择的空间不会变小。反过来，如果明明能用 10+5 却硬花掉三张 5 元，
后面遇到 10 元顾客就可能无钱可找。因此「优先花 10 元」是安全的。

**为什么不需要考虑更大的面额**：题目里顾客只会付 5、10、20，找零最大也就 15 元，所以只需
关心 5 元和 10 元两种零钱的存量，20 元钞票收进来也无法用于找零（找给不了 20），不必计数。

**代码**（`src/greedy/lemonade_change.py` / `.cpp`）：

```python
def lemonade_change(bills):
    five = 0
    ten = 0
    for bill in bills:
        if bill == 5:
            five += 1
        elif bill == 10:
            if five == 0:
                return False
            five -= 1
            ten += 1
        else:
            if ten >= 1 and five >= 1:
                ten -= 1
                five -= 1
            elif five >= 3:
                five -= 3
            else:
                return False
    return True
```

```cpp
bool lemonadeChange(const std::vector<int> &bills) {
    int five = 0, ten = 0;
    for (int bill : bills) {
        if (bill == 5) {
            ++five;
        } else if (bill == 10) {
            if (five == 0) return false;
            --five;
            ++ten;
        } else {
            if (ten >= 1 && five >= 1) {
                --ten;
                --five;
            } else if (five >= 3) {
                five -= 3;
            } else {
                return false;
            }
        }
    }
    return true;
}
```

- **复杂度**：时间 O(n)（一次遍历），空间 O(1)（只数两种零钱的张数）。
- **易错点**：处理 20 元时**先试 10+5、再试 5+5+5**，顺序反过来就可能在不该失败的地方失败；
  收到 10 元却一张 5 元都没有时立即返回 `False`；不要给 20 元钞票计数（它不能用于找零，
  计了也没用）；Python 里判断用 `is True` / `is False` 只是为了更严格，实际返回布尔值即可。
- **相似题**：122. 买卖股票的最佳时机 II（把每天的正收益都吃掉，见动态规划篇）；
  452. 用最少数量的箭引爆气球（排序后贪心，见本分类后续）；
  406. 根据身高重建队列（贪心选择的顺序本身需要精心设计，见本分类后续）。

## 模式三：一次遍历维护极值

**适用信号**：答案和「某个位置的最优前缀信息」有关，且前缀信息可以用一个变量边走边更新。

**核心动作**：从左往右扫，用常数个变量记录「到当前为止的某种极值 / 最优解」，每读一个新元素
就用它更新这两个量。关键是**更新顺序**要与问题的因果方向一致。

### 121. 买卖股票的最佳时机（简单）

**题目**：给定数组 `prices`，`prices[i]` 表示第 `i` 天的股票价格。你只能选择某一天买入、
并在未来某一天卖出，最多完成一笔交易，求能获得的最大利润；若无法获利则返回 0。

**思路**：

只允许「先买后卖」，那么在第 `i` 天卖出能拿到的最大利润，就是 `prices[i]` 减去**第 `i` 天
之前出现过的最低价**。于是从左往右扫一遍，维护两个量：

- `min_price`：到目前为止见过的最低价格（即当前最佳买点）；
- `best`：到目前为止的最大利润。

每读到一天价格 `p`，先用 `p - min_price` 更新 `best`（把今天当作卖出日），再用 `p` 更新
`min_price`（今天也可以成为将来的买点）。**顺序不能反**：必须先用旧的最低价算利润、再更新
最低价，否则会把「今天买、今天卖」算进去，得到 0 而不是真实利润。

**为什么贪心是对的**：固定「卖出日」`i` 之后，能和它配对的最优买入日就是 `i` 之前价格最低
的那天——卖出价固定，买入价越低利润越大。所以枚举所有可能的卖出日、每个都配上它之前的历史
最低价，取最大值，就必然是全局最优。这本质上等价于「把每一天都当作买点试一遍」，只是用
`min_price` 把平方级的枚举压成了线性。

**与动态规划的关系**：本题也可以用状态机 DP 求解——用 `hold` / `cash` 两个状态边走边转移
（见动态规划篇）。两种做法都是 O(n) / O(1)，贪心版更直白，只维护一个最低价，是「一次遍历 +
维护极值」的典型模板；DP 版则更容易推广到「多笔交易」「含冷冻期」等变体。

**代码**（`src/greedy/best_time_to_buy_and_sell_stock.py` / `.cpp`）：

```python
def max_profit(prices):
    min_price = float("inf")
    best = 0
    for p in prices:
        best = max(best, p - min_price)
        min_price = min(min_price, p)
    return best
```

```cpp
int maxProfit(const std::vector<int> &prices) {
    int minPrice = INT_MAX;
    int best = 0;
    for (int p : prices) {
        best = std::max(best, p - minPrice);
        minPrice = std::min(minPrice, p);
    }
    return best;
}
```

- **复杂度**：时间 O(n)（一次遍历），空间 O(1)。
- **易错点**：**先算利润、再更新最低价**，两步顺序写反会得到错误的 0；初值 `best = 0`
  正好处理「全程下跌、无法获利返回 0」的情况，不必额外判断；最低价初值用无穷大
  （C++ 用 `INT_MAX`，需 `<climits>`）；`p - min_price` 是「今天卖出」的利润，别忘了。
- **相似题**：122 / 123 / 188 买卖股票系列（多次交易 / 限定笔数，见动态规划篇）；
  53. 最大子数组和（同样是「一次遍历维护局部最优 + 全局最优」，见分治与动态规划篇）；
  309 / 714（含冷冻期 / 含手续费的变体，见动态规划篇）。

## 模式四：按右端点排序的区间贪心

**适用信号**：给一堆区间，要求「挑出尽量多互不重叠的区间」或「用尽量少的点覆盖所有区间」，
以及它们的各种换皮。

**核心动作**：把所有区间按**右端点**升序排序，然后从左往右扫，维护「上一次选择结束的位置」。
右端点越小，右边留下的空闲空间就越大，所以永远优先选**结束最早**的区间，或把覆盖点放在
**右端点**上。

### 435. 无重叠区间（中等）

**题目**：给定区间的集合 `intervals`，返回需要移除区间的最小数量，使剩余区间互不重叠。
端点相接不算重叠（`[1,2]` 与 `[2,3]` 不冲突）。

**思路**：

「删掉的区间最少」等价于「保留的互不重叠区间最多」。把区间按右端点从小到大排序，然后从左往右
扫，维护上一个被保留区间的右端点 `end`：

- 若当前区间的左端点 `>= end`，它和已保留的区间不冲突，保留它，更新 `end`；
- 否则它与已保留的区间重叠，只能删掉，`removed++`。

**为什么贪心是对的（交换论证）**：设最优方案保留的第一个区间是 `A`，而按右端点排序后的第一个
区间是 `B`。由于排序，`B` 的右端点不大于 `A` 的右端点。把最优方案里的 `A` 换成 `B`：`B` 结束
得更早，它右边能容纳的区间只会比 `A` 更多，不会更少。所以「每次保留结束最早、且不和前面冲突的
区间」不会让保留数变少。区间已按右端点排序，一趟扫下来即可。

**代码**（`src/greedy/non_overlapping_intervals.py` / `.cpp`）：

```python
def erase_overlap_intervals(intervals):
    if not intervals:
        return 0
    intervals.sort(key=lambda x: x[1])
    end = intervals[0][1]
    removed = 0
    for i in range(1, len(intervals)):
        if intervals[i][0] < end:
            removed += 1
        else:
            end = intervals[i][1]
    return removed
```

```cpp
int eraseOverlapIntervals(std::vector<std::vector<int>> intervals) {
    if (intervals.empty()) return 0;
    std::sort(intervals.begin(), intervals.end(),
              [](const std::vector<int> &a, const std::vector<int> &b) {
                  return a[1] < b[1];
              });
    int end = intervals[0][1];
    int removed = 0;
    for (int i = 1; i < static_cast<int>(intervals.size()); ++i) {
        if (intervals[i][0] < end) {
            ++removed;
        } else {
            end = intervals[i][1];
        }
    }
    return removed;
}
```

- **复杂度**：时间 O(n log n)（排序），空间 O(1)。
- **易错点**：按**右端点**排序而不是左端点——按左端点排会漏掉最优；端点相接不算重叠，
  所以冲突判断用严格 `<` 而不是 `<=`；注意 `end` 初始化为第一个区间的右端点，
  循环从第二个区间开始，别把第一个区间也当成「待判断」重复计数。
- **相似题**：
  452. 用最少数量的箭引爆气球（同一个「按右端点排序」的孪生题，见下）；
  646. 最长数对链（求最多能选多少对不重叠，是本题的正面问法）；
  763. 划分字母区间（本质也是区间调度，见模式六）。

### 452. 用最少数量的箭引爆气球（中等）

**题目**：每个气球用区间 `points[i] = [x_start, x_end]` 表示它覆盖的 x 轴范围。一支箭竖直射
在位置 `x`，若 `x` 落在某气球区间内则该气球被引爆。求引爆所有气球所需的最少箭数。

**思路**：

要让箭尽可能少，每支箭就应该尽量多穿几个气球。把所有气球按右端点排序，先射一支箭在第一个
气球的右端点，然后从左往右扫：

- 若当前气球的左端点 `<=` 当前箭位置，说明这支箭也能射中它，不用新箭；
- 若当前气球的左端点 `>` 当前箭位置，说明它完全在这支箭右边、射不到，必须再射一支，并把箭
  挪到这个气球的右端点。

**为什么贪心是对的（交换论证）**：按右端点排序后第一个气球右端为 `e`，任何最优方案里射中它的箭
位置 `p` 必满足 `p <= e`。把箭从 `p` 平移到 `e`：这个气球照样被射中；而由于排序后所有气球的
右端点都不小于 `e`、且与 `p` 有公共点的气球其左端点 `<= p`,所以这些气球也一定包含 `e`。因此
第一支箭放在 `e` 不影响最优性，对剩余气球重复该论证即可。

**代码**（`src/greedy/minimum_number_of_arrows.py` / `.cpp`）：

```python
def find_min_arrow_shots(points):
    if not points:
        return 0
    points.sort(key=lambda x: x[1])
    arrows = 1
    end = points[0][1]
    for start, finish in points:
        if start > end:
            arrows += 1
            end = finish
    return arrows
```

```cpp
int findMinArrowShots(std::vector<std::vector<int>> points) {
    if (points.empty()) return 0;
    std::sort(points.begin(), points.end(),
              [](const std::vector<int> &a, const std::vector<int> &b) {
                  return a[1] < b[1];
              });
    int arrows = 1;
    int end = points[0][1];
    for (const auto &p : points) {
        if (p[0] > end) {
            ++arrows;
            end = p[1];
        }
    }
    return arrows;
}
```

- **复杂度**：时间 O(n log n)（排序），空间 O(1)。
- **易错点**：判断「射不到」用的是 `start > end` 的严格大于——区间是闭的，箭落在端点上算射中，
  所以端点重合（`start == end`）不新增箭；`arrows` 从 1 开始（第一个气球至少要一支箭）。
- **相似题**：435. 无重叠区间（把「覆盖」反过来看就是「不重叠」，见上）；
  757. 设置交集大小至少为 2（每段要放两个点，是本题加强版）。

## 模式五：维护「能到达的最远位置」

**适用信号**：从起点出发、每个位置能向前推进一段距离，问「能不能到终点」或「最少几步到终点」。

**核心动作**：从左往右扫，用一个变量记录「当前能到达的最远下标」。能不能到某个位置，只看它
是否落在可达范围内；每到一个新位置，就尝试把可达右边界继续往右推。

### 55. 跳跃游戏（中等）

**题目**：给定非负数组 `nums`，从第一个下标出发，每个元素表示该位置能跳跃的最大长度。判断
能否到达最后一个下标。

**思路**：

从左往右扫，用 `reach` 记录当前能到达的最远下标：

- 若当前位置 `i > reach`，说明这个位置根本走不到，返回 `False`；
- 否则用 `i + nums[i]` 更新 `reach`。

**为什么贪心是对的**：能不能到达某个位置，只取决于它是否落在可达范围内，与「具体怎么跳过来」
无关。只要当前位置可达，从它出发就能把右边界推到 `i + nums[i]`。我们不断把右边界往右推，
推到哪里，就代表那之前的每个位置都可达。因此只需要维护这一个最远可达点。

**代码**（`src/greedy/jump_game.py` / `.cpp`）：

```python
def can_jump(nums):
    reach = 0
    for i, step in enumerate(nums):
        if i > reach:
            return False
        reach = max(reach, i + step)
    return True
```

```cpp
bool canJump(const std::vector<int> &nums) {
    int reach = 0;
    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        if (i > reach) return false;
        reach = std::max(reach, i + nums[i]);
    }
    return true;
}
```

- **复杂度**：时间 O(n)，空间 O(1)。
- **易错点**：`reach` 是「能到达的最远下标」，不是「剩余步数」，两者别混；判断用 `i > reach`
  （走不到）而不是 `i >= reach`；注意是从可达范围内的**每个**位置都尝试扩展右边界，而不是只从
  起点或某个固定点跳。
- **相似题**：45. 跳跃游戏 II（在本题基础上求最少步数，见下）；
  1306. 跳跃游戏 III（能往左右跳，退化成网格/图 BFS）；
  1345. 跳跃游戏 IV（等值跳跃，用 BFS 求最短路）。

### 45. 跳跃游戏 II（中等）

**题目**：同 55，但保证一定能到达终点，求到达最后一个下标的最少跳跃次数。

**思路**：

把过程看成 BFS 分层：第 0 层是起点，第 1 层是「跳 1 次能到达的所有位置」，第 2 层是「跳 2 次
能到达的所有位置」……同一层代价相同，每跨过一层边界，跳跃次数就 +1。用两个变量：

- `cur_end`：当前这一层能到达的最远下标（本层边界）；
- `farthest`：扫描本层过程中看到的、下一层能到达的最远下标。

从左往右扫到倒数第二个位置（终点不用再跳）：每到一个位置就用 `i + nums[i]` 更新 `farthest`；
当 `i == cur_end` 时说明本层扫完，`jumps++` 并把 `cur_end` 更新为 `farthest`。

**为什么贪心是对的**：每一层代表「用当前步数能到达的全部位置」，我们总是把下一层的右边界扩张
到最远。这样下一次跨层时，用同样的步数覆盖的范围最大，所以到达终点所需的层数（跳跃数）最少。
这正是「最少步数 BFS」的贪心本质。

**代码**（`src/greedy/jump_game_ii.py` / `.cpp`）：

```python
def jump(nums):
    n = len(nums)
    if n <= 1:
        return 0
    jumps = 0
    cur_end = 0
    farthest = 0
    for i in range(n - 1):
        farthest = max(farthest, i + nums[i])
        if i == cur_end:
            jumps += 1
            cur_end = farthest
    return jumps
```

```cpp
int jump(const std::vector<int> &nums) {
    int n = static_cast<int>(nums.size());
    if (n <= 1) return 0;
    int jumps = 0;
    int curEnd = 0;
    int farthest = 0;
    for (int i = 0; i < n - 1; ++i) {
        farthest = std::max(farthest, i + nums[i]);
        if (i == curEnd) {
            ++jumps;
            curEnd = farthest;
        }
    }
    return jumps;
}
```

- **复杂度**：时间 O(n)，空间 O(1)。
- **易错点**：循环只到 `n - 1`（最后一个位置不用再跳，否则可能多算一步）；`cur_end` 和
  `farthest` 分工要清楚——不要在没走到层边界时就提前 `jumps++`；长度为 1 时返回 0。
- **相似题**：55. 跳跃游戏（只问可行性，见上）；1024. 视频拼接、1326. 灌溉花园的最少水龙头
  数目（都是「用区间覆盖一段」的最少个数版本）。

## 模式六：边扫描边结算（重置起点 / 切分）

**适用信号**：一串数据按顺序处理，每读一部分就累积一个「代价 / 覆盖范围」，一旦越过某个
临界点，就在这里做一个「结算」——要么重置起点重新开始，要么切一刀分出一段。

**核心动作**：维护一个累积量（油箱余额、当前片段必须延伸到的右端），当它「由负转正」或
「扫到边界」时结算，并把状态复位。

### 134. 加油站（中等）

**题目**：环形路上有 `n` 个加油站，第 `i` 站有 `gas[i]` 升油，从第 `i` 站开到第 `i+1` 站耗
`cost[i]` 升油，油箱无限大、初始为空。求能绕环路行驶一周的出发站编号（有解则唯一），否则
返回 -1。

**思路**：

把每站看成净收益 `diff[i] = gas[i] - cost[i]`。绕一圈能完成等价于所有 `diff` 之和 `>= 0`；
若总和为负，无论从哪出发都不够，直接返回 -1。判断有余：

- `total` 累加所有 `diff`，用于判断整体是否有解；
- `tank` 记录从当前候选起点到现在的油箱余额；
- 若 `tank < 0`，说明从当前起点到此撑不过，于是把起点设为 `i + 1`、`tank` 清零重来。

最后 `total >= 0` 时，记录的起点就是答案（题目保证有解时唯一）。

**为什么「tank 变负就把起点跳到 i+1」是对的**：设当前起点为 `s`，从 `s` 到 `i` 的净油量之和
为负。那么对 `s` 与 `i` 之间的任意站 `j`，从 `s` 到 `j` 的净油量都是正的（否则起点早就跳过
去了）；设这段正余量为 `P > 0`，则从 `j+1` 到 `i` 的净油量 `< -P < 0`，也就是从 `j` 出发同样
会在到达 `i` 之前耗尽。所以 `s..i` 之间没有可行起点，整段跳过、从 `i+1` 重来，不会漏解。

**代码**（`src/greedy/gas_station.py` / `.cpp`）：

```python
def can_complete_circuit(gas, cost):
    total = 0
    tank = 0
    start = 0
    for i in range(len(gas)):
        diff = gas[i] - cost[i]
        total += diff
        tank += diff
        if tank < 0:
            start = i + 1
            tank = 0
    return start if total >= 0 else -1
```

```cpp
int canCompleteCircuit(const std::vector<int> &gas, const std::vector<int> &cost) {
    int total = 0;
    int tank = 0;
    int start = 0;
    int n = static_cast<int>(gas.size());
    for (int i = 0; i < n; ++i) {
        int diff = gas[i] - cost[i];
        total += diff;
        tank += diff;
        if (tank < 0) {
            start = i + 1;
            tank = 0;
        }
    }
    return total >= 0 ? start : -1;
}
```

- **复杂度**：时间 O(n)，空间 O(1)。
- **易错点**：`total` 与 `tank` 是两个不同的量——`total` 判断全局有没有解，`tank` 用来找起点；
  重置时是 `start = i + 1` 而不是 `i`；起点可能落到 `n`（理论上会绕回，但有解时不会出现）。
- **相似题**：53. 最大子数组和（同样是「前缀和变负就丢弃、重新开始」的思想，见分治与动态规划
  篇）；763. 划分字母区间（下面一题，也是扫描到临界点就结算）。

### 763. 划分字母区间（中等）

**题目**：把字符串 `s` 划分成尽可能多的片段，同一字母最多出现在一个片段中，返回各片段长度。

**思路**：

同一个字母不能跨片段，所以一个片段一旦包含某字母，就必须延伸到该字母最后出现的位置。
先扫一遍记下每个字母最后出现的下标 `last[c]`；再从左往右扫，用 `start`、`end` 标记当前片段
的起点和「必须延伸到的右端」：

- 每读到一个字母，把它的 `last[c]` 并入 `end`（取较大者）；
- 当扫描下标 `i == end`，说明当前片段内所有字母都不会再往右出现，可以在此切一刀，记录长度
  `end - start + 1`，并把 `start` 移到 `i + 1`。

**为什么这样能切出尽可能多的片段**：每个片段的结束位置有硬性下界——必须覆盖其中所有字母的
最后出现位置。我们在满足约束的前提下**尽早切分**（一碰到 `i == end` 就切），于是每段尽量短、
段数尽量多，且不会让任何字母跨越切点。

**代码**（`src/greedy/partition_labels.py` / `.cpp`）：

```python
def partition_labels(s):
    last = {c: i for i, c in enumerate(s)}
    result = []
    start = 0
    end = 0
    for i, c in enumerate(s):
        end = max(end, last[c])
        if i == end:
            result.append(end - start + 1)
            start = i + 1
    return result
```

```cpp
std::vector<int> partitionLabels(const std::string &s) {
    int last[26];
    std::fill(last, last + 26, -1);
    for (int i = 0; i < static_cast<int>(s.size()); ++i) {
        last[s[i] - 'a'] = i;
    }
    std::vector<int> result;
    int start = 0, end = 0;
    for (int i = 0; i < static_cast<int>(s.size()); ++i) {
        end = std::max(end, last[s[i] - 'a']);
        if (i == end) {
            result.push_back(end - start + 1);
            start = i + 1;
        }
    }
    return result;
}
```

- **复杂度**：时间 O(n)（两趟线性扫描），空间 O(1)（字母表大小视为常数）。
- **易错点**：`end` 要不断取 `max`，不能直接赋值成当前字母的 `last`（否则会把之前字母的右界
  缩小）；切分条件是 `i == end` 而不是 `i >= end`；C++ 若用 `-1` 初始化 `last` 需注意字符串只含
  小写字母。
- **相似题**：435. 无重叠区间（把「字母的出现范围」看成区间，就是区间调度，见模式四）；
  56. 合并区间（先合并再统计，思路相近，见数组与双指针篇）。

## 模式七：先排序，再按规则重构

**适用信号**：要还原一个满足若干「相对关系约束」的排列，而约束只和「比自己高 / 大」的元素有关。

**核心动作**：按约束里那个**主导维度**（通常是身高/大小）从大到小排序，让高个子先就位，
再依次把每个人插到它要求的位置上——后插入的矮个子不会影响已就位者的相对关系。

### 406. 根据身高重建队列（中等）

**题目**：每个人用 `(h, k)` 表示，`h` 是身高，`k` 是这个人**前面**身高**大于或等于** `h` 的
人数。请重建队列，使每个人都满足自己的 `k`。

**思路**：

身高高的人更不受矮个子影响，所以先安排高个子：

1. 所有人按身高 `h` 从大到小排序；身高相同时，按 `k` 从小到大排序；
2. 依次把每个人插入到结果队列下标为 `k` 的位置。

**为什么贪心是对的**：处理到某个人时，队列里已经全是「身高 >= 他」的人（更高的先处理，同高的
按 `k` 升序也排在前面）。把他插到下标 `k`，恰好有 `k` 个不矮于他的人在他前面；之后再插入的
都是更矮的人，无论插在他前还是后，都不算进「>= h」的计数，所以不会破坏他的 `k`。身高相同时
按 `k` 升序，是为了让 `k` 小的先占前位、后插的 `k` 大的自然落到后面，互相不干扰。

**代码**（`src/greedy/queue_reconstruction_by_height.py` / `.cpp`）：

```python
def reconstruct_queue(people):
    people.sort(key=lambda x: (-x[0], x[1]))
    result = []
    for person in people:
        result.insert(person[1], person)
    return result
```

```cpp
std::vector<std::vector<int>> reconstructQueue(std::vector<std::vector<int>> people) {
    std::sort(people.begin(), people.end(),
              [](const std::vector<int> &a, const std::vector<int> &b) {
                  if (a[0] != b[0]) return a[0] > b[0];
                  return a[1] < b[1];
              });
    std::vector<std::vector<int>> result;
    for (const auto &person : people) {
        result.insert(result.begin() + person[1], person);
    }
    return result;
}
```

- **复杂度**：时间 O(n^2)（每次插入最坏 O(n)，共 n 次；用的是数组/列表），空间 O(n)。
- **易错点**：排序是**身高降序、`k` 升序**，两个方向别写反；插入位置就是 `k` 本身（不需要
  再加减）；C++ 用 `result.begin() + person[1]` 定位插入点，`person[1]` 即 `k`。
- **相似题**：135. 分发糖果（两次遍历满足左右的相对约束，见本分类模式一的相似题）；
  861. 翻转矩阵后的得分（先按「第一位」排序的思想类似）。

## 规律总结

1. **贪心的两个动作**：定义一个「当前最优选择」的规则，再证明它不会让答案变差。规则通常是
   「排序后按序处理」「优先花掉不灵活的资源」「实时维护极值」；证明手段几乎都是**交换论证**
   ——假设最优解与贪心选择不同，把它改造成贪心的样子且不更差。

2. **贪心题常见的几种骨架**：
   - **排序 + 双指针**（455）：先排序，让「最优选择」排在最前面，然后一趟扫描配对；
   - **边走边做局部选择**（860）：逐个元素处理，每步优先保留用途更广的资源；
   - **一次遍历维护极值**（121）：用一个或几个变量记录前缀信息，边读边更新；
   - **按右端点排序的区间贪心**（435 / 452）：结束越早，留给后面的空间越大；
   - **维护可达最远位置**（55 / 45）：只关心「能推到多远」，不关心具体路径；
   - **边扫描边结算**（134 / 763）：累积量越界就重置起点，或扫到边界就切一刀；
   - **先排序再按规则重构**（406）：按主导维度降序排，再依次插到约束要求的位置。

3. **「为什么不用贪心」和「为什么能用贪心」一样重要**：先想清楚局部最优是否能推出全局
   最优；不能时不要硬套。经典反例是零钱兑换（面额不规整时贪心会错），那类问题要用动态
   规划。**能用贪心时优先用**——它通常比 DP、回溯更简单、更快。

4. **贪心与排序的关系**：多数贪心题的「选谁先处理」需要一个合理的顺序，而排序常常就是
   产生这个顺序的手段（455 按胃口/尺寸排序，后续的区间题按右端点、按身高排序）。顺序选错，
   贪心就会失效。

5. **贪心常常是某个 DP 的简化版**：121 的贪心解和它的 DP 解复杂度相同，只是省去了状态
   定义；一旦问题增加约束（多笔交易、有冷冻期），贪心往往不再适用，得退回 DP。遇到「贪心
   想不到证明」时，退回 DP 或回溯也常能拿到正确答案。

6. **区间题的排序键决定了成败**：区间调度（435 / 452）按**右端点**排序，因为「越早结束越
   好」；而合并区间（56）却按**左端点**排序，因为要处理的是「相接/重叠就合并」。同样是区间，
   问题问法不同，排序键也不同，不能死记。

7. **「排序 + 一次扫描」之外，还有「扫描时结算」**：134 用 `tank` 累计余额，变负就重置起点，
   本质是「前缀和变负就丢弃」；763 用 `end` 记录当前片段必须覆盖到的最右位置，扫到边界就切分。
   这类题的共同点是把问题切成若干独立的小段分别处理，段与段之间不相干。

8. **贪心与 BFS / DP 的边界**：45 的「最少跳跃数」若用普通 DP 是 O(n^2)，用「按层推进」
   的贪心压成 O(n)；56 的区间问题若用贪心要小心排序键，不确定时退回 DP 或排序后区间合并。
   记住：**贪心省的是「回头比较」的那一层枚举**，代价是你必须能证明不回头也不会错。
