# 数学：逐位处理、进制映射与数论小结论

数学类题目往往「代码不长，但要想得巧」。它们不依赖复杂的数据结构，考察的是对**整数本身
结构**的理解：一个整数可以被拆成一个个十进制位，可以被看成某个进制下的位串，也可以利用
整除、同余、因子这些数论性质直接得出结论。遇到这类题，先用一两个具体数字在草稿纸上推一遍，
再想「有没有只看某几位 / 只用某个因子就能定结果」，通常比硬模拟更省事也更不易错。

本篇收 10 道经典题，按四种套路分组：**逐位处理整数**（7、9）先把数字拆成位来操作；
**数字系统的编码映射**（13、12、171、168）处理两种表示之间的互转；**数论小结论**（172、
204、258）用因子与同余把答案直接算出来；最后 **29** 展示「没有乘法除法时，如何用二进制
位把除法做出来」。四种套路彼此独立，但都围绕同一个主题：**把整数的十进制 / 二进制结构
当成可操作的零件**。

| 模式 | 题目 | 难度 |
|---|---|---|
| 模式一：逐位处理整数 | 7. 整数反转 / 9. 回文数 | 中等 / 简单 |
| 模式二：编码与进制映射 | 13. 罗马数字转整数 / 12. 整数转罗马数字 | 简单 / 中等 |
| 模式二：编码与进制映射 | 171. Excel 表列序号 / 168. Excel 表列名称 | 简单 / 简单 |
| 模式三：数论小结论 | 172. 阶乘后的零 / 204. 计数质数 / 258. 各位相加 | 中等 / 中等 / 简单 |
| 模式四：把除法拆成二进制位 | 29. 两数相除 | 中等 |

> 逐位拆数字这件事，和 `16-bit` 篇「逐位搬移」是同一视角的两面：那边按二进制位操作，
> 这边按十进制位操作。遇到进制转换（如 12 / 171 / 168）时，把它想成「高位到低位累乘」
> 就与二进制构造整数完全同构。

## 模式一：逐位处理整数

**适用信号**：题目关心一个整数的「每一位数字」，比如把它反过来、判断它左右对称、
逐位求和。

**核心动作**：用 `x % 10` 取出末位、`x //= 10` 丢掉末位，配一个累加器把取出的位
按需要的顺序重新组合。取位是「从右往左」，写位时的「乘基数再放新位」决定了新数字落在
哪一端。

### 7. 整数反转（中等）

**题目**：给定一个 32 位有符号整数 `x`，返回把数字部分反转后的结果；若反转后超出
`[-2^31, 2^31 - 1]`，返回 0。

**思路**：

反复取出末位并推入结果：

```python
def reverse_integer(x):
    sign = -1 if x < 0 else 1
    x = abs(x)
    rev = 0
    while x:
        rev = rev * 10 + x % 10
        x //= 10
    rev *= sign
    if rev < -(2 ** 31) or rev > 2 ** 31 - 1:
        return 0
    return rev
```

```cpp
int reverseInteger(int x) {
    long long rev = 0;
    while (x != 0) {
        rev = rev * 10 + x % 10;
        x /= 10;
    }
    if (rev < INT_MIN || rev > INT_MAX) {
        return 0;
    }
    return static_cast<int>(rev);
}
```

**为什么「乘 10 再加末位」就是反转**：设原数为 `d_k … d_0`。每一轮先取末位，再把已有的
`rev` 整体乘 10（腾出个位），把新取到的数字放进个位。读的顺序是从右往左（`d_0, d_1, …`），
但由于每次都会把旧结果往高位顶，先读到的 `d_0` 最终落在最左、后读到的落在右边，结果恰好
是原数倒过来。

**为什么先拆符号**：Python 中负数取模的结果是非负的（`-123 % 10 == 7`），直接对负数做
`rev * 10 + x % 10` 会把符号信息搅乱；先取绝对值、只反转数字，最后补回符号最清晰。
C++ 里可以依赖 `-123 % 10 == -3` 直接处理负数，但用 `long long` 承接以防中间结果溢出。

**为什么在最后统一判溢出**：题目要的是「反转之后」是否越界，而非反转前，所以全部反转完
再检查一次即可。C++ 若用 `int` 累加，反转过程中就会因溢出得到未定义行为，因此必须用
`long long` 装中间值。

- **复杂度**：时间 O(log|x|)，空间 O(1)。
- **易错点**：`x` 为 0 时循环不执行、直接返回 0，这是对的；负号要单独处理；C++ 用
  `int` 累加会溢出，务必升到 `long long` 再判断。
- **相似题**：9. 回文数（同款逐位反转，但只需反转一半）；190. 颠倒二进制位
  （把「十进制位」换成「二进制位」，见 `16-bit` 篇）；344. 反转字符串
  （把「位」换成「字符」，见 `15-string` 篇）。

### 9. 回文数（简单）

**题目**：判断一个整数正着读和倒着读是否相同。

**思路**：

只反转一半数字，反转部分追上未反转部分时就停：

```python
def palindrome_number(x):
    if x < 0 or (x % 10 == 0 and x != 0):
        return False
    rev = 0
    while x > rev:
        rev = rev * 10 + x % 10
        x //= 10
    return x == rev or x == rev // 10
```

```cpp
bool palindromeNumber(int x) {
    if (x < 0 || (x % 10 == 0 && x != 0)) {
        return false;
    }
    int rev = 0;
    while (x > rev) {
        rev = rev * 10 + x % 10;
        x /= 10;
    }
    return x == rev || x == rev / 10;
}
```

**为什么可以只反转一半**：回文在中间对称，只要确认「后半段反转后等于前半段」即可，
不必把整个数反转完。循环条件 `x > rev` 保证 `rev` 一旦追上或超过 `x`，两者位数就已相当：
偶数位时正好各占一半，`x == rev`；奇数位时 `rev` 会多出一位（中间那位），`x == rev // 10`。

**为什么要提前排除「末尾是 0 的非零数」**：像 10、120 这样的数，最高位非 0、最低位是 0，
左右必然不同；但反转后前导零被丢弃、位数变短，如果只靠后面比较可能看不出差异，提前判断
更稳妥。

**为什么比直接反转整个数更好**：反转一半把循环次数和中间值都减半，也顺带避开了溢出
（不需要像第 7 题那样判断范围）。

- **复杂度**：时间 O(log x)（只处理一半位数），空间 O(1)。
- **易错点**：别漏掉 `x == 0` 应返回真（它走不进循环，`0 == 0` 成立）；`x % 10 == 0`
  必须配合 `x != 0`；奇数位要比较 `rev // 10`。
- **相似题**：7. 整数反转（完整反转版）；125. 验证回文串（把整数换成字符串，用对撞
  双指针，见 `01-array` 篇）；5. 最长回文子串（求「最长」而非「是否」，需中心扩展或区间
  DP，见 `13-dynamic-programming` 篇）。

## 模式二：编码与进制映射

**适用信号**：两种表示之间互转，如罗马数字 ↔ 阿拉伯数字、Excel 列名 ↔ 列序号。

**核心动作**：把一种表示看成「带位权的位串」，按位权累加或除法取余；转换成字符串时，
从低位往高位取、最后倒序。

### 13. 罗马数字转整数（简单）

**题目**：把罗马数字字符串转成整数。基本字符 `I=1, V=5, X=10, L=50, C=100, D=500,
M=1000`；小数写在大数左边时表示相减（`IV=4`、`IX=9`、`XL=40` 等）。

**思路**：

从左往右扫，根据「右边一位」决定当前位是加还是减：

```python
def roman_to_integer(s):
    values = {
        "I": 1,
        "V": 5,
        "X": 10,
        "L": 50,
        "C": 100,
        "D": 500,
        "M": 1000,
    }
    total = 0
    n = len(s)
    for i, ch in enumerate(s):
        v = values[ch]
        if i + 1 < n and v < values[s[i + 1]]:
            total -= v
        else:
            total += v
    return total
```

```cpp
int romanToInteger(const std::string &s) {
    std::unordered_map<char, int> values = {
        {'I', 1},   {'V', 5},   {'X', 10},  {'L', 50},
        {'C', 100}, {'D', 500}, {'M', 1000}};
    int total = 0;
    int n = static_cast<int>(s.size());
    for (int i = 0; i < n; ++i) {
        int v = values[s[i]];
        if (i + 1 < n && v < values[s[i + 1]]) {
            total -= v;
        } else {
            total += v;
        }
    }
    return total;
}
```

**为什么只需比较相邻两位**：所有减法组合（`IV, IX, XL, XC, CD, CM`）都恰好是「左字符的
值小于右字符」的相邻两位。把这种「小于右边」的左字符记为负，其余记为正，累加即得到定义
中的结果。无需特判具体是哪一个组合，规则统一。

**为什么不用「先替换子串」的写法**：比如先把 `IV` 换成 4 再逐个字符相加，听起来直观，
但替换顺序很容易踩坑（先换 `I` 就会破坏 `IV`）。相邻比较是一遍扫描、无顺序依赖。

- **复杂度**：时间 O(n)，空间 O(1)。
- **易错点**：判断「右邻存在」的边界 `i + 1 < n`；比较的是值而不是字符；查表别漏字符。
- **相似题**：12. 整数转罗马数字（逆过程，见下）；171 / 168（同样是把「位串 ↔ 数值」
  互转，见下）。

### 12. 整数转罗马数字（中等）

**题目**：把整数（1 ≤ num ≤ 3999）转成罗马数字。

**思路**：

把 13 个「面值」（含 6 个减法组合）从大到小排好，贪心地尽量取：

```python
def integer_to_roman(num):
    pairs = [
        (1000, "M"),
        (900, "CM"),
        (500, "D"),
        (400, "CD"),
        (100, "C"),
        (90, "XC"),
        (50, "L"),
        (40, "XL"),
        (10, "X"),
        (9, "IX"),
        (5, "V"),
        (4, "IV"),
        (1, "I"),
    ]
    res = []
    for value, sym in pairs:
        while num >= value:
            res.append(sym)
            num -= value
    return "".join(res)
```

```cpp
std::string integerToRoman(int num) {
    const std::vector<std::pair<int, std::string>> pairs = {
        {1000, "M"},  {900, "CM"}, {500, "D"}, {400, "CD"}, {100, "C"},
        {90, "XC"},   {50, "L"},   {40, "XL"}, {10, "X"},   {9, "IX"},
        {5, "V"},     {4, "IV"},   {1, "I"}};
    std::string res;
    for (const auto &p : pairs) {
        while (num >= p.first) {
            res += p.second;
            num -= p.first;
        }
    }
    return res;
}
```

**为什么贪心一定最优**：标准罗马数字要求从左到右面值非增。把 `900, 400, 90, 40, 9, 4`
这些减法组合也当成独立面值排进表里，每一步取「当前还能取的最大面值」就保证了不会出现
需要回头补的情况。整数范围内标准表示唯一，所以贪心不会失败。

**为什么必须把减法组合列进面值表**：只用七个基本字符会写出 `IIII` 这种非标准形式。把
六个减法组合当作面值后，`4` 会直接取 `IV` 而不是四个 `I`，一举得到规范写法。

- **复杂度**：时间 O(1)（面值表固定，循环次数只与位数相关），空间 O(1)（不计输出）。
- **易错点**：面值表必须从大到小且包含全部 13 项；`while` 用 `>=` 而非 `>`；
  3999 是标准表示的边界，别漏 `CM`。
- **相似题**：13. 罗马数字转整数（逆过程）；168 / 171（同样是「查表 + 按位处理」的
  编码转换，见下）。

### 171. Excel 表列序号（简单）

**题目**：把 Excel 列名（`A`、`AB`、`ZY`）转成列号（`1`、`28`、`701`）。规则是
`A→1, …, Z→26, AA→27`，像一个「没有 0」的 26 进制。

**思路**：

从左到右「乘 26 加本位」：

```python
def excel_sheet_column_number(s):
    res = 0
    for ch in s:
        res = res * 26 + (ord(ch) - ord("A") + 1)
    return res
```

```cpp
int excelSheetColumnNumber(const std::string &s) {
    int res = 0;
    for (char ch : s) {
        res = res * 26 + (ch - 'A' + 1);
    }
    return res;
}
```

**为什么是「乘 26 再加」**：这就是十进制「从高位到低位」读数的通用写法
（`253 = ((2*10)+5)*10+3`），只是把进制换成 26、每位取值从 0~25 改成 1~26。

**为什么必须加 1**：`A` 对应 1 而不是 0。若用 `ord(ch) - ord('A')`，`A` 会算成 0，
`AA` 就变成 `0*26+0 = 0`，与题意不符。

- **复杂度**：时间 O(n)，空间 O(1)。
- **易错点**：字符值要 `+1`；不要错误地按「从右往左」累乘 26 的幂（虽然等价，但容易
  写错下标）。
- **相似题**：168. Excel 表列名称（逆过程，注意「先减 1」，见下）；13 / 12（同为
  编码映射）。

### 168. Excel 表列名称（简单）

**题目**：把列号转成列名，是 171 的逆过程。

**思路**：

每次「先减 1，再对 26 取模」收集最低位，最后倒序：

```python
def excel_sheet_column_title(column_number):
    res = []
    n = column_number
    while n > 0:
        n -= 1
        res.append(chr(ord("A") + n % 26))
        n //= 26
    return "".join(reversed(res))
```

```cpp
std::string excelSheetColumnTitle(int columnNumber) {
    std::string res;
    int n = columnNumber;
    while (n > 0) {
        n -= 1;
        res.push_back(static_cast<char>('A' + n % 26));
        n /= 26;
    }
    std::reverse(res.begin(), res.end());
    return res;
}
```

**为什么一定要先减 1**：这是「1 起始」的 26 进制。`n % 26` 的取值范围是 0~25，而我们要
表达 1~26。以 `n = 26` 为例：若不减 1，`26 % 26 == 0` 映射成 `A`，再 `26 / 26 == 1`
又贡献一个 `A`，得到 `AA`；但正确答案是 `Z`。先把 `n` 减 1，26 就落到 25 上、正确映射
成 `Z`，商也变成 0，循环结束。

**为什么最后要倒序**：取模先取出的是最低位（最右边的字母），而拼接是从左到右，所以
收集完再整体反转。

- **复杂度**：时间 O(log n)，空间 O(log n)（输出长度）。
- **易错点**：漏掉 `n -= 1` 会得到错误结果；`n = 0` 时不应进入循环；记得反转。
- **相似题**：171. Excel 表列序号（逆过程，注意别把「加 1 / 减 1」弄反）；
  7. 整数反转（同样是「取余收集、倒序拼接」）。

## 模式三：数论小结论

**适用信号**：答案可以由某个因子、同余性质或筛选法直接得出，不必逐个模拟。

**核心动作**：先问「答案由谁决定」，把问题化归成一个更简单的计数或取模。

### 172. 阶乘后的零（中等）

**题目**：求 `n!` 末尾有多少个零。

**思路**：

数因子 5 的个数：

```python
def factorial_trailing_zeroes(n):
    count = 0
    while n > 0:
        n //= 5
        count += n
    return count
```

```cpp
int factorialTrailingZeroes(int n) {
    int count = 0;
    while (n > 0) {
        n /= 5;
        count += n;
    }
    return count;
}
```

**为什么数 5 就够了**：末尾每个 0 来自一对因子 (2, 5)（`10 = 2 × 5`）。在 `n!` 里因子
2 的数量远多于 5，所以瓶颈是 5 的个数。

**为什么用「除以 5 再累加」而不是逐个数 5**：一个数里可能含多个 5（如 25 含两个）。
`n // 5` 数出「至少含一个 5」的数的个数，下一轮再 `// 5` 数出「至少含两个 5」的数
（即 25 的倍数）的个数，逐层补齐，正好把每个数里的 5 因子一个不落地算进来。

- **复杂度**：时间 O(log_5 n)，空间 O(1)。
- **易错点**：不能先算阶乘再数零（会溢出且慢）；`n = 0`、`n = 1` 应返回 0。
- **相似题**：204. 计数质数（同样是从因子/整除角度切入）；258. 各位相加（同余性质）。

### 204. 计数质数（中等）

**题目**：统计小于 `n` 的质数个数。

**思路**：

埃拉托斯特尼筛：

```python
def count_primes(n):
    if n < 3:
        return 0
    is_prime = [True] * n
    is_prime[0] = is_prime[1] = False
    i = 2
    while i * i < n:
        if is_prime[i]:
            for j in range(i * i, n, i):
                is_prime[j] = False
        i += 1
    return sum(is_prime)
```

```cpp
int countPrimes(int n) {
    if (n < 3) {
        return 0;
    }
    std::vector<bool> isPrime(n, true);
    isPrime[0] = isPrime[1] = false;
    int i = 2;
    while (i * i < n) {
        if (isPrime[i]) {
            for (int j = i * i; j < n; j += i) {
                isPrime[j] = false;
            }
        }
        ++i;
    }
    int count = 0;
    for (bool v : isPrime) {
        if (v) {
            ++count;
        }
    }
    return count;
}
```

**为什么这样能筛掉所有合数**：任何合数 `m` 都有最小质因子 `p < m`。当外层走到 `p` 时
会把 `p` 的所有倍数划掉，`m` 自然被覆盖。

**为什么内层从 `i * i` 开始**：小于 `i * i` 的 `i` 的倍数，形如 `i * k`（`k < i`），
已经在更早的轮次被 `k` 的质因子筛掉了，从 `i * i` 开始才不重复。

**为什么外层只需到 `sqrt(n)`**：合数 `i` 必有不超过 `sqrt(i)` 的质因子，早已被筛掉；
比 `sqrt(n)` 大的未标记数一定是质数。

- **复杂度**：时间 O(n log log n)，空间 O(n)。
- **易错点**：`n < 3` 要返回 0（小于 3 时没有质数）；下标别越界；统计的是「小于 n」
  而不是「小于等于 n」。
- **相似题**：172. 阶乘后的零（都按因子计数）；`13-dynamic-programming` 里的
  279 完全平方数、`14-greedy` 里与质因数相关的问题（思路相近）。

### 258. 各位相加（简单）

**题目**：反复把各位数字相加，直到结果为一位数，返回它。

**思路**：

用数字根公式直接求：

```python
def add_digits(num):
    if num == 0:
        return 0
    return 1 + (num - 1) % 9
```

```cpp
int addDigits(int num) {
    if (num == 0) {
        return 0;
    }
    return 1 + (num - 1) % 9;
}
```

**为什么数字根就是模 9 的结果**：因为 `10 ≡ 1 (mod 9)`，所以 `10^k ≡ 1 (mod 9)`，
一个数和它的各位数字之和对 9 同余。反复各位相加不改变这个余数，最终停在一位数上时，
那位数就是 `num mod 9`（范围落在 1~9）。

**为什么写成 `1 + (num - 1) % 9`**：当 `num` 是 9 的倍数时，`num % 9 == 0`，但数字根
应取 9。这条公式把 9 的倍数（结果为 9）和非 9 倍数统一起来，也自然处理了 `num = 0` 之外的
所有情况；`num = 0` 单独返回 0。

- **复杂度**：时间 O(1)，空间 O(1)。
- **易错点**：`num = 0` 必须返回 0；9 的倍数返回 9 而不是 0；别写成 `num % 9` 直接
  返回（会把 9 的倍数变成 0）。
- **相似题**：172. 阶乘后的零（同余 / 因子视角）；`16-bit` 篇的数位与进制相关题目。

## 模式四：把除法拆成二进制位

**适用信号**：题目禁用乘、除、取模，要求用位运算或其他基本运算实现除法 / 乘法。

**核心动作**：把商写成若干个 2 的幂之和，用「除数 << k」去逼近被除数，逐块扣除。

### 29. 两数相除（中等）

**题目**：不用乘法、除法、取模，计算两整数相除的商（向零截断），溢出时返回 `2^31 - 1`。

**思路**：

位运算倍增：每轮减掉最大的「除数 × 2^k」：

```python
def divide_two_integers(dividend, divisor):
    if dividend == -(2 ** 31) and divisor == -1:
        return 2 ** 31 - 1
    negative = (dividend < 0) != (divisor < 0)
    a = abs(dividend)
    b = abs(divisor)
    result = 0
    while a >= b:
        shift = 0
        while a >= (b << (shift + 1)):
            shift += 1
        a -= b << shift
        result += 1 << shift
    return -result if negative else result
```

```cpp
int divideTwoIntegers(int dividend, int divisor) {
    if (dividend == INT_MIN && divisor == -1) {
        return INT_MAX;
    }
    bool negative = (dividend < 0) != (divisor < 0);
    long long a = std::llabs(static_cast<long long>(dividend));
    long long b = std::llabs(static_cast<long long>(divisor));
    long long result = 0;
    while (a >= b) {
        int shift = 0;
        while (a >= (b << (shift + 1))) {
            ++shift;
        }
        a -= b << shift;
        result += 1LL << shift;
    }
    return negative ? static_cast<int>(-result) : static_cast<int>(result);
}
```

**为什么这样能求出商**：商本身是一个整数，可以写成二进制。`1 << shift` 就是在给商
逐位试填。每轮找到「当前被除数还能容纳的、最大的 `b × 2^shift`」，把它从 `a` 中扣掉，
并把对应的 2 的幂加进 `result`，等价于二进制长除法。

**为什么不会超时**：若每次只减一个 `b`，最坏要减 2^31 次。倍增按二进制位成组扣除，
外层每轮至少减掉当前最大的一堆，总轮数只有 O(log^2 n)。

**为什么要处理边界**：`INT_MIN` 取绝对值会溢出，C++ 先升到 `long long` 再取绝对值；
唯一溢出结果是 `INT_MIN / -1 = 2^31`，超出有符号上界，需提前返回 `INT_MAX`。

- **复杂度**：时间 O(log^2 n)，空间 O(1)。
- **易错点**：符号要用「两数异号」而非「有负数」；别用 `abs(INT_MIN)`；`b << (shift+1)`
  要保证计算在足够宽的整型里进行（C++ 用 `long long`）。
- **相似题**：50. Pow(x, n)（快速幂也是「把次数拆成二进制幂」，见
  `12-divide-conquer` 篇）；`05-binary-search` 篇的「二分答案」在思想上与「逐块逼近」
  一致。

## 规律总结

1. **逐位处理的固定骨架**：`digit = x % 10; x //= 10` 取位，`acc = acc * 10 + digit`
   写位。取位方向从右往左，写位时「乘基数再放新位」决定新数字落在哪端。第 7 题
   （反转）、第 9 题（回文，反转一半）是同一骨架的两种用法。

2. **「反转一半」是回文类问题的省力技巧**：不必把整体算完，只需让两个指针在中间相遇。
   奇数长度要多处理中间那一位（`rev // 10`）。这与字符串回文的对撞双指针
   （`01-array` 篇 125）是同一思想。

3. **进制转换两个方向、两个套路**：
   - 字符串 → 数值：`res = res * base + 本位值`，从左往右一遍扫（171、13 中加法的部分）。
   - 数值 → 字符串：`digit = n % base` 收集、最后倒序；若该进制「1 起始」，先 `n -= 1`
     （168）。
   罗马数字（12、13）的特殊性在于「减法组合」，处理方式是**把组合也当成一个独立面值**
   （12）或**比较相邻两位决定加减**（13）。

4. **数论题先问「答案由谁决定」**：阶乘末尾零由 5 的个数决定（172），数字根由模 9 决定
   （258），质数个数用筛法（204）。想清楚决定因素后，往往只剩一个简单计数或取模。

5. **同余是个好工具**：`10 ≡ 1 (mod 9)` 带来数字根（258），`K` 进制逐位等价于按位权
   展开（171、168）。遇到「反复运算直到一位数」「循环节」「整除」这类描述，先试着找
   模运算下的不变量。

6. **禁用乘除时，用二进制位代替**：把商写成 2 的幂之和，用移位与减法逐位逼近（29）。
   这和快速幂（把指数拆成二进制位）、二分答案（逐段逼近）共享「化整为零、按位/按段
   逼近」的思想。

7. **溢出与边界要主动想**：整数题几乎都要么用 Python 的无界整数规避，要么在 C++ 里
   升到 `long long` 并在最后统一判界（7、29）。特别当心 `INT_MIN` 取绝对值、`-1` 作
   除数这类极端输入。
