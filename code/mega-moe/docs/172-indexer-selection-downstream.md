# indexer 选择翻转对下游稀疏注意力输出的端到端影响（H100 实测）

> 本文是「DeepSeek Mega MoE 前向 / 反向算子实现解析」专题的第 172 篇（P162 增量）。
> 第 171 篇（P161-1）把 DeepSeek Sparse Attention（DSA）indexer 的**选择**这一环单独量了：
> FP8/MXFP8 量化下 `Top-k(I_t,:)` 的 recall ~0.966、MXFP4 ~0.851，决定稳定性的不是相邻
> 间隔（margin）而是阈值附近 ±σ 的**候选池**。但那篇结尾明说「④ 未接真实 DeepEP/dispatch，
> 选择翻转对**下游稀疏注意力输出**的端到端影响未量」。本篇把这一格补上。
>
> 问题：indexer 选错 3.4%（FP8）/15%（MXFP4）的支持集，真的会让 attention 输出错同样比例吗？
> 答案在 H100(sm90) 上量出来是**二阶的**——翻转发生在选择边界、那里承载的注意力质量最小，
> 但「二阶」有边界：注意力越平（长上下文 / 低温）、indexer 与注意力越脱节，代价越大。
>
> 主 kernel 的 MXFP4/MXFP8 UMMA 部分 **SM100 专属、仅分析**；选择统计与注意力归约**架构无关**，
> 用真实 SM90 `fp8_fp4_mqa_logits` 锚定。目标卡代号敏感：全文用「目标卡」指代。

## 1. 定位：从「选得准不准」到「选错有多大后果」

第 171 篇停在 indexer 自己的指标上（recall / Jaccard / 概率质量）。但 DSA 的推理与训练
关心的不是支持集本身，而是**支持集决定的注意力输出**：

```
S_t = Top-k(I_t,:)                      # indexer 选择（indexer 自己的 q/kv/weights）
O_t = softmax_{j∈S_t}(a_{t,j}) · V_j    # 稀疏注意力：softmax 只在支持集内归一化
```

其中 `a` 是**主注意力的打分**（`q/k` 与 indexer 不是同一套权重）。所以「选择翻转 → 输出误差」
这条链里有两个可能被混淆的量：

1. **稀疏近似本身**：就算 indexer 完全正确，`Top-k` 也丢掉了 `C−K` 个 token 的注意力质量；
2. **量化导致的选择漂移**：量化 logits 把支持集换掉一部分。

第 171 篇量的是 ② 的**发生率**（翻转数）；本篇量 ② 的**后果**（输出误差），并与 ① 对比——
这样才能回答「indexer 用 FP4 省 2× 带宽，代价到底值不值」。

## 2. 模型与实验设计

`harness/exp_indexer_downstream.py`（`bash harness/exp_indexer_downstream.sh` 跑出 `.out.txt`）。
规模 `T=1536, C=32768, H=32, D=64, Top-k=2048(=C/16), block=16, dv=64`；logits 用与第 171 篇
完全相同的构造（`q/kv ~ N(0,1)` bf16、`weights ~ N(0,1)` fp32、单序列 `ks=0, ke=C`）。

**两个建模假设（明确标注）**：

- **自洽档（Part B/D/E）**：把 **indexer 打分本身当作注意力打分**（`a = I`）。这是「选择与
  注意力完全对齐」的**下界**模型——差异**只**来自「换了支持集」，隔离出「选择」这一环。
- **失配档（Part C）**：注意力打分 `a = ρ·I + √(1−ρ²)·σ_row(I)·noise`，用相关系数 `ρ` 旋钮
  把 indexer 与主注意力「脱节」的程度参数化。真实 DSA 里 indexer 是另训的小模型，`ρ<1`。

**下游输出**：把 `softmax` 限制在支持集上再对值向量 `V`（随机 bf16，`dv=64`）加权
（`attn_output`，分块避免 OOM）；对照 `dense_output` 是全上下文 softmax。

**关键的下游变量是「注意力有多平」**：`I` 的尺度 ~18（32 头 relu 点积求和），`tau=1` 时
softmax 极尖锐、top-2048 几乎含全部质量（teacher 质量 = 1.000000），遴选翻转自然无关痛痒。
真实注意力的尖锐度取决于主注意力的打分尺度，所以本篇用**温度 `tau` 扫描** `{1,4,8,16}`
坐实「输出敏感度 = 注意力平坦度」这条依赖。诊断量仍沿用第 171 篇的语言：**丢掉/错补的
注意力质量**。

## 3. 结果

### 3.1 Part A：kernel 锚定 + 三档支持集（与第 171 篇逐位一致）

```
kernel vs torch-fp8 ref: max-abs-rel = 2.499e-04
[fp8  ] top-2048 recall = 0.9662 (flipped 69)
[mxfp8] top-2048 recall = 0.9650 (flipped 72)
[mxfp4] top-2048 recall = 0.8507 (flipped 306)
```

真实 SM90 kernel 与 torch 复刻 fp8 档最大相对差 **2.5e-4**（fp32 累加顺序差），复现第 171 篇。

### 3.2 Part B：自洽档——换支持集的下游输出误差随「注意力平坦度」变化

```
tau=  1.0: teacher 质量=1.000000 | 稀疏基线 relL2=1.143e-04 | 随机支持 relL2=1.362e+00
    [fp8  ] vs O(t) relL2=4.120e-08 cos=1.000000 | 丢=5.70e-18
    [mxfp4] vs O(t) relL2=6.170e-08 cos=1.000000 | 丢=1.91e-14
tau=  4.0: teacher 质量=0.999803 | 稀疏基线 relL2=3.410e-04 | 随机支持 relL2=1.527e+00
    [fp8  ] vs O(t) relL2=8.727e-06 cos=1.000000 | 丢=1.51e-05
    [mxfp4] vs O(t) relL2=9.612e-05 cos=1.000000 | 丢=1.21e-04
tau=  8.0: teacher 质量=0.950933 | 稀疏基线 relL2=5.589e-02 | 随机支持 relL2=2.037e+00
    [fp8  ] vs O(t) relL2=2.619e-03 cos=0.999987 | 丢=1.75e-03
    [mxfp8] vs O(t) relL2=2.669e-03 cos=0.999986
    [mxfp4] vs O(t) relL2=9.069e-03 cos=0.999924 | 丢=1.05e-02
tau= 16.0: teacher 质量=0.565434 | 稀疏基线 relL2=8.320e-01 | 随机支持 relL2=2.086e+00
    [fp8  ] vs O(t) relL2=5.154e-02 cos=0.998264 | 丢=1.15e-02
    [mxfp4] vs O(t) relL2=1.163e-01 cos=0.991709 | 丢=5.93e-02
```

三个结论：

- **选择翻转是二阶的**：任何一档下，量化选择带来的输出误差都**远小于稀疏近似本身**
  （`tau=8`：fp8 `2.6e-3` vs 基线 `5.6e-2`，约 **21×**；`tau=4`：`8.7e-6` vs `3.4e-4`，约 **39×**）。
  原因就是第 171 篇的洞察的下游版：翻转发生在**第 K 名边界**，而边界 token 的 softmax 权重最小。
- **输出误差 ≈ 丢掉质量**：`tau=8` fp8 丢 `1.75e-3`、输出误差 `2.62e-3`；mxfp4 丢 `1.05e-2`、
  误差 `9.07e-3`——同一数量级。所以「翻转的概率质量」（第 171 篇 Part D）就是下游误差的
  正确预测器，不需要重跑 attention 也能估。
- **精度差 → 后果差**：mxfp4 相对 fp8 的输出误差比在 `tau=4/8/16` 分别是 **11× / 3.5× / 2.3×**，
  随注意力变平而收窄（fp8 自己在变差，比值收敛）。
- **随机支持集对照 `relL2≈1.4–2.1`**（cos 掉到 0.07）证明指标不是恒小、筛选确实起了作用。

### 3.3 Part C：失配档——indexer 与注意力的相关性 ρ 才是主变量（tau=8）

```
rho=1.0: 稀疏基线=5.589e-02  fp8=2.619e-03/cos 0.999987  mxfp8=2.669e-03  mxfp4=9.069e-03/cos 0.999924
rho=0.7: 稀疏基线=3.723e-01  fp8=3.464e-02/cos 0.997760  mxfp8=3.371e-02  mxfp4=1.018e-01/cos 0.988186
rho=0.4: 稀疏基线=1.266e+00  fp8=9.731e-02/cos 0.982452  mxfp8=9.228e-02  mxfp4=2.913e-01/cos 0.920775
rho=0.0: 稀疏基线=2.325e+00  fp8=1.755e-01/cos 0.956546  mxfp8=1.709e-01  mxfp4=5.148e-01/cos 0.817209
```

- `ρ=1` 与 Part B 逐位对上（自洽档）。
- `ρ=0.4` 时 fp8 的选择误差 `9.7e-2` 已经**超过** FP8 量化本身在 `ρ=1` 时的贡献（`2.6e-3`）
  **一个数量级以上**。换言之：**indexer 与主注意力的对齐质量比 logits 精度更重要**。
  同档下 mxfp4/ fp8 的比值仍稳定 ~2.9–3.5×（精度差是乘性的）。
- `ρ=0`（选择与注意力无关）时，即便「选得对」（teacher 选择）基线也崩（`2.3`），且量化
  选择额外加到 `1.8e-1`——支持集与注意力解耦后，选择本身不再有意义。

### 3.4 Part D：块级（compressed indexer）下游，tau=8

```
block=16, top-128 blocks → 2048 tokens; 块级 vs token 级 O(teacher): relL2=2.871e-01
[fp8  ] 块 recall=0.9497 | 块级下游 vs O(块级 teacher): relL2=2.080e-02
[mxfp8] 块 recall=0.9477 | 块级下游 vs O(块级 teacher): relL2=2.115e-02
[mxfp4] 块 recall=0.7841 | 块级下游 vs O(块级 teacher): relL2=5.939e-02
```

注意这里的「块 recall」（0.9497/0.7841）是**块集合对块集合**的匹配率，与 token 级 recall
不是同一个量，不能直接比大小；有意义的是同一套块级选择下的**下游输出误差**。

反直觉但没有矛盾：**每次块翻转的下游代价比 token 级更重**。块级 teacher vs token teacher
输出就差了 `0.287`（compressed indexer 用块 `max` 聚合，与 token 级 top-k 是**不同的近似**）；
块级量化选择再叠加 `2.1e-2`（fp8）/`5.9e-2`（mxfp4）——比 token 级（`2.6e-3`/`9.1e-3`）
**大 ~8×**。原因：一次块翻转同时移动 16 个 token 的位置，而块分数是 `max` 聚合、更粗的统计量，
翻转边界处的块内 token 可能各自都承载可观质量。

> 第 171 篇说「块级比 token 级稳（fp8 7/128 个块翻转 vs token 级 70/2048）」，那是**翻转率**
> 意义上的稳（块少、每个块代表 16 个 token）；本篇说块级**单次翻转的后果**更重。两个口径
> 都对，合起来：块级把「翻转次数」换成「每次更重」——不能只按翻转率判断粒度优劣。

### 3.5 Part E：长上下文（tau=8，top-2048 固定）

```
C=  8192 (top-2048/8192=0.250, 稀疏基线=9.113e-03):  fp8 relL2=5.867e-04  mxfp4=2.016e-03
C= 32768 (top-2048/32768=0.062, 稀疏基线=5.596e-02):  fp8 relL2=2.612e-03  mxfp4=9.039e-03
C=131072 (top-2048/131072=0.016, 稀疏基线=1.594e-01): fp8 relL2=5.809e-03  mxfp4=2.038e-02
```

长上下文下 ① 稀疏基线变差（top-2048 占比变小）、② 量化选择误差也单调升（fp8
`5.9e-4→2.6e-3→5.8e-3`，约 **10×**），但**始终约比基线小一个数量级**（比值 15.5/21.4/27.4×）。
注意力越平（上下文越长、相关 token 越多），边界 token 承载的质量越大、翻转越有后果——
但同一效应也同步放大了稀疏近似误差，故「选择误差 ≪ 稀疏误差」这个结论在长上下文下**依然成立**。

## 4. 训练 / 推理含义

- **FP4 indexer 的选择代价在输出上是可控的二阶项**：在「top-k 已捕获 ~95% 注意力质量」的
  工作点（`tau=8`、`C=32768`），FP8 加 `2.6e-3`、FP4 加 `9.1e-3`；而同一工作点的稀疏近似
  本身就有 `5.6e-2` 误差。所以「FP4 省 2× 带宽」在端到端输出上**不是**被选择抖动否决的，
  被否决的只是极平注意力 / 极端 ρ 脱节的边界情形。
- **正确性口径应是「注意力质量」而非「支持集匹配」**：只要 indexer 与主注意力对齐（ρ 高），
  支持集在边界上抖一点几乎不影响输出；反之 ρ 低时，再高的 logits 精度也救不回
  （`ρ=0.4` 的 fp8 `9.7e-2`）。**对齐质量优先于量化精度**。
- **块级 vs token 级不是简单的「谁更稳」**：块级翻得少但每次更重，且块 `max` 聚合与
  token top-k 是不同的近似（本身差 `0.287`）。选粒度时要按「输出误差 = 翻转率 × 单次代价」
  算，不能只看翻转率。
- **长上下文要留余量**：`C` 从 8K→128K，选择误差涨 ~10×（`5.9e-4→5.8e-3` fp8），
  虽然仍远小于稀疏误差，但绝对量已不容忽略（FP4 到 `2e-2`）。

## 5. 边界与未做

① 主体模型是**自洽档**（indexer 打分 = 注意力打分）与**参数化失配档**（ρ 旋钮），二者都
不是真实 DSA 的完整前向后向；真实主注意力的 `q/k` 布局、per-head `softmax` 的 `1/√d`
缩放、以及 GQA/MQA 的头共享未建模。② 输入取 iid 高斯，真实 hidden 有重尾/低秩结构。
③ 本机无 SM100，MXFP4/MXFP8 主 kernel 的 UMMA/UTCCP 部分**仅分析**，量化用官方
`tests/test_attention.py` 的 torch 复刻（`quantize_mqa_q:59-72`、`ref_mqa_logits:78-101`）。
④ 未接真实 DeepEP/dispatch（NCCL 版本阻塞，见 ROADMAP「阻塞」）；稀疏注意力的**训练反向**
（第 157~160 篇）与选择翻转的联合误差未量。

## 6. 结论

把第 171 篇的「选择」再往下推一环到**下游注意力输出**，在 H100(sm90) 上用真实 SM90
`fp8_fp4_mqa_logits` 锚定 + torch 下游复刻量出：

**indexer 量化导致的选择翻转在下游是二阶的——因为翻转发生在第 K 名边界、那里承载的
softmax 质量最小；输出误差 ≈ 丢掉/错补的注意力质量，且始终比稀疏近似本身小一个数量级。
主权变量是 indexer 与主注意力的对齐 ρ 与注意力的平坦度（温度 / 上下文长度），精度
（FP8 vs FP4）是乘性的下一档。**

给出 DSA 的两条隐含设计准则：**(1) 训练 indexer 的对齐质量优先于 logits 精度；
(2) 块级选择用「翻转率换单次代价」，粒度要按输出误差而非支持集匹配来选。**

配套实验：`harness/exp_indexer_downstream.{py,sh,out.txt}`（H100 sm90 真机）。
