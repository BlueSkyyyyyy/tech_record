# indexer 蒸馏 loss 的逐头权重：该按「值范数」而不是「熵」

> 本篇是「DeepSeek Mega MoE 前向 / 反向算子实现解析」专题的增量（P165-1）。
> 承接第 173 篇（`docs/173`）：那篇把 indexer 的选择接进**真实 DSA 头结构**（per-head softmax、
> GQA/MQA 共享支持集、另训 q/k），量到**逐头敏感度差异极大**（最平 1/4 头输出误差是最尖 1/4 头
> 的 246×、熵-误差相关 +0.82），并在 §4 提出一条直觉：**「KL 蒸馏的权重/诊断应落在平坦头上」**。
> 第 174 篇（`docs/174`）则从另一侧发现：indexer **自身**的逐头权重 `w_h` 已经编码了重要性，
> 逐头分精度没有新杠杆。两条线指向一个**没被回答的实现问题**——
>
> **indexer 是一个单头打分器，它一次选出的支持集 `S_t = Top-k(I_t,:)` 对全部 `H_q` 个主注意力头
> 共享。那么构造蒸馏目标（主注意力分布）时，各主注意力头该按什么权重 `λ_h` 进这个目标？**
> 按「熵」（第 173 篇的直觉，把平坦头顶上去）？按「下游输出重要度」（值范数）？还是干脆均匀？
>
> 本篇把它做成能核对的数，结论是一次**修正**：**该按下游输出重要度 `ν_h`（≈值范数²）加权，
> 而不是按熵**；`ρ=0.9` 的已对齐工作点上逐头权重是个 **≤0.5%** 的小杠杆，`ρ` 越小（头越不一致）
> 越大（`ρ=0.5` 时熵加权比均匀**差 7.1%**、值范数加权比均匀**好 2.8%**）。**熵是「误差出现在哪」
> 的诊断量，不是「该选什么」的权重**；而**量化噪声把这一切淹没**（fp8 档误差是无量化的 2.5×、
> mxfp4 档 10.2×）。
>
> 主 kernel 的 MXFP4/MXFP8 UMMA 部分 **SM100 专属、仅分析**；indexer 打分用真实 SM90
> `fp8_fp4_mqa_logits` 锚定，主注意力头结构 / per-head softmax / 蒸馏不动点 **架构无关**。

## 0. 结论先行

在真实 SM90 `fp8_fp4_mqa_logits` 锚定的 DSA 头结构上（`T=256, C=16384, H_q=32, H_kv=8, G=4,
D=128, topk=2048`，indexer `H=32, d=64`，逐头温度 `τ_h∈[10^{-1},10^{1}]`，逐 KV 组值尺度随机），
H100(sm90) 实测：

1. **逐头权重 `λ_h` 唯一决定 indexer 学到的目标排序**：KL 蒸馏的不动点是 `softmax_S(I)=p_λ`、
   `p_λ = Σ_h λ_h P_h / Σ_h λ_h`，故支持集 `Top-k(I)=Top-k(p_λ)`。用一个稠密 KL 训练自由打分
   `I` 去匹配 `p_λ` 验证：**支持集 recall 从随机 0.125 收敛到 1.0000**、
   `||softmax(I)−p_λ||₁ = 3.0e-7`（§3.5）。
2. **正确的方向是「下游输出重要度」`ν_h`（值范数²），不是熵**：`ρ=0.9` 下按 `ν` 加权
   `δ_value = 4.8288e-2`、均匀 `4.8455e-2`、按**熵加权反而更差** `4.8541e-2`；只有单个最尖头
   的极端方案 `5.2326e-2` 明显更差（§3.3）。
3. **`λ = ν^p` 的δ_value 在 p≈2 最小**（p=0：4.8455e-2、p=1：4.8288e-2、**p=2：4.8209e-2**、
   p=3：4.8243e-2、p=4：4.8296e-2）——一阶预测是 `λ∝ν`，银幕上的最优点略偏重（§3.4）。
4. **熵确实是「误差出现在哪」的诊断量**（均匀支持下的逐头误差 `err_h` 与 `ent_h` 相关 **+0.837**，
   与 `ν_h` 相关仅 **−0.255**）——但它**不是**该选什么的权重：熵高的头误差大，是因为它们本来
   就平、边界质量多，而不是因为该让支持集去服务它们（§3.6，**这句修正了第 173 篇 §4 的措辞**）。
5. **影响随 `ρ`（indexer↔主注意力对齐度）放大**：`ρ=1.0`（完全对齐）时三种权重**逐位相同**；
   `ρ=0.9` 熵罚 +0.18% / 值范数收益 +0.35%；`ρ=0.7` +2.50% / +1.41%；**`ρ=0.5` +7.14% / +2.75%**
   （§3.3）。头越不一致，逐头权重越重要。
6. **量化噪声把逐头权重淹没**：换成 fp8 量化打分后 `δ_value` 从 `4.85e-2` 抬到 **`1.21e-1`（2.5×）**、
   mxfp4 抬到 **`4.92e-1`（10.2×）**，而三种 `λ` 方案在同一量化档内的差异只到第 4 位有效数字
   （§3.7）。**保打分精度比调逐头权重重要两个数量级。**
7. **头共享本身有 ~12% 的头香**：逐头 oracle（每头各自 top-k）`δ_equal = 4.7717e-2` vs 共享
   均匀 `5.3467e-2`——但这是 DSA 的既定设计（一次选择全头共享），单靠改逐头权重**补不回来**
   （§3.2）。

## 1. 定位：从「敏感度在逐头」到「蒸馏目标怎么加权」

第 173 篇建立的图景：

```
S_t = Top-k(I_t,:)                         # indexer 选择：逐 token 一次，对全部 H_q 头共享
P_h[t,s] = softmax_s( a[t,h,s] )           # 每头各自 softmax；a = <q_main[t,h], k_main[s,g(h)]>/√d
O[t,h,:] = Σ_{s∈S_t} P_h_renorm[t,s]·V[s,g(h)]
```

第 173 篇发现「敏感度藏在逐头尖锐度里」（平头误差 246× 于尖头）后，自然的问题是：
**既然平头对选择最敏感，那训练 indexer（蒸馏到主注意力）时是不是应该把平头顶上去？**

要回答它，必须先想清楚 **indexer 到底在学什么**。indexer 是一个**单头打分器** `I_t,·`；
它和主注意力之间的桥是 KL 蒸馏。若把蒸馏目标写成**逐头加权的主注意力分布**

```
p_λ[t,s] = Σ_h λ_h·P_h[t,s] / Σ_h λ_h
L = Σ_t KL( p_λ[t,·] || softmax_{S_t}(I_t,·) )
```

那么在支持集 `S_t` 上极小化 KL，不动点就是 `softmax_{S_t}(I_t,·) = p_λ[t,S_t]`（renormalized），
从而 `I_t` 的排序 = `p_λ[t,·]` 的排序，**支持集 = `Top-k(p_λ)`**。于是「该按什么加权」变成
一个**可测的离散优化**：哪个 `λ` 选出的支持集，让真实下游输出误差最小。

关键：**这与「误差出现在哪」是两回事**。误差出现在平头（熵诊断），但支持集是所有头共享的，
该为哪些头服务取决于**它们对最终 loss 的贡献 `ν_h`**（本实验用逐头值范数² `||V_h||²` 代理）。

## 2. 模型与实验设计

`harness/exp_indexer_head_weighting.py`（`bash harness/exp_indexer_head_weighting.sh` 跑出 `.out.txt`）。
规模 `T=256, C=16384, H_q=32, H_kv=8(G=4), D=128, dv=64, topk=2048`，indexer `H=32, d=64`。

- **indexer 打分**由真实 SM90 `fp8_fp4_mqa_logits` 锚定（`attention.hpp:67-134`），
  FP8/MXFP8/MXFP4 三档用官方 torch 量化语义复刻（`math.py`，MX 档 SM100 专属、仅分析）。
- **主注意力逐头结构**（与第 173 篇一致、架构无关）：`a[t,h,s] = ρ·Î[t,s] + √(1−ρ²)·g_h·ε[t,h,s]`，
  再除逐头温度 `τ_h = logspace(−1, 1, H_q)` 造出尖锐度各异的头；`Î` 是逐行标准化的 indexer 打分。
- **逐头值范数 `ν_h`**：`V`,`V_{s,g}~N(0,1)` 乘逐 KV 组随机尺度 `[0.3, 3.8]`，则该组内
  query 头重要度 `ν_h = ||V_{·,g,·}||_F²`。**刻意让 `ν` 与 `τ`/`熵` 解耦**（`corr(ent,ν)=+0.03`），
  才能分开检验两个假设。
- **候选逐头权重**：均匀、`∝熵`、`∝1/熵`、`∝ν`、只留最尖头。每个 `λ` 生成 `p_λ → Top-k → 支持集`，
  用真实下游输出误差评判：`δ_equal`（各头等权相对 L2）与 `δ_value`（按 `ν` 加权）。

```
值范数 ν_h: min=0.344 max=2.826 mean=1.591
corr(ent, ν) = +0.031   （≈0 ⇒ 熵与下游重要度解耦，可分开检验）
```

### Part C：逐头权重方案 → 下游误差（ρ=0.9）

```
λ=uniform      δ_equal=5.3467e-02  δ_value=4.8455e-02  recall vs uniform=1.0000
λ=entropy(+)   δ_equal=5.3566e-02  δ_value=4.8541e-02  recall vs uniform=0.9856
λ=inv-entropy  δ_equal=5.3436e-02  δ_value=4.8435e-02  recall vs uniform=0.9811

λ=sharp-only   δ_equal=5.7602e-02  δ_value=5.2326e-02  recall vs uniform=0.7931
```

**排序稳定且反直觉**：`ν` 加权 < `1/熵` < 均匀 < 熵加权 ≪ 只留尖头。**按熵加权比均匀还差**——
第 173 篇 §4 的措辞（「权重落在平头」）在**选择目标**上是错的。注意各支持集之间 recall 仍有
0.97–1.00 的重叠，所以 `ρ=0.9`（已对齐）下差异小；真正的分水岭在 `ρ` 小的时候（Part C3）。

### Part C2：头共享的头香

```
oracle（每头各自 top-k）  δ_equal=4.7717e-02  δ_value=4.3018e-02
```

共享支持集（均匀）`5.3467e-2` vs oracle `4.7717e-2` —— 头共享本身带来 **~12%** 的历本，靠调
`λ` 补不回来（`λ=ν` 只到 `4.83e-2`）。这是 DSA 设计的选择（省一个 indexer 打分），不是 bug。

### Part C3：ρ 扫描——头越不一致，逐头权重越重要

```
ρ=1.0: uniform=4.1829e-02 entropy=4.1829e-02 value=4.1829e-02  熵罚=+0.000%  值范数收益=+0.000%
ρ=0.9: uniform=4.8455e-02 entropy=4.8541e-02 value=4.8288e-02  熵罚=+0.177%  值范数收益=+0.346%
ρ=0.7: uniform=6.7073e-02 entropy=6.8753e-02 value=6.6127e-02  熵罚=+2.504%  值范数收益=+1.410%
ρ=0.5: uniform=8.9530e-02 entropy=9.5925e-02 value=8.7069e-02  熵罚=+7.142%  值范数收益=+2.750%
```

- `ρ=1`（indexer 与主注意力完全对齐）时三种 `λ` **逐位相同**——因为每头都对齐同一个 `Î`，
  支持集完全一致；
- 头越不一致（`ρ` 越小），**熵加权越差、值范数加权越值**——`ρ=0.5` 时各自到 **+7.1% / −2.8%**。
  这给出一条可执行准则：**对齐越好，逐头权重越无所谓；一旦对齐变差，就按下游重要度加权。**

### Part C4：`λ = ν^p` 扫描

```
p=0.0: δ_value=4.8455e-02   p=1.0: 4.8288e-02   p=2.0: 4.8209e-02
p=0.5: δ_value=4.8353e-02   p=3.0: 4.8243e-02   p=4.0: 4.8296e-02
```

δ_value 在 **p≈2** 最小（`4.8209e-2`），一阶预测 `λ∝ν`（p=1）只差 0.16%；p≥3 因过度聚焦、
低 `ν` 头被牺牲而回升。**方向明确（正幂次）、最优点平宽**（p∈[1,2] 几乎无差）。

### Part D：熵是诊断量、不是权重

```
corr(ent_h, 均匀支持下的逐头误差 err_h) = +0.837
corr(ν_h,  均匀支持下的逐头误差 err_h) = -0.255
```

**复现第 173 篇**：逐头误差与**熵**强相关（+0.84）——平头误差大。但它与**值范数**弱负相关。
所以「误差出现在平头」和「该给平头加权」是两句话：前者是诊断，后者是错的（Part C 已证熵加权更差）。

### Part E：KL 不动点自检（λ 唯一决定学到的排序）

```
收敛后 KL=8.063e+00  |  支持集 recall: 训练前=0.1251 → 训练后 vs Top-k(p_λ)=1.0000
||softmax(I) − p_λ||₁ (mean/token) = 3.015e-07
```

用一个**自由打分 `I[T,C]`** 做稠密 KL 蒸馏（`min_I KL(p_λ || softmax(I))`），收敛后
`softmax(I)=p_λ`、`Top-k(I)=Top-k(p_λ)`（recall **1.0000**、L1 差 `3e-7`）。这坐实了第 1 节的推导：
**逐头权重 `λ` 就是「indexer 学到的目标」的定义**，不容含糊。真实训练用的是「支持集内稀疏 KL +
每步重选 `top-k`」的迭代，其不动点的**排序**与稠密版相同。

### Part F：量化把逐头权重淹没

```
[fp8]   uniform=1.2102e-01  entropy=1.2107e-01  value=1.2097e-01
[mxfp4] uniform=4.9174e-01  entropy=4.9178e-01  value=4.9172e-01
```

把 indexer 打分换成量化档（支持集从量化打分选、下游注意力仍用未量化头结构，隔离「选择」这一环）：

- fp8：δ_value `4.85e-2 → 1.21e-1`（**2.5×**）；mxfp4 `→ 4.92e-1`（**10.2×**）；
- 三种 `λ` **在同一量化档内差异只到第 4 位有效数字**（如 fp8 的 `1.2097e-1` vs `1.2107e-1`，
  0.08%）。

**结论与第 174 篇一致**：先保打分精度（量化是 2.5–10× 的一阶项），再谈逐头权重（≤3% 的二阶项）。

## 4. 三条「为什么」

1. **为什么 `λ` 决定学到什么**：KL 蒸馏的作用是把 indexer 打分分布拉向**目标分布** `p_λ`；
   `p_λ` 由逐头权重定义，故 `λ` 是「训练信号」的全部自由度。支持集是 `I` 的 top-k，
   于是问题退化成「哪个混合分布的 top-k 对下游最好」（Part E 坐实）。
2. **为什么该按 `ν` 而不是熵**：共享支持集 `S` 下，某头的输出误差平方期望
   `E[err_h²] = σ_h²·(mass_out_h + mass_out_h²/mass_in_h)`（`mass_out_h = 1−Σ_{s∈S}P_h[s]`）。
   按最终 loss 聚合时应按头的重要度 `ν_h` 加权，一阶最优化 ⇒ 最大化 `Σ_{s∈S} Σ_h ν_h P_h[s]`，
   即 **`Top-k(Σ_h ν_h P_h)` = `λ∝ν`**。熵只出现在 `mass_out_h` 的**大小**里（平头 mass_out 大），
   不决定该把谁顶上去。
3. **为什么 `ρ` 小的时候差异才大**：`ρ→1` 时每头都对齐同一个 `Î`，`P_h` 彼此几乎共线，
   任何 `λ` 的混合 `p_λ` 排序都一样；`ρ` 小则各头分布分散，混合权重才真正改变 `Top-k`。
   所以「逐头权重」是**对齐失败时的补偿手段**，不是常态。

## 6. 结论与边界

- **结论**：indexer 一次选出的共享支持集对全部主注意力头通用，蒸馏目标 `p_λ = Σ_h λ_h P_h`
  的逐头权重 `λ` **唯一决定 indexer 学到的排序**（KL 不动点，Part E）。评判标准是下游输出误差，
  **正确的 `λ` 是下游重要度 `ν_h`（≈值范数²），不是尖锐度/熵**——按熵加权比均匀**更差**
  （`ρ=0.5` 差 7.1%），按 `ν` 加权比均匀好 2.8%（`λ=ν^p` 在 p≈2 最优）。**熵是诊断量**：
  它预测「误差出现在哪一头」（corr +0.84），但不决定「支持集该服务谁」。这条**修正了第 173
  篇 §4 的措辞**。且**量化优先**：fp8 把误差抬 2.5×、mxfp4 抬 10.2×，远超逐头权重那 ≤3% 的空间。
- **边界 1**：主注意力头结构是**参数化建模**（`ρ` 旋钮 + 逐头 iid 噪声 + 逐头温度），不是
  真训练出的 DSA；下游重要度用**随机 `V` 的范数²**代理，真实 loss 对头的权重另有来源
  （如各头对应的下游模块）。「按 `ν` 加权」的正确性依赖 `ν` 的选取，本实验只证明「按熵加权是错的、
  按一个合理的下游重要度加权是对的」。
- **边界 2**：本机 H100（sm90）只能跑 **fp8 档**真实 kernel（`attention.hpp:124-130`）；
  MXFP8/MXFP4 是 SM100 专属，用纯 torch 复刻（`math.py` 语义）分析，**仅分析**。主 kernel 的
  UMMA/UTCCP 部分未在本机执行。
- **边界 3**：输入取 iid 高斯；真实 hidden 有重尾/低秩，头间可能有结构性相关（低秩共享 q/k）。
  实验用 `ρ` 参数化对齐、用逐头温度造尖锐度谱，是「可扫描的工作点」而非真实训练分布。
