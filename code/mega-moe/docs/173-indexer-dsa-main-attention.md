# indexer 选择翻转接进【真实头结构】的 DSA 主注意力：per-head softmax、GQA/MQA 与训练反向（H100 实测）

> 本文是「DeepSeek Mega MoE 前向 / 反向算子实现解析」专题的第 173 篇（P163 增量）。
> 第 171 篇（P161-1）量了 indexer 的 top-k 选择在 FP8/MXFP8/MXFP4 量化下的稳定性；
> 第 172 篇（P162-1）把选择接进「单头、单 softmax」的下游注意力输出，结论是**二阶**的。
> 但那篇 §5 明确留下口子：真实 DSA 主注意力的 **per-head softmax**、**GQA/MQA 的头共享**
> 未建模，且与第 157~160 篇的**训练反向**的联合误差未量。本篇补上「真实头结构」这一格。
>
> 问题：真实 DSA 里一个 query token 有 H_q 个头、索引选择只做一次却对**全部头共享**，
> 每个头又各有自己的 softmax 尖锐度。这种头结构会不会把「选错 3.4%/12% 的支持集」
> 放大成某几个头的大误差？训练反向（主注意力 `dV`、indexer KL 蒸馏 `dw/dq`）会不会更敏感？
>
> 答案在 H100(sm90) 上量出来：**头共享（GQA/MQA）几乎不改变选择误差**（G=1→32 只差 0.6%），
> 真正的敏感度藏在 **per-head 尖锐度**里（最平 1/4 头的误差是最尖 1/4 头的 **246×**），
> 反向 `dV` 与正向同量级、不放大；而 indexer 自己的训练梯度 **`dw` 出错的主因是「打分被量化」
> 而不是「选择被换掉」**（差 57×）。
>
> 主 kernel 的 MXFP4/MXFP8 UMMA 部分 **SM100 专属、仅分析**；indexer 打分用真实 SM90
> `fp8_fp4_mqa_logits` 锚定，主注意力头结构、per-head softmax、反向 **架构无关**。

## 1. 定位：从「单头下界」到「真实头结构」

第 172 篇把支持集换掉后的输出误差建模成「一个 softmax」，得到「选择翻转是二阶的」——翻转
发生在第 K 名边界、那里承载的 softmax 质量最小。但真实 DSA 的主注意力是**多头**的：

```
S_t = Top-k(I_t,:)                      # indexer 选择：逐 token 一次，对全部 H_q 个 query 头共享
O[t,h,:] = Σ_{j∈S_t} P[t,h,j]·V[j, g(h)]   # 每头自己的 softmax P[t,h,j]；g(h)=h//G 是 GQA 分组
P[t,h,j] = softmax_{j∈S_t}( a[t,h,j] ),  a[t,h,j] = <q_main[t,h], k_main[j,g(h)]>/√d
```

三个和第 172 篇不同的结构因素：

1. **per-head softmax**：每个头有各自的 `P[t,h,·]`，同一批翻转 token 在不同头里的权重不同；
2. **头共享**：支持集只做一次、全部头共用，一次翻转同时移动 G 个头（GQA/MQA 的 `G=H_q/H_kv`）；
3. **另训的 q/k**：indexer 与主注意力是**两套权重**，对齐但不相同（`ρ<1`）。

第 172 篇的「失配档」已用 `ρ` 旋钮参数化 ③，但只做了 ①② 的单头退化。本篇把 ①②③ 一起做，
并把「选择」这一环接到**训练反向**。

## 2. 模型与实验设计

`harness/exp_indexer_head_shared.py`（`bash harness/exp_indexer_head_shared.sh` 跑出 `.out.txt`）。
规模 `T=256, C=16384, H_q=32, D=128(=dv), Top-k=2048, block 无`；indexer 用 `H=32, d=64`
（与第 171/172 篇一致，bfloat16 高斯输入、fp32 权重、单序列 `ks=0, ke=C`）。

**indexer 打分**仍由真实 SM90 `fp8_fp4_mqa_logits` 锚定（`attention.hpp:67-134`），
FP8/MXFP8/MXFP4 三档用官方 torch 量化语义复刻（`per_token_cast_to_fp8/fp4`）。

**主注意力头结构（明确建模，不是训练出来的）**：真实 DSA 的 indexer 是对主注意力做 KL 蒸馏
训出来的，与主注意力**对齐但不相同**。本实验用逐头加性噪声建模这种「对齐」：

```
â[t,h,j] = ρ·Î[t,j] + √(1−ρ²)·g_h·ε[t,h,j]        # Î 是逐行标准化后的 indexer 打分
a[t,h,j] = â·√d / √d = â                          # 显式 1/√d（ε~N(0,1)、g_h 逐头增益）
```

`ρ=1` 即「indexer 与主注意力完全对齐」（第 172 篇的自洽档），`ρ` 越小越脱节；`ε` 逐头 iid。
这样做而非真造一副独立 q/k 的理由在 §3.2 用**真实独立 q/k** 坐实：未训练的 q/k 与 indexer
经验相关 `ρ_h≈0`，选择将完全无意义，必须用 `ρ` 参数化「已对齐」的工作点。

**反向量**：① 主注意力对 `V` 的梯度 `dV`（token 索引，可跨支持集逐元素比较）；
② indexer 自身 KL 蒸馏梯度 `dw/dq`（第 157 篇：`dL/dI = softmax_S(I) − p_S`，稀疏版在支持集内
重新归一化）。`dV` 用解析式算（`attn_backward_dV`），并用 `torch.autograd` 小规模对拍自检。

## 3. 结果

### 3.1 Part A：kernel 锚定 + 三档支持集

```
kernel vs torch-fp8 ref: max-abs-rel = 2.538e-04
[fp8  ] top-2048 recall = 0.9715 (flipped 58)
[mxfp8] top-2048 recall = 0.9708 (flipped 60)
[mxfp4] top-2048 recall = 0.8756 (flipped 255)
```

真实 SM90 kernel 与 torch 复刻 fp8 档最大相对差 **2.5e-4**（fp32 累加顺序差），复现第 171/172 篇。
recall 比第 172 篇（0.966/0.851）略高，因为这里 `C=16384`（top-2048 占 1/8，而非 1/16）——
边界竞争更轻。三档支持集**对全部 H_q 个 query 头共享**。

### 3.2 Part A2：真实独立 q/k 的经验逐头对齐 ρ_h（为什么必须用 ρ 旋钮）

```
独立 q/k: ρ_h mean=-0.00000 std=0.00037 min=-0.00076 max=+0.00079  (iid 地板 ~1/sqrt(T·C)=4.88e-04)
用独立 q/k 打分、teacher vs fp8 支持集: 输出 relL2=2.389e-01（≈随机支持集量级）
对照：本实验 ρ=0.9 构造的 head0 经验对齐 = +0.9000（≈旋钮值）
```

给主注意力配一副**独立随机**的 q/k（= 与 indexer 未对齐），逐头与 indexer 打分在全 `[T,C]`
上的皮尔逊相关都落在 iid 地板上（`4.88e-4`）——此时「选得对」与「注意力要的」无关，
换不换支持集输出都差到 `2.4e-1`（≈随机支持集）。这坐实：真实 DSA 能工作，**前提就是 indexer
被蒸馏到与主注意力对齐**（`ρ→1`）；本实验用 `ρ` 旋钮正是为了在「已对齐」的工作点附近扫描，
而不是拿一副无意义的未训练 q/k。同时验证构造本身：`ρ=0.9` 的 head0 经验对齐恰为 `+0.9000`。

### 3.3 Part B：GQA/MQA 头共享几乎不改变选择误差（rho=0.9）

```
G= 1 (Hkv=32):  fp8 relL2=1.134e-01/cos=0.993309  mxfp4 relL2=2.424e-01/cos=0.969781
G= 2 (Hkv=16):  fp8 relL2=1.134e-01/cos=0.993314  mxfp4 relL2=2.419e-01/cos=0.969916
G= 4 (Hkv= 8):  fp8 relL2=1.136e-01/cos=0.993290  mxfp4 relL2=2.424e-01/cos=0.969791
G= 8 (Hkv= 4):  fp8 relL2=1.140e-01/cos=0.993247  mxfp4 relL2=2.436e-01/cos=0.969516
G=32 (Hkv= 1):  fp8 relL2=1.141e-01/cos=0.993213  mxfp4 relL2=2.438e-01/cos=0.969434
```

**G 从 1（MHA）扫到 32（MQA）只让误差动 0.6%**（fp8 `1.134e-1→1.141e-1`；mxfp4 同理）。
为什么？——因为 DSA 的支持集**本来就是逐 token 共享**的（不是每头各自选），G 只改变
「一组 KV 被几个 query 头复用」，而 `ε` 是逐头 iid 的，共享与否不改变每个头自己看到的
翻转集合与权重。所以「头共享会不会放大误差」的答案是**不会**：真正的变量不是 G，而是 §3.5 的
**逐头尖锐度**。（若把支持集改成「每头各自 top-k」，才会出现 G 相关的行为——那不是 DSA 的设计。）

### 3.4 Part B2：平坦度校准——把量级接回第 172 篇

```
tau=0.5 (质量=0.766):  fp8=1.840e-02  mxfp4=4.258e-02
tau=1.0 (质量=0.410):  fp8=1.136e-01  mxfp4=2.424e-01
tau=2.0 (质量=0.244):  fp8=1.796e-01  mxfp4=3.774e-01
tau=4.0 (质量=0.178):  fp8=2.104e-01  mxfp4=4.401e-01
```

把分数整体除 `tau`（= 降低打分尺度、让 softmax 变平）。第 172 篇发现「输出误差 = 支持集
丢掉/错补的注意力质量」，这里换成真实头结构后**结论不变**：`tau=0.5` 时 teacher 支持集已捕获
**76.6%** 质量、fp8 只差 `1.84e-2`；`tau=4` 时只捕获 17.8%、fp8 差到 `2.1e-1`。
第 172 篇 `tau=8` 的工作点（质量 ~0.95、误差 `2.6e-3`）对应这里 `tau≪0.5`——两篇的 `tau` 不是
同一刻度（那边 indexer logits 尺度 ~18，这边标准化后 std~1），但**「质量高则误差小」是同一律**。

### 3.5 Part C：per-head 尖锐度才是敏感度所在（G=4, rho=0.9）

用逐头温度 `τ_h∈[10^{-1},10^{1}]` 造出尖锐度各异的头，量化档取 mxfp4：

```
熵-误差 corr=+0.820
最平 8 头（熵~7.618）err=4.536e-01 | 最尖 8 头（熵~1.929）err=1.841e-03 | 平/尖=246.41x
```

**聚合误差（`2.4e-1`）是个掩盖**：最平的 1/4 头误差高达 `0.45`，最尖的 1/4 头只有 `1.8e-3`，
相差 **246×**，且逐头误差与该头注意力熵的相关达 **+0.820**。原因与 §3.4 同：
平头里 top-2048 装不下多少质量，边界的翻转 token 权重可观；尖头里几乎全部质量都在
支持集内，翻转无关痛痒。**这条把「选择精度」从全局指标变成了逐头指标**——聚合 relL2
不能用来判断某个头是否需要更准的 indexer。

### 3.6 Part D：主注意力训练反向 dV 与正向同量级、不放大（G=4）

```
rho=1.0:  fp8 fwd=9.84e-02 dV=9.82e-02  mxfp4 fwd=2.11e-01 dV=2.11e-01
rho=0.9:  fp8 fwd=1.14e-01 dV=1.13e-01  mxfp4 fwd=2.42e-01 dV=2.42e-01
rho=0.7:  fp8 fwd=1.44e-01 dV=1.43e-01  mxfp4 fwd=3.04e-01 dV=3.04e-01
rho=0.4:  fp8 fwd=1.87e-01 dV=1.87e-01  mxfp4 fwd=3.92e-01 dV=3.92e-01
```

**`dV` 误差≈正向输出误差**（每个 ρ 下几乎相等），且随 `1-ρ` 单调升。原因：稀疏 softmax 的
反向是 `dV_j = Σ_t P[t,h,j]·dO[t,h]`，支持集被换掉时 `P` 的扰动与「丢掉/错补的质量」成正比，
而后者正是正向误差的来源——**反向不会额外放大选择翻转**。所以「§3.5 里最平的头」在反向里
同样是最脏的头，量级一致（不自洽训练的失真不会因反向而爆炸）。
自检：解析 `dV` 与 `torch.autograd` 小规模对拍 `relL2=0.000e+00`（逐位）。

### 3.7 Part E：indexer KL 训练反向 `dw/dq`——主因是「打分被量化」而非「选择被换」

```
[fp8  ] dw relL2=2.243e-01 | dq relL2=2.661e-01 | dw cos=0.975018 | 仅换支持集 dw=3.901e-03 | 仅量化打分 dw=2.243e-01
[mxfp8] dw relL2=2.075e-01 | dq relL2=2.580e-01 | dw cos=0.978525 | 仅换支持集 dw=3.896e-03 | 仅量化打分 dw=2.076e-01
[mxfp4] dw relL2=6.632e-01 | dq relL2=7.679e-01 | dw cos=0.784319 | 仅换支持集 dw=1.281e-02 | 仅量化打分 dw=6.640e-01
```

把 `dw` 误差拆成两半：**「仅换支持集」**（支持集换成量化档选出的、但打分仍用 teacher 的 I）
误差只有 `3.9e-3`（fp8）；**「仅量化打分」**（支持集用 teacher、但 `I` 用量化档）却有 `2.24e-1`——
**相差 57×**。也就是说 indexer KL 梯度 `dL/dI = softmax_S(I) − p_S` 的误差**几乎全部来自
`softmax_S` / `p` 用了被量化的 logits**（FP8 的 ~3.6e-2 量化噪声进了 softmax 的指数），
而不是「选择漂移」本身。MXFP4 更明显（`dw` `0.66`、cos 掉到 `0.78`）。
**含义**：想稳住 indexer 训练，优先要保的是**打分精度**（用了量化打分就付这个价），
而不是去追「支持集别翻」——后者对梯度的影响小两个量级。

## 4. 训练 / 推理含义

- **头共享（GQA/MQA）不是敏感度来源**：DSA 的支持集本就逐 token 共享，G=1→32 只差 0.6%。
  担心「MQA 让一次翻转损坏一组头」是错觉——`ε` 逐头 iid，翻转集合对每个头相同。
- **敏感度要逐头看**：聚合误差把最平头（`0.45`）与最尖头（`1.8e-3`）平均掉。**KL 蒸馏的
  权重/诊断应落在平坦头上**（熵大的头 top-k 装不满质量、翻转最伤）；用全局 relL2 判断
  「indexer 够不够准」会漏掉这些头。
- **对齐优先、与第 172 篇一致**：未训练 q/k 的 `ρ_h≈0` 时选择无意义；`ρ<1` 的对齐损失
  线性地进输出/梯度误差。真实 scheme 的根基是「indexer 被蒸馏到主注意力」。
- **反向不会放大**：`dV`≈正向、`dw/dq` 的主因是量化打分（57×）。训练里真正脆的是
  **用被量化的 logits 去算 softmax 梯度**（KL 蒸馏的 `dL/dI`），而非选择翻转。

## 5. 边界与未做

① 主注意力头结构是**参数化建模**（`ρ` 旋钮 + 逐头 iid 噪声 + 逐头温度），不是真训练出来的
DSA——真实 head 的 `q/k` 有低秩/共享结构、`ρ_h` 逐头不均。② 输入取 iid 高斯，真实 hidden 有
重尾/低秩。③ 本机无 SM100，MXFP4/MXFP8 主 kernel 的 UMMA/UTCCP 部分**仅分析**，量化用官方
`tests/test_attention.py` 的 torch 复刻；本实验的「主注意力」是标准 softmax 注意力（torch 复刻），
**不是** DeepGEMM 的 MQA-logits kernel。④ 未接真实 DeepEP/dispatch（NCCL 版本阻塞，见 ROADMAP
「阻塞」）。⑤ indexer 的 KL 蒸馏只做了 `dw/dq`，`dkv/dscale`（第 157~160 篇）未纳入本轮。

## 6. 结论

把第 172 篇的「单头下界」推进到**真实 DSA 头结构**（per-head softmax + GQA/MQA 共享支持集 +
另训 q/k）并接到训练反向，在 H100(sm90) 上用真实 SM90 `fp8_fp4_mqa_logits` 锚定 + torch 复刻量出：

**头共享（GQA/MQA）几乎不改变选择误差（G=1→32 差 0.6%）；真正的敏感度藏在逐头尖锐度里
（最平 1/4 头误差是最尖 1/4 头的 246×，熵-误差 corr +0.82）；主注意力反向 `dV` 与正向同量级、
不放大；indexer 自身训练梯度 `dw` 出错的主因是「打分被量化」（`2.2e-1`）而非「选择被换掉」
（`3.9e-3`），差 57×。**

给出 DSA 头结构的四条准则：**(1) 不必担心 MQA 放大选择误差；(2) indexer 的训练/诊断要逐头
加权到平坦头；(3) 对齐（ρ）仍是一阶变量、未对齐则选择无意义；(4) 保 indexer 打分精度比保
支持集稳定更重要（梯度侧差 57×）。**
