# indexer 的「可训练容量」：把 KL 蒸馏真的跑起来，indexer 到底需要多少秩

> 本篇是「DeepSeek Mega MoE 前向 / 反向算子实现解析」专题的增量（P168-1）。
> 承接第 175 篇（`docs/175`）与第 166 篇（`docs/176`）。第 175 篇用**自由打分** `I` 做稠密 KL 训练，
> 解析地给出不动点 `softmax_S(I)=p_λ`（`p_λ=Σ_h λ_h P_h/Σ_h λ_h`），即 `λ` 唯一决定 indexer 学到的排序；
> 第 166 篇用**真实低秩 q/k** 量到主注意力头高度冗余（`H_eff=1.97/32`）、逐头对齐 `ρ_h` 是一个谱，
> 并明确留下口子：**「用真实训练（非参数化）的 indexer 复核」**。
>
> 生产里 indexer 恰恰是**另训的小模型**：它由主注意力分布做 KL 蒸馏训练得到（README `:88-110` 的
> `out_ij = Σ_h ReLU(<q_i,h, kv_j>)·w_{i,h}` 打分算子）。前面各篇要么解析推导、要么一次性拟合，
> **从没真的用梯度下降训过它**。本篇把这一步补上，追问三件事：
> ① 优化是不是瓶颈？② 表示（秩）是不是瓶颈、`recall(R)` 长什么样？
> ③ indexer 需要多少秩**才够下游用**？
>
> **结论**：① 自由 logits 的 SGD 训到 `KL=0`、`recall=1.0`——第 175 篇不动点不是纸面结论，真能收敛；
> ② 一旦限制成低秩 `I=U Vᵀ`，**表示立刻成为瓶颈**，且所需秩远超直觉：`recall≥0.95` 需 **R=64**、
> 达到 FP8 级（`≥0.96`）需 **R=128**、`≥0.99` 要 **R=256**；但**梯度训练远优于最优秩-R 近似**
> （R=64：0.955 vs 0.635）；③ **下游误差却很快饱和**——`recall` 只有 0.76（R=8）时下游 `relL2`
> 才抬 10%，R=32–64 已到满秩级——**「排序 recall」和「下游质量」要的秩不是一个量级**。
>
> 真实 SM90 `fp8_fp4_mqa_logits` 锚定打分算子；训练/评估全纯 torch。**H100(sm90) 真机可跑**。

## 0. 结论先行

在真实 SM90 `fp8_fp4_mqa_logits` 锚定（max-abs-rel **2.538e-04**，与第 166 篇逐位一致）的 indexer
打分上，用**真实低秩共享 q/k**（`rank=8`、头间相关 `+0.641`、`H_eff=1.97/32`）造主注意力，蒸馏目标
`p_λ = Σ_h P_h / H_q`（`T=256, C=16384, H_q=32, G=4, D=128, top-k=2048`，H100 sm90 实测）：

1. **优化不是瓶颈**：自由 logits `I∈R^{T×C}` 用 Adam 训 300 步即 `KL=0.000e+00`、`recall@k=1.0000`
   （随机基线 `k/C=0.125`）。第 175 篇的 KL 不动点 `softmax(I*)=p_λ` **由真实 SGD 复核成立**。
2. **表示才是瓶颈，且所需秩远比直觉大**：低秩 `I=U Vᵀ` 的 `recall(R)`：
   `R=1→0.236`、`R=8→0.795`、`R=64→0.955`、`R=128→0.977`、`R=256→0.995`。
   **`recall≥0.95` 需 R=64、达 FP8 级（`≥0.96`）需 R=128、`≥0.99` 要 R=256。**
3. **蒸馏目标不是低秩**：共享打分子空间只有 `rank=8`，但 `p_λ` 经过 **softmax 混合**后，其
   `log p_λ` 的 99% 能量秩高达 **176/256**——这是「所需秩大」的根因。
4. **梯度训练 ≫ 最优秩-R 近似**：同样 R=64，训练 recall **0.955** vs `svd_lowrank` 的 **0.635**；
   R=256 时 0.995 vs 0.835。因为 KL/top-k 只在乎**softmax 顶部**，Frobenius 最优近似把能量花在长尾。
5. **秩需求由主注意力内在秩决定**：扫共享子空间 `srank`（`1→32`），`log p_λ` 内在秩
   `2→236`，`recall@R=16` 从 `0.913` 单调掉到 `0.493`——**头结构越丰富，indexer 越需要秩**。
6. **下游误差很快饱和**：`recall=0.76`（R=8）下游 `relL2=3.36e-2`，仅比满秩 `3.05e-2` 抬 10%；
   `R=32→3.13e-2`、`R=64→3.07e-2`，已贴满秩。逐头 oracle（头共享下界）是 `2.90e-2`。
   **要「排序 recall」和要「下游质量」所需的秩不是一个量级。**

**一句话**：indexer 的可训练性不是「优化」问题而是「**容量/秩**」问题；但这条容量曲线要分两把尺子看——
**撑起 top-k recall 要很高的秩（R≈128），撑起下游输出只要很低的秩（R≈32）**。

## 1. 定位：解析不动点 → 真实训练

第 175 篇的核心是一条**解析**结论：把 indexer 的 KL 蒸馏目标写成

```
min_I  KL( p_λ || softmax(I) ),   p_λ = Σ_h λ_h P_h / Σ_h λ_h
```

其最优解就是 `I* = log p_λ + const`，故 `softmax(I*) = p_λ`；支持集 `S_t = Top-k(I*_t,:) = Top-k(p_λ_t,:)`。
那篇用一个**自由打分矩阵** `I` 验证过（一次性拟合到 `||softmax(I)−p_λ||₁=3.0e-7`），但**没真的跑梯度下降**，
也没有回答「**如果 indexer 不是任意函数、而是有容量的（低秩/参数化），会发生什么**」。

真实 DSA 的 indexer 有自己的 q/k 投影（`iheads=32, idim=64`）、是一个**有容量的打分器**；它由 KL 蒸馏
训练。于是问题变成：**训练能把一个有容量的 indexer 推到离不动点多远？** 这就是本篇要量的事。

本篇用一个**受控的容量旋钮**：把 indexer 限制成低秩 `I = U Vᵀ ∈ R^{T×C}`（rank R）。这抽象了
「indexer 的内部维度/表达力」。`R=0`（自由）是上界、`R` 越小越受限。所有档都用**同一个 KL 目标 +
同一套 Adam** 训练——于是 `recall(R)` 曲线就是「容量 → 排序质量」的转换率。

## 2. 实验设置

- **indexer 打分算子**：真实 SM90 `fp8_fp4_mqa_logits`（`attention.hpp:67-134` / `:124-130`），
  `q=(fp8, None)`、`kv=(fp8, 逐 token fp32 sf)`、`weights` fp32，与纯 torch fp8 复刻对拍。
- **主注意力头结构**：`build_real_qk`（第 166 篇同款）——共享 rank 维子空间 `Kbase=B@U` + 逐 KV 组 /
  逐 query 头偏移 `α_h`（`logspace(-1.5, 0.5)`）；`A_h` 标准化后除逐头温度 `tau_h=logspace(-1,1)`。
- **蒸馏目标**：`P_h = softmax_C(A_h)`、`p_λ = Σ_h λ_h P_h / Σ_h λ_h`（`λ` 默认均匀）。
- **indexer 训练**：`I=U Vᵀ`（或自由 `I`），Adam，`lr=0.05`、400 步；损失
  `CE(p_λ, softmax(I)) = -Σ p_λ log softmax(I)`；报告的 **KL = CE − H(p_λ)**（扣掉地板）。
- **判据**：`recall@k = |Top-k(I) ∩ Top-k(p_λ)| / k`（`k=2048`）；对照 `svd_lowrank` 的最优秩-R 近似。
- **下游**：per-head softmax + GQA（`G=4`）共享支持集、随机 `V`，量 `‖O_sparse−O_full‖/‖O_full‖`。

## 3. 结果

### 3.1 Part A：kernel 锚定

```
kernel vs torch-fp8 ref: max-abs-rel = 2.538e-04
```

与第 166 篇逐位一致（同 seed、同量化语义）——所有训练都在这块**真实算子**的量化地板上做。

### 3.2 Part B：头冗余 + 蒸馏目标的内在秩

```
头间平均相关=+0.641  H_eff=1.97/32
log p_λ 的 99% 能量秩 = 176 / 256
目标熵 H(p_λ) = 7.9484
逐头熵 ent_h min=0.875 max=9.699
```

- 主注意力头高度冗余（`H_eff≈2`），**共享子空间只有 rank=8**——直觉上「indexer 只需分解很低的秩」。
- 但 **`log p_λ` 的 99% 能量秩是 176/256**：`p_λ` 是 32 个**各自 softmax** 的混合，
  `log(Σ_h softmax(A_h))` **不是**低秩的。这就是后面「所需秩大」的根源。

### 3.3 Part C：自由 logits 训练（优化不是瓶颈）

```
step  100: KL=2.119e-02  recall@k=1.0000
step  200: KL=9.537e-07  recall@k=1.0000
step  300: KL=0.000e+00  recall@k=1.0000
→ 自由 logits 训到 KL=0.00e+00、recall@k=1.0000（随机基线 0.1250）
```

- `KL` **单调压到 0**、`recall` 一步到 1.0——第 175 篇的不动点 `softmax(I*)=p_λ` 由真实 SGD 复核成立。
- **优化本身不是瓶颈**：`recall@k` 甚至在 KL 还没收敛时（step 100）就已 1.0——因为 top-k 只看排序。

### 3.4 Part D：低秩 indexer —— `recall(R)` 与最小充足秩

```
   R    KLafter  recall@k  svd_recall
   1  1.171e+00    0.2362     0.2357
   2  8.863e-01    0.3530     0.2673
   4  5.029e-01    0.5004     0.2914
   8  1.064e-01    0.7950     0.3821
  16  4.370e-02    0.8422     0.4486
  32  1.624e-02    0.9053     0.5423
  64  3.589e-03    0.9552     0.6349
 128  6.886e-04    0.9774     0.7386
 256  8.488e-05    0.9949     0.8346
最小充足秩：R*(>=0.95)=64  R*(>=0.96,=FP8级)=128  R*(>=0.99)=256
```

- **表示是瓶颈**：`R=1` 只能 recall 0.236、`R=8` 才 0.795、`R=64` 到 0.955、`R=256` 到 0.995。
  曲线**缓慢爬升、没有陡膝点**——与第 176 篇「内在秩 176」吻合。
- **训练远优于 SVD**：R=64 时训练 **0.955** vs `svd_lowrank` **0.635**；R=256 时 0.995 vs 0.835。
  原因：`recall` 只在乎 `softmax` **顶部**（top-2048 是概率质量高度集中的一小撮），而 Frobenius
  最优近似把误差均摊到整条长尾。**top-k 是「局部」目标，训练（KL）天然对准它。**
- **达到 FP8 级排序（recall≈0.96）需 R≈128**：这对「indexer 内部维度」是一个不低的要求。

### 3.5 Part E：秩需求由内在秩决定

```
 srank    corr   H_eff intr_rank R*(0.95)  R*(0.99)  rec@R=16
     1  +0.466    3.13         2       64      None    0.9128
     2  +0.566    2.35        10        8      None    0.9588
     4  +0.624    2.05        76       32       256    0.9344
     8  +0.641    1.97       176      128       256    0.8380
    16  +0.667    1.88       222      256      None    0.7775
    32  +0.671    1.86       236      256      None    0.4930
```

- `log p_λ` 内在秩随共享子空间 `srank` 从 **2 涨到 236**，`recall@R=16` 从 **0.913 单调掉到 0.493**。
  **头结构越丰富（内在秩越高），indexer 越需要秩**——这正是「容量由任务的内在维度决定」。
- 注意 `H_eff` 随 `srank` **下降**（3.13→1.86），却与「越难」反向：说明单纯的头间**相关度**不是
  indexer 容量的正确预测器，**`log p_λ` 的内在谱秩才是**。
- `srank=1` 是个例外（内在秩最低却要 R=64）：单一共享方向上，逐头偏移成为**全部**信号，
  混合分布在 top 区呈多峰，排序仍需一定秩才稳——留作边界。

### 3.6 Part F：逐头权重 `λ` 在训练后的影响

```
λ=uniform: 自由 recall=1.0000  低秩(R=8) recall=0.8008
λ=entropy: 自由 recall=1.0000  低秩(R=8) recall=0.8489
λ=value   : 自由 recall=1.0000  低秩(R=8) recall=0.7620
```

- **满秩下 `λ` 完全无影响**（都 recall=1.0）：不动点 `Top-k(softmax(I*))=Top-k(p_λ)` 对任何正 `λ` 都成立，
  但 `p_λ` 本身随 `λ` 变——满秩能精确拟合，故 recall 恒 1。
- **只有低秩瓶颈下 `λ` 才起作用**（R=8 时 ±5 点)：`λ` 改变「低秩子空间优先抓哪些方向」。
  这里 `entropy` 略优于 `uniform`/`value`，与第 166 篇「按 `ν` 加权更好」的**静态 δ_value 排序不直接可比**——
  因为两篇的尺子不同（那篇量下游误差、本篇量目标支持集 recall；且那篇 `λ` 进的是**同一次前向**的
  静态支持集，本篇 `λ` 进的是**训练目标**）。**边界：`λ` 的下游结论以第 166 篇为准，本篇只给「对 recall 无影响」**。

### 3.7 Part G：下游误差很快饱和

```
indexer rank= 0: recall=1.0000  输出 relL2=3.0535e-02
indexer rank= 2: recall=0.3464  输出 relL2=1.2736e-01
indexer rank= 8: recall=0.7630  输出 relL2=3.3627e-02
indexer rank=32: recall=0.8893  输出 relL2=3.1264e-02
indexer rank=64: recall=0.9428  输出 relL2=3.0713e-02
逐头 oracle（头共享下界）: 输出 relL2=2.9037e-02
```

- **下游对 rank 极不敏感**：`R=8`（recall 只有 0.76）下游才 `3.36e-2`，比满秩 `3.05e-2` 只抬 **10%**；
  `R=32→3.13e-2`、`R=64→3.07e-2`，已基本贴满秩。只有 `R=2`（recall 0.35）才明显崩到 `1.27e-1`。
- 复现第 172 篇「**选择翻转是二阶的**」：换掉 ~1/4 的支持集，输出误差只变第一位的十几个百分点，
  因为**丢掉/补进的都是概率质量很小的一小撮**。
- 逐头 oracle（每头各自 top-k）是 `2.90e-2`——**头共享的税很小**（第 166 篇结论），indexer 只要
  大致选对共享支持集即可。

## 4. 三条「为什么」

1. **为什么 `log p_λ` 内在秩这么高**：`p_λ` 是 `Σ_h λ_h softmax(A_h)`——**每个 softmax 的 log 是
   分段线性但非低秩**，混合后 `log(Σ_h ...)` 更不是。即便所有 `A_h` 只张成 rank-8 的子空间，
   softmax 的逐行归一化（减 `logsumexp`）会把「和」引入，秩被抬到 176。**softmax 混合放大了秩。**
2. **为什么梯度训练远优于 SVD**：`recall@k` 是**排序**目标，只由 `I` 顶部 2048 个分量决定。
   `svd_lowrank` 最小化 Frobenius 范数、把误差均摊到 16384 个分量（长尾占绝大多数），
   而 KL（`CE`）经 softmax 后由**顶部概率质量**主导——**目标对齐了，同样的秩就更管用**。
3. **为什么「排序 recall」和「下游质量」要的秩不同**：`recall` 是 **0/1 的集合重叠**，对每一个换掉的槽
   都计满罚；下游输出是**概率加权**，被换掉的槽里大部分概率质量极小（第 171 篇：翻转集中在
   「阈值±σ 候选池」，其概率质量只占几个百分点）。于是**下游只看「有没有选到质量大的槽」，
   对排序的细枝末节不敏感**——`R=32` 就够了。

## 6. 结论与边界

- **结论**：indexer 的可训练性不是「优化」问题（自由 logits 训到 `KL=0`），而是**容量/秩**问题。
  但容量曲线要分两把尺子：撑 **top-k recall** 要很高的秩（`R*≈64–128`，因为蒸馏目标 `log p_λ`
  经 softmax 混合后内在秩高达 176），撑 **下游输出质量**只要 **R≈32**（选择翻转是二阶的）。
  且**同样的秩，梯度训练远优于最优秩-R 近似**（top-k 是局部目标，KL 天然对齐它）。
- **边界 1**：低秩 `I=U Vᵀ` 是「indexer 容量」的**受控抽象**，不等同于 DSA indexer 真实的
  `Σ_h w_h ReLU(q_h·k)` 结构（那有自己的头/维超参）；本篇量的是「容量→排序」的转换率，
  不是某个具体 indexer 架构的绝对秩。真实架构的秩/维度需在真 kernel 上另测。
- **边界 2**：`p_λ` 用主注意力的**同一分布**做 teacher（`λ` 均匀），是「学得动到什么程度」的
  上界口径；真实蒸馏里 teacher 还含 `ρ<1` 的失配（第 173 篇），会进一步压低可达 recall。
- **边界 3**：本机 H100（sm90）只能跑 **fp8 档**真实 kernel（`attention.hpp:124-130`）；
  训练/评估是纯 torch，SM100 的 MXFP4/MXFP8 主 kernel 部分**仅分析**。主 kernel 的
  UMMA/UTCCP 未在本机执行——但「排序-容量」「下游-容量」两条曲线**架构无关**。
