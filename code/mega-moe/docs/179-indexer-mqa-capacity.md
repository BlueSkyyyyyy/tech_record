# 真实 indexer 架构的可训练容量：ReLU 让打分不再是低秩，「秩」的故事变了

> 本文对应路线图 **P169-1**，是「DeepSeek Mega MoE 前向 / 反向算子实现解析」的第 179 篇。
> 第 175 篇（P165-1）用**自由打分** `I∈R^{T×C}` 做稠密 KL 训练，证明不动点
> `softmax_S(I)=p_λ`（`p_λ=Σ_h λ_h P_h / Σ_h λ_h`）；第 166 篇（P166-1）用**真实低秩 q/k**
> 量到主注意力头高度冗余、逐头对齐 `ρ_h` 是一个谱；第 168 篇（P168-1）**真的用梯度下降训 indexer**，
> 给出「撑 top-k recall 要 R≈64–128」的容量结论。
>
> 但第 168 篇训的是**自由 logits** 与**低秩 `I=U Vᵀ`**——**两者都不是生产 indexer 的架构**。
> 生产里 indexer 是一个 **MQA 打分算子**（`README.md:88-110`）：
> `out_ij = Σ_h relu( q[i,h,:] · kv_j ) · weights[i,h]`（`README.md:105-108`）。
> **唯一的差别是那个 `relu`**：`Σ_h (q_h·k_h) w_h` 是一个双线性型、等价于秩 ≤ `H_i·d_i` 的 `U Vᵀ`；
> 而 `relu` 逐元素作用在低秩矩阵上会把**秩打满**。于是「indexer 需要多少秩」这个问题在真实架构下
> **提法就不对**——真正的资源是**内维 `H_i·d_i`（q/k 的投影预算）**，不是输出 logits 的秩。
>
> 本篇用梯度下降真训四种打分器（同一蒸馏目标、同一优化器、同一初始化），在**参数 / 内维预算**上对拍：
> 自由 logits、低秩 `U Vᵀ`、线性多头求和、**真实 MQA+ReLU indexer**。回答四件事：
> ① 生产尺寸的 indexer 有效容量等于多大的秩？② `relu` 到底值多少 recall、在哪个区间？
> ③ 内维形状 `(H_i, d_i)` 哪个轴是瓶颈？④ 下游是否跟上？
>
> **可跑性**：主 kernel（UMMA/MXFP4 block-scale）是 **SM100 专属、仅分析**；但打分**语义**与
> 这一整套容量问题架构无关。本篇在 **H100(sm90)** 上用真实 SM90 `fp8_fp4_mqa_logits` kernel 锚定
> （`csrc/apis/attention.hpp:67`），训练/评估全纯 torch。实验
> `harness/exp_indexer_mqa_capacity.{py,sh,out.txt}`。目标卡代号敏感：全文用「目标卡」。

## 1. 问题：第 168 篇训的模型类，不是生产 indexer

第 168 篇（`docs/178`）为回答「indexer 需要多少容量」训了三类东西，但它们和生产算子有本质差距：

| 模型类 | 形式 | 输出 logits 的秩 | 生产里对应 |
|---|---|---|---|
| 自由 logits | `I∈R^{T×C}` | ≤ `min(T,C)` | 上界，不可实现 |
| 低秩 | `I=U Vᵀ`，`U∈R^{T×R}` | ≤ `R` | 第 168 篇的「容量」代理 |
| **真实 indexer** | `I_tj = Σ_h relu(q[t,h,:]·k[j,:])·w[t,h]` | **无 rank 上界**（relu 非线性） | `fp8_fp4_mqa_logits` |

第 168 篇的结论「`recall≥0.95` 需要 R≈64」建立在**低秩模型类**上；但真实 indexer 根本不是一个低秩
双线性型。`relu·w` 逐元素非线性，把低秩核 `⟨q_h,k_h⟩`（秩 ≤ `d_i`）作用成**高秩矩阵**，所以
「需要秩 R」这句话对真实架构**无从谈起**。本篇把这件事量清楚。

生产算子的精确定义（`README.md:105-108`，逐行可核）：

```python
kv_j = kv[0][j, :] * kv[1][j].unsqueeze(1)   # [head_dim]，逐 token 的 fp32 scale
out_ij = q[i, :, :] @ kv_j                    # [num_heads]  —— 逐头内积
out_ij = out_ij.relu() * weights[i, :]        # [num_heads]  —— ReLU + 逐 token 权重
out_ij = out_ij.sum()                         # 标量
```

host 侧契约在 `csrc/apis/attention.hpp:18-44`（`check_mqa_logits_q_and_weights`：`q_sf` 的
`is_mx_sf==(arch_major==10)` `:32`、weights 行 16B 对齐 `:42`），入口 `fp8_fp4_mqa_logits:67`、
分页版 `:174`，SM90 走 `sm90_fp8_mqa_logits`（第 19 篇）——**这些算子语义都是本篇要复刻的对象**。

## 2. 四种打分器：同一目标、同一优化器、同一初始化

实验坐标（与第 166/168 篇逐位一致，便于对拍）：`T=256, C=16384, H_q=32, H_kv=8(G=4), D=128,
topk=2048`；主注意力用真实低秩共享 q/k（共享 `rank=8`，`build_real_qk`），逐头温度
`τ_h=logspace(-1,1,32)`，蒸馏目标 `p_λ` 取均匀 `λ`（`mixture_target`）。

四种打分器全部**直接可训练**（参数张量即模型），用 Adam 最小化 `CE(p_λ, softmax(I))`（等价 KL，
因目标熵是常数 `H(p_λ)=7.9484`）：

- **A 自由 logits** `I∈R^{T×C}`：`num_params = T·C = 4.19M`（上界）。
- **B 低秩** `I=U Vᵀ`：`num_params = (T+C)·R`。
- **C 线性多头求和** `Σ_h (q_h·k_h/√d) w_h`：`num_params = T·H_i·d_i + C·d_i + T·H_i`，
  输出秩 ≤ `H_i·d_i`（第 168 篇低秩的一种**结构化**实例）。
- **D 真实 MQA indexer** `Σ_h relu(q_h·k_h/√d) w_h`：与 C 同参数、同初始化，**只差一个 ReLU**。

关键对照设计：**C 与 D 参数、初始化、学习率完全相同，唯一变量是 ReLU**——这样「ReLU 值多少 recall」
就是一个干净的控制实验，而不是模型类差异。

## 4. 自由 logits 的上界与「拟合秩」（Part C）

```
== Part C: 自由 logits I∈R^{T×C} ==
  自由 logits: KL=0.00e+00  recall@k=1.0000  参数=4.19M  训后 logits 能量秩=67
```

上界照旧：自由 logits 训到 `KL=0`、`recall=1.0`。**但注意训后 `I` 的能量秩只有 67**——远低于目标
`p_λ` 的 176。这正是第 168 篇「训练 ≫ SVD」的机制：top-k 是**局部**目标、CE 只对准 softmax 顶部，
拟合出的 logits 只需在**高分尾部**匹配，不必复刻整个 176 维谱。所以「需要的秩」应读作**拟合秩**，
而不是目标的谱秩。

## 5. 主轴：同内维预算下，线性 vs ReLU（Part D）

把 `H_i` 固定为 1、`d_i=P`（故线性版输出秩 ≤ `P`，ReLU 版**不受此限**），扫 `P`：

```
== Part D: 同内维预算 P=Hi·Di 下，线性多头求和 vs 真实 ReLU indexer ==
      P    params |  linear rec  linear KL rank_lin |  relu rec   relu KL rank_relu
      8     0.13M |      0.7424  1.285e-01        8 |    0.8038 5.479e-02       161
     16     0.27M |      0.8359  4.820e-02       15 |    0.9010 1.696e-02       147
     32     0.53M |      0.8888  1.912e-02       30 |    0.9162 1.002e-02       126
     64     1.07M |      0.9428  5.375e-03       52 |    0.9416 4.935e-03       107
    128     2.13M |      0.9664  1.855e-03       73 |    0.9655 3.139e-03       101
    256     4.26M |      0.9787  8.011e-04       80 |    0.9798 2.523e-03       100
```

三件事读出来：

1. **ReLU 确实把秩打满**：`rank_lin` 紧贴内维 `P`（8→8、16→15、32→30…），而 `rank_relu`
   在 `P=8` 时高达 **161**（是 `P` 的 20 倍）——`relu(⟨q,k⟩)` 逐元素非线性，把秩从 `P` 抬到接近
   `T`。**这就是「真实 indexer 不是低秩模型」的硬证据**。
2. **ReLU 的收益在「内维不够」时最大**：`P=16` 时 `0.8359→0.9010`（**+6.5 点**）、`P=8`
   `0.7424→0.8038`（+6.1）、`P=32` +2.7；到 `P≥64` 两者打平（`P=64`：0.9428 vs 0.9416）。
   即 **ReLU 是内维预算不足时的容量替代品**。
3. **但秩高 ≠ 一定更好**：`P≥64` 后 ReLU 的 `rank_relu` 反而**单调收缩**（107→101→100）——
   训练把输出秩压到与拟合目标匹配的 ~100，这与 Part C 的「拟合秩 67」同向。

## 6. 生产尺寸：真实 indexer ≈ 参数匹配的低秩 R≈95（Part E + 部分 F）

低秩 `U Vᵀ` 的 `recall(R)`：

```
== Part E: 低秩 I=U Vᵀ（秩 R） —— 与真实 indexer 在同参数量上对拍 ==
     R    params   recall         KL
    64     1.06M   0.9553  3.580e-03
    95     1.58M   0.9669  1.609e-03
   128     2.13M   0.9773  6.862e-04
   256     4.26M   0.9949  8.583e-05
```

生产 indexer 默认形状 `(H_i,d_i)=(32,64)` 的参数量是
`T·32·64 + C·64 + T·32 = 524288 + 1048576 + 8192 = 1,581,056 ≈ 1.58M`；而低秩 `R=95` 的参数
`(T+C)·R = 16640·95 = 1,580,800 ≈ 1.58M`——**两者参数几乎精确相等**。对应的 recall 见 Part F：
`(32,64)` 真实 indexer `0.9693`，低秩 `R=95` 是 `0.9669`。**几乎重合。**

> **结论 1**：第 168 篇「撑 top-k recall 要 R≈64–128」的结论，**在真实 MQA+ReLU 架构下依然成立**：
> 生产 indexer 的有效容量 ≈ 参数匹配的低秩 `R≈95–128`。它那巨大的**内维（`H_i·d_i=2048`）并没有
> 白换到更高 recall**——真正定容量的是参数预算（主要由 **KV 投影 `C·d_i`** 决定，`C·64=1.05M`
> 占了 2/3），不是内维。

## 7. 形状 `(H_i, d_i)` 与逐头权重（Part F）

```
== Part F: 真实 indexer 的形状 (Hi,Di) 与逐头权重 w 的作用 ==
   Hi   Di  P=Hi·Di  relu rec  no-w rec no-relu rec
    1   64       64    0.9420    0.9400      0.9429
    4   64      256    0.9524    0.9485      0.9497
    8   64      512    0.9633    0.9644      0.9498
   16   64     1024    0.9704    0.9697      0.9479
   32   64     2048    0.9693    0.9699      0.9462
   32    8      256    0.7140    0.7184      0.7996
   32   16      512    0.9097    0.8833      0.8410
   32   32     1024    0.9598    0.9599      0.8972
    8  128     1024    0.9708    0.9717      0.9640
```

- **`d_i`（逐头内维）是关键轴，`H_i`（头数）不是**。同 `P=1024`：`(8,128)=0.9708`、
  `(16,64)=0.9704`、`(32,32)=0.9598`、`(32,16)=0.9097`——**把内维摊薄成很多小头会被惩罚**。
  同一头数 `H_i=32` 下 `d_i=8→16→32→64` 是 `0.7140→0.9097→0.9598→0.9693`，**`d_i` 每翻倍都涨**。
- **`H_i` 可以砍**：`H_i=32→8`（`d_i=64`）recall 只从 `0.9693` 掉到 `0.9633`（−0.6 点），而 q 侧参数
  从 `T·32·64=524K` 降到 `T·8·64=131K`（总参数 1.58M→1.18M，−25%）。**头多而薄的 indexer
  是最差的形状**。
- **逐头权重 `w` 几乎无用**：`no-w`（`w≡1`，只训练 q/k）与训练 `w` 的差异处处 ≤0.6 点
  （`(8,64)`：0.9633 vs 0.9644——`no-w` 甚至略好）。这与第 175/176 篇「逐头权重杠杆塌了」在
  **真实可训练架构**里再次吻合：`w` 不是容量瓶颈。
- **ReLU 在 `d_i≥16` 稳定加分、在 `d_i=8` 反有害**：`(32,64)` `0.9462→0.9693`（+2.3）、
  `(32,32)` `0.8972→0.9598`（+6.3）、`(32,16)` `0.8410→0.9097`（+6.9），但 `(32,8)`
  `0.7996→0.7140`（**−8.6**）。机制清楚：`d_i` 极小时线性多头求和已近满秩（`H_i·d_i=256=T`），
  ReLU 只是**扔掉负内积**、损失信息；`d_i` 小时线性被秩卡住，ReLU 才救场。

## 8. 下游误差：很快饱和（Part G）

把训好的 indexer 支持集 `S=Top-k(I)` 接进真实下游（per-head softmax + GQA 共享，与第 172/173 篇同款）：

```
== Part G: 训好的真实 indexer 支持集的下游误差（per-head softmax + GQA 共享）==
                  config   recall      relL2
      indexer Hi=1,Di=16   0.9020 9.1879e-02
      indexer Hi=1,Di=32   0.9168 6.5078e-02
      indexer Hi=8,Di=64   0.9633 6.5028e-02
     indexer Hi=32,Di=64   0.9698 6.4967e-02
```

`Hi=8,Di=64`（recall 0.9633）与 `Hi=32,Di=64`（0.9698）的下游 `relL2` **都是 6.50e-2**——在
`Hi=8` 之后完全饱和；只有掉到 `Hi=1,Di=16`（recall 0.9020）才抬到 9.19e-2。**这与第 168 篇
「下游很快饱和、R=32 已贴满秩」以及第 172 篇「选择翻转是二阶」一致**：撑下游质量所需的 indexer
容量，比撑 top-k recall 更小。

> **结论 2**：从生产视角看，`(H_i=8, d_i=64)` 的 indexer（参数 −25%、recall −0.6 点、下游**不变**）
> 是一个有吸引力的配置；而 `(32,8)` 这种「多头薄内维」是最差形状。

## 9. 小结与边界

- **真实 indexer 架构的容量，用「参数匹配的低秩秩」来读，与第 168 篇一致**：生产 `(32,64)`
  （1.58M 参数）≈ 低秩 `R≈95`（1.58M）；它的巨大内维 `H_i·d_i=2048` **没有**换成更高 recall。
- **`ReLU` 的作用被精确定位**：它让输出 logits 的能量秩从内维 `P` 抬到 ~161（`P=8`），在
  **内维不足**（`P≤32`）时值 +3~7 点 recall；在 `d_i≥16` 的生产区间稳定 +1.3~6.9 点；
  但在 `(32,8)` 这种线性已满秩的极端形状下**反有害**。**「indexer 需要多少秩」这一问法，
  只有在把 ReLU 拿掉、退化成双线性型时才成立。**
- **形状准则**：`d_i`（逐头内维）是瓶颈轴、`H_i`（头数）可砍；逐头权重 `w` 是零头。
- **下游饱和**：`Hi≥8` 之后下游 `relL2` 不再改善——容量该给「撑 recall」而不是「撑下游」。

**边界**：① 主 kernel（UMMA、MXFP4/MXFP8、`packed UE8M0`）是 **SM100 专属、仅分析**；本篇用
SM90 `fp8_fp4_mqa_logits` 锚定**算子语义**，量化档为 fp8（`tests/test_attention.py:59-72`
的 `quantize_mqa_q` 语义；MXFP4 见 `deep_gemm/utils/math.py:84` `_quantize_to_fp4_e2m1`）。
② 训练用的是**目标 p_λ（均匀 λ）**、真实低秩共享 q/k；换 λ 或换头结构（第 175/176 篇的旋钮）
会移动数值，但「有效容量 ≈ 参数匹配低秩秩」「ReLU 是内维替代品」的定性结论来自架构，不依赖 λ。
③ `(32,8)` 的无 ReLU 点（0.7996）受优化限制（结构化分解的训练难度），已在 §7 注明，不影响主结论。
④ 全部数字为真机单次运行（绑空闲卡，`T=256,C=16384`），非多次平均。
