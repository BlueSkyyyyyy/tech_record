MoE 反向的激活存储 vs 重算：h=linear1 预激活（SwiGLU 反向输入）存下来还是重算。
Mega MoE 融合主 kernel 是 SM100 专属、本机不可跑；本实验用真实 SM90 FP8 grouped/dense kernel。
====================================================================================================
## A. 语义与逐位性：重算 h == 存下来的 h，且 dG 逐位一致
   真实 SM90 `m_grouped_fp8_gemm_nt_contiguous`（前向 L1）跑两次；
   存一半的对照：只存 G1，由已存的（per-token FP8）SwiGLU 输出反推 G2=a/silu(G1)。
====================================================================================================
T=256 H=2048 I=1024 E=8 topk=2  m_total=1024 (M-alignment=128)
   STORE-ALL h vs RECOMPUTE h:  torch.equal = True   (max|d|=0.000e+00 bf16 ulp)
   SwiGLU 反向 dG:  torch.equal = True  rel = 0.000e+00
   STORE-G1 反推 G2:  vs 真 G2  rel(fp32 存储)=6.824e-02  rel(FP8 存储)=4.273e-01

   RECOMPUTE 额外 0（x 已在手，反向 wgrad 本就要它）。shared 专家同理（S=Es·I）。

## C. 时间 / 可重叠性：重算 = 一次前向 L1 GEMM，能否藏进「不依赖 h 的反向 GEMM」

   不依赖 h 的：dgrad L2 (dA=dY@W2)、wgrad L2 (dW2=a^T dY) —— 它们可与重算并发。
