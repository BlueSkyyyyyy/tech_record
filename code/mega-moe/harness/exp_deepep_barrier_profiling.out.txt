### Part F：真实 `bench_kineto` 的 barrier 测时路径（8×H100 NCCL + DeepGEMM FP8 kernel）
  kernel = sm90_fp8_gemm_1d2d（M=N=K=4096）；每次 bench_kineto 15 tests × 2 批，重复 3 次
  torch.cuda._sleep(2e7) 墙钟 = 13.47 ms（注释标 ~10ms，用大 kernel 削发射抖动）
  模式                     dur[us] 三次                            min      max   spread
  no-barrier             [99.8, 99.7, 99.8]                   99.7     99.8     0.1%
  barrier=all_reduce     [101.1, 101.1, 100.9]               100.9    101.1     0.2%
  barrier=custom         [101.5, 101.5, 101.5]               101.5    101.5     0.1%
  disabled(env)          [99.0, 98.7, 98.6]                   98.6     99.0     0.4%
  中位数：no-barrier=99.8us  all_reduce=101.1us  custom=101.5us
  disabled(env) 中位数 = 98.7us → 应与 no-barrier 同区间（barrier_comm_profiling 被环境变量置 0）
  **event 计时参考**（flush 在 start event 之前，不计入）：min=104.7us med=106.0us
  ⇒ 真实 kernel 时长 ≈ 106us（快档）。将所有「无 sleep」测量（no-barrier + disabled(env) + sleep=0 扫描）合并看：这些样本横跨 98–419us，呈**双峰**（快档 ~100us、慢档 ~417us，≈4×）；而三种 barrier 模式每次都落在快档且 spread <0.3%。
