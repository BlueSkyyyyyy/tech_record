# 09 · Megatron 真层端到端前反向对拍（M10-1）

> 系列第 10 篇。前九篇把 FLA `fla/ops/kda` 的前反向、门控/布局边界、chunk/pad/varlen/CP
> 都锚定到了 `src/kda_ref.py`，并在 M9-1 用**逐字复刻调用变换的 shim**核对了 Megatron
> `kda.py` 的调用契约——但 M9-1 从头到尾**没有 import 过真实的 `KimiDeltaAttention` 模块**，
> 因为容器里 `import megatron.core` 会在 import 期触发一条版本断言。本篇（M10-1）先把这条
> 阻塞拆掉，然后**实例化真实层**、跑它的训练前向/反向，并在两个粒度上对拍：
>
> - **Part B（核心算子）**：把真实层交给 `chunk_kda` 的**那份操作数**截获下来，
>   在**同一批操作数**上比 FLA `chunk_kda` 与 fp64 参考 `src/kda_ref.py`（前向 + 六项梯度）；
> - **Part C（整模块端到端）**：用一份**权重完全相同**的第二模块，把核心算子换成 fp64
>   参考，其余（in_proj / conv1d / gated RMSNorm / out_proj）一字不动，比整模块输出、
>   `hidden_states.grad` 与全部参数梯度。
>
> 脚本：`harness/check_port_e2e.py`；原始输出：`harness/check_port_e2e.out.txt`。
> 行号按本机版核对：`Megatron-LM`（`kda.py`、`dist_checkpointing/strategies/nvrx.py`）与
> 容器内 pip 包（`fla==0.5.2`、`deep_ep`）。

## 1. 先拆 import 阻塞：两条版本断言

M9-1 的「已知坑」记了一条：容器内 `import megatron.core.ssm.gated_delta_net.kda` 失败，
根因是 `nvidia-resiliency-ext` 版本断言。实际动手后发现是**两条** import 期断言，且都
与 KDA 本身无关：

### 1.1 `nvidia-resiliency-ext` 版本（0.5.0 < 0.6.0）

`import megatron.core` 会走到分布式 checkpoint 的 nvrx 探测
（`megatron/core/dist_checkpointing/strategies/nvrx.py:44-46`）：

```python
assert (
    is_nvrx_min_version()
), f"Minimum required nvidia-resiliency-ext package version is {NVRX_MIN_VERSION}."
```

它比较的是**运行时模块的 `__version__`**（`nvrx.py:85`：`str(nvrx.__version__)`），容器里
装的是 `0.5.0`、门槛 `0.6.0`。**修法**：在 `import megatron` **之前**把内存里的版本号改到
满足门槛（脚本 `check_port_e2e.py` 顶部）：

```python
import nvidia_resiliency_ext as _nvrx
_nvrx.__version__ = "0.6.0"     # 只骗过版本断言；async-ckpt 符号探测照旧
```

这不改变任何 KDA 数值——它只是让 checkpoint 特性探测通过（真正的能力探测仍走
`has_nvrx_async_support()` 的符号检查）。

### 1.2 DeepEP 的 NCCL 版本硬校验

过了第一条，下一条来自 MoE 的 `deep_ep`（被 `megatron.core` 的 import 链拉进来）。它在
import 期跑 `check_nccl_so()`（`deep_ep/__init__.py:55`），逐字节比较**运行时加载的
libnccl** 与**它链接时预期的 libnccl**（`:19-56`），本机是 `libnccl.so.2.29.7` vs
`.../nvidia/nccl/lib/libnccl.so.2` 不一致、直接 `AssertionError`。**修法**：它留了逃生开关
（`:24`）：

```python
if int(os.environ.get('EP_SUPPRESS_NCCL_CHECK', 0)):
    return
```

设 `EP_SUPPRESS_NCCL_CHECK=1` 即可（脚本也已内置 `NCCL_NVLS_ENABLE=0`，与 M8 的
CP 单机约束一致）。

两条都置好后，真实层才 import 得进来：

```python
from megatron.core.ssm.gated_delta_net import KimiDeltaAttention  # OK
```

**这是本系列第一次在容器里跑真实 `KimiDeltaAttention` 模块**（M9-1 只跑 shim）。

## 2. 建模块与建「参考芯」模块

模块构造照抄 Megatron 自己的单测（`tests/unit_tests/ssm/gated_delta_net/test_kda.py`）：
小配置（`hidden=128`、`H=K=V=32`、`linear_conv_kernel_dim=4`、`kda_safe_gate=True`、
`kda_lower_bound=-5.0`）、单卡 tp=cp=1、`use_cpu_initialization=True`。dist 用单进程
`nccl`，`ps.initialize_model_parallel(1, 1)`。

两个关键手法：

**(a) 截获核心算子的入参。** 模块把核心算子存成属性 `self.gated_delta_rule`
（`kda.py:141`：`self.gated_delta_rule = chunk_kda`），调用在 `kda.py:439-449`。用一个
**记录器**包住它，就能把这份操作数原样拿到：

```python
orig = kda.gated_delta_rule
def recorder(**kw):
    captured.clear(); captured.update(kw)   # 存 q/k/v/g/beta/A_log/dt_bias + 门控 flags
    return orig(**kw)
kda.gated_delta_rule = recorder
```

**为什么截获比「照 `pre_gated_delta_rule` 再算一遍」更硬**：截获到的是模块**真正**喂给
kernel 的张量（已经过 in_proj 切段、conv1d、l2norm、CP 头置换），Part B 因此没有任何
「复刻变换」的自由度，能干净地隔离**核心算子本身**。

**(b) 参考芯模块。** 建第二份逐位同权重（`load_state_dict`）的模块，把
`gated_delta_rule` 换成一个调用 `src/kda_ref.py` 的包装器：

```python
def gdr(q, k, v, g, beta, A_log, dt_bias, ..., safe_gate=False, lower_bound=None, **kw):
    act_g = ref.kda_gate(g, A_log, dt_bias, lower_bound if safe_gate else None)
    o, fs = ref.kda_chunked_fwd(q, k, v, act_g, beta, chunk_size=64)
    return o.to(q.dtype), fs
```

注意**门控要在包装器里现场激活**：Megatron 设 `self.use_gate_in_kernel = True`
（`kda.py:120-121`），即把 $A_\text{log}$/`dt_bias` 的激活留给内核；参考侧就对应
`kda_gate(..., lower_bound)`（safe-gate 分支，`src/kda_ref.py:63-68`）。`beta` 已是
sigmoid 后的值（`kda.py:181`），两边都直接吃。`chunk_size=64` 与 FLA `chunk_kda` 默认一致
（M8-1 已证 KDA 只允许 32/64）。

## 3. Part A：真实层前向/反向 smoke

三种形状（`T×B = 64×2 / 128×2 / 250×1`，`250` 非整除 64）、`float32` 与 `bfloat16`：

```
  -- Part A: real-layer fwd/bwd smoke
     T=  64 B=2  shape/dtype=True  hs.grad finite=True  nonfinite_params=0
     T= 128 B=2  shape/dtype=True  hs.grad finite=True  nonfinite_params=0
     T= 250 B=1  shape/dtype=True  hs.grad finite=True  nonfinite_params=0
```

输出形状/dtype 与输入一致、`bias is None`、`hs.grad` 有限、**每个**有梯度的参数都有限
（`A_log`/`dt_bias` 仍是 fp32，`kda.py:117-118` 的 `mark_keep_in_fp32` 生效）。

## 4. Part B：核心算子在截获操作数上的对拍（FLA vs fp64 参考）

在真实层**当次**喂给 `chunk_kda` 的那份操作数上，分别用 FLA `chunk_kda` 与 fp64 参考跑
前向、再对 `mean(o²)` 反传比六项梯度。

`float32`（FLA 对 fp32 输入走 tf32）：

```
     fwd o: (2,64,4,32)  max_abs=9.565e-05  rel=1.675e-03
     grad q     max_abs=2.098e-09  rel=2.679e-03
     grad k     max_abs=5.134e-09  rel=3.087e-03
     grad v     max_abs=3.087e-09  rel=3.073e-03
     grad g     max_abs=3.611e-11  rel=2.920e-03
     grad beta  max_abs=9.237e-09  rel=3.232e-03
```

`bfloat16`：

```
     fwd o: (2,64,4,32)  max_abs=2.441e-04  rel=4.878e-03
     grad q  rel=4.082e-03   grad k  rel=6.061e-03   grad v  rel=8.511e-03
     grad g  rel=4.673e-03   grad beta rel=3.579e-03
```

**结论**：真实层与参考在核心算子上落 **tf32/bf16 底噪**（fp32 ~2–3e-3、bf16 ~4–9e-3），
与 M6/M7/M8 的「直调 FLA」锚定同量级——说明**真实层里的那一次调用没有任何隐藏的
布局/门控/精度偏差**，M9-1 用 shim 得出的契约在真层上被重新确认。

## 5. Part C：整模块端到端对拍

两个权重逐位相同的模块，一个核心走 FLA、一个核心走 fp64 参考，其余层一字不动，比整模块
输出 `out`、输入梯度 `hidden_states.grad`、以及全部参数梯度（`A_log`/`dt_bias`/in_proj/
conv1d/RMSNorm/out_proj）。

`float32`：

```
     T=  64 B=2  out max_abs=4.671e-04  hs.grad max_abs=2.476e-08  param.grad max_abs=1.312e-06
     T= 128 B=2  out max_abs=4.926e-04  hs.grad max_abs=1.445e-08  param.grad max_abs=1.567e-06
     T= 250 B=1  out max_abs=5.095e-04  hs.grad max_abs=1.394e-08  param.grad max_abs=2.011e-06
```

`bfloat16`：

```
     T=  64 B=2  out max_abs=2.441e-03  hs.grad max_abs=1.192e-07  param.grad max_abs=7.629e-06
     T= 128 B=2  out max_abs=2.808e-03  hs.grad max_abs=6.706e-08  param.grad max_abs=3.815e-06
     T= 250 B=1  out max_abs=2.930e-03  hs.grad max_abs=8.941e-08  param.grad max_abs=4.768e-06
```

**读法**：
- `out` 的 bf16 差（~2.4–2.9e-3）主要是**输出被量化到 bf16** 后的台阶，量级与核心算子的
  bf16 底噪一致；fp32 下收到 5e-4。
- `hs.grad` 差 fp32 ~1.4–2.5e-8、bf16 ~7e-8–1.2e-7，`param.grad` 差 fp32 ~2e-6、bf16 ~7.6e-6
  ——**端到端梯度**也只差 fp32/tf32 底噪。这是 M10-1 最关键的结论：**把核心算子从 FLA 换成
  独立 fp64 参考，经过 in_proj/conv1d/RMSNorm/out_proj 的完整前反向之后，梯度仍在底噪内**，
  即移植边界的误差不会被外层模块放大。

## 6. 结论与边界

- 真实 `KimiDeltaAttention` 模块在容器内跑通（先拆两条 import 期版本断言），前向/反向
  数值健全；
- 真实层当次喂给 `chunk_kda` 的操作数，在**核心算子**与**整模块**两个粒度上都只与 fp64
  参考差 tf32/bf16 底噪——M9-1 的 shim 契约在真层上确认；
- **边界**：仍是**单卡 tp=cp=1、SBHD 非 packed**（`cu_seqlens=None`、`cp_context=None`）；
  packed/THD、headwise/chunkwise CP、GVA（Megatron KDA 本就不支持，见 `docs/08`）与
  `gdn_pre_gated_delta_rule_fusion` 缺口均未覆盖；
- **复现**：见 `harness/check_port_e2e.py` 顶部两条环境变量 / 版本 patch；RNG 由
  `model_parallel_cuda_manual_seed` 与 `torch.manual_seed` 固定。
