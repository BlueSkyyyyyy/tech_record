## 一、System One：先量可靠性，再谈要几层

### 1. SO-Arena（57↑）

SO-Arena: Benchmarking the Capability Spectrum and Reliability of System One Models · National University of Singapore · [2611.15777](https://huggingface.co/papers/2611.15777) · [code](https://github.com/holdrain/SO-Arena) · [项目页](https://lichenlillc.github.io/SO-Arena)

- 问题：System One 模型主打「不写长 CoT、一次前向出决策」，但现有 benchmark 只看聚合准确率，既看不出能力覆盖的宽度，也看不出决策在边界条件下是否可靠。
- 基准：覆盖 11 个领域、5 类能力；用可靠来源做证据约束，并把参考标签对照模型可见输入做人工复核；领域内还有细粒度难度标准，以及让模型在 sandbox 里逐步执行动作的交互式评测。
- 可靠性：除准确率外单列两项——受控改变选项集合后的决策稳定性，以及没有有效选项时能否识别「无法作答」。推理密集任务还可做 System One 与 System Two 的对照。
- 数字：评了 21 个模型。scaling 与额外推理带来的收益在不同领域差异很大；更关键的是，总表现最好的 System One 模型在可靠性上只排第七。
- 为什么值得看：全日最高票说明社区也在等这把尺子。对训练系统，可靠性指标应该进固定 eval suite，而不是等上线后靠 bad case 发现。

### 2. Actor, Judge, or Teacher?（26↑）

Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents · Zhejiang University · [2611.17167](https://huggingface.co/papers/2611.17167) · [code](https://github.com/ZJU-REAL/decision-agents) · [项目页](https://zjureal.com/decision-agents/)

- 问题：决策模型用「带概率的类型化输出」回答，因此同一个模型可以选动作（actor）、评动作（judge），也可以给每个动作打分来教策略（teacher）。以往工作主要把它当 actor，用「会不会做」判断价值。
- 实验：3 个决策模型 + 3 个通用 LLM，在 ALFWorld 上分别当 actor 和 judge；再用 JEV 当 teacher，在 ALFWorld 与 WebShop 上教一个 Qwen2.5-1.5B 策略。
- 发现：六个模型当 actor 时都会被更容易的 subgoal 拉走，漏掉必须先完成的那个；但同一批模型看完整条轨迹当 judge 时，能正确给通向该 subgoal 的步骤记功。问「这一步有没有帮助」比问「任务会不会成功」更能区分有用与无用动作。
- 数字：JEV 当 teacher，用 GRPO 把 1.5B 策略的 ALFWorld 成功率从 72.8% 提到 82.9%，WebShop 从 56.8% 提到 71.4%。
- 为什么值得看：actor 与 teacher 的能力可以解耦。对 agent RL，这意味着过程奖励未必要由最强的执行模型给，一个看得到结局的 judge 可能更便宜也更准。

### 3. 从 LLM 到高效 System One（2↑）

From Large Language Models to Efficient System One Models via Adaptive Computation · [2611.16321](https://huggingface.co/papers/2611.16321) · [code](https://github.com/minhkks/NestOne)

- 问题：把 LLM 改成 System One 决策模型，通常只把语言模型头换成 decision head，骨架全保留，于是每次决策都要付所有层的计算。
- 发现：决策信息集中在中间层，前几层负责建基础特征，最后六层可以直接去掉而不掉点；独立训练的小模型大多在模仿完整模型，并没有发展出专门的决策能力。
- 方法：联合训练完整模型与若干前缀子模型，子模型共享最后的层和 decision head，通过自蒸馏对齐；一个轻量 gate 读每个出口的 hidden state，决定是否继续算下去，让同一个模型在多个深度上运行。
- 数字：7 个决策 benchmark 上，每个深度都不低于独立训练的同深度模型，并通过自适应计算取得更好的 accuracy-efficiency 权衡；摘要没有给具体延迟或 FLOPs 数字。
- 为什么值得看：结论不是「换小模型」，而是「共享不同深度的计算」。最后六层可删这一条，对推理栈的层间调度是直接可试的剪枝假设。

## 二、Agent 工程：判官、压力测试与验收口径

### 4. DeepStress（3↑）

DeepStress: Stress-Testing Deep Search Agents · Orange · [2607.13920](https://huggingface.co/papers/2607.13920)

- 问题：search agent 在多步问答上表现不错，但对低质量证据的鲁棒性几乎没被测过——这类证据在 benchmark 语料里罕见，失败也难以复现。
- 方法：把 retrieval 模块换成合成环境，按每个 query 动态生成文档，并独立控制可信度、相关性与事实性三个维度，从而按受控比例注入「坏证据」。
- 评测：不只看二分类准确率，而是把最终答案分成五类，另设 RAS 与 CoPRAS 两个 reliability-aware 指标，前者奖励谨慎行为，后者把计算成本算进去。
- 发现：在 HotpotQA 与 BrowseComp-Plus 上评了 12 个系统。若干开源 agent 在来源有显而易见可信度红旗时仍自信作答；不少 HotpotQA 问题即使返回的文档全是事实错误，也能被参数知识答对。
- 为什么值得看：检索 agent 的分数里混着记忆。评测必须能区分「读对了」和「本来就知道」，否则检索模块坏了也看不出来。

### 5. Evidence-Guided Recovery（3↑）

Evidence-Guided Recovery for AI Agents with Ambiguous Tool Outcomes and Partial Execution · [2610.41453](https://huggingface.co/papers/2610.41453)

- 问题：工具超时会让 agent 面对不确定结果与部分执行——动作可能失败、已提交或仍在飞行中，而工作流的其他步骤已经完成。
- 方法：把恢复问题形式化为「在已批准义务、provider 能力、与公开证据相容的状态」上做证据引导的规划；共享的 admissibility 检查处理 key 过期、授权时序、依赖与残留效应。
- 证书：用 terminal certificate 把「真正达成目标」与「公开证据支持的安全完成」分开，避免把「看起来做完了」当成成功。
- 数字：37 个 assignment 的有限研究里，规划与三个 active control 各认证 28 次完成；预注册的 held-out 对照覆盖 19 个任务族、58 个配对单元，planning advice 认证 30 次完成对 evidence prompting 的 9 次，差 36.2 个百分点（family sign-flip 精确检验 p=0.0078），分别用 272 与 399 个 proposal；116 条轨迹全部通过独立 replay。
- 为什么值得看：生产环境的 agent 需要能「开出证书」的成功定义。把目标满足与安全完成拆开，比再刷一个任务成功率更接近可运维。

### 6. Agent-R²（3↑）

Agent-R^2: Scaling Agents for Realistic Productivity Work via Real-Source Data Synthesis · Zhejiang University · [2611.08219](https://huggingface.co/papers/2611.08219) · [code](https://github.com/ZJU-REAL/Agent-R2)

- 问题：真实生产力任务需要跟长程专业流程、理解异构文件、按细要求交付可用产物，而当前 agent 做不完；瓶颈是缺少同时反映真实工作意图、真实文件环境与交付级评价的后训练数据。
- 方法：不手写 workflow，也不用 LLM 凭空生成文件，而是用真实职业种子、从语料抽出的工作流证据、以及网上真实文件做全链路 grounding。
- 数据：从 10k 个 web-corpus 候选里蒸馏出 4k 个任务实例，每个都配真实多格式附件与细粒度、交付级 rubric；在其上做 SFT + rubric-based RL，得到 Agent-R²-4B。
- 数字：只用 4k 实例，在 GDPval 上 51.0% 对 Qwen3-235B-A22B-Thinking-2507 的 48.0%，OfficeQA 上 14.8% 对 13.8%；分析显示它缓解了「先交表面成品、再补依据」的 shortcut，并鼓励持续探索。
- 为什么值得看：4k 条真实文件任务赢过 235B 模型，说明数据真实性比数据规模更值钱；rubric 落在交付物层，也顺带把评测口径固定下来。

### 7. Learning the Task or Learning the Verifier?（3↑）

Learning the Task or Learning the Verifier? Rethinking Criteria Exposure in Embodied Self-Improvement · DAGroup-PKU · [2611.08318](https://huggingface.co/papers/2611.08318) · [项目页](https://dagroup-pku.github.io/PyRUA-Lean/RSIJudge/)

- 问题：自我改进的具身 agent 越来越多在机器人仿真 benchmark 上比较，而一些工作把 benchmark 的成功判据直接暴露给学习 agent（作者称为 Criteria Exposure，CE）。这些判据原本用于验证模仿学习策略，要求常高于语言指令，未必反映「指令任务」是否完成。
- 实验：同一个自改进 agent 在有无 CE 两种条件下做受控对比；再轻微修改判据但不改原始指令，并测试跨任务迁移。
- 发现：有 CE 时，agent 很快写出在该判据下成功率更高的代码；但判据稍改，优势就消失；在 CE 下学到的技能跨任务迁移很差。作者提出的 instruction-faithful criteria 更贴近指令任务的真实完成度。
- 为什么值得看：verifier 是训练信号的一部分。可验证奖励一旦被 agent 看见，就会被优化；benchmark 必须留一份 held-out criteria，否则测到的是「学会判据」。

### 8. JustRUA（1↑）

JustRUA: A Controlled Study of GPT-6 Robot-Use Agents · [2611.16009](https://huggingface.co/papers/2611.16009) · [code](https://github.com/ZefanW/JustRUA) · [项目页](https://zefanw.github.io/JustRUA/)

- 问题：GPT-6 Astra 已能通过固定 harness 直接驱动机械臂，RoboDojo 上的分数快速上涨；但各家系统同时改 harness、测试子集和多个设计，很难判断涨分到底来自哪。
- 方法：把设计拆成四轴——模型外围的 harness、动作接口、经验复用、给模型看的场景几何——放进同一框架做受控测试。
- 发现：保留完整 episode history、并让每个动作提前停止的 lean harness 就很有效；复用经验会改变模型行为，但不是免费午餐；场景几何帮助最大，即使 depth 只是从 RGB 预测出来的。
- 数字：从官方 L3 harness 出发只保留最关键项，在没有学习策略、没有自改进循环、没有任务微调的情况下，RoboDojo 分数从 29.7 提到 50.3。
- 为什么值得看：只有 1 票，但结论很硬——robot-use agent 的「能力」有很大一块在 harness 里。评测不锁 harness，就没法比模型。

### 9. 自进化多模态 agent 综述（1↑）

A Cross-Scenario Survey and Analysis of Self-Evolving Multimodal Agents · [2611.14256](https://huggingface.co/papers/2611.14256) · [code](https://github.com/jingjing12110/SE-MMAgents) · [项目页](https://jingjing12110.github.io/SE-MMAgents/)

- 问题：多模态 agent 的自我改进机制通常在单一场景里设计、也在单一场景里评估，跨场景迁移的前提条件没有被验证。
- 框架：覆盖多模态推理、多模态生成、GUI/Web 导航、具身操作四个场景；用四条标准加 self-reference 的 differentia 定义「自进化」，再以「经验生成 → 反馈获取 → 更新固化」三阶段循环为分析框架，把各场景定位在 rollout 数量与反馈保真度的上限上。
- 结论：每个机制都可重写为一种 trade-off——以提高某个稀缺因子为目标，同时预设某种任务结构资源（如输出等价性、可检查结果）；据此判为 portable、conditional、blocked 或 redundant。
- 为什么值得看：它给「为什么同一套自改进在导航有效、在操作无效」一个结构性解释，也列出了可能推翻这些判断的 matched-budget 测量清单。

## 三、世界模型：把「结构」变成另一路可生成的视频

### 10. BirdDreams（41↑）

BirdDreams: Joint Perspective and BEV Video Generation for a Plausible, Reactive Driving World Model · NVIDIA · [2611.14815](https://huggingface.co/papers/2611.14815) · [项目页](https://research.nvidia.com/labs/sil/projects/birddreams/)

- 问题：驾驶世界模型要同时做到周围车辆运动合理、ego 轨迹精确可控。只从透视视频学车辆运动很难，因为运动与外观纠缠，车辆还会互相遮挡。
- 方法：自回归地联合生成透视视频与 schematic BEV 视频。BEV 由场景标注渲染，用固定米制尺度把道路和车辆画成简单形状，遮挡少；透视视频保留 BEV 没有的交通灯与物体外观。两路各一个视频 diffusion transformer，用 joint attention 在生成中互相提供信息。
- ego 控制：把预测 BEV 的最新一帧按输入 ego 轨迹做平移与旋转，得到的帧作为 soft condition，表示「只有 ego 在动时场景会怎么变」。推理时只给一张相机图，不需要 HD map 或车辆状态输入。
- 数字：在 PhysicalAI-AV 与 nuScenes 上，比已有驾驶世界模型更忠实地跟随输入 ego 轨迹，也能在没有 ego-action conditioning 时生成更合理的 ego 运动；人类评测显示，周围车辆行为的真实感优于只用透视视频的 baseline。摘要没有给 FVD 等定量分数。
- 为什么值得看：把 layout 从「输入条件」变成「预测结果」，同时去掉了未来轨迹与 HD map 依赖。双流 video DiT 的同步与 joint attention 也是训练系统能直接借鉴的工程。

### 11. Duo（32↑）

Duo: A Reciprocal World Model for Full-Duplex Interaction · inclusionAI · [2611.15131](https://huggingface.co/papers/2611.15131) · [code](https://github.com/inclusionAI/Duo) · [项目页](https://duo-v1.github.io/)

- 问题：现有世界模型主要在模拟物理现实，把推理与决策当成外部控制；而全双工交互要求模型持续感知音视频，并实时决定是否响应、何时打断。
- 框架：Reciprocal World Model 把 Intent（交互背后的认知与参与决策）与 Realization（生成连贯的音视频行为）视为构成世界的两种同等基本能力。
- 方法：用自回归建模做连续交互推理与参与决策，而不是只把 AR 用于理解 diffusion 的指令；为每个 chunk 构造条件，并在统一时间轴上同步 Intent 与 Realization 的 token；module-specific attention mask 同时约束 chunk 内与 chunk 间的因果，禁止访问未来输入。
- 稳定训练：用 dual rollout distillation，在自回归生成的 Intent token 与 Realization 合成的音视频历史上训练，缓解两个模块的分布偏移。
- 数字：摘要没有给延迟、打断成功率等定量指标；这是一份 v1 report。能力面包括实时音视频文本输入、自发对话与打断，以及分享实物、改虚拟场景、指导助手、玩音视频游戏。
- 为什么值得看：把「该不该开口」做成 AR 决策，而不是 diffusion 的指令理解；「不看未来」的时序约束是 full-duplex 最硬的工程点。

### 12. PhysLoop（31↑）

PhysLoop: Harnessing LLMs' Physics Awareness for Self-Improving Video Generation Models · DAGroup-PKU · [2611.16748](https://huggingface.co/papers/2611.16748) · [code](https://github.com/DAGroup-PKU/PhysLoop) · [项目页](https://chenyx24.github.io/PhysLoop-site/)

- 问题：视频生成模型画面越来越真实，但物理动力学与因果一致性仍差；要从生成视频里学习，需要细粒度物理监督，而可靠的质量判断、修正对和受控变体都很难获得。
- 方法：一个统一的 harness，在生成、筛选、修正三个环节引导并约束 LLM，把 LLM 的物理知识蒸馏进物理一致的视频；同一套框架既支持可控训练数据构造，也支持推理时的视频修复。
- 数据：放出 10 万条视频，覆盖多样的室内外真实场景，附生成工具，以及 PhysLoop-Gen 与 PhysLoop-Repair 两个评测集；另在外部 Physics-IQ Verified 上评物理行为。
- 数字：摘要只给了数据规模，没有给生成质量或修复成功率的提升数值。
- 为什么值得看：「LLM 当物理判官 + 自动修数据」是通往递归自我改进的一条现实路径；但目前证据主要是数据与工具 release，定量结论还要等。

### 13. Ropedia Xperience 2（15↑）

Ropedia Xperience 2: A Gold Standard for Scaling Physical AI Environments and Behaviors · Ropedia · [2611.17060](https://huggingface.co/papers/2611.17060) · [code](https://github.com/Ropedia/Ropedia-Xperience-2) · [项目页](https://ropedia.com/xperience/2-research/)

### 14. WorldDraft（14↑）

WorldDraft: If Code Builds the World, Can Video Models Just Render It? · [2611.16217](https://huggingface.co/papers/2611.16217) · [code](https://github.com/KevinHuge/WorldDraft) · [项目页](https://haroldchen19.github.io/WorldDraft-site/)

## 四、生成架构：压缩 token、烤进 MLP、开放配方

### 15. G-STAR（39↑）

G-STAR: Group-Scaled Token Capacity for Deeply Compressed Autoregressive Generation · LongCat · [2611.13004](https://huggingface.co/papers/2611.13004) · [code](https://github.com/DAGroup-PKU/G-STAR) · [项目页](https://dagroup-pku.github.io/G-STAR/)

- 问题：离散自回归图像生成有个基本 trade-off——token 序列长则表示质量好但生成慢，空间压缩激进则表示容量下降。
- 理论：基于 product quantization，作者证明在固定 nominal information budget 下，group size 应该随每轴空间压缩因子二次增长，而不是线性增长。
- 方法：按这个关系做 spatial-group co-scaling，支持 32× 甚至有效 64× 压缩；更大的 group 带来组内依赖，于是设计 semi-autoregressive decoder，用并行特征计算加轻量因果建模来兼顾延迟与质量。
- 数字：在 GenEval、DPG-Bench、PRISM、LongText-Bench、Qwen-Image-Bench 五个文生图 benchmark 上与领先模型竞争；1024×1024 分辨率下比此前的离散自回归模型快 20×，单张 NVIDIA H200 每张图 2.5 秒。
- 为什么值得看：压缩率与 group size 的二次关系是可复用的设计公式；2.5 秒/H200 则把离散 AR 拉进了实用区间。

### 16. TTB（19↑）

TTB: Test-time Baking for Efficient Rendering of Decoder-only View Synthesis Models · NVIDIA · [2611.17331](https://huggingface.co/papers/2611.17331) · [code](https://github.com/NVlabs/DVSM) · [项目页](https://test-time-baking.github.io/)

- 问题：带 KV-cache 的 decoder-only 大视角合成模型（LVSM）靠神经网络直接回归新视角，质量已是 SOTA；Test-Time Training（TTT）层能省算力，但会掉质量。
- 方法：Test-Time Baking 把 cross-view attention 里的全局场景信息烤进一个轻量 MLP。关键一，复用 TTT 的 fast-weight MLP，显式学习 cross-view attention 的输入输出映射，而不是用 MLP 整个替代 attention，于是拿到 TTT 级渲染效率，同时质量高得多。
- 关键二：解决 context prefilling 与 novel-view rendering 的模态错位——把 context token 拆成只有相机的 context rendering token（作 TTB 输入）与带图像内容的 context ground-truth token（作映射目标），让烤出来的 MLP 不必再处理 context 到新视角的模态泛化。
- 数字：在多个 benchmark 上最高 23× 渲染加速，质量与 SOTA 持平。
- 为什么值得看：把「在线更新」换成「烤一次」，是推理系统熟悉的 compile/bake 思路；23× 是今天生成侧最直接可算的账之一。

### 17. Open Vision Banana（17↑）

Open Vision Banana: A Fully Open Recipe for Generative Visual Perception · Fundamental AI Lab at UTN · [2611.15844](https://huggingface.co/papers/2611.15844) · [code](https://github.com/OpenVisionBanana/OpenVisionBanana) · [项目页](https://openvisionbanana.github.io/)

- 问题：Vision Banana 证明预训练图像生成器编码了超出图像合成的世界理解，把视觉任务当条件图像编辑即可；但它的数据、权重、代码和实现细节都不公开。
- 方法：给出一套完全开放、可复现的配方，把预训练生成器转成统一多任务感知系统；从 4B 与 9B 开放权重底座出发，用公开数据集构造 210 万–380 万训练对。
- 分析：识别出对泛化最关键的设计——颜色编码、prompt 设计、参数适配、任务配平；这些选择相互作用，单独有益的组合放在一起可能反而有害。
- 数字：Cityscapes 零样本 73.9 mIoU，超过 Vision Banana 报告的 69.9；与 SOTA 的 affine-invariant depth 估计器相当；非零样本变体在 referring 与 reasoning segmentation 上距 Vision Banana 不到 5 分，instance segmentation 仍落后。
- 测试时扩展：legend ensembling 用多套 class-color legend 分别分割，再多数投票融合，纠正不稳定的颜色—类别绑定；不重训即可在 Cityscapes 提升最多 8.7 分、COCO-Object 提升 15.0 分。
- 为什么值得看：开放配方比多一个点更有价值；legend ensembling 则是不动权重的 test-time scaling，工程上非常便宜。

### 18. UniSpark（12↑）

UniSpark: Exploring Hybrid Attention for Multimodal Understanding and Generation · Ant Group · [2611.16517](https://huggingface.co/papers/2611.16517) · [项目页](https://lucaria-academy.github.io/UniSpark/)

- 问题：统一多模态理解与生成时，full attention 的显式 token 交互强但长上下文贵，linear attention 省却要压缩上下文，两者如何配比没有定论。
- 方法：UniSpark-9B 建在 Mixture-of-Transformer-Experts 骨架上，每个分支约 9B 参数；full attention 负责显式交互，GatedDeltaNet 线性注意力负责紧凑的上下文传播；自回归文本预测与视觉 flow matching 联合支持 VQA、文生图、指令编辑与交错图文预测。
- 交错生成：把带噪视觉目标与后续预测隔离，同时让干净视觉表示作为后文的上下文；blockwise protocol 在 full-attention 层用 attention mask、在 linear-attention 层用 recurrent-state retention 规则来落实这个区分。
- 数据/数字：训练源含 1.597 亿生成样本、2.134 亿理解样本、62.48 万交错序列；四阶段 curriculum 联合训练理解与生成，把图像合成扩到 2K；MME-S 2470.3，GenEval 0.83。
- 为什么值得看：hybrid attention 同时服务理解与生成，是统一模型的一条务实路线；但每分支 9B 的 MoE 训练成本与 2K 推理账，摘要没有给。

## 五、训练系统：连接与二阶矩，都在砍「重复访问」

### 19. SimpleHC（25↑）

On the Design of Hyper-Connections: Simplification, Stability, and Scalability · dots studio · [2611.05984](https://huggingface.co/papers/2611.05984) · [code](https://github.com/aHapBean/SimpleHC)

- 问题：Hyper-Connections 已被前沿语言模型采用，但各组件的作用没被讲清，还带来不可忽略的训练开销。
- 消融：两个有效交互组——「学 read/write gating 但不 mixing」与「固定 gate 但无约束 mixing」——各自单独就能达到与 mHC 相当的性能；同时发现，反复访问扩展后的 residual state 是主要开销来源，即使不做 mixing 也存在。
- SimpleHC：去掉 residual mixing，用共享内存访问简化执行；利用由此得到的加法结构与共享 gate 输入，让 layer-specific gate 共享 group-entry state，从而批量读、延迟写；标量修正精确保持前序 sublayer 的输出贡献。
- 数字：最大测试规模上，端到端训练时间只比 vanilla residual 多 2.4%；从 15B 扩到 30B MoE 时性能与 mHC 可比，标准训练下梯度动态更平滑，stress 条件下保持稳定。
- 为什么值得看：「简化换效率」的正面案例。2.4% 是能进生产预算的数字，而共享内存访问比堆算子融合更接近瓶颈本身。

### 20. FOAM（12↑）

Factored One-sided Adam-Moment for Practical and Scalable SOAP · NAVER AI Lab · [2611.16905](https://huggingface.co/papers/2611.16905) · [code](https://github.com/naver-ai/foam)

- 问题：Shampoo、SOAP 等二阶优化器每步收敛更快，但 optimizer state 内存与特征分解开销大；能否以接近 AdamW 的效率拿到 SOAP 的收益？
- 方法一：input-only preconditioning，去掉 output-side Kronecker factor，省内存并少一次特征分解。Hessian 的 Kronecker 结构说明，output-side curvature 为对角时这一步精确，接近对角时也几乎无损（作者实测如此）。
- 方法二：用基于行、列统计的 factored Adam-moment estimator 替代 SOAP 的 dense rotated second moment。在 K-FAC Fisher 假设加对角 output curvature 下，这个估计器精确恢复 SOAP 的稠密二阶矩；实测 K-FAC violation 只有 15–20%，对更新影响可忽略。
- 数字：在 LLM 预训练各规模上匹配强 SOAP 与 Muon baseline 的 validation loss；optimizer state 是 SOAP 的一半；wall-clock 与 Muon 同级；在 3 倍学习率范围内保持稳健；结论覆盖 124M–760M 参数。
- 为什么值得看：二阶优化的瓶颈常是 state 与分解，不是数学。FOAM 两个都砍，而且给了从 124M 到 760M 的完整证据链。

## 六、多模态记忆、表示与安全：便宜的证据与昂贵的捷径

### 21. HiVe-Mem（2↑）

HiVe-Mem: Interleaving Horizontal Memory Expansion and Vertical Evidence Composition for Multimodal Agents · Nanyang Technological University · [2611.12872](https://huggingface.co/papers/2611.12872) · [code](https://github.com/ViktorAxelsen/HiVe-Mem) · [项目页](https://viktoraxelsen.github.io/HiVe-Mem/)

- 问题：多模态 agent 的交互历史越来越长，现有记忆系统多靠压缩记忆上的语义检索，并暴露预定义表示；这可能漏掉相关记忆，也忽略不同 query 对证据形态的不同需求。
- 横向扩展：把 memory episode 用文本与视觉 anchor 组织成关系图，从语义检索到的 seed 出发扩到相关邻居，补回互补信息。
- 纵向组合：每条被检索的记忆保留多种证据形态——紧凑摘要、caption、grounded 视觉视图、原图、交互历史；一个轻量可训练 selector 为每条记忆独立组合证据子集，实现 query-adaptive 使用。
- 数字：3 个多模态记忆 benchmark 上跨 base model 稳定提升；相比最强的同类高效 baseline，token 消耗约降 90%。
- 为什么值得看：记忆系统的成本大头是「把什么放进 context」。90% 的 token 节省加上按 query 选证据，是能直接落地的接口设计。

### 22. 光学光谱上的表示不变性（2↑）

Do Multimodal Models Decide Consistently on Equivalent Optical Spectra? · [2611.00428](https://huggingface.co/papers/2611.00428)

- 问题：同一条光谱可以用纳米单位的表格给，也可以用光子能量的图给，决策不应随表示改变；当回答问题所需的数据缺失时，模型应该说「无法确定」。
- 实验：用硅超表面（MOCLIP）与金纳米颗粒的实测光谱，标签由数据计算；每条光谱给四种表（nm、μm、科学计数法、eV）和两种图（nm、eV），partial spectra 分别去掉查询范围内或范围外的数据；评 d3-nano、Jev 1.13、三个 GPT-6 Luna 配置与 Qwen3.5-2B。
- 数字：只换表示，单个模型的 accuracy 最多变 41 个百分点，且主要集中在光子能量表/图；同样的证据，改用光子能量提问，有些 model-view 组合提升 16–50 分，有些反而掉最多 25 分；去掉相关极值后，未经适配的模型很少回答 undetermined。
- 捷径：d3-nano 的 LoRA 微调在训练过的表格式上变好，但它在不可答问题上的增益很大一部分来自「输入被截断就弃答」的 shortcut；用可答的截断样本训练，6/6 seed 都能避开，held-out 结构上 inside 与 outside cut 后的弃答率差 90–100 分；而用等量原始任务数据训练，6 个 seed 里仍有 5 个保留 shortcut。
- 为什么值得看：科学多模态评测不能只看平均 accuracy。表示不变性与弃答要单列，否则微调会把 shortcut 当能力收进去。

### 23. Humanized but Still True?（2↑）

Humanized but Still True? Auditing Facts and Detection in AI-Text Humanizers · [2611.00359](https://huggingface.co/papers/2611.00359)

- 问题：AI humanizer 改写机器文本，让检测器判成人类所写；公开 leaderboard 只评 evasion 与 embedding 相似度，不查数字、日期、人名/机构名、引用片段是否还在。
- 方法：用规则检查器核对这些可查单元是否存活，并由两个 AI annotator 验证（precision 0.84–1.00、recall 0.93–0.95；无人工标注）；看 2026-10 与 2026-09 两个 leaderboard cycle。
- 数字：10 月 cycle 里 11 个商业工具全部在 35–65% 含可核查单元的文档中改动或删掉至少一个；大多数改动落在引用片段；只算数字与人名，仍有 10/11 在 20% 以上文档里改过；9 月 cycle 类似，为 19–50%。一个开放 12B humanizer 在事实密集的美国联邦文本里保留了至少 97% 的数字与人名，却改写 67–78% 的引用片段，违背自己的 prompt。
- 检测：通用决策模型 Jev 用单次 zero-shot 提问区分人类原文与 humanized 改写，AUROC 0.864（0.827–0.902），比 Binoculars、Fast-DetectGPT 和对抗训练的 RADAR 高 0.18–0.22；但在 0.5 阈值下把 24% 的人类原文判成 AI。对 2026 模型写的 AI-styled 改写，两个基于 perplexity 的检测器低于随机（AUROC 0.37 与 0.39）。
- 为什么值得看：「像人」和「保真」是两件事。unit retention 与 detector evasion 没有清晰相关（Spearman rho = -0.46，95% CI -0.65 到 0.08），leaderboard 应该把事实保留单列。

### 24. Fisher 几何的置信扰动（2↑）

Structured Confidence Perturbation via Fisher Geometry for Adversarial Training · XJTLU · [2611.14046](https://huggingface.co/papers/2611.14046)

- 问题：对抗训练常被 pseudo-attack 困扰——扰动让 loss 大涨，却没有真正改变模型的置信结构。
- 方法一：在传统 loss 最大化之外引入 hybrid objective，把 cross-entropy 与 KL divergence 合在一起，迫使对抗样本同时破坏预测准确率与分布一致性。
- 方法二：几何重构对抗训练，在 confidence manifold 上最大化分布距离来生成扰动；理论分析表明最优扰动方向对齐 Fisher 信息矩阵的主特征向量，并给出避免高维矩阵计算的高效算法。
- 数字：摘要没有给具体鲁棒性提升数值，只说在多个数据集与模型架构上优于现有方法，robust transferability 更好，尤其擅长高置信区域内的结构扰动。
- 为什么值得看：它把「攻击有没有真的改变置信结构」变成可计算的几何问题；但缺定量结果，目前只能当方法线索。

### 25. Unbundling Multimodal Vision Encoding（9↑）

Unbundling Multimodal Vision Encoding · Meta · [2611.17334](https://huggingface.co/papers/2611.17334) · [项目页](https://unbundling.github.io/)

- 问题：多模态模型的视觉编码有三条流行路线——用预训练视觉编码器、和语言模型一起从零训练、以及干脆不要编码器。公开模型的数据、结构、算力都不同，放在一起比无法归因。
- 方法：统一从零预训练、共用数据、按 matched lifetime compute 比较；把「视觉编码器」拆成三个正交选择：上游预训练带来的 visual prior、专用视觉容量、以及容量放在 fusion 之前还是之内。
- 结论一：visual prior 不必要。联合从零训练的编码器与预训练编码器打平，还省掉一个独立训练阶段。
- 结论二：专用视觉容量必要。encoder-free 模型即使把语言主干扩大相当于编码器的参数量，视觉理解仍然落后；但这份容量不必放在 fusion 之前，把 vision-only 模块加到主干早期层（in-fusion），效果与 pre-fusion 编码器相当，还能降低 time to first token。
- 稳健性：上述结论在多种主干规模、把编码器预训练视为免费、以及从预训练语言模型出发时都成立。
- 为什么值得看：这直接改多模态训练流水线——少一个预训练阶段、少一次跨模态对齐，TTFT 还更好；但「容量必须专用」说明不能靠加大语言主干糊弄过去。

### 26. TurtLES（4↑）

TurtLES: A Large-Scale Benchmark for Turbulent 3D Neural PDE Surrogates · Sorbonne University · [2611.09567](https://huggingface.co/papers/2611.09567) · [code](https://github.com/itsakk/TurtLES)

- 问题：ML surrogate 越来越多用于加速 CFD，但缺能刻画真实、时变湍流的 benchmark，进展被卡住。
- 数据：14 TB，3D 湍流圆柱尾迹，位于 shear-layer transition regime，用高保真 implicit large-eddy simulation 算出；400 条轨迹 × 400 个时间步，每帧 3–11 million 个点，覆盖几何、Reynolds 数与攻角变化。
- 特点：同时具备由 vortex stretching 驱动的 active energy cascade、dense irregular mesh、以及长时程动力学，这三点是已有数据集少有的组合。
- 发现：benchmark 了 SOTA neural operator 的自回归 rollout，主要 failure mode 是时间不稳定、小尺度能量丢失、以及在大而不规则域上难学。
- 数字：摘要只给数据规模，没有给误差指标。
- 为什么值得看：14 TB 的规模把「科学 ML 的 benchmark 债」摆上台面；小尺度能量丢失是自回归 surrogate 的通病，与视频/世界模型的长 rollout 同构。

### 27. Who Remembers What?（3↑）

Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction · Amazon Web Services · [2611.10439](https://huggingface.co/papers/2611.10439) · [项目页](https://wangyz1999.github.io/who-remembers-what/)

- 问题：self-evolving agent 会从经验里改自己的技能与记忆，group-evolving agent 还把这些 lesson 跨 agent 共享；但多数系统没有决定「谁该受益于哪条经验」以及「什么信息必须留在私有范围」。
- 方法：MixUA 把独立的 user-agent 轨迹蒸馏成 lesson，再按受益者与可披露范围分配到四级 scope：user-agent pair、user、agent、global。
- 评测：CrossLearnBench 把既有 agent 任务与用户偏好、隐私探针配对，专门检验私有事实会不会泄漏到别的用户可读的记忆；规模是 5 个用户、7 个 agent。
- 数字：pass rate 比无记忆最高 +16 分，比单一 global memory +5 分，而且在「只有别的用户/别的 agent 试过」的任务上也有效；保留最多 90% 此前声明的偏好；最多 0.02% 的隐私探针能在禁止 scope 里找到植入的私有事实。
- 为什么值得看：记忆的 scope 本质是访问控制。把泄漏率当成一等指标，比只测召回更接近可上线。

### 28. Consensus Capture（3↑）

Consensus Capture in Reference-Based UAV Video Stabilization · EPFL · [2611.17190](https://huggingface.co/papers/2611.17190) · [code](https://github.com/rfonod/stabilo-benchmark)

- 问题：参考帧稳定把悬停无人机视频逐帧配准到一个参考帧，保持物体位置可比；但配准 pipeline 都是在「只有相机动」的特征匹配 benchmark 上选型的。繁忙路口里，同向运动的车辆会提供互相一致的对应点，把 robust homography 拉向车流——作者称为 consensus capture，inlier 统计看不出来。
- 基准：static protocol 在 4K 航拍帧、精确已知 homography 下评 10 条 pipeline，在 site-disjoint split 上按匹配分辨率与特征预算调参；dynamic protocol 在离线与实时预算下评，悬停片段只从视频选，覆盖不同运动前景量与一致性，另设静止 control。
- 指标：背景对齐、物体位置误差、估计跟随运动群体位移的比例；pseudo-ground-truth 用人工标注的 ground control points 审计，并用它给每个候选打分。
- 数字：静态场景里 tuned AKAZE、RootSIFT、SIFT、BRISK 领先；重调 matcher 阈值最多把 mAA 提高 0.0062，masking 成本不到 0.005。未 masking 的 ORB 在 304 个实时动态对里被 capture 28 个、离线 6 个；被 capture 的实时估计中位角点误差 18.8 px，但 inlier 数量与比例看起来完全正常。Masking 消除了所有 pipeline 的 capture，且不改变领先者排序。
- 为什么值得看：inlier count 不是安全指标。任何「用鲁棒估计对齐动态场景」的系统——SLAM、视频稳定、BEV 对齐——都该把这个失败模式单独测。

## 五、新增 · 具身与视频生成

### 29. The Narrative Gap（2↑）

The Narrative Gap: Can LLMs Help Us Navigate Diverse Narratives Across Languages? · Johns Hopkins University · [2611.12750](https://huggingface.co/papers/2611.12750) · [code](https://github.com/isle-dev/Narrative-Bench-NeurIPS-2026)

- 问题：LLM 正在成为跨语言的信息入口，但对争议话题，不同语言与地区的叙事并不一致；要让用户看到 competing accounts，模型需要一组专门能力。
- 六项能力：基础三层是 narrative inclusion、narrative exclusion、missing narrative identification；高层三层是呈现多元叙事、在 confirmatory query 下保持覆盖、以及跨语言的信息对等。
- 基准：NarrativeBench 含 1,333 篇新闻、23 种出版语言、23 个争议话题、460 条 Reddit-grounded query；评了 14 个 LLM，覆盖 24 种 query 语言。
- 发现：现有模型不能可靠地导航多元叙事；即使明确要求 diversity，竞争叙事的曝光仍有大缺口；不同 query 框架与语言下信息获取结果不同，可能形成 echo chamber 与 linguistic filter bubble。摘要没有给具体分数。
- 为什么值得看：它把「信息对等」拆成可测能力；对 RAG 与搜索 agent，query 的语言本身就是一种偏差源。

### 30. Experience-Handoff RL（2↑）

Experience-Handoff Reinforcement Learning for Recursive Self-Improvement · KAIST AI · [2611.16409](https://huggingface.co/papers/2611.16409) · [code](https://github.com/doyoungkim-ml/ehrl)

- 问题：用 scalar reward 做 agent RL 会丢掉环境里的细粒度信息，比如 error log；现有 harness 用 reflection 或 compaction 把经验交给后续 rollout，但「交接物」（如 playbook）的构造本身没有被学习。
- 方法：固定 Agentic Context Engineering 的 harness，训练同一个模型同时做三件事——act、reflect、curate task-local playbook。
- 训练信号：候选交接物按「对后续 actor rollout 的下游效果」评估，在固定 scaffold 下联合优化 action generator、insight reflector 与 playbook curator。
- 结果：在多个 agentic benchmark 上 held-out 表现高于 baseline；摘要没给具体分数或提升幅度。
- 为什么值得看：训练目标从「当前 rollout 的动作」扩展到「未来 rollout 继承的经验」，这是递归自我改进的一个可优化接口；但缺数字，目前只能算方向验证。

### 31. The Value of Thinking（2↑）

The Value of Thinking: Learning When to Reason in Hybrid Decision Models · [2611.16961](https://huggingface.co/papers/2611.16961) · [code](https://github.com/zhengxuyu/HDM-code)

- 问题：现有 adaptive reasoning 要么缩短显式推理，要么切换模式，但答案仍然要逐 token 写出来；真正该问的是「这一次要不要进入慢模式」。
- 方法：zero-or-T thinking。快模式在一次前向里用隐式思考给出答案、生成 0 个 token；慢模式花 T 个 token 做完整自回归推理。一个冻结主干加一个轻量 self-routing block 估计「思考的价值」，即慢模式相对快模式的预期增益，只有超过按请求设定的价格 λ 才走慢模式。
- 训练：没有 per-decision label 时（例如 episodic agent 任务），用 CDPO 从 episode-level return 训练 routing block。
- 数字：JevBench 上 HDM-4B 得 0.857，对 Jev 的 0.851（+0.7%），中位延迟 0.179 s 对 0.652 s（-72.5%）；MiniWoB 上 HDM-27B 把 token 成本降 80.1%。评了 MMLU-Pro、AGIEval、GPQA-Diamond、JevBench、BANKING77 与 MiniWoB。
- 为什么值得看：把推理成本做成 per-request 的 λ，运维上可以直接调；「0 token 快模式」比「少写几步 CoT」更彻底。

## 四、新增 · 3D 世界的数据与标定

### 32. Back to Pixels（2↑）

Back to Pixels: Lifting Latent Video Diffusion into Pixel Space · Roblox Corporation · [2611.17336](https://huggingface.co/papers/2611.17336) · [项目页](https://chenshuo20.github.io/PixVid/)

- 问题：前沿视频模型在 VAE latent 空间做时空压缩，训练因此可行，但现在限制高分辨率、可控与交互：分辨率翻倍 token 数变 4 倍；条件作用在帧组而不是单帧；每次响应要等整个多帧 block 生成完。
- 方法：PixVid 保留 diffusion transformer，把 VAE decoder 换成卷积 head，直接逐帧渲染像素。
- 关键取舍：作者发现「预测 clean video 而不是 velocity」加上更大的 noise shift，对质量最重要。
- 数字：从 Wan2.1-14B 微调，在 1.3M 训练 clip 内与 latent baseline 竞争；逐帧工作使其在同 per-frame token 数下生成 2× 分辨率；深度条件视频编辑在快速运动下仍保持对齐；每个动作在下一帧就能响应。
- 为什么值得看：交互式生成的瓶颈常常是「等一个多帧 block」。逐帧像素空间把响应粒度从 block 降到 frame，代价是 token 账要重算。

### 33. Neuro-VL（1↑）

A frontier machine intelligence for human neuroimaging · Machine Learning in Neurosurgery Lab · [2611.15094](https://huggingface.co/papers/2611.15094) · [code](https://github.com/MLNeurosurg/neuro-vl) · [项目页](https://neurovl.mlins.org/)

- 问题：现有医疗模型多做受限任务，而通用闭源模型拿不到私有临床影像，难以形成专科能力。
- 方法：Neuro-VL 用近 100 万份来自常规临床流程的神经影像研究训练，能读完整检查，并用自然语言讨论发现。
- 结果：在内部与国际数据集上，诊断、定位、描述异常、生成完整放射报告均优于 frontier 通用模型与专科医疗模型；还能比较序列检查评估疾病进展。
- 稳健性：面对误导性的临床假设，Neuro-VL 比 OpenAI 与 Google 的领先模型更不容易被带偏。
- 数字：摘要只给「近 100 万份」训练规模，没有给具体准确率或 AUROC。
- 为什么值得看：这是「数据壁垒大于模型规模」的一个清晰案例；纵向比较与抗暗示才是临床落地的真门槛。

## 三、新增 · Agent 的记忆与经验

### 34. EgoX（1↑）

EgoX: Egocentric Cross-Embodiment Manipulation with Embodiment Dreaming · Carnegie Mellon University · [2611.16728](https://huggingface.co/papers/2611.16728) · [code](https://github.com/egox-dream/egox) · [项目页](https://egox-dream.github.io/)

- 问题：通用操作策略可以从人类、真机、仿真数据互补受益，但形态、传感、控制接口的差异让混合演示很难学。
- 方法：EgoX 按语义对应的观测/动作模态组织异构演示；MXT+ 为每种观测模态配专用 tokenizer、为每种动作模态配专用 expert，Transformer trunk 跨具身共享；训练时加 embodiment dreaming，预测未来视觉与本体状态的 latent。
- 数字：13 个 task-embodiment 对、5 个任务、6 种具身（5 台真机 + 1 个仿真人形）；跨具身预训练把平均归一化任务进度从 0.63 提到 0.80；OOD 条件下从 0.53 提到 0.77。
- 消融：更广的预训练混合、模块化接口、embodiment dreaming 都有贡献；dreaming 让不同具身之间的 latent 几何更接近。
- 为什么值得看：跨具身的关键可能不是统一动作空间，而是「共享 trunk + 模态专用接口」；dreaming 是训练-only 的辅助目标，不增加推理成本。

## 今天的三个观察

**一、Top 10 里只有三个新模型，其余大半是尺子、配方、数据与方法**。SO-Arena 是 benchmark，Actor/Judge/Teacher 是能力分析，PhysLoop 是数据与 harness，OVB 是开放配方，Ropedia 是数据采集流水线，SimpleHC/TTB 是架构与推理方法；真正的新模型只有 BirdDreams、G-STAR、Duo 三个。热度分布也配合这个判断：13 篇上双、11 篇只有 1–3 票，中间层几乎是空的。社区注意力集中在怎么量、怎么造数据、怎么把结构外置，而不是再发一个通用模型。

**二、System One 正在从「一个 head」变成一整条栈**。SO-Arena 说总准确率第一的模型可靠性只排第七；Actor/Judge/Teacher 说不会当 actor 的模型仍能当 teacher，JEV 把 1.5B 策略从 72.8% 教到 82.9%；NestOne 说最后六层可以删、真正要的是跨深度共享计算；JustRUA 更直接，不训任何策略，只换 lean harness 就把 RoboDojo 从 29.7 拉到 50.3。四篇合起来，决策质量至少由 eval、teacher、depth、harness 四块共同决定，backbone 只是其中之一。对 agent RL 的启示很具体：过程奖励可以从执行模型解耦，评测则必须把 reliability 和 harness 一起锁住。

**三、生成侧在同一天给出两条完全不同的「效率」答案**。一条是压缩 token：G-STAR 用 group size 随压缩因子二次增长的规律做到 32×/有效 64×，1024² 单张 H200 2.5 秒、比此前离散 AR 快 20×；TTB 把 cross-view attention 烤进 MLP，渲染最高 23×。另一条是补结构：BirdDreams 把 BEV 变成预测结果，WorldDraft 用代码搭 4D 世界、让视频模型只做 renderer，PhysLoop 放 10 万条视频让 LLM 当物理判官。前一条已经能算清账，后一条大多还在「造数据、造尺子」阶段——Duo 与 PhysLoop 的摘要都没给定量增益。**这也是今天最值得警惕的地方：世界模型的故事很大，但可复现的数字仍然偏少**。
