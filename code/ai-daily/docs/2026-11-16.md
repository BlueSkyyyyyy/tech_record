## 一、Agentic robotics：把 harness 提到与模型并列

### 1. Agentic Robotics（96↑）

Envisioning Agentic Robotics: A New Era of Robotic Systems · [2611.18359](https://huggingface.co/papers/2611.18359) · [项目页](https://grid-robotics-official.github.io/agentic-robotics-roadmap)

- 问题：机器人长期按任务族训练专用策略；GPT-6 Astra 之后，带 agentic harness 的前沿模型在数周内就在多个具身 benchmark 上追平或超过专用策略，但社区对「什么是 agentic robotics」还没有共同定义、可靠评测与路线图。
- 主张：Embodied System 2 由基础模型加 embodied harness 组成，是这类系统的决策核心；中心难题是在有限反应时间、机械极限、环境突变和不可逆后果的约束下，把通用推理翻译成有效且可验证的动作。
- 框架：评测分两轴，既量模型能力，也量闭环系统表现；同时区分哪些原则能从数字 agent 迁移到物理 agent、哪些必须重新解决。路线图从执行单个 primitive 走向承担 standing role，即持续、可靠、责任范围逐步扩大的自主。
- 数字：摘要没有给实验数字，这是一篇 position / roadmap 论文；96 upvotes 是当日最高，说明社区缺的正是这套共同语言。
- 为什么值得看：它把 harness 放到了和基础模型同等的位置。对机器人评测，锁住模型不够，还要锁住闭环接口与失败恢复策略。

### 2. Gamer（69↑）

Gamer: A Generalist Vision-Language-Action Foundation Model for Long-Horizon Real-Time Game Agent · [2611.18397](https://huggingface.co/papers/2611.18397) · [code](https://github.com/RainBowLuoCS/Gamer) · [项目页](https://mihoyo-gamer.github.io/)

- 问题：长程实时游戏 agent 要同时处理感知、记忆和多步推理，而 2D 图形界面与 3D 模拟世界通常需要两套完全不同的 pipeline。
- 训练：先用数万小时设备级键盘鼠标交互轨迹做继续预训练，轨迹覆盖模拟游戏与具身环境；再用 sparse-thinking 指令微调砍掉冗余计算，同时保住复杂决策需要的推理；最后用稳定的多轮 RL 处理有限上下文、rollout 误差累积和稀疏奖励。
- 部署：cloud-edge 推理引擎并发服务大量模拟游戏环境，支持无界上下文执行，并压低在线推理延迟。这一块是「实时」二字的真正门槛，摘要里反而着墨最少。
- 数字：在多个有挑战的 3D 开放世界里，泛化与运行效率达到与熟练玩家相当的水平；在一批传统 2D 游戏 benchmark 上有竞争力。摘要没给具体胜率、延迟或上下文长度。
- 为什么值得看：键鼠轨迹信息密度很低，却仍能撑起数据与算法的 scaling。对 agent 工程，sparse thinking + 多轮 RL + 云边部署是一套可以直接拆开复用的长程配方。

### 3. HALO（10↑）

HALO: Human-Aligned Data Collection for WhoLe-body MObile Manipulation · Robbyant Research · [2611.16439](https://huggingface.co/papers/2611.16439) · [code](https://github.com/robbyant-research/Lingbot-ALOHA) · [项目页](https://robbyant-research.github.io/Lingbot-ALOHA/)

- 问题：全身移动操作需要双臂动作与移动底座在较大工作空间内协同的演示，但现有采集接口在「直接控制机器人」「感知与动作对齐」「操作者自然移动」三者之间只能三选二。
- 方法：操作者通过动觉示教引导机器人末端执行器，同时推动一个低阻力平台（不是驱动部署时的移动底座），从而在做双臂操作时保持自然行走与直接力反馈。
- 对齐：人机紧密耦合会带来演示与部署的差异；作者用 deployment-aligned demonstration processing 把平台运动标定并时间对齐到真实底座响应，再把录制画面里演示者的手遮掉并 inpaint。
- 数字：相比 Mobile ALOHA 与 VR 遥操作，采集速度快最多 2.9×，成功率相当或更高；六阶段长程移动操作任务（反复协调底座与手臂）成功率 73.3%，还能完成扎带紧固这类精细操作。
- 为什么值得看：采集接口的形状直接决定数据分布。遮手与底座响应对齐是两个便宜、可复用的工程技巧，比换一个更强的策略网络更先见效。

## 二、Agent 系统：记忆、持续学习与「采用门」

### 4. MIRIX-2.0（18↑）

MIRIX-2.0: Multi-Agent Memory System · [2611.12068](https://huggingface.co/papers/2611.12068) · [code](https://github.com/Mirix-AI/MIRIX) · [项目页](https://mirix.io/)

- 问题：长期记忆的三条路各有硬代价——参数化记忆要训练，consolidation 可能永久丢细节，全量保留则检索库随历史无限增长。
- 方法：六类 typed memory agent 保存完整记录，作为 system of record；provenance hypergraph 用 n-ary frame 索引 episodic 与 semantic 记录，并引用到原始行；检索在显式预算下运行，问题能看到的证据不随历史变长。
- 整理：AutoDream 在写路径之外合并重复 anchor、把任务会话蒸馏成 skill，且不改写任何记录；关掉它系统仍能工作，只是少了整理。
- 数字：五个 QA benchmark 中四个最准；LoCoMo 91.4%、LongMemEval-S 72.6%，后者比最强 baseline 高 14.3 点；关掉 AutoDream 时，单跳与多跳文档 QA 分别比 HyperMem 高 31.0 与 22.0 点；ALFWorld 与 WebShop 上程序性记忆平均成功率最高，MetaClaw-Bench 49.2% 对 MetaClaw skill library 的 44.0%。
- 为什么值得看：无需微调，闭源与开源模型都能跑；关掉 AutoDream 后五个计时 benchmark 全部快于 HyperMem。对 agent 基础设施，「完整记录 + 预算内检索 + 可追溯」比「压进参数」更可控。

### 5. G-CAST（15↑）

G-CAST: Governed Continual Self-Training for E-Commerce Agents under Evolving Demands · [2611.17814](https://huggingface.co/papers/2611.17814)

- 问题：电商 agent 同时面对两种漂移——新品类、新采购场景、新功能请求改变用户需求的分布与复杂度；产品的执行 harness（工具、skill、操作流程）又持续演化，要求模型会用新能力且不丢旧行为。周期性人工重训太慢、太贵。
- 方法：把每天的生产证据转成 reward-routed、entropy-prioritized 的训练数据，并做 governed reward evolution；累计评测下的 governed checkpoint transition 控制每一次模型更新。
- 目标：让新引入的行为学得会，同时把已接受的能力守住——本质上是把「不回退」写成更新约束，而不是事后回归测试。
- 数字：在真实生产电商 agent 上，比强 autonomous post-training baseline 更适应新需求、也更好地保留旧行为；消融显示数据编排与 reward evolution 都重要；系统已部署在阿里 1688 的 B2B 采购 agent 元采。摘要没给具体提升幅度。
- 为什么值得看：持续学习在工业界的真问题不是「学不学得会」，而是「会不会把已经能用的东西弄坏」。治理式更新比再设计一个 reward 更稀缺。

### 6. MEM-SQL（15↑）

MEM-SQL: Memory-Empowered Text-to-SQL · The University of Hong Kong · [2611.18338](https://huggingface.co/papers/2611.18338)

- 问题：主流 Text-to-SQL benchmark 把每个问题独立评，忽略了一个现实：同一数据库上的历史 query 往往已经提供了可复用的 join 或计算。
- 基准：HARE 含 1,600 个请求，来自四个数据集、823 条已验证 query；标注记录每个请求保留哪些组件、需要哪些编辑，从而区分整句复用与部分复用。
- 方法：记忆里存整句模板、可复用 SQL block、领域概念到 schema 元素的映射；只有某一层的所有需求都超过该层阈值时才启用这一层；On-demand Schema Linking 只在没有层可用、或生成器判断检索证据不足时才去查 schema。
- 数字：六个语言模型上平均执行准确率从 Direct Generation 的 37.1% 提到 50.0%；输入 token 少 76.6%、延迟低 68.8%。但需要复用多条已验证 query 的请求仍是瓶颈，准确率从 56.7% 掉到 29.7%。
- 为什么值得看：历史是免费上下文，但复用结构越复杂越容易拼错。OSL 在另外三个记忆设计上都降成本，说明「何时查 schema」是可以独立优化的接口，而准确率收益取决于记忆怎么存。

### 7. Evidence-Governed Evolution（10↑）

Evidence-Governed Adoption of Self-Generated Updates in Autonomous AI Agents · [2611.16378](https://huggingface.co/papers/2611.16378)

- 问题：自主 agent 会用交互历史改 prompt、记忆、工具、工作流和策略，但「看起来合理」不等于适合长期采用：候选是按历史自适应挑出来的，评测器并不完美，局部提升还可能掩盖相对旧 baseline 的退化。
- 方法：把候选生成与确认采用彻底分开；冻结候选，在新的 paired audit 上评估；要求预设主目标有实质提升；用 reference-relative non-inferiority 测试保护已声明能力；通过治理约束后才进入 bounded canary 部署。
- 统计：为可数的自适应候选序列构造 evaluator-calibrated simultaneous lower bound，把 candidate-wise Hoeffding 界与独立校准样本结合；还形式化了 reference replacement 的 bridge test、版本谱系上的累计退化界，以及 effect size、样本量与接受概率之间的审计规划条件。
- 边界：Monte Carlo 压力测试只说明 candidate-dependent evaluator optimism 下的校准行为，不是部署 agent 的实证；保证依赖有界 paired score、fresh sampling、有效的 reference construct 和声明的评测分布，不覆盖任意分布漂移。
- 为什么值得看：自我改进系统需要的是「采用门」，不是「生成门」。这篇给的是统计契约，而不是又一个 self-refine 循环。

### 8. Aligning AI Teams（10↑）

Aligning AI Teams · [2611.17820](https://huggingface.co/papers/2611.17820)

- 问题：单 agent 上做 alignment 训练，效果不一定迁移到多 agent 团队；已有工作看到了现象，但没有解释机制。
- 实验：两个软件工程任务（脓毒症分诊、新闻推荐）加十个咨询提案生成任务，比较单 agent 与团队的安全行为。
- 发现：单 agent 与团队的安全差距不随模型更强而单调缩小——Anthropic Mythos Preview 在一个任务上差距最大、在另一个任务上最小；互相 critique、群聊协调等自然干预都不能可靠恢复；责任扩散是主要解释，团队成员更少主动检查系统级安全失败，更倾向忽略、合理化或推卸责任。
- 干预：指定一个 safety lead agent 负责系统级安全，再由 coordinator agent 发布 safety specification 文档，能有效把团队拉回单 agent 的 alignment 行为；同时放出 magelab 多 agent 编排与实验框架。
- 为什么值得看：多 agent 安全首先是组织设计问题。「谁负责」要写进角色和文档，不能指望模型在群里自发形成。

### 9. Continual-ARC（0↑）

Continual-ARC: Measuring Skill Acquisition over a Working Lifetime · Unify · [2611.14505](https://huggingface.co/papers/2611.14505) · [code](https://github.com/unifyai/continual-arc) · [项目页](https://continual-arc.unify.ai)

- 问题：现有 continual learning benchmark 通常只覆盖单一应用域、每个实例只出现一次、且默认只有一类 learner，导致记忆型与权重型系统很难在同一尺度上比较。
- 基准：用三届 ARC-AGI 构造一条终身任务流；旧任务在 dormant gap 之后以新实例回归，新任务同时不断到来。每个实例上 learner 可以付费买 demonstration、提交答案或在 harness 内行动，答错重试也要付费，最终按消耗的反馈预算打分。
- 实验：冻结权重的 agent harness（有/无 persistence）跑 Qwen3.5-9B 与 GLM-5.3 Flash，对比两个 prompting floor、一个 program induction 方法，以及 Qwen3.5-9B 模仿 GLM-5.3 Flash 的权重学习。
- 结果：harness persistence 一般不能提升记忆，除非给显式专家指导；多数 harness 方法在所有测试模型上都不如「把每个任务的 demonstration 缓存起来」这个 floor；没有任何 harness 方法在未见任务上取得提升，而权重学习有实质提升。
- 为什么值得看：0 票，但结论很尖锐——「把经验存进上下文」可能连缓存都打不过；持续学习的收益更可能来自权重，而不是更长的 memory。

## 三、Agent 评测：从「做完没有」到「怎么做、看得懂吗」

### 10. VibePrevisBench（80↑）

VibePrevisBench: Evaluating Agentic Coding for 4D Scene Generation in Blender · Kling-Keye · [2611.15789](https://huggingface.co/papers/2611.15789) · [code](https://github.com/vibeprevisbench/vibeprevisbench) · [项目页](https://vibeprevisbench.github.io/)

- 问题：可控真实视频生成可以用渲染出的 graybox proxy 视频做条件，从而固定 layout、运动和相机；coding agent 能在 Blender 里重建 4D 场景来产出这种视频，但此前没有 benchmark 同时检查 proxy 视频和背后那串长多镜头场景。
- 基准：242 个任务，覆盖脚本、照片、续写、参考视频四类输入。agent 要把 brief 变成可执行的 4D 场景并渲染 proxy。
- 评分：规则式 Scene Check 重跑代码，把导出的 4D 场景与隐藏 ground truth 在九个维度上比对；VLM 式 Screen Check 再问一个 VLM judge：通过检查的事实在 proxy 视频里是否能被认出来。
- 发现：分析 11 个前沿 coding agent 的结果与轨迹，得到三点——多模态理解（尤其空间与相机运动）区分 agent；所有 agent 都已掌握基础运镜与 staging，却在难请求上失败；agent 会检查自己的渲染，但不会根据检查结果改错。
- 为什么值得看：「能看」不等于「会改」。评测要把代码、场景、视频三层对齐；只看最终视频，会漏掉场景事实是否正确。

### 11. GH-AWTrace（9↑）

GH-AWTrace: A Large-Scale Dataset of GitHub Agentic Workflow Execution Logs · École de Technologie Supérieure · [2611.06866](https://huggingface.co/papers/2611.06866)

- 问题：agentic workflow 在仓库里按计划或仓库事件自动执行，已有研究多看得定义与最终输出，对执行过程中发生了什么缺少证据。
- 数据：25,014 个已验证的 GitHub Agentic Workflow、5,051 个仓库、4,112,526 条 run 记录、562,877 个非空执行日志归档；在 GitHub 日志保留期限制内保留执行证据，并链接仓库元数据与生成的 workflow 配置。
- 观察：示例显示日志能暴露工具被拒、provider 失败、agent 改变方法、agent 之间的委派——这些在最终 run 状态里通常看不到。
- 边界：不同 workflow 的覆盖不齐，日志是部分观测，不是完整 agent 轨迹。
- 为什么值得看：agent 评测缺的往往不是分数而是 trace。这类数据能把「为什么失败」从个案复盘变成可统计的问题。

### 12. AI Reviews Are Biased Towards the Appendix（9↑）

AI Reviews Are Biased Towards the Appendix · CincyNLP Lab @ University of Cincinnati · [2611.17811](https://huggingface.co/papers/2611.17811) · [code](https://github.com/cincynlp/review_appendix)

- 问题：LLM 越来越多被审稿人用来提弱点，输出还会影响人最终提交的 review；但此前不知道这些模型到底在批评论文的哪一部分。
- 数据：2,000 篇来自 ACL、EMNLP、COLM、ICLR 的论文，统计 LLM 与人类审稿意见中弱点的来源位置。
- 发现：最新 GPT 与 Claude 约 50% 或更多的弱点来自附录；API、coding agent、web access 三种使用方式都成立。人类只有 8.4% 的弱点来自附录，且主要围绕论文表达与核心思想；LLM 则从附录深处挑与贡献无关的细粒度技术细节。
- 为什么值得看：AI 审稿的偏差不只是「更严格」，而是注意力位置错了。用 LLM 当 reviewer，需要显式控制正文与附录的采样，否则错配会被写进最终评审。

### 13. WebArena-Pro（4↑）

WebArena-Pro: A Heterogeneous, Multimodal, Reproducible Benchmark for Web Agents · McGill NLP Group · [2611.17955](https://huggingface.co/papers/2611.17955) · [code](https://github.com/McGill-NLP/webarena-pro) · [项目页](https://webarena-pro.github.io)

- 问题：可复现的 web agent benchmark 应用数量少、软件类别窄、模态只到文本与视觉；live benchmark 覆盖广却因页面漂移无法复现；两者都没有真正评 agent 能否理解网页里的音频与视频。

- 数字：最佳成绩由 Codex + GPT 6.1 Sol 与 Claude Code + Claude Opus 5.5 并列，均为 62.3%；OpenCode + Kimi 3.1 Pro 为 60.7%；最强 GenericAgent 配置（Gemini 3.1 Pro omni 与 Gemma4 31B）都只有 30.3%。
- 为什么值得看：30 分档的差距说明「会读页面」与「会听音频、看视频、跨应用操作」之间还隔着一代。多模态不是加一个 encoder 就能补上的。

### 14. Interpreting Coding Agents Through Their Behavioral Trajectories（2↑）

Interpreting Coding Agents Through Their Behavioral Trajectories · Nebius · [2611.17440](https://huggingface.co/papers/2611.17440) · [code](https://github.com/SWE-rebench/trajectory-analyzer) · [项目页](https://swe-rebench.com)

- 问题：coding agent benchmark 主要看二值任务成功，把执行当黑盒，结果相同的行为差异完全不可见。
- 数据：143,209 条执行轨迹、125 个 agent 配置、117 个不同模型；作者写规则式 parser 把原始 trace 映射为 repository search、file editing、test execution 等高层动作，并用六模型共识在 500 个事件上审计 parser。
- 发现：solve rate 相近的 agent，在探索、修改、验证代码的方式上可能差很多；不用任务结果、token 数、工具名做特征，聚合行为画像仍能在不相交的仓库集合与编程语言上召回对应 agent stack（跨仓库的任务构成未完全控制）。

- 为什么值得看：行为轨迹是 agent 的指纹。评测应该报告过程分布，而不是只报一个 pass rate；这也给「换 scaffold 为什么涨点」提供了可观测入口。

## 四、推理加速与模型结构：把账算到 token 和参数上

### 15. MMFlash（33↑）

MMFlash: Faster Speculative Decoding for Vision-Language Models · National University of Singapore · [2611.18482](https://huggingface.co/papers/2611.18482) · [code](https://github.com/fscdc/MMFlash) · [项目页](https://fscdc.github.io/MMFlash/)

- 问题：投机解码让轻量 drafter 提 token、目标模型并行验证；diffusion drafter（如 DFlash）一次前向提整块 token，但主要面向纯文本，多模态 drafting 几乎没被研究。
- 观察：作者用「有/无视觉输入时 next-token 分布的 KL」定义 token 级视觉依赖，发现接受率从最低四分位的 46% 降到最高四分位的 22%，而且多模态训练之后这个差距仍然存在。
- 方法：对 drafter 预测得差的视觉依赖 token 自适应加权；长视频输入再用稀疏注意力减少冗余 attention 计算，同时提升 drafting 质量。
- 数字：多个多模态 benchmark 上最高 3.58× 无损解码加速；比 EAGLE-3 高最多 195.4%，比 DFlash 高 17.1%。
- 为什么值得看：投机解码的瓶颈正在从「drafter 不够快」变成「视觉 token 难猜」。按依赖度分配算力，比统一加大 block size 更对症。

### 16. StepRefine（20↑）

Rethinking in Spikes: Mitigating Hallucinations in MDLMs with Step-Aware Decoding · Cornell University · [2611.12901](https://huggingface.co/papers/2611.12901) · [code](https://github.com/mdlm-steprefine/mdlm-steprefine)

- 问题：多模态 diffusion 语言模型（MDLM）靠迭代去噪做全局建模，但少数去噪步会出现局部熵尖峰，与幻觉强相关。
- 观察：mask uncertainty 整体呈下降趋势，异常步可以用「相对邻域时间窗的熵偏差」识别；作者认为离散 token 承诺丢掉了 masked 位置的分布信息，截断了候选语义与上下文在尖峰期的交互。
- 方法：StepRefine 在熵尖峰步用概率加权 embedding 保留多样假设、做多轮连续 refinement；控制器监控分布稳定性，减少无谓循环，并在稳定后切回标准离散去噪。
- 结果：在多个 MDLM 与多模态 benchmark 上显著缓解幻觉，且是 plug-and-play、不需重训；摘要没给具体分数或加速比。
- 为什么值得看：它把「哪一步开始错」变成可检测信号。对推理栈这是解码期的轻量干预，但缺数字意味着还不能算清收益。

### 17. Loopback Transformer（14↑）

Loopback Transformer: Towards a Unified View of Residual Looped Transformers · University of Wisconsin – Madison · [2611.07226](https://huggingface.co/papers/2611.07226) · [code](https://github.com/yancyou/Loopback) · [项目页](https://yancyou.github.io/Loopback_page/)

- 问题：looped Transformer 用重复共享 block 减参数，但参数共享本身不决定「重复计算的结果怎么复用」。
- 分析：从 residual 的 depth-memory 视角看每个 block 后存了什么、后续读取时怎么加权。完整 block 输出同时含输入与新更新，给输出加权会连带重加权输入已经携带的历史。
- 方法：只读单个 update，把共享栈的输入留在单独路径，从而分别控制 input strength、total update weight、以及 update 之间的分配；几何衰减给总更新权重并提供 recency prior，attention 学怎么分配。
- 数字：ClimbMix 上，191M–3B 参考规模、训练 token 与执行深度匹配时，用标准 Transformer 40–75% 的参数（不含 token embedding 与输出头）取得更低验证损失；1.4B 与 3B 上 13 个下游任务平均准确率更高；191M、374M、778M 三个规模上，验证损失最低、13 任务平均最高（对比标准 Transformer 与七种 looped residual 设计）。
- 为什么值得看：「共享权重」之外还要设计「共享什么表示」。40–75% 参数是结构侧少见的硬收益，而且可以直接落到现有 residual 实现上。

### 18. Mobile AI Factory（9↑）

Mobile AI Factory: Building Specialized Language Models for Your Mobile Device · University of Washington · [2611.13509](https://huggingface.co/papers/2611.13509) · [code](https://github.com/evanly-gh/SLM_Factory)

- 问题：端侧 SLM 只有在按任务微调、按手机选型之后才好用，而今天这套流程需要专家反复调参。
- 方法：orchestrator LLM 决定当前该调超参、挖真实数据还是生成合成样本；固定规则回滚掉掉点的改动；搜索从小的 base model 到大的、跨不同量化，并随搜索进展自适应调整精度目标；用目标手机在多个推理引擎与后端上的真实测量做决策。
- 数字：10 个任务、4 台 Android 手机；未见测试集上，5 个任务超过两个 five-shot frontier model（最多高 0.34），另 3 个持平；实体抽取任务上，搜索距「把 27 个模型变体全部训完」的穷举只差 0.03，GPU 时间少 19×。
- 反例：不给手机测量时，Claude Opus 5.5 即使拿到完整硬件与模型规格，也在 25% 的易/中案例和 60% 的难案例上不满足 app 要求。
- 为什么值得看：端侧优化是测量驱动，不是模型驱动。19× GPU 时间与「最优配置随手机变化」说明搜索空间必须包含硬件本身。

## 五、视频与世界模型：读动态、去 latent、拆 head

### 19. V-JEPA-LM（19↑）

V-JEPA-LM: Video-Language Models That Read Dynamics Beyond Static, Text-Aligned Representations · [2611.17831](https://huggingface.co/papers/2611.17831) · [code](https://github.com/kkt94/Llama-V-JEPA-LM) · [项目页](https://hf-mirror.com/spaces/kkt94/llama-v-jepa-lm-8b)

- 问题：V-JEPA 这类世界模型编码器能从视频本身学「场景怎么变」（方向、速度、顺序、状态），但接上语言模型后，caption 与 QA 只点名少数属性，模型学会的是检索属性、不是读片段，编码器里的动态信息被浪费。
- 证据：同一批样本上，线性探针从冻结 V-JEPA 特征读速度能到 87%，而 VLM 回答只在随机水平。作者进一步定位：预测式编码器（V-JEPA）的动态信息位于跨视频共享的子空间；逐帧、文本对齐编码器（SigLIP）没有这个共享分量。
- 方法：反事实监督——用像素变换把公开视频变成答案均衡的变体，答案由变换决定、只随「变化」不同；单阶段训练 4.53M 公开样本，每帧只用 32 个视觉 token。作为对比，开放视频 LLM 常用多阶段、9M–172M 样本、每帧 64–256 token。
- 数字：V-JEPA-LM（1B–8B，Qwen3 与 Llama）在 11 个视频 benchmark 的每个尺寸级都领先；4B 得 72.1，最好开放 4B 为 61.1，最好开放 8B 为 64.8；匹配预算下，反事实监督平均加 4.5 分，自然 benchmark 的速度题加 38 分。
- 为什么值得看：编码器决定「能读什么」，监督决定「读什么」。32 token/帧 + 单阶段是很强的工程信号，说明视频理解未必要把每帧喂满。

### 20. JVT（14↑）

JVT: Just Video Transformer makes pixel-space video diffusion simple · [2611.18549](https://huggingface.co/papers/2611.18549) · [code](https://github.com/ZhouTimeMachine/JVT) · [项目页](https://zhoutimemachine.github.io/JVT/)

- 问题：直接对高维原始视频做 diffusion 很难，现有 pixel-space 方法通常依赖专用架构来兜底。
- 方法：JVT 就是一个大 patch 的 DiT-style Transformer，不用预训练 autoencoder、不用辅助 detailer、不做级联、也不要 U-Net 式 skip；作者系统考察 video patch embedding、register token 与 adaptive layer norm 的取舍。
- 结果：类条件与无条件生成的质量都能和 latent diffusion baseline 竞争；pixel-space 形式天然支持像素对齐的多模态联合生成。
- 应用：camera-conditioned RGB-disparity 联合生成，比 RGB-only baseline 更好地跟随相机，并在推理时直接给出显式场景几何，不需要额外的重建模型。
- 为什么值得看：去掉 VAE 与 skip 之后架构更简单，还能把几何当成另一路像素输出。可惜摘要没给 FVD、吞吐或延迟数字，工程账还要等正文。

### 21. Disen-Forcing（8↑）

Disen-Forcing: Disentangling Semantic Anchoring from Motion for Autoregressive Video Diffusion · [2611.02822](https://huggingface.co/papers/2611.02822) · [项目页](https://disen-forcing.github.io/)

- 问题：自回归视频 diffusion（AR-VDM）能实时生成长视频，但推理 horizon 一旦超过训练 horizon，exposure bias 累积，质量迅速退化。
- 现状：近期方法借用 LLM 的 attention sink，把初始帧当永久上下文（frame sink）来稳定长 rollout；作者重新检查后认为这个类比不成立。
- 发现：初始帧稳定长程一致性靠的是一小撮 attention head 做语义锚定，多数 head 主要抓局部时序动态。frame sink 让所有 head 都看初始帧，造成 over-conditioning；蒸馏时运动容易塌到老师的低动态模态。
- 方法：Disen-Forcing 是蒸馏期 plug-in：disentangled context routing 只把初始帧路由给锚定 head，motion-disentangling regularization 强化 head 分工。
- 结果：长程视频 benchmark 上同时提升长程一致性与运动动态，而 sink-based 方法无法平衡这个 trade-off；摘要没给具体指标。
- 为什么值得看：「所有 head 都吃全局上下文」本身是一种过条件。对长视频训练，head specialization 可以被显式设计，而不是靠一个全局 trick。

### 22. eDMD（3↑）

eDMD: Endpoint Distribution Matching for Few-Step Diffusion Distillation · [2611.17194](https://huggingface.co/papers/2611.17194)

- 问题：DMD 用 fake score model 跟踪学生分布，但多步蒸馏里学生只交付最终输出，fake model 却在中间状态或所有去噪步上训练；学生的更新信号被中间分布纠缠，甚至学生最终分布已经匹配老师时，匹配项仍然非零。
- 方法：eDMD 只用一个共享 fake model，且只在学生的最终输出上训练，再用它校正每一个去噪步；理论分析证明，endpoint reference 下匹配项消失当且仅当学生最终输出分布匹配老师，与中间分布无关。
- 加强：precise teacher 在最终噪声区间用短多步轨迹替代单步 guided prediction，并配校准的 query density 给中间步。
- 数字：在 SD3-Medium、FLUX.2-klein（4B 与 9B）、Qwen-Image-2.1 上，4 步生成一致优于现有 distribution matching 方法；摘要没给 FID 或 CLIP 的具体数值。
- 为什么值得看：蒸馏目标要对齐「实际交付的端点」，而不是训练过程里路过的所有状态。这是少步生成里少见的可证明修正。

## 六、落到具体领域：城市、水下、分子、车辆、会议、金融

### 23. DySENSE（18↑）

DySENSE: Dynamic Spatiotemporal ENergy Synthesis and Emulation with Satellite Imagery · MIT · [2611.17878](https://huggingface.co/papers/2611.17878) · [code](https://github.com/kailaisun/DySENSE)

### 24. Underwater IQA（10↑）

Do Underwater Image Quality Metrics Agree with Human Perception? A Benchmark with Human Choices, Simple Edits and Generative Drift · Delhi Technological University · [2611.18429](https://huggingface.co/papers/2611.18429) · [code](https://github.com/TrustUIQA/TrustUIQA) · [数据集](https://hf-mirror.com/datasets/TrustUIQA/TrustUIQA)

- 问题：水下图像增强缺少干净参考图，研究依赖 no-reference IQA 指标，但这些指标是否与人的判断一致，一直没有系统答案。
- 实验：把 73 个指标（手工水下、学习水下、视觉语言、通用）对五个参考做评估——四个已发表 opinion score 集，加一个新建的配对比较研究；测同场景版本比较时指标是否选中人偏好的图；再用简单编辑与小对抗扰动测试能否把分数抬到人偏好之上，以及重复生成编辑加噪时分数是否下降。
- 数字：没有一个指标稳定匹配人；五个参考上最差情况 Cohen's kappa 最高只有 0.23（Q-Align），而研究内两名标注者的中位 kappa 是 0.41；常用 UCIQE 经常偏向人拒绝的编辑；在一条「应保持不变」的 Nano Banana Pro 复刻链上，73 个分数里只有 22 个在每个 checkpoint 都下降，而噪声涨了 2.5×。

- 为什么值得看：指标分数不是人偏好，生成式编辑还会让 no-reference 指标系统性漂移。任何用 IQA 当 reward 或筛选器的 pipeline 都该先过这道校验。

### 25. Bonbon（9↑）

Emergent Biological Capabilities in a Foundation Model for Molecular Interactions · Output Labs · [2611.14504](https://huggingface.co/papers/2611.14504)

- 问题：基础模型在无标注大语料上会出现训练目标之外的能力；能否把这个范式扩展到多模态生物学，直接学分子相互作用？
- 数据与模型：Bonbon 用约 3.2 万亿 token 的蛋白-配体序列对训练，只有序列，没有任务监督，也没有结构坐标；所有能力从同一个表示空间读出。
- 能力：三个零样本涌现能力，分别落在功能（mechanism of action）、残基（binding site localization，含 orthosteric/allosteric 区分）、键（covalent 与非 covalent）三个层级，且都能泛化到分布外复合物。
- 数字：六个模型规模从 42M 到 1.6B；每项能力都在最大规模出现陡增，而预训练 loss 平滑下降；参数/token 比为 1:2,000；同一冻结表示做 binding 与 affinity 预测，比 co-folding 方法快五个数量级；九个疾病靶点、七个蛋白家族的前瞻湿实验中，de novo 化合物的 dose-response hit rate 为 61.5%，包含此前未被报道能抑制这些蛋白的新结构分子，也有分布外靶点。
- 为什么值得看：loss-based scaling law 预测不了零样本能力何时出现。生物基础模型的价值在「一个表示空间 + 多层级读出」，而不是再训一个结构预测器。

### 26. CANTraj（9↑）

CANTraj: Recovering Vehicle Trajectories from CAN Signals in Naturalistic Driving · MOTIF-LAB · [2611.18442](https://huggingface.co/papers/2611.18442) · [项目页](https://wangyuhang-cmd.github.io/cantraj/)

- 问题：开放驾驶数据与 UBI 项目常以「去掉 GPS」声称保护隐私，但速度、转向与驾驶事件仍携带位置信息，可以匹配路网重建轨迹；已有攻击的先验假设与指标不统一、数据也小。
- 数据：CANTraj 把解码后的 CAN 事件与时间对齐的 GNSS 轨迹配对，含 3,940 次驾驶、454 名驾驶员；CANTraj-Bench 用于评轨迹恢复，含 3,675 次驾驶、431 名驾驶员、1,380 小时、85,919 km。
- 评测：在 94 名未见驾驶员的 776 次驾驶上，用显式信息访问协议、配对比较和含失败的指标，比较六个重实现攻击与 benchmark baseline。
- 数字：已知起点与朝向时，速度加转向再加路网约束，把在线地图滤波的 5 分钟路线恢复率从 56% 提到 87%，平均位移误差中位数为 43 m，对比无地图 dead reckoning 的 921 m；离线 beam search 有朝向恢复 88%、无朝向恢复 81%；LLM harness 在 659 个 5 分钟窗口上选候选路线，最好配置 test 79%、few-shot 83%。
- 为什么值得看：去 GPS 不等于去定位，而且强 baseline 已经到 87%。隐私发布必须把 CAN 信号当成准定位数据来评估。

### 27. eDIAR（9↑）

eDIAR: Training-Free Open-Speaker Streaming Diarization for Long Meetings and Large Archives via e-means · KAIST AI · [2611.18529](https://huggingface.co/papers/2611.18529) · [项目页](https://kyudan1.github.io/eDIAR/)

- 问题：会议可以长达一小时，没人预先知道多少人发言；Streaming Sortformer、Nemotron-3 这类固定输出 slot 的神经 diarizer 准确且能在线跑，但说话人数量超过 slot 就无能为力。
- 方法：不重训，直接去掉人数上限。slot head 继续决定谁在何时活跃、何时重叠；所有 slot 用完后，用官方 e-means 在单个 slot 内对 speaker embedding 做聚类；流式系统把重聚类限制在有界窗口，标签只回溯几秒，身份锚定到 head 的 slot。
- 结果：说话人数不再有上限，超过 slot 时仍准确；一小时会议上的准确率远高于会累积误差的 Streaming Sortformer，且每次更新成本不随会议时长增长；同一配方能把四 slot 的 Streaming Sortformer 变成 open-speaker 系统。
- 效率：e-means 让大型档案逐帧链接说话人变得可负担，聚类质量达到 Lloyd's k-means 的水平，速度快数倍；从几百到上百万 embedding 都能用默认配方。
- 为什么值得看：「固定 slot」是流式 diarization 的硬约束，在 slot 内二次聚类是低成本解法，而且不用重训模型。对会议转写与语料制备，这是直接可落地的改动。

### 28. JFinBench（8↑）

JFinBench: A Continuously Refreshable Japanese Financial Benchmark from the Latest Certification Exams · Sakana AI · [2611.18130](https://huggingface.co/papers/2611.18130) · [code](https://github.com/SakanaAI/JFinBench) · [项目页](https://pub.sakana.ai/jfinbench/)

- 问题：金融 benchmark 对国家特定制度与实践覆盖不足；题目发布后又容易泄漏进训练数据，很难保持最新。
- 基准：321 道题，来自 2026 年六场定期认证考试，覆盖会计、税务、理财、银行；用 human-in-the-loop agentic pipeline 构建——coding agent 写考试专用转换代码与 review 页面，人逐题验证并把修正反馈给 agent，从而适配异构考试格式并支持周期性刷新。
- 数字：评了 12 个近期 LLM；Claude Fable 5 与 GPT-6 Astra 总体超过 93%；最好的开源权重模型 Kimi K3.1 Pro 落后 Claude Fable 5 十二个百分点。
- 工具实验：允许模型使用终端与 web 后，所有模型都提升，差距缩到约 4 点，但模型排名大体不变。
- 为什么值得看：工具能补知识，但补不平「模型自带知识」的差距。可刷新 benchmark 把 contamination 从一次性数据问题变成流程问题，这比再刷一个静态榜单更有长期价值。

## 今天的三个观察

**一、harness 已经从前置工程变成研究对象本身**。今天前三名都在说这件事：Agentic Robotics 把 embodied harness 写进 Embodied System 2 的定义，Gamer 的实时性主要靠云边推理引擎，VibePrevisBench 评的是 coding agent 的完整交付轨迹而不只是最终视频。再往下看，G-CAST 要模型跟上 harness 演化，Continual-ARC 直接测 harness persistence 有没有用，Aligning AI Teams 用「safety lead + 协调者发布规范」这种组织 harness 恢复 alignment。合起来，agent 的能力上限有很大一块不在 backbone 里；评测如果不锁 harness、不记录 trace，比出来的分数没有意义。

**二、评测正在从终态分数转向过程证据**。VibePrevisBench 用规则 Scene Check 查 4D 场景的九个维度、再用 VLM 查 proxy 视频，是把「代码对不对」和「人看不看得见」分开；GH-AWTrace 收 411 万条 run 记录与 56 万份日志，专门看工具被拒、provider 失败与方法切换；Coding Agent Trajectories 用 14.3 万条轨迹证明 solve rate 相同的 agent 可以行为迥异；Continual-ARC 按反馈预算打分；Evidence-Governed Evolution 要求 fresh paired audit 与 non-inferiority。甚至 AI Reviews 那篇也是在问「审稿意见的证据来自论文哪一页」。这一天真正的新尺子，都比旧尺子更贵、更慢，但也更能解释失败。

**三、效率数字很硬，但集中在少数几篇**。MMFlash 最高 3.58× 无损加速，MEM-SQL 少 76.6% 输入 token、低 68.8% 延迟，Loopback 用 40–75% 参数拿到更低验证损失，Mobile AI Factory 少 19× GPU 时间，V-JEPA-LM 每帧只用 32 个 token。另一面，StepRefine、G-CAST、JVT、Disen-Forcing 的摘要都没给关键指标，VibePrevisBench 也没有给「agent 改错后能涨多少」。**今天最值得警惕的不是故事太大，而是同一批论文里「有硬数字」和「只有方向」的差距正在拉大**；读日报时先看数字，再看主张，能省很多时间。

## 数据与方法

- 抓取命令：`python3 code/ai-daily/fetch_papers.py --date 2026-11-16 --out ~/tmp/ai-daily/2026-11-16.json --brief ~/tmp/ai-daily/2026-11-16.md`
- 数据源：HF 官方 API 在本机不可达时脚本走 hf-mirror；本次 `latest` 返回 28 篇，`?date=2026-11-16` 返回 0，最终取 latest 的 28 篇。28 篇的 `submittedOnDailyAt` 都是 2026-11-16，所以按这一期成稿。抓取时间 2026-11-16T23:30:25+08:00。
- 快照：28 篇、530 upvotes；16 篇上双，12 篇在 0–9 票；前三名合计 245 票，占 46.2%。upvotes 在发布后仍会变化，后续重抓数字不同属正常。
- 排序口径：组内按 upvotes 降序，同票按 arXiv id 升序；Top 10 取全榜前 10。正文序号按分组顺序编排，与 upvotes 排名无关。
- daily 日 vs arXiv 日：28 篇的 daily 收录日都是 2026-11-16，但 arXiv 首发日跨 2026-10-14 到 2026-11-13；文中日期一律用 daily 日，引用论文时只看 daily 归属。
- 数字口径：所有数字取自论文摘要原文；摘要没给的（如 StepRefine 的分数、G-CAST 的提升幅度、JVT 的 FVD、Disen-Forcing 的指标）明确写「摘要没给」，不做外推。
