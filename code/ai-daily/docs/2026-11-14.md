## 二、新增 · 多模态怎么「看」

### 1. Unbundling Multimodal Vision Encoding（13↑）

Unbundling Multimodal Vision Encoding · Meta · [2611.17334](https://huggingface.co/papers/2611.17334) · [项目页](https://unbundling.github.io/)

- 问题：多模态模型的视觉编码有三条流行路线——用预训练视觉编码器、和语言模型一起从零训练、以及干脆不要编码器。公开模型的数据、结构、算力都不同，放在一起比无法归因。
- 方法：统一从零预训练、共用数据、按 matched lifetime compute 比较；把「视觉编码器」拆成三个正交选择：上游预训练带来的 visual prior、专用视觉容量、以及容量放在 fusion 之前还是之内。
- 结论一：visual prior 不必要。联合从零训练的编码器与预训练编码器打平，还省掉一个独立训练阶段。
- 结论二：专用视觉容量必要。encoder-free 模型即使把语言主干扩大相当于编码器的参数量，视觉理解仍然落后；但这份容量不必放在 fusion 之前，把 vision-only 模块加到主干早期层（in-fusion），效果与 pre-fusion 编码器相当，还能降低 time to first token。
- 稳健性：上述结论在多种主干规模、把编码器预训练视为免费、以及从预训练语言模型出发时都成立。
- 为什么值得看：这直接改多模态训练流水线——少一个预训练阶段、少一次跨模态对齐，TTFT 还更好；但「容量必须专用」说明不能靠加大语言主干糊弄过去。

### 2. The Narrative Gap（2↑）

The Narrative Gap: Can LLMs Help Us Navigate Diverse Narratives Across Languages? · Johns Hopkins University · [2611.12750](https://huggingface.co/papers/2611.12750) · [code](https://github.com/isle-dev/Narrative-Bench-NeurIPS-2026)

- 问题：LLM 正在成为跨语言的信息入口，但对争议话题，不同语言与地区的叙事并不一致；要让用户看到 competing accounts，模型需要一组专门能力。
- 六项能力：基础三层是 narrative inclusion、narrative exclusion、missing narrative identification；高层三层是呈现多元叙事、在 confirmatory query 下保持覆盖、以及跨语言的信息对等。
- 基准：NarrativeBench 含 1,333 篇新闻、23 种出版语言、23 个争议话题、460 条 Reddit-grounded query；评了 14 个 LLM，覆盖 24 种 query 语言。
- 发现：现有模型不能可靠地导航多元叙事；即使明确要求 diversity，竞争叙事的曝光仍有大缺口；不同 query 框架与语言下信息获取结果不同，可能形成 echo chamber 与 linguistic filter bubble。摘要没有给具体分数。
- 为什么值得看：它把「信息对等」拆成可测能力；对 RAG 与搜索 agent，query 的语言本身就是一种偏差源。

### 3. Neuro-VL（1↑）

A frontier machine intelligence for human neuroimaging · Machine Learning in Neurosurgery Lab · [2611.15094](https://huggingface.co/papers/2611.15094) · [code](https://github.com/MLNeurosurg/neuro-vl) · [项目页](https://neurovl.mlins.org/)

- 问题：现有医疗模型多做受限任务，而通用闭源模型拿不到私有临床影像，难以形成专科能力。
- 方法：Neuro-VL 用近 100 万份来自常规临床流程的神经影像研究训练，能读完整检查，并用自然语言讨论发现。
- 结果：在内部与国际数据集上，诊断、定位、描述异常、生成完整放射报告均优于 frontier 通用模型与专科医疗模型；还能比较序列检查评估疾病进展。
- 稳健性：面对误导性的临床假设，Neuro-VL 比 OpenAI 与 Google 的领先模型更不容易被带偏。
- 数字：摘要只给「近 100 万份」训练规模，没有给具体准确率或 AUROC。
- 为什么值得看：这是「数据壁垒大于模型规模」的一个清晰案例；纵向比较与抗暗示才是临床落地的真门槛。

## 三、新增 · Agent 的记忆与经验

### 4. Who Remembers What?（5↑）

Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction · Amazon Web Services · [2611.10439](https://huggingface.co/papers/2611.10439) · [项目页](https://wangyz1999.github.io/who-remembers-what/)

- 问题：self-evolving agent 会从经验里改自己的技能与记忆，group-evolving agent 还把这些 lesson 跨 agent 共享；但多数系统没有决定「谁该受益于哪条经验」以及「什么信息必须留在私有范围」。
- 方法：MixUA 把独立的 user-agent 轨迹蒸馏成 lesson，再按受益者与可披露范围分配到四级 scope：user-agent pair、user、agent、global。
- 评测：CrossLearnBench 把既有 agent 任务与用户偏好、隐私探针配对，专门检验私有事实会不会泄漏到别的用户可读的记忆；规模是 5 个用户、7 个 agent。
- 数字：pass rate 比无记忆最高 +16 分，比单一 global memory +5 分，而且在「只有别的用户/别的 agent 试过」的任务上也有效；保留最多 90% 此前声明的偏好；最多 0.02% 的隐私探针能在禁止 scope 里找到植入的私有事实。
- 为什么值得看：记忆的 scope 本质是访问控制。把泄漏率当成一等指标，比只测召回更接近可上线。

### 5. Experience-Handoff RL（2↑）

Experience-Handoff Reinforcement Learning for Recursive Self-Improvement · KAIST AI · [2611.16409](https://huggingface.co/papers/2611.16409) · [code](https://github.com/doyoungkim-ml/ehrl)

- 问题：用 scalar reward 做 agent RL 会丢掉环境里的细粒度信息，比如 error log；现有 harness 用 reflection 或 compaction 把经验交给后续 rollout，但「交接物」（如 playbook）的构造本身没有被学习。
- 方法：固定 Agentic Context Engineering 的 harness，训练同一个模型同时做三件事——act、reflect、curate task-local playbook。
- 训练信号：候选交接物按「对后续 actor rollout 的下游效果」评估，在固定 scaffold 下联合优化 action generator、insight reflector 与 playbook curator。
- 结果：在多个 agentic benchmark 上 held-out 表现高于 baseline；摘要没给具体分数或提升幅度。
- 为什么值得看：训练目标从「当前 rollout 的动作」扩展到「未来 rollout 继承的经验」，这是递归自我改进的一个可优化接口；但缺数字，目前只能算方向验证。

### 6. The Value of Thinking（2↑）

The Value of Thinking: Learning When to Reason in Hybrid Decision Models · [2611.16961](https://huggingface.co/papers/2611.16961) · [code](https://github.com/zhengxuyu/HDM-code)

- 问题：现有 adaptive reasoning 要么缩短显式推理，要么切换模式，但答案仍然要逐 token 写出来；真正该问的是「这一次要不要进入慢模式」。
- 方法：zero-or-T thinking。快模式在一次前向里用隐式思考给出答案、生成 0 个 token；慢模式花 T 个 token 做完整自回归推理。一个冻结主干加一个轻量 self-routing block 估计「思考的价值」，即慢模式相对快模式的预期增益，只有超过按请求设定的价格 λ 才走慢模式。
- 训练：没有 per-decision label 时（例如 episodic agent 任务），用 CDPO 从 episode-level return 训练 routing block。
- 数字：JevBench 上 HDM-4B 得 0.857，对 Jev 的 0.851（+0.7%），中位延迟 0.179 s 对 0.652 s（-72.5%）；MiniWoB 上 HDM-27B 把 token 成本降 80.1%。评了 MMLU-Pro、AGIEval、GPQA-Diamond、JevBench、BANKING77 与 MiniWoB。
- 为什么值得看：把推理成本做成 per-request 的 λ，运维上可以直接调；「0 token 快模式」比「少写几步 CoT」更彻底。

## 四、新增 · 3D 世界的数据与标定

### 7. TurtLES（4↑）

TurtLES: A Large-Scale Benchmark for Turbulent 3D Neural PDE Surrogates · Sorbonne University · [2611.09567](https://huggingface.co/papers/2611.09567) · [code](https://github.com/itsakk/TurtLES)

- 问题：ML surrogate 越来越多用于加速 CFD，但缺能刻画真实、时变湍流的 benchmark，进展被卡住。
- 数据：14 TB，3D 湍流圆柱尾迹，位于 shear-layer transition regime，用高保真 implicit large-eddy simulation 算出；400 条轨迹 × 400 个时间步，每帧 3–11 million 个点，覆盖几何、Reynolds 数与攻角变化。
- 特点：同时具备由 vortex stretching 驱动的 active energy cascade、dense irregular mesh、以及长时程动力学，这三点是已有数据集少有的组合。
- 发现：benchmark 了 SOTA neural operator 的自回归 rollout，主要 failure mode 是时间不稳定、小尺度能量丢失、以及在大而不规则域上难学。
- 数字：摘要只给数据规模，没有给误差指标。
- 为什么值得看：14 TB 的规模把「科学 ML 的 benchmark 债」摆上台面；小尺度能量丢失是自回归 surrogate 的通病，与视频/世界模型的长 rollout 同构。

### 8. Consensus Capture（3↑）

Consensus Capture in Reference-Based UAV Video Stabilization · EPFL · [2611.17190](https://huggingface.co/papers/2611.17190) · [code](https://github.com/rfonod/stabilo-benchmark)

- 问题：参考帧稳定把悬停无人机视频逐帧配准到一个参考帧，保持物体位置可比；但配准 pipeline 都是在「只有相机动」的特征匹配 benchmark 上选型的。繁忙路口里，同向运动的车辆会提供互相一致的对应点，把 robust homography 拉向车流——作者称为 consensus capture，inlier 统计看不出来。
- 基准：static protocol 在 4K 航拍帧、精确已知 homography 下评 10 条 pipeline，在 site-disjoint split 上按匹配分辨率与特征预算调参；dynamic protocol 在离线与实时预算下评，悬停片段只从视频选，覆盖不同运动前景量与一致性，另设静止 control。
- 指标：背景对齐、物体位置误差、估计跟随运动群体位移的比例；pseudo-ground-truth 用人工标注的 ground control points 审计，并用它给每个候选打分。
- 数字：静态场景里 tuned AKAZE、RootSIFT、SIFT、BRISK 领先；重调 matcher 阈值最多把 mAA 提高 0.0062，masking 成本不到 0.005。未 masking 的 ORB 在 304 个实时动态对里被 capture 28 个、离线 6 个；被 capture 的实时估计中位角点误差 18.8 px，但 inlier 数量与比例看起来完全正常。Masking 消除了所有 pipeline 的 capture，且不改变领先者排序。
- 为什么值得看：inlier count 不是安全指标。任何「用鲁棒估计对齐动态场景」的系统——SLAM、视频稳定、BEV 对齐——都该把这个失败模式单独测。

## 五、新增 · 具身与视频生成

### 9. Back to Pixels（2↑）

Back to Pixels: Lifting Latent Video Diffusion into Pixel Space · Roblox Corporation · [2611.17336](https://huggingface.co/papers/2611.17336) · [项目页](https://chenshuo20.github.io/PixVid/)

- 问题：前沿视频模型在 VAE latent 空间做时空压缩，训练因此可行，但现在限制高分辨率、可控与交互：分辨率翻倍 token 数变 4 倍；条件作用在帧组而不是单帧；每次响应要等整个多帧 block 生成完。
- 方法：PixVid 保留 diffusion transformer，把 VAE decoder 换成卷积 head，直接逐帧渲染像素。
- 关键取舍：作者发现「预测 clean video 而不是 velocity」加上更大的 noise shift，对质量最重要。
- 数字：从 Wan2.1-14B 微调，在 1.3M 训练 clip 内与 latent baseline 竞争；逐帧工作使其在同 per-frame token 数下生成 2× 分辨率；深度条件视频编辑在快速运动下仍保持对齐；每个动作在下一帧就能响应。
- 为什么值得看：交互式生成的瓶颈常常是「等一个多帧 block」。逐帧像素空间把响应粒度从 block 降到 frame，代价是 token 账要重算。

### 10. EgoX（1↑）

EgoX: Egocentric Cross-Embodiment Manipulation with Embodiment Dreaming · Carnegie Mellon University · [2611.16728](https://huggingface.co/papers/2611.16728) · [code](https://github.com/egox-dream/egox) · [项目页](https://egox-dream.github.io/)

- 问题：通用操作策略可以从人类、真机、仿真数据互补受益，但形态、传感、控制接口的差异让混合演示很难学。
- 方法：EgoX 按语义对应的观测/动作模态组织异构演示；MXT+ 为每种观测模态配专用 tokenizer、为每种动作模态配专用 expert，Transformer trunk 跨具身共享；训练时加 embodiment dreaming，预测未来视觉与本体状态的 latent。
- 数字：13 个 task-embodiment 对、5 个任务、6 种具身（5 台真机 + 1 个仿真人形）；跨具身预训练把平均归一化任务进度从 0.63 提到 0.80；OOD 条件下从 0.53 提到 0.77。
- 消融：更广的预训练混合、模块化接口、embodiment dreaming 都有贡献；dreaming 让不同具身之间的 latent 几何更接近。
- 为什么值得看：跨具身的关键可能不是统一动作空间，而是「共享 trunk + 模态专用接口」；dreaming 是训练-only 的辅助目标，不增加推理成本。

## 今天的三个观察

**一、换榜滞后和票数累积，都说明「日报」拍的是快照，不是终值**。11-14 21:02 抓到的 34 篇，daily 收录日全部是 11-13；昨晚 23:30 发布时是 24 篇、364 票，现在同一批是 34 篇、501 票。票数涨幅也不小：SO-Arena 57→82（+43.9%）、PhysLoop 31→44（+41.9%）、Open Vision Banana 17→32（+88.2%）。这意味着两件事：第一，发布时点与榜单时点必须分开记，否则同一批论文会被写成两天；第二，跨天的 upvotes 不可比，热度只能同一天横比。

**二、新增 10 篇的共同主题是「把隐性的东西变成可训练、可审计的模块**」。Unbundling 把视觉编码器拆成 visual prior、专用容量、放置位置三个可独立验证的选择；MixUA 把记忆的可见范围做成 user-agent/user/agent/global 四级 scope；Experience-Handoff 把 playbook 的构造纳入 RL；HDM 把「要不要想」变成对 λ 的收益判断。没有一个是新 backbone，全是把原来靠手工约定或隐式习惯的部分显式化。对训练系统，这比再堆一个模型更可复用。

**三、低票区的定量证据仍然稀薄，能算账的只有四篇**。新增 10 篇里 9 篇 ≤5 票；TurtLES 只有数据规模（14 TB、400×400、3–11M 点/帧），Neuro-VL 只有「优于 frontier」没有具体分数，Experience-Handoff 只说 held-out 更好，NarrativeBench 只给 14 个模型/24 种语言的覆盖而没有分数。真正能落到工程账上的是 HDM（-72.5% 延迟、-80.1% token）、EgoX（0.63→0.80、OOD 0.53→0.77）、PixVid（2× 分辨率、同 per-frame token 数）和 MixUA（+16 分、≤0.02% 泄漏）。这和前几天的模式一致：热度集中在尺子和数据，能算账的增益往往在低票区。

## 数据与方法

- 抓取命令：`python3 code/ai-daily/fetch_papers.py --date 2026-11-14 --out ~/tmp/ai-daily/2026-11-14.json --brief ~/tmp/ai-daily/2026-11-14.md`
- 数据源：HF 官方 API 在本机不可达（latest 各 limit 均无数据，`?date=` 报 Network is unreachable）；hf-mirror 的 latest 与 `?date=` 都返回 0，最终由 `hf-mirror.com/papers/date/2026-11-14` 页面内嵌 JSON 解析出 34 篇。抓取时间 2026-11-14T21:02:38+08:00。
- daily 日 vs 发布日：34 篇的 `daily_at` 全部是 2026-11-13，11-14 21:00 HF 尚未换榜。因此本期是 11-13 批次的终值快照，不是 11-14 的新榜单；标题日期用发布日，论文归属仍按 daily 日。
- 去重口径：24 篇已在 11-13 期详述，本期只给终值与票数变化；新增 10 篇全展开（Unbundling、Who Remembers What、TurtLES、Consensus Capture、Narrative Gap、Experience-Handoff、Value of Thinking、Back to Pixels、Neuro-VL、EgoX）。
- 排序口径：组内按 upvotes 降序，同票按 arXiv id 升序；Top 10 取全榜前 10。upvotes 会随时间变化，后续重抓数字不同属正常。
- 数字口径：所有数字取自论文摘要原文；摘要没有给的（Neuro-VL 的准确率、Experience-Handoff 的提升幅度、TurtLES 的误差、NarrativeBench 的分数）明确写「摘要没给」，不做外推。
