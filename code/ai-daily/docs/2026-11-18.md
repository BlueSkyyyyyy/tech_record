## 一、前沿模型与训练系统

### 1. Xing 4（146↑）

TeleChat to Xing4: Advancing Frontier Agentic Models on Domestic Chips and Frameworks · [2611.22115](https://huggingface.co/papers/2611.22115) · XingChen-AGI · [项目](https://github.com/XingChen-AGI)

- 问题：TeleChat 系列要在 Ascend 生态上做前沿 agent 模型，架构选择与训练基础设施不能分开讨论——稀疏激活、attention 形式、深度宽度、投机解码都在「容量 / 计算 / 访存 / 执行开销」之间换位置。
- 规模：285B 参数模型，8,192 张 Ascend 910C 预训练。这是本篇最硬的一个数字，也是国产栈上少见的公开系统报告。
- 系统：MindSpore HyperParallel 上做拓扑感知混合切分、分布式优化器执行、长序列与激活显存的协同管理；再用 CPU 亲和性与核隔离压宿主调度干扰。摘要没给 MFU、吞吐或切分比例。
- 后训练：TeleGym 把执行、评测、轨迹构造接到策略优化上；用 disaggregated 异步执行、bounded oversampling、partial rollout 应对任务时长异构，同时保持跨策略更新的轨迹连续性。这三件套和 agentic RL 的工程痛点一一对应。
- 为什么值得看：对「通算并行」主线，拓扑感知切分与宿主调度隔离是能直接对照的两块；对 agent 后训练，partial rollout 的轨迹连续性是最容易被忽略、又最容易毁掉训练信号的一环。

### 2. 权重空间编程不需要 Transformer（40↑）

Weight-Space Programming Doesn't Need Transformers · [2611.22055](https://huggingface.co/papers/2611.22055) · POSTECH · [代码](https://github.com/effl-lab/Weight-Space-Programming)

- 问题：Transformer 被选中，是因为它在梯度下降下好训、在 GPU 上快跑。但在 weight-space programming 里，LLM 直接手写权重、根本不做梯度训练——这两条理由同时失效，「还要不要 Transformer」就成了真问题。
- 设置：极简指导、10 个标注样本、一个 sandbox，任务主要是多选题；让三个前沿 LLM 二选一：给固定架构生成权重，或自己设计架构。
- 结果：三个模型获得自由后都做了同一件事——把纯文本事实编译成稀疏表，再用固定过程查询，最高 54.4% 测试准确率。LLM 自己设计的模型比同一个 LLM 写出的最准 Transformer 还准，参数少约 1,800×。
- 可解释性：没有梯度，模型就选表，因为每个权重的含义可以被陈述、错误行可以被找到并改写；每个错误答案指向一行，删掉一行大约只改变另一个答案。
- 效率与边界：据此提出 associative-memory 模型，GPU 上比同尺寸 Transformer 快最多 17×。但预训练 LLM 仍更准——作者的主张只限于「写权重时该造什么结构」，不是「Transformer 该淘汰」。

### 3. Multi-Branch Transformer（34↑）

Multi-Branch Transformer · [2611.19800](https://huggingface.co/papers/2611.19800) · [代码](https://github.com/GaotangLi/Multi-Branch-Transformer)

- 问题：语言模型通常靠加宽 block 或加深堆叠来扩，本文试第三条路：branching，把完整 Transformer block 并行组合。
- 结构：输入先过共享初始层，然后并行执行若干条独立参数化的 sequential block 分支，融合后再过共享末端层。三个变体分别是 Wide-Shallow（保宽度）、Narrow-Deep（保深度）、Balanced（插值）。
- 结果：四个 MoE 规模、0.8B–2.1B 总参数的受控预训练里，2 分支 Wide-Shallow 在参数与训练算力匹配时稳定优于 sequential；Balanced 更好，且分支数增加质量不降。拟合出的 scaling 曲线显示，标准 Transformer 需要最多 1.26× 的训练 body 算力才能匹配其验证损失。
- 推理：Joint-KV 在每个深度上从各分支表示构造共享 KV cache，配上利用分支分组与缓存复用的推理引擎；全模型 KV cache 存储最多降 34%，单张 H200 解码吞吐最多 +51.4%。
- 为什么值得看：分支只在中间层最有效，这条消融对结构搜索很有用；KV 共享把「并行分支」从训练技巧变成了推理侧的真实收益——否则多分支只是多花显存。

### 4. Regularized Score Centering（3↑）

Regularized Score Centering · [2611.21791](https://huggingface.co/papers/2611.21791) · UIUC

- 问题：异步 RL 提吞吐，但来自 stale policy 的数据、加上训练与推理的数值不匹配，会让学习不稳定。
- 方法：score centering（SC）去掉 reward baseline 对期望更新的影响；梯度诊断显示 SC 的梯度比 importance sampling（IS）温和，但 learner 离 behavior policy 太远时仍会失效。RSC 因此加一项 reverse KL 惩罚，让 learner 的 next-token 分布贴近 behavior policy，并可与截断重要性采样（TIS）叠加。
- 数字：dense 与 MoE 模型、数学推理加 agentic 任务（网购、工具调用、游戏、全异步软件工程）；RSC+TIS 在全部 agentic benchmark 上提升样本效率，同样的采样回答数下训练奖励更高。最终评测里六个 agentic 任务全部第一，AppWorld +14.3%，BabyAI 达到最强基线的 9.9×。
- 为什么值得看：全异步 SWE 训练正是训练系统最难的场景之一；reverse KL 这一项几乎没有额外成本，却能给出收敛性保证——属于「便宜且该默认打开」的改动。

### 5. M3OPD-Reasoner（1↑）

M3OPD-Reasoner: An Open Recipe for Post-Training Multimodal Reasoning with Multi-Teacher On-Policy Distillation · [2611.23034](https://huggingface.co/papers/2611.23034)

- 问题：多教师 on-policy distillation（MOPD）能让一个学生从自己的生成里吸收多个域教师的能力，但「先做 SFT 再蒸馏」还是「直接 GSPO 训教师」、蒸馏完还要不要 RL，缺少同口径对照。
- 数据：M3OPD-SFT-1.35M 与 M3OPD-RL-193K，覆盖 image STEM、image perception、video 三个域；21 个评测 benchmark 都已对训练数据做过去污染。
- 结果：每个域一个教师、用 GSPO 直接从 Qwen3.5-9B 训（不做 SFT warm-up），再 MOPD 蒸馏进单个学生，是最佳配方——学生在各自域接近教师，同 prompt 上平均高于混合数据训练（MixSFT / MixRL）的基线。
- 关键实验：MOPD 学生再叠 MixRL，同 prompt、同设置，仍继续涨且不 collapse，得到 M3OPD-Reasoner-9B。作者称此前没有 VLM 配方研究过这个顺序，于是 MOPD 与 MixRL 成了「把同一批数据吃两遍」的连续两阶段。
- 为什么值得看：数据、代码、每个阶段的 checkpoint 全开放，是少见的可复现后训练流水线；对「教师怎么训、学生怎么接、RL 放哪」这三个决策给出了明确排序。

### 6. TPHC（0↑）

TPHC: Improving Hyper-Connections with Tensor-Parallel Grouped Updates · [2611.23026](https://huggingface.co/papers/2611.23026) · [代码](https://github.com/wuyou2002/TPHC)

- 问题：Hyper-Connections 把残差流扩成 N 条并行流，manifold 约束版（mHC）能在大规模稳定，但流数超过 4 之后收益很小。作者定位到原因：每个 sublayer 只写一个输出到所有流，流与流之间根本没有独立更新的空间。
- 方法：把 TP shard 与 HC stream 接起来——每个 TP shard 路由各自的残差流 mixture，写回时保留各 shard 输出独立，于是每条流可以收到不同的混合。attention 与 FFN 子层不增加参数、不增加 FLOPs。
- 数字：8B 模型、4 条流时训练时间只比 mHC 多 9%；流数从 4 加到 16 只再多 19%。1.1B 模型、100B token 上，验证损失相对 mHC 降 0.7–1.0%，六个常识推理 benchmark 的 zero-shot 平均准确率 +0.3–0.7 点（N∈{4,8,16} 匹配比较）。
- 为什么值得看：这是把并行维度当结构先验用——TP 本来只是切分手段，这里成了残差流的独立来源。和本站 llm-arch 残差流那篇正好接上：HC 的瓶颈不在流数，在写入路径。

## 二、Kernel 与推理效率

### 7. AscendGYM（90↑）

AscendGYM: A Cost-Aware Kernel Optimization Benchmark for Real-World Workloads on Ascend NPUs · [2611.17621](https://huggingface.co/papers/2611.17621) · SLAI-AITP · [代码](https://github.com/SLAI-AITP/AscendGYM) · [项目页](https://slai-aitp.github.io/AscendGYM/)

- 问题：Ascend 上现有的 kernel benchmark 主要测「生成新 kernel」，很少测 agent 在真实 workload 的输入配置下「优化已有实现」——而后者才是工程里天天做的事。
- 基准：首版 48 个 kernel、三档难度；每个 kernel 配的 test case，其 dtype 与 tensor shape 都采自真实训练与推理任务，所以在 AscendGYM 上的提升能直接映射回对应 workload。执行环境完整复现真实 pipeline 的调用方式。
- 评测：支持 model evaluation 与 model-harness evaluation 两种模式，既能测训好的模型，也能测自定义 agent；model 模式自带 harness，含搜索编排与经验积累。
- 指标：Speedup-Token Score（STS）把加速比与 token 成本联合起来，衡量「预算内还能不能打」——单看 speedup，堆搜索预算总能刷上去。
- 为什么值得看：和本站 kernel-opt 主线同题。真实 shape 加成本归一化，比裸 speedup 更难刷分；Ascend 侧的 agent 优化基准此前基本是空白。摘要没给 baseline 的具体分数。

### 8. FMT（9↑）

FMT: Lossless Image Compression in a Fixed Number of Parallel Steps · [2611.23108](https://huggingface.co/papers/2611.23108) · Lab of Efficient AI and Data

- 问题：学习型无损编码器文件更小，但我们归档和训练用的图像还是经典编码器——原因是时间：一张照片学习型解码要秒级，经典编码器毫秒级；而学习型编码器的「快速变体」又把省下来的体积让回去了。
- 观察：作者认为这些时间主要花在「等」而不是「算」——网络在等它依赖的值，算术解码器又一个一个读。
- 方法：FMT（Fixed-step Multiscale Tree）把解码顺序与熵编码器一起设计：图像存成 coarse-to-fine 树，每步的值相互独立，GPU 一次预测一整步，并行 rANS lane 跨步携带状态，于是任意尺寸图像都在固定步数内解完。树上搭了一族 bit-exact codec，从无网络的规则到大网络都有。
- 数字：同一张 GPU 上，没有任何 codec 能在体积与速度两项同时赢过其中任一；不带网络时体积与速度都胜 NVIDIA HTJ2K；带大网络时，Kodak 照片解码比同 A100 上跑的学习型 codec 快 9–61×，体积相同或更小。
- 为什么值得看：把「自回归解码的串行等待」换成固定步数，这个思路对 LLM 解码同样成立——只是本文把它做在图像上，且做到了 bit-exact。

## 三、Agent 与交互

### 9. AURA 2.0（32↑）

Beyond Answering: Learning to Speak First and Act in Streaming Video · [2611.17048](https://huggingface.co/papers/2611.17048)

- 问题：多数助手只在被问时回应，视频流里出现了值得讨论的事件也保持沉默——交互完全由用户驱动。
- 三个升级：Model-Initiated Conversation 让模型在演化中的视觉流里识别值得说的话题并选时机主动开口；Stream-Aware Tool Calling 用当前视觉与对话上下文调外部工具、把返回信息并回交互；Interactive Visual Grounding 同时支持用户标注物体与模型输出 frame-aligned bounding box。
- 训练：专门构造了 streaming 交互数据集，用三阶段训练把新行为与 AURA 原有能力融合；再加 Long-Horizon Interaction Memory 维持长视频流的上下文连续性。
- 结果：公开 streaming benchmark 上在开源流式模型里领先，针对性评测验证了三项新交互能力——摘要没给具体分数。
- 为什么值得看：交互范式从「请求-响应」转向「主动发起」，评测口径也必须跟着变：什么时候该沉默、开口说错怎么算，这些问题现在还没有共识指标。

### 10. SIM（25↑）

Self-Improvement Memory Enables Continual Recursive Self-Improvement · [2611.18856](https://huggingface.co/papers/2611.18856) · Google

- 问题：harness 优化通常在固定 policy 模型与固定 benchmark 下研究。一旦换 benchmark 或换模型，优化器必须决定哪些改过的 harness 部分该复用、哪些该重写——但 harness 本身不记录「当初为什么这么改、后来效果如何」。
- 设定：Continual Recursive Self-Improvement（CRSI），让已有的 harness 优化方法能跨兼容 benchmark 或 policy 模型继续跑。
- 方法：Self-Improvement Memory 装给 harness optimizer，而不是装给解题 policy。它按反复出现的 harness 问题给编辑分组，记录理由、预测结果与观测结果、以及评测上下文；新尝试在这段历史上续写。
- 数字：四个域上最终分数高于 harness-only 与 root-cause-only 两种延续方式（跨数据集与成对跨模型比较）；coding 域十个独立 source run 的成对延续，SIM 平均 +2.36 分，p=0.003。
- 为什么值得看：把「优化经验」变成一等公民，是 harness 工程从手工调参走向可累积资产的关键一步；p=0.003 在这个样本量下算干净。

### 11. VideoNexus（17↑）

VideoNexus: Video Perception Beyond the Reasoning Context · [2611.21392](https://huggingface.co/papers/2611.21392) · Kling-Keye

- 问题：理解长视频要定位证据、辨清细节、再整合成答案。把帧回传给 planner，视觉信息就在推理上下文里越积越多；换成委派感知，稀疏采样又会漏掉决定性细节，逐帧描述同样让上下文持续膨胀。
- 方法：training-free，把细粒度感知与证据驱动规划彻底分开。planner 决定看哪里、解析什么、采样多密；perception 子 agent 在各自独立上下文里处理原生音视频，只返回紧凑、带时间锚点的证据，供 planner 迭代搜索与验证。
- 数字：规划与感知都用 Gemini 3.8 Flash 时，full LVBench 88.6%，比同 backbone 的静态喂入高 3.6 点、比其内置 agentic 处理高 1.1 点，而 API 成本只有后者的 44%。配对子集消融显示 planner 输入更少、准确率更高；把共享 backbone 换成 Kimi K3，比官方 Video-GAIA ReAct harness 高 8.5 点。
- 为什么值得看：「证据交换」的接口设计比换更强 backbone 更划算——44% 成本这一条是硬账，也说明长视频 agent 的瓶颈在上下文卫生，不在视觉编码器。

### 12. RepoFactory（8↑）

From Repositories to Training Environments: Scaling Long-Horizon Coding Agents with Environment Evolution Loop · [2611.21152](https://huggingface.co/papers/2611.21152) · IQuest

- 问题：长程 coding agent 需要带可验证反馈的训练环境。现有流水线是线性的、到验证就结束，只保证「能用」，不指导「训练价值」。递归自我改进要么靠 rollout、要么靠训练后再评测，在长程任务上成本与反馈延迟都被放大。
- 方法：把真实仓库转成可验证环境，agent 按语言规格从零构建完整项目；Environment Evolution Loop 用及时、可靠的 proxy 信号优化一个乘性目标——有效性 × 结构耦合 × 实现规模。
- 数字：17 个软件域、10,159 个环境。Qwen3.5-35B-A3B 在这些环境上训成 RepoHorizen-35B-A3B，NL2Repo-Bench +22.6 点，五个覆盖长程 coding 与 agentic 任务的 benchmark 平均 +8.5 点；不做环境进化只有 +17.5 与 +6.4 点。
- 为什么值得看：环境进化带来 +5.1 与 +2.1 点的净增量，说明在合成数据这条路上，「把环境调得更有训练价值」比「把环境堆得更多」更值钱。

### 13. Agentic OPD 重塑 ReAct 模式（6↑）

Agentic On-Policy Distillation Implicitly Reshapes LLMs' ReAct Patterns · [2611.19244](https://huggingface.co/papers/2611.19244)

- 问题：on-policy distillation 能把专门能力迁移给 agent，但它对交互模式（推理、动作、取观测）的跨域副作用没人系统看过。
- 发现：跨数学、ALFWorld、τ²-bench 三个域，看 ReAct 模式怎么变。通用推理监督把数学上的工具尝试从 70.4% 压到 14.4%，同时准确率从 16.7% 升到 38.0%；code-interpreter 监督改善了 household actions 与 retail queries。
- 负面结果：ALFWorld 监督把 τ²-bench 准确率从 41.5% 打到 6.6%，伴随大量违反用户信息依赖的工具调用——能力没迁过去，坏习惯迁过去了。
- 缓解：只用源域训练轨迹，按「域内 RL 前后教师偏好变化」做 selective OPD；保留 top 95% 的位置把 τ² 从 11.5% 提到 29.9%，代价是源域学习有 trade-off。
- 为什么值得看：负迁移是可测的，而且能靠教师偏好变化定位——多域 agent 后训练如果不做这一步，域间互害会被平均分掩盖。

### 14. agent 还需要被教怎么自我改进吗（3↑）

Do LLM Agents Still Need to Be Told How to Self-Improve? · [2611.23219](https://huggingface.co/papers/2611.23219) · MIT

- 问题：自我改进方法把模型优化的各个组件交给模型自己。模型越强，这个问题越尖锐：还需要人规定「该怎么自我改进」吗？
- 设定：给基本原语、资源和一个笼统的自我改进目标，agent 自己构造基于上下文的自我学习算法。测试台是游戏：冻结的 LLM 拿到算力预算与「收集经验 / 更新文本文档」的工具，没有外部强加的循环，也拿不到真实世界数据。
- 结果：足够强的模型确实能自我改进，其策略与经典自我调节学习框架、以及自生成课程的学习文献对得上；学到的文本产物能迁移到不同游戏时长、不同机制与 3D 导航。
- 局限：摘要没给具体分数、也没列模型清单，所以「足够强」的门槛目前无法量化。
- 为什么值得看：这是「harness 由谁设计」的极限提问。对 agent 工程的现实含义偏保守——至少现在，人的价值在给原语和预算，而不是给 loop。

## 四、具身与机器人

### 15. ForceHarness（38↑）

ForceHarness: Turning Force into Action and Physics for Frozen Frontier Models · [2611.21099](https://huggingface.co/papers/2611.21099) · Show Lab · [代码](https://github.com/showlab/ForceHarness) · [项目页](https://showlab.github.io/ForceHarness/)

- 问题：前沿多模态模型已经能零样本从图像控制机器人，但很多操作依赖接触力，而图像看不到力。把力接进 API-only 的冻结模型有两个硬约束：接触演化远快于 API 的决策延迟；冻结模型读不懂原始力流。
- 方法：先从腕部力传感器或仅关节力矩标定手部力；用 self-terminating force primitives 在模型之下自己调力、到接触事件才返回，把快环闭合在模型以下；再用 physics translation layer 把每条力轨迹翻成带不确定度的物理量，作为 tool result 返回。全程不需要示范，也不需要微调。
- 数字：真机、无腕部力传感器，GPT-6 Astra 的零样本成功率从 3.3% 提到 90.0%。仿真里 ForceBench +17.5 点、HiddenPhys +34.3 点，两个 benchmark 都超过用示范训练的 force-aware policy，HiddenPhys 上追平手写专家控制器。
- 附带的基准：HiddenPhys 是 7 任务 MuJoCo benchmark，物理变量对模型隐藏；消融显示小模型拿到物理量、而不是原始力值时，决策明显更好。
- 为什么值得看：这是 harness 的教科书形态——模型来不及做的下沉成 primitive，模型读不懂的翻译成它能推理的量。3.3%→90.0% 说明瓶颈从来不是模型能力，而是接口形式。

### 16. TCP4D（23↑）

TCP4D: A Unified Tool-Center-Point Tracking and Generation Model for Robot Manipulation · [2611.23143](https://huggingface.co/papers/2611.23143)

- 问题：机器人操作视频很多，但从 RGB 观测里恢复动作与夹爪状态仍然难，跨本体更是如此。
- 方法：用 embodiment-agnostic 的 tool-center-point（TCP）位姿当动作空间，让一个共享 4D 场景表示同时做两件事：跟踪观测到的 TCP 运动，以及生成未来的 TCP 轨迹。输入单目视频加初始 2D TCP query，tracker 直接给出 SE(3) 度量位姿、夹爪状态、场景几何与相机参数。
- 生成：generator 沿恢复出的 TCP 轨迹从同一 4D 表示采样局部特征，结合机器人观测与语言指令预测未来 TCP 状态。
- 数字：tracker 在 DROID 与 RoboLab 上绝对轨迹误差 7.60 / 16.07 mm，10 个示范即可适配新本体；generator 在 RoboTwin 平均成功率 69.19%，两个真机任务超过成熟 policy 模型。源域与增强示范联合训练，比只用增强示范把目标机器人成功率再提 41.5%。
- 为什么值得看：跨本体增强不需要源机器人状态——「无标注 RGB 视频 → 另一个本体的示范」这条链路，对数据荒比再训一个更大的 VLA 更实际。

### 17. Heave-Ho（19↑）

Heave-Ho: Decentralized Long-Horizon Multi-Humanoid Collaboration · [2611.22275](https://huggingface.co/papers/2611.22275) · University of Southern California

- 问题：多 humanoid 协作要全身协调、长程规划、跨机精确同步，在去中心化条件下三件事互相拉扯。
- 低层：multi-agent post-training，把 humanoid 基础 tracking 模型适配到 humanoid 之间的物理耦合交互，只凭局部观测就能做去中心化协调控制。
- 高层：训一个 vision-language planner，并设计基于语音的 leader-follower 协调机制——不靠网络通信来同步去中心化执行。
- 规模与结果：两个相同 humanoid 训练，系统扩到 10 台，且零重训泛化到异构队伍；配套 HH-Bench 有 12 个任务、2–10 台、含异构队。系统评测一致优于基线，真机实验验证了去中心化协作——摘要没给具体成功率。
- 为什么值得看：「用语音代替网络」反直觉但工程上合理：同步带宽降到人说话的量级，同时把通信故障从系统里整个拿掉。

### 18. ResWAM（4↑）

ResWAM: Learning What Changes, Not What Stays, for World-Action Models · [2611.19559](https://huggingface.co/papers/2611.19559) · OPTML Group @ MSU

- 问题：world-action model 用完整未来观测做监督，但一个 action chunk 内画面变化很小，损失被「复制静态背景」主导，学不到机器人与物体的任务相关运动；同时现有 WAM 依赖大视频生成模型或独立 world model，训练与推理算力都重，阻碍闭环部署。
- 方法：visual residual learning——只在冻结的 DINOv3 空间里监督「当前帧到未来帧的特征变化」。相比完整未来特征，残差目标的特征秩更高、对场景变化的表示更丰富，空间上集中在机械臂与被操作物体而不是背景。
- 结构：ResWAM 共 2.3B 参数，其中 0.5B 是双分支 DiT，action 分支与 residual 分支用 conditional flow matching 联合训练。
- 数字：不做机器人预训练（即不用 benchmark 示范之外的机器人轨迹预训练），LIBERO-Plus 81.1%、RoboTwin 2.0 93.8%、RoboDojo 9.40% success / 13.41 score，训练 2.7–4.0 TFLOPs、推理 1.0–1.4 TFLOPs 均为最低；真机 Open/Put/Stack 平均 80.0%，比 π0.5 高 10.0 点，延迟 92.7 ms。
- 为什么值得看：「只学变化」既提质量又省算力，是把监督信号做减法的好例子；92.7 ms 已经把闭环可用性摆到台面上。

### 19. HubEgo-100K（3↑）

HubEgo-100K: In-the-Wild Egocentric Video of Skilled Work for Robot Learning · [2611.21938](https://huggingface.co/papers/2611.21938) · Hub

- 问题：模仿学习策略在训练环境之外泛化差。已发表的数据 scaling 研究说，泛化随训练环境与物体的多样性增长，而不是随每个环境的示范数量增长。机器人数据跨环境采集贵，第一人称人类视频能在野外大规模采——但现有 egocentric 数据多是日常生活，缺真实工作场所的技能劳动。
- 数据 v1.0：10,124 小时 1080p 第一人称视频，配 100 Hz IMU，单个头戴手机相机；12,227 名贡献者、15,548 个环境、11 类场所、30 个工作类别、56 种任务、35 个动作族，83% 的小时数发生在工作场所。
- 规模与格式：72,754 个 episode，带机器生成的动作与语言标注，LeRobot 与 MCAP 两种格式，CC BY 4.0。
- 分析：逐轴测多样性；把 episode 随机排序后，新贡献者和新词仍持续出现；并把测量结果与已发表的六项「与策略性能相关」的数据属性（含手部可见性、惯性传感）对上。
- 为什么值得看：这是「多样性优先」的一次大规模下注。但 v1.0 只有数据，benchmark 与通往 100,000 小时的后续版本都还没来，短期内不要指望直接拿来当评测集。

## 五、视频、4D 与世界模型

### 20. FastFrames（19↑）

FastFrames: Video Generation at Interactive Latency · [2611.23226](https://huggingface.co/papers/2611.23226) · Apple

- 问题：自回归视频扩散模型按新观测逐帧生成，是交互式视觉体验的理想介质，但现有模型慢了几个数量级，谈不上「流体式交互」。
- 发现：profile 整条推理链路后，被当成固定实现细节的两块——VAE 解码与 KV cache 更新——合计占端到端延迟的一半以上。
- 方法：直接质疑这两块「不可省」的假设，用轻量替代把它们换掉。
- 数字：1.3B 变体在单张 B200 上每帧 36 ms、即 28 RPS，质量匹配慢近 8× 的 SOTA 模型；14B 变体在 8×B200 节点上每帧 45 ms、22 RPS，视觉质量与真实感显著更好。相机条件与物理条件两类应用里都做到了实时交互。
- 为什么值得看：延迟账必须按整条 pipeline 拆，只盯 denoise 步数会漏掉一半；对「实时视频生成」这类产品形态，36 ms/帧是硬门槛。

### 21. π^4（10↑）

π^4: A Foundation Model for 4D Scene Geometry and Motion · [2611.23144](https://huggingface.co/papers/2611.23144) · Shanghai AI Laboratory · [代码](https://github.com/yyfz/Pi4)

- 问题：4D 场景感知要同时拿到稠密几何、相机位姿、度量尺度、2D/3D 点轨迹与运动物体掩码，现有系统通常把这几件事分工给不同模型。
- 方法：geometry 分支加一个 geometry-conditioned motion 分支；motion 分支预测图像空间对应关系，再用重建出的目标视角几何 lift 到 3D。输入可以是单张图、无序图像集合或视频，且无需标定。
- 数字：几何评测里综合平均排名第一，单视/多视 2D 与 3D 点跟踪、运动物体分割都有竞争力；整系统约 0.5B 参数，不到多数基线的一半；一次前向同时出重建与轨迹，能处理上千张输入的大场景——尽管训练上下文最多 64 个视角。
- 为什么值得看：小模型加统一表示，把「4D 基础模型」从堆参数拉回架构设计；对具身与世界模型的数据管线是直接可用的组件。

### 22. MPEG-Diffusion（4↑）

MPEG-Diffusion: Mixed-Resolution Video Generation · [2611.12069](https://huggingface.co/papers/2611.12069) · Roblox Corporation

- 问题：视频 DiT 算力重。混合分辨率生成——重要区域高分辨率、其余低分辨率——能省算力，但现有方法在视频上质量掉得厉害，而且必须预先知道高分辨率区域在哪。
- 诊断：作者认为这些失败不是混合分辨率的固有代价，并归到三个根因，各给一招：dual-resolution attention，每个 query 只读自己分辨率的 K/V，缓解「mixed-resolution curse」；mixed-resolution decoder，解码前先混合 HR/LR latent 消除失真；self-selected HR region，用 DiT 自己的知识找重要区域，不需要预先指定。
- 数字：只处理 30% 的全分辨率 token，Wan2.1 14B 上去噪加速 4.8×（1.3B 上是 3.8×），几乎每项指标都超前作；用户研究里 90% 以上的成对比较优于先前的混合分辨率方法，评分接近全分辨率。
- 为什么值得看：30% token 换 4.8×，是稀疏计算在视频 DiT 上少见的干净结果；「让模型自己选重要区域」也顺手去掉了对额外显著性模型的依赖。

### 23. PanDWM（1↑）

PanDWM: Panoramic 4D Driving World Models · [2611.19857](https://huggingface.co/papers/2611.19857) · Peking University

- 问题：驾驶 world model 通常从六个针孔相机生成视频，光心不同、重叠很小，模型还得额外学会保持这些视角一致。
- 方法：把六路拼成一条 360° 全景带。相机边界落在同一张图内部，于是「保持视角一致」变成「保持图像连续」，而每个像素仍然记录自己的相机射线。条件于 layout，因果 student 以四个步骤窗口式生成，从因果 teacher 蒸馏并在自己的 rollouts 上训练；前馈解码器沿射线把每帧 lift 成 3D Gaussians，邻帧静态 Gaussian 补成 4D 场景。
- 数字：nuScenes 上按单张拼接的 360° 视角评分，FID 与 FVD 都低于多相机基线，速度是它们的 8–46×；保持 50 步 teacher 的 FID，同时把 FVD 降 22–25%。
- 为什么值得看：把「多视角一致性」重构成「单图连续性」是问题重构的漂亮例子；8–46× 的速度来自四步因果蒸馏，而不是更小的 backbone。

## 六、评测与可靠性

### 24. Breath-Dx（30↑）

Breath-Dx: A Time Series Classification Benchmark for Disease Screening with eNose · [2611.15348](https://huggingface.co/papers/2611.15348)

- 问题：电子鼻呼气筛查有便携、无创的优势，但缺系统 benchmark——尤其 sensor drift 这个已知却很少被量化的失效模式。现有研究多是小样本私有数据、协议不一致，结果不可比。
- 数据：基于 S-OH，迄今最大的公开临床 eNose 数据集，1,234 名患者、9 个诊断组，每人一条 17 通道多变量时间序列，配显式的时间切分（考虑 drift）。
- 方法：系统评测四族 10 种方法——feature-based tabular、convolution、graph、time series 架构。
- 数字：时间验证下所有方法显著退化，AUC 比随机交叉验证低 0.05–0.12，说明 drift 里嵌着很强的时间信号。这个现实口径下，最好的方法在某些肺部疾病上 ROC AUC 0.74–0.76，另一些仍接近随机；recurrent 架构跨病最稳，专用时间序列方法峰值最高。
- 混杂：人口学变量很重要——有的病呼气信号有独立诊断价值，有的在年龄之外几乎不增信息。
- 为什么值得看：0.05–0.12 的 AUC 落差就是「随机切分骗自己」的量化证据。任何时序临床模型都该按这个口径复测，而不是只报随机 CV。

### 25. VisualArtifactSpec 1.0（3↑）

VisualArtifactSpec 1.0: Evaluating Visual Artifacts under Task Specifications · [2611.21382](https://huggingface.co/papers/2611.21382) · Accio

- 问题：视觉产物任务考的是「把规格与素材变成可用交付物」的能力，但缺跨媒介的系统评测，分不清哪些是通用 authoring 能力、哪些只是某个媒介的专长。
- 基准：211 个创建与修改任务，覆盖 slides、静态图形、动画与视频、web 界面；每个任务都规定写作目标、素材、约束与交付物。
- 评分：把 Task Fulfillment（显式要求与功能是否满足）与 Artifact Performance（Content / Organization / Visuals / Delivery）分开评；按目标受众、用途、媒介实例化 rating anchors，判断以素材与产物检查记录为依据。
- 数字：9 个 model-harness 配置跑全部 211 个任务，总分区间 42.12–70.52；最高与最低配置之间 73.4% 的差距由 Artifact Performance 解释。
- 为什么值得看：近四分之三的差距来自「做得好不好看、组织得如何」，而不是「功能对不对」。agent 交付物的真短板在这里，而多数 benchmark 只测前者。

### 26. 量化对比的噪声地板（1↑）

The Noise Floor of a Quantization Comparison: Engine, restart, batch and kernel drift, measured against 8-bit and 4-bit effects in two decision models · [2611.15671](https://huggingface.co/papers/2611.15671) · Level5

- 问题：量化模型通常直接与 BF16 原版比，但这个比较同时换掉了别的东西：serving engine、服务器实例、请求 batch，甚至库只看 import 了哪些包就选不同 kernel。
- 方法：在 NVIDIA GB10 上，对 Cloudflare 两个决策模型 Clef-flash（9B）与 Clef（27B）、同一批 2,400 条公开决策逐项测量，并把每个量化效应表述为「超出这些噪声」的增量。
- 非量化噪声：0–0.92% 的决策会被翻动。llama.cpp 重启逐条 bit-identical；vLLM 重启在 BF16/FP8/NVFP4 上分别翻 0/5/20 条（Clef-flash）与 4/0/22 条（Clef）。BF16 下换引擎翻 6–16 条，改 batch size 翻 8–15 条，transformers 未经要求自选的 Gated DeltaNet kernel 翻 10–14 条。
- 量化本身：Q8_0 在 0.88%/1.04%、FP8 2.12%/1.62%、Q4_K_M 5.79%/3.50%、NVFP4 5.79%/5.67%（Clef-flash / Clef）。两个模型上，每个 4-bit 区间都排除了所有非量化来源。
- 反例与掩盖效应：五个预注册预测里两个失败——FP8 并不落在重启噪声内、换引擎翻动的决策数反而少于 8-bit 量化；27B 复跑同样这两个失败。准确率会把这一切盖住：Clef 的 Q4_K_M 净变化 6 题（−0.02 点，[−0.20, +0.16]），但 436 条决策实际变差；NVFP4 让 Clef-flash 掉 0.95 点、Clef 掉 0.65。
- 为什么值得看：量化评测的对照组必须锁到「同一实例、同一 batch、同一 kernel」，否则 4-bit 的效应会被噪声吞掉或放大。这是本站「量化与推理」最该抄的协议，也是今天方法学上最扎实的一篇。

## 七、专业领域

### 27. MedJev（10↑）

MedJev: A System One Vision-Language Decision Model for Fast and Effective Medical Image Understanding · [2611.20992](https://huggingface.co/papers/2611.20992) · The Chinese University of Hong Kong

- 问题：医学 VLM 靠自回归生成推理与答案 token，成本随回答长度线性涨，答案还要从自由文本里解析出来，延迟与决策错误都是自找的。
- 方法：System One 决策模型，一次多模态前向直接把图像、问题、候选答案映射成决策，完全不做自回归生成。为此去掉上层语言层与生成输出通路，但保留完整视觉通路与全部 visual token；decision head 用预训练的 query–key 匹配给候选打分，再用轻量 MLP 残差修正。
- 数字：基于 Qwen3.5-4B，在四个医学图像分类与 VQA benchmark 上准确率与速度都超过原模型——绝对准确率 +7.93%，端到端 6.04× 加速；与 20 个前沿模型相比，在 4B–9B 的通用与医学 VLM 里取得 SOTA 且推理最快。
- 为什么值得看：把「生成」换成「打分」是老思路，但同时拿到 +7.93% 与 6.04×，说明关键在 decision head 的设计（预训练匹配结构 + 任务特定的非线性判别），而不是简单砍层。

### 28. Glyph（2↑）

Glyph: An Interpretability Engine for AI-Driven Scientific Discovery in Clinical Data · [2611.08922](https://huggingface.co/papers/2611.08922) · Stanford MIMI Group · [代码](https://github.com/StanfordMIMI/Glyph)

- 问题：自动科学发现靠预定义表型抽取，而预定义的特征集本身就限定了能发现什么；用这些工具查人群数据的 agentic 系统继承了同样的限制。临床基础模型的 latent 里可能有未定义的新特征，但难解释。
- 方法：多阶段框架——用基础模型加 sparse autoencoder 从多模态非结构化临床数据里抽特征，解释成编码后的临床概念，再评估这些概念对科学发现的价值。
- 数据与结果：41,628 名患者、跨机构的腹部 CT、CT 报告与实验室测量；找到 397 个有预测力的概念，由 4,463 个 Bonferroni 显著关联支撑；多数关联能在不同站点的 held-out 队列里自动复现；这些概念与文献来源的标志物互补，并带来预测力增益。
- 为什么值得看：SAE 从「解释模型」走到「产出可检验的临床假设」，是可解释性少见的正向用途；4,463 个显著关联里多数可复现，这个比例比数字大小更有说服力。

### 29. CADMAGEDDON（2↑）

CADMAGEDDON: High-Fidelity CAD Reconstruction with Local Inference · [2611.22563](https://huggingface.co/papers/2611.22563) · [代码](https://github.com/kulibinai/cadmageddon)

- 问题：CAD 从业者手里的专有零件不愿传给外部服务；个人与小公司要本地化，又得用买得起的算力。
- 方法：开源 agent，从 mesh 重建可编辑 CAD，能跑在单 GPU 系统与当代笔记本上。它把复杂任务拆成一串「建什么、改什么」的简单视觉决策，几何工具负责精确构造，agent 只做视觉推理，并集成进 FreeCAD。
- 数字：用中等规模的 Qwen3.8-27B，在所有主要 benchmark 上重建质量超过先前方法，包括基于前沿模型的系统——摘要没给具体指标。
- 为什么值得看：本地 27B 打赢前沿模型系统，说明「工具承担数值精度、模型只做视觉判断」的分工比模型规模更重要。这条结论对专业 agent 普遍成立。

### 30. MillBill（2↑）

MillBill: A Machining Agent with Geometric Feedback · [2611.22565](https://huggingface.co/papers/2611.22565) · [代码](https://github.com/kulibinai/millbill)

- 问题：把 CAD 模型变成加工程序，既要工艺知识又要几何精度。让语言模型直接写几何与刀路代码，等于把数值执行也算进模型任务，误差无处兜底。
- 方法：把加工决策与几何执行/验证分开。给定 B-rep 零件、毛坯与材料，本地部署的中等规模开源模型提出工序与切削参数（三轴 indexed 加工）；几何 harness 生成刀路、模拟去料、把反馈送回用于改计划；setup planning 按刀具实际可达性规划，而不只看可见性。
- 评测：用模拟加工后目标表面积落在公差内的比例来评程序。Qwen3.8-27B 在这批加工任务上超过「自建几何与刀路工作流」的前沿模型方案——摘要没给具体比例。
- 为什么值得看：和 CADMAGEDDON 是同一套分工，两篇合看就是「专业 agent 该怎么切」的样本：模型做工艺判断，几何库做精确执行，harness 做验证闭环。

### 31. AuXSpec（1↑）

AuXSpec: Learning to Autoformalize Program Specifications via Executable Postconditions · [2611.21421](https://huggingface.co/papers/2611.21421) · ETH Zurich · [模型与数据](https://hf-mirror.com/collections/eth-algopt/auxspec) · [主页](https://auxspec.org)

- 问题：形式化规格定义程序的预期行为，是验证的基础，但在 Lean 这类定理证明器里写规格慢且吃专家，成为形式正确代码规模化的瓶颈。从自然语言自动形式化的难点在反馈：怎么廉价判断生成的规格有没有抓住意图。
- 方法：Lean 框架把声明式 postcondition 与可执行对应物配对——能靠类型类解析就自动生成，否则单独定义并证明等价；于是测试用例可以通过执行来评规格，一致率直接当 RL reward。
- 数据与数字：合成 3,037 个 LeetCode 问题，再用 Codeforces 上的 expert iteration 扩到 19.5K 样本。Qwen3.5-9B 与 Qwen3.8-27B 的 SpecGen pass@4 从 0.7%→82.7%、14.3%→84.3%，27B 超过所有前沿模型。
- 域外：在 Verina（原 prompt）上两个模型从 7.0%→90.5%、21.9%→90.5%；pass@1 为 73.7% / 84.5%，超过开源规格模型此前 SOTA VeriSpecGen-30B-A3B 的 47.6%；pass@4 90.5% 对比其 pass@10 的 63.9%。
- 为什么值得看：把「规格对不对」变成可执行测试，是把 RL 真正用到形式化上的关键一步。90.5% 这种跳跃说明此前缺的是 reward 信号，不是模型能力。

## 今天的三个观察

**一、国产算力这期交的是系统账，不是跑分**。前两名 236 票、占 40.3%，且都是 Ascend：Xing 4 给的是 285B / 8,192 张 910C 的预训练系统报告——拓扑感知混合切分、分布式优化器、CPU 亲和性与核隔离，都是「多卡跑得稳不稳」的账；AscendGYM 则把 kernel benchmark 从生成挪到优化已有实现，并用 STS 把 token 成本除进加速比。两篇合起来，说明 Ascend 生态的讨论重心已经从「能不能跑」进到「怎么把系统账算清」。对本站 kernel-opt 与通算并行两条线，这两篇是同一批工程问题的外部参照。

**二、harness 的胜负手是接口形式，不是 backbone**。ForceHarness 的两个设计——把力闭环下沉成 self-terminating primitive、把力流翻成带不确定度的物理量——分别解决了「模型来不及」和「模型读不懂」，于是同一个冻结模型从 3.3% 跳到 90.0%；消融还给了更普遍的结论：小模型拿到物理量比拿到原始力值决策更好。同一天的 SIM 记的是「上次为什么这么改」，VideoNexus 交换的是「带时间锚点的紧凑证据」，RepoFactory 优化的是环境的训练价值。这四篇的贡献都不在 backbone 上，而在接口上。

**三、「平均分」正在系统性地掩盖决策级差异**。Noise Floor 是今天最该读的一篇：非量化噪声翻动 0–0.92% 的决策，4-bit 量化翻动 3.5–5.8%，而准确率上 Q4_K_M 只动 6 题（−0.02 点）、却掩盖了 436 条变差的决策；Breath-Dx 说随机切分把 AUC 高估 0.05–0.12；VisualArtifactSpec 说配置间 73.4% 的差距来自产物表现而非功能满足；连 MedJev 的 +7.93% 也是「换成决策头」而不是「模型更懂医学」。这批论文的共同方法学是：先定义什么算一次决策、再把噪声和口径写清楚。分数越容易刷，口径就越值钱。
