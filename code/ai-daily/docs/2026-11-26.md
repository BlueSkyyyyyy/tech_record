## 一、具身智能：数据从视频、代码和失败里来

这一组 17 篇，共同点是**不再等人类遥操作演示**：从真实视频编出可跑的仿真、让 coding agent 写策略、把人类视频当上下文、把仿真里的失败当监督。评测也开始追问「过程是否合规」。

### 1. Real2SimLab（108↑）

[HF 论文页](https://huggingface.co/papers/2611.34849) · PKU-VaLuE-Lab · [代码](https://github.com/Real2SimHub/Real2SimLab)

- 问题：real2sim 指从真实观测造仿真，但每个基准自定义输入、交付物与评分，N 个方法评测在 M 个基准上要做 N×M 套集成，结果也不可比。
- 方法：统一平台只做一件事——运行方法写出的仿真程序，再用各基准**原来的 scorer** 打分；另提供造训练数据与 reward 的管线，先过滤掉基准里已有的录像避免污染，每条录像生成程序后用与评测同一份代码算 reward。
- 数字：已支持 47 个 coding agent、5 个非 agent 方法、6 个基准；配套 Awesome-Real2Sim 收录近 300 篇 real2sim 论文。
- 为什么值得看：它把「造数据」和「评数据」压到同一份 reward 代码上，是少见的基础设施型工作——基准不再是各自为战的排行榜。

### 2. PyRUA-Dex（44↑）

[HF 论文页](https://huggingface.co/papers/2611.33144) · DAGroup-PKU · [项目页](https://vme0522.github.io/PyRUA-Dex/)

- 问题：灵巧操作卡在演示数据：人类视频 retarget 不精确、遥操作没有力反馈、外骨骼采集难扩展。
- 方法：让 coding agent 写「程序化策略」，不要演示。探索期多个 agent 并行找任务技能与组合方式，蒸馏 agent 把成功尝试压成一个任务库加一个程序；精修期用随机布局提升鲁棒性与执行效率。
- 数字：Bench2Dex 得分 72.9（SOTA）；DexJoCo 全随机化成功率 81.0%，两个基准上都超过所有训练过的策略；真机双臂各 22-DoF 的手学一首钢琴曲最快 30 分钟。
- 为什么值得看：策略变成可读可改的程序后，数据瓶颈换成「环境 API 是否可编程」；30 分钟学新曲是这条路线目前最直观的账。

### 3. Entangle（26↑）

[HF 论文页](https://huggingface.co/papers/2611.28732) · [项目页](https://entangle-robotics.github.io/)

- 问题：用人类视频做机器人上下文学习有两个坎：任务级的人-机对在时间上对不齐；标准动作损失会让策略走「初始场景」或「任务身份」的捷径，而不是真的跟踪视频。
- 方法：一个 in-context world-action model，输入单个人类视频与当前机器人观测，输出未来视觉状态与可执行动作；用 video-to-video 把已有机器人视频转成匹配的人类上下文来扩数据；训练时组合变长视频窗与任务内对比目标，把配对轨迹与同任务的其他执行区分开。
- 数字：六个未见任务在 Astribot S1 上平均 83.5/100；RoboTwin 七个未见任务平均成功率 69.5%，超 Zero-WAM 22.6 个百分点；只在场景对齐的配对上训练，也能在重排布局、替换工具下迁移。
- 为什么值得看：它把「人类视频 ICL」的 scaling 归因到**时间对齐的数据量**，而不是模型规模——这条曲线此前没人干净地画出来。

### 4. HOG-WAM（22↑）

[HF 论文页](https://huggingface.co/papers/2611.34811) · intelligence++ · [代码](https://github.com/iPPLab/HOG-WAM)

- 问题：world-action model 同时预测未来观测与动作，视觉 corruption（噪声、遮挡、光照）会顺着共享表征直接破坏控制。
- 方法：加一路未来 HOG（方向梯度直方图）预测当结构监督，辅助 HOG DiT 通过非对称注意力读 RGB 特征，让这个目标反过来塑形控制用的视觉表征；模块只在训练时存在，推理删掉，保持原 FastWAM 的 RGB→动作路径。
- 数字：自建 RoboTwin-Plus 的四种受控 corruption 上全部最优；混合噪声成功率 78.86%→82.86%；LIBERO Plus 总成功率 74.49%→75.26%，传感器噪声 74.14%→78.89%；四个 Franka 真机任务干净观测 40%→59%、噪声下 17%→24%。
- 为什么值得看：零推理开销的鲁棒性补丁，而且真机绝对增益（+19 点）远大于仿真（+0.77 点）——这类「仿真涨一点、真机涨很多」的差距值得警惕也值得跟。

### 5. EgoUseBench（20↑）

[HF 论文页](https://huggingface.co/papers/2611.34466) · 浙江大学 · [代码](https://github.com/YurunChen/EgoUseBench)

- 问题：智能眼镜把 agent 的上下文从屏幕扩到物理周围，任务可以从用户正在做的事发起；但第一人称视角受佩戴者视野限制，证据不完整、有歧义，新观测还会改写意图。
- 方法：定义 Ego Use 范式，设三种上下文强度（纯指令的 Computer-Use、执行前给录像的 Offline、执行中持续给观测的 Online）；用 74 小时以上真实第一人称录像构造 693 个任务，并按信息变化分 Graft（需求改）、Refresh（新观测）、Clarify（agent 主动问）。
- 数字：Online Ego Use 的平均成功率比 Computer-Use 低 26.3%。
- 为什么值得看：26.3% 这个缺口说明「能看」不等于「会用」；把意图演化拆成三类，比笼统说「动态环境」更能定位失败。

### 6. DexEngine（19↑）

[HF 论文页](https://huggingface.co/papers/2611.33579) · POSTECH Computer Vision Lab · [代码](https://github.com/wongyun-yu/DexEngine)

- 问题：人类手-物演示 retarget 到机械手后，要装到整机上仍然运动学可行、物理可执行，还得规模化生产，现有 floating-hand 流程只保证「手像」。
- 方法：仿真管线分三步——把每个 clip 的手-物运动摆到手臂可达的位置，求一条跟随人类手的手臂轨迹，再用残差强化学习在物理仿真里校正穿模、滑落与不可达。
- 数字：九个人类手-物数据集，为四种灵巧手各生成约 5,200 个 clip，扩成 65,000 条轨迹（116 小时）与 325,000 个 episode（578 小时）；带手臂仍比 floating-hand 跟物更准，比 RL 类方法快 10 倍以上；用物理校正数据训的策略明显优于「不做校正」与「floating-hand 后再接手臂」，mid-training 同预算还能再涨。
- 为什么值得看：它把「retarget 质量」拆成可达性、接触物理、规模三个可分别验证的量，并证明物理校正不是可选后处理。

### 7. AIRIS（17↑）

[HF 论文页](https://huggingface.co/papers/2611.34347) · 腾讯 · [代码](https://github.com/AIRIS-bench/AIRIS)

- 问题：围绕人工作的具身 agent 不只要认出社交线索，还要判断「证据够不够、该不该介入、怎么回应才不违规」；现有基准要么孤立测这些能力，要么直接给完整视频，看不出在线决策错在哪。
- 方法：把社交具身智能写成时间锚定的 A-I-R-I 链（Attention、Intention、Reaction、Interaction），做因果流式基准：357 段第一人称 clip、11 类场景、36 个能力维度、8,000 个专家题；每次提问只给当时可见的前缀，指标奖励校准过的等待与完整反应、惩罚过早表态。
- 数字：评测 45 个专有与开源模型（通用、具身、流式视频、全模态），通用 VLM 擅长被动线索与意图识别，具身专家擅长孤立的反应子决策；但所有家族都常在证据出现前猜意图，且无法在同一 episode 内对齐介入时机、动作域与具体执行。
- 为什么值得看：它测的是「何时开口」而不是「说得对不对」——这与今天多篇 agent 停时决策的工作形成同一条线。

### 8. ROAM-Bench（13↑）

[HF 论文页](https://huggingface.co/papers/2611.33143) · 京东 · [代码](https://github.com/rxjfighting/ROAM-Bench)

- 问题：具身空间智能要求 agent 主动探索、拿到证据再行动，但现有基准只看最终状态，分不清「蒙对」和「按任务要求做到了」。
- 方法：250 个手工验证任务、11 种类型、27 个室内场景，在机器人运动与碰撞约束下，用仿真状态和 episode 记录做独立检查——结果之外还查几何、覆盖、放置等更强条件。
- 数字：人类在 100 个抽样任务上严格成功率 84%；七个前沿 VLM 暴露两类互补失败：结果正确但任务要求未满足，以及通过了更强检查但结果错误；oracle 输入诊断显示更完整的目标观测与校准反馈能改善空间判断。
- 为什么值得看：它把「过程合规」变成独立于答案的指标，这是具身评测里最少见、也最容易被刷分的地方。

### 9. WorldReforge（13↑）

[HF 论文页](https://huggingface.co/papers/2611.33925) · 浙江大学 · [项目页](https://aim-uofa.github.io/WorldReforge/)

- 问题：机器人训练数据几乎全是成功演示，world model 一离开 happy path 就崩：抓歪、时机错、物体被推倒或滑落时预测失效。五个预训练动作条件模型的对象运动误差最多只比「复制首帧」的静态基线低 10.4%，有两个还不如基线。
- 方法：构造 Reforge 数据集，62k 条仿真轨迹，按位置、朝向、闭合时机扰动参考抓取，记录每次 push/slip/failed pickup 与真值物体位姿、接触、表面点；转成两个训练信号——Interaction Alignment 把重建聚焦到小物体与接触区，Surface Correspondence 让骨干特征跨帧跟踪同一物理表面点。
- 数字：Cosmos3 Nano 上对象轨迹误差整体降 28.2%、未见物体降 35.0%，两动作结果分歧的预测误差降 43.3%；只在仿真训练，DROID 与真实失败视频上也改善。
- 为什么值得看：失败数据不是「加噪声」，而是教互补的物理——失败接触教物体怎么响应，成功握持教抓取状态怎么保持；两者缺一不可。

### 10. SEEK（11↑）

[HF 论文页](https://huggingface.co/papers/2611.33915) · 南洋理工大学 · [项目页](https://zeyangguan.github.io/SEEK-Agentic-Robot-Manipulation/)

- 问题：通用机器人基础模型只在工作上下文里保留执行知识，任务一结束就忘；下次做同一件事仍要花同样时间、犯同样错误。而直接重放旧动作也不行，效果依赖当前场景。
- 方法：自进化程序化策略（SEPP）把操作写成可执行过程、按当前观测决定每一步；执行时把动作的实测效果（包括失败）记进持久 Action-Effect Bank（PAEB）；过程覆盖到的条件直接执行、不问模型，覆盖不到时用这些效果证据改写。
- 数字：RoboDojo 上十次尝试把平均分从 27.0 提到 54.4、成功率 19.7%→48.0%（全部 42 个任务）；其中 34 个任务用 GPT-6.2 Astra 五次达到 80.1，同模型直接执行是 49.6，模型请求少 77.6%。
- 为什么值得看：不更新权重也能跨尝试变强，关键配方是「程序 + 效果账本」——程序保证可复用，账本保证能改对。

### 11. iMFPO（10↑）

[HF 论文页](https://huggingface.co/papers/2611.33922) · 北京大学 · [代码](https://github.com/AIGeeksGroup/iMFPO)

- 问题：flow 策略想一步出动作，但在线 RL 中动作分布一直在变，瞬时速度学习与区间平均生成之间出现不一致，少步生成的精度掉。
- 方法：一个共享的 interval-conditioned actor 同时承载瞬时速度监督与区间平均动作生成；用 JVP 校正的速度回归与 reward 目标联合优化，训练时由冻结的 PPO 教师给动作级引导；推理直接输出区间平均速度，不做迭代积分。
- 数字：Go2、G1、H1、Spot 四个平台零 latent 平均回报 35.69 / 34.44 / 416.23 / 29.86；Go2 上动作生成延迟从 15.57 ms 降到 0.41 ms（对比 64 步 RFPO）。
- 为什么值得看：约 38 倍的延迟下降把生成式策略真正拉进实时控制区间，路线是「训练时多算、推理时少算」。

### 12. RoboEvo^2（9↑）

[HF 论文页](https://huggingface.co/papers/2611.34675) · [代码](https://github.com/kaiknower/RoboEvo2)

- 问题：VLA 策略执行高效但要新演示才能适应陌生环境；推理 agent 能用先验知识探索，却要反复 deliberation 与 repair，成本高。
- 方法：harness 与 policy 互相进化。Policy-to-Harness：策略失败驱动 coding agent 在 Code、Code+ICL、Code+Policy 三条路搜索，验证过的解沉淀为技能、路由策略与经验记忆；Harness-to-Policy：验证过的轨迹做监督，反事实偏好蒸馏（CPD）让策略在同一初始状态下偏好成功修正而非失败。
- 数字：LIBERO-PRO 上单独策略成功率 11.0%→84.1%、hybrid 30.4%→90.5%；RoboTwin C2R 类似增益且 agent 成本下降；Unitree G1-D 上 hybrid 95.0%，并展示跨本体 harness 迁移。
- 为什么值得看：把「agent 探索」与「策略执行」接成闭环，且全程不加人类演示——这是具身自进化目前最完整的循环。

### 13. DemoFoundry（2↑）

[HF 论文页](https://huggingface.co/papers/2611.34671) · [代码](https://github.com/RobbinW/DemoFoundry)

- 问题：机器人演示要同时有真实视觉与可靠动作监督：仿真合成有视觉 gap，纯视频生成物理不一致、还给不出对齐的动作标签。
- 方法：coding agent 从已有机器人 episode 构造对齐的 real-proxy 视频对来训渲染器，并针对新任务写可执行交互程序；程序在物理仿真里跑出带状态与动作的 proxy 视频，渲染器再把外观换成照片级、保持场景一致。
- 数字：摘要未给量化指标；作者称视觉质量与动作-视频一致性提升，生成数据训的策略优于纯仿真、接近等量真实演示。
- 为什么值得看：把「生成」拆成物理正确的仿真加只负责外观的渲染，比端到端视频生成更可控——代价是每个场景仍要写程序。

### 14. CARE-3D（1↑）

[HF 论文页](https://huggingface.co/papers/2611.29969) · 昆士兰大学 · [代码](https://github.com/xiaoqian-UQ/CARE-3D)

- 问题：3D 场景里的具身推理 agent 多从监督轨迹学「按固定套路找证据」，优化的是模仿得像，而不是「返回的证据是否支撑答案」；只看结果奖励，又给不了中间工具选择足够的信用。

### 15. SimPWM（1↑）

[HF 论文页](https://huggingface.co/papers/2611.32786) · MBZUAI-IFM · [代码](https://github.com/TingtingLiao/SimPWM)

- 问题：机器人视频世界模型越来越多以仿真或渲染 proxy 为条件，默认「视频会照着 proxy 演」，但没人验证这个假设。
- 方法：给定标定相机，从首帧就用机器人 3D 模型与抓手可触物体的 3D 点建立显式状态；一个无训练参数的规则模拟器按动作移动它们，视频模型只负责渲染，同时返回视频与仿真状态。检验手段是冻结仿真物体、只让机械臂按录像动，看视频还会不会「抬起」物体。

- 为什么值得看：它给「视频模型到底有没有用仿真状态」提供了可证伪的反事实实验，而且顺带暴露不同基座对同一扰动的敏感度差异巨大。

### 16. SOLVE（0↑）

[HF 论文页](https://huggingface.co/papers/2611.34750) · NVIDIA · [项目页](https://serenos.github.io/solve-website/)

### 17. Look Back（0↑）

- 数字：摘要未给具体数值；理论加实验显示，当环境演化比动作效应更难预测时，反事实模型更好学、策略也更好。

### 18. Sage-Med（89↑）

[HF 论文页](https://huggingface.co/papers/2611.34575) · 上海 AI Lab · [代码](https://github.com/Sage-Med/Sage-Med-Preview)

- 问题：医学 MLLM 的 scaling law 一直没立起来。作者的系统评测发现：现有医学 MLLM 普遍打不过前沿通用 MLLM；单纯加参数主要涨文本能力、不涨多模态感知；开推理模式也补不上视觉差距。
- 方法：Sage-Med-Preview，35B 总参 / 3B 激活的 MoE 医学多模态模型；从 322.7M 条候选记录做分阶段数据策展，课程依次是医学预训练、分阶段 SFT、自适应 RL，每一段都验证到稳定增益再进下一段。
- 数字：覆盖 40 多种模态、61 个公开 + 13 个多中心私有基准、238 个临床任务，对比 77 个模型；31 个公开多模态基准均分 58.26%，超过开源 SOTA Hulu-Med-235B-A22B 的 50.99% 与科学模型 Intern-S2-Preview 的 52.24%，在综合理解、报告生成、视觉 grounding 上接近 GPT-6.2-Sol。
- 为什么值得看：3B 激活打赢 235B 总参的专用模型，说明医学多模态的瓶颈更可能在数据课程而非参数量；作者也明说复杂临床推理与多步工作流仍是短板。

### 19. Mixture-of-Loops Transformer（68↑）

[HF 论文页](https://huggingface.co/papers/2611.34923) · ByteDance Seed · [代码](https://github.com/hustvl/MoLT)

- 问题：looped Transformer 复用共享层换表达能力，但相邻 loop 之间到底传什么，决定了表达与效率的边界；全量重跑又太贵。
- 方法：MoLT 用注意力里的 K/V 当跨深度、跨 loop 的记忆。MoLT-R 保留残差流、读局部 KV；MoLT-KV 从 embedding 重启、读当前 loop 的局部 KV 加前面 loop 的记忆 KV，消掉同位置跨 loop 依赖，配合 loop forcing 并行训练，可在训练 loop 数之外做单遍历解码。U-MoLT 再把记忆构建与预测读出分开，跳过无用的 decoder 遍历而不改预测。
- 数字：400B token 预训练，700M/1.5B dense 与 3B MoE 全面超 OLMo3；700M 上验证 CE 的 token 效率 1.7×，3B MoE 十域困惑度改善 0.75、十任务准确率 +2.1 点；Qwen3.5-0.8B-Base 续训 100B token，11 个域 CE 全降、平均 1.4× token 效率；S 尺寸（约 113M）上 MoL-Hybrid-2 延迟 996.6 ms 对 OLMo3 的 1,000.6 ms。
- 为什么值得看：它没有靠加层数换表达，而是把「循环几次」变成可训练、可跳过的计算预算——这是 looped 架构第一次在同等延迟下给出全面增益。

### 20. DyLoMo-DiT（57↑）

[HF 论文页](https://huggingface.co/papers/2611.30844) · [代码](https://github.com/OneBoxCream/DyLoMo-DiT)

- 问题：DiT 加容量要么加参数、要么加算力；MoE 变体省了每 token 计算，却仍要存大量参数。
- 方法：不添参数、复用参数——权重共享的 loop 反复跑中间层，稀疏专家按 token 分配容量；网络变深而参数不变，省下的预算可以加专家或加独立层；同时按噪声级动态分配 pass 数，低噪声步多跑几遍。
- 数字：ImageNet 256×256 上，匹配参数与算力预算时 FID 比 DiT 降 11–24%、比 DiT-MoE 降 36–56%；文生图版本 GenEval 0.714 超过 FLUX.1 的 0.673，激活参数 1.05B 对 12B。
- 为什么值得看：扩散模型的「深度」第一次变成可复用的免费资源；低噪声多算、高噪声少算的分配也符合去噪的误差结构。

### 21. Integral（27↑）

[HF 论文页](https://huggingface.co/papers/2611.31237) · KAIST AI · [代码](https://github.com/the-jb/integral)

- 问题：统一多模态模型想把理解与生成放进一个模型，但两边的视觉表征是异质的；直接接一个生成头，预训练 VLM 的知识用不上。
- 方法：把预训练 VLM 改造成统一模型，核心是**共享视觉表示空间**。Abstraction Fusion 聚合冻结视觉编码器的层级特征成共享 visual token；Block-wise MoT 加一条轻量生成流，只在 block 边界与 VLM 交互，从而保住理解能力。
- 数字：受控比较显示，在重建保真度相近时，共享表征的生成学习明显优于独立表征空间；改造后理解能力保持，生成显著增强。
- 为什么值得看：它把「统一模型」的胜负手定位在表征而不在参数量或数据量，而且给出了可复现的受控对照。

### 22. DocSEAM（27↑）

[HF 论文页](https://huggingface.co/papers/2611.34420) · MMLab@NTU · [代码](https://github.com/mossbee/DocSEAM)

- 问题：多页文档 VLM 逐页独立编码，页边界出现特征断层：视觉 token 形成时看不到邻页，语言模型只能在这些「孤立页表示」上推理。
- 方法：在预训练视觉编码器与语言模型之间插一个轻量模块。每页与左右邻页组成 triplet，做中心锚定的掩码自注意力，配方向显著性门控融合邻页信息，只返回增强后的中心页 token，visual token 数不变；先跨页 warm-up，再多页微调时冻结该模块。
- 数字：9B 模型在五个多页文档 VQA 基准上，是 10B 以内开放权重模型中的 SOTA；受控重排版实验显示对页边界位置更不敏感，跨页 span 定位更好。
- 为什么值得看：不增 token、不改主干就补上跨页上下文，工程上几乎可以即插即用。

### 23. HiGLR（15↑）

[HF 论文页](https://huggingface.co/papers/2611.33636) · 首尔市立大学 · [代码](https://github.com/dslisleedh/HiGLR)

- 问题：all-in-one 图像复原的多尺度架构要在高分辨率阶段处理大特征图，算力与显存带宽都吃不消，但直接砍掉又掉细节。
- 方法：先分析自注意力与 ConvFFN 的空间冗余，定位三处：最细尺度的 per-query 读出、中间尺度相邻 query 的 key 路由、ConvFFN 扩展空间里的空间混合。对应改成——最细尺度用输入无关的学习核，中间尺度用 Block-Routed Hybrid Attention（粗尺度稠密 + 细尺度对 value 残差的块稀疏，路由索引在相邻 query 间共享），FFN 拆成紧凑空间做空间混合、扩展空间做逐点非线性，便于 kernel 融合。
- 数字：SOTA 性能的同时，相对现有方法最高 4.24× 推理加速。
- 为什么值得看：三条冗余各自对应一种 kernel 融合机会，是「先测冗余再改结构」的典型，不是拍脑袋稀疏化。

### 24. PanBase（2↑）

[HF 论文页](https://huggingface.co/papers/2611.32002) · KAIST VIClab · [代码](https://github.com/KAIST-VICLab/PanBase)

- 问题：全色锐化网络普遍在 4× 插值的低分辨率多光谱图上加残差，全色图的高频细节只能通过残差间接进入——既然有清晰细节，为什么要从模糊底座起步。
- 方法：构造更锐利的起点 PanBase：按传感器物理特性融合全色空间细节与低分辨率多光谱的光谱信息，并在传感器特定模糊下强制与观测一致；不训练网络，每个波段只用闭式校准估 9 个系数。接入现有骨干只需换 skip 底座、再把它拼进输入。
- 数字：WorldView-3、QuickBird、GaoFen-2 上多数降分辨率与全分辨率指标提升，平均训练收敛快 4.4×；在 WorldView-2 做零样本，单独 PanBase 已具竞争力，不需目标传感器拟合。
- 为什么值得看：一个 9 系数、无训练的底座就能让整套骨干收敛快 4.4 倍，说明低层视觉里「起点选错」的成本一直被低估。

### 25. VibeVideoAgent（55↑）

[HF 论文页](https://huggingface.co/papers/2611.34237) · Kling-Keye · [代码](https://github.com/Kling-Keye/VibeVideoAgent)

- 问题：代码驱动视频生成让 agent 写渲染程序，排版、数据可视化、音画同步都能精确控制；但程序正常退出不代表画面正确——标签重叠、镜头对空、物体穿插、旁白漂移都不会抛异常。把帧和音频塞回编码会话会撑爆长上下文，只看最终成片又把早期设计错误拖成昂贵重写。
- 方法：免训练框架，让编码 agent 在生产过程中检查草稿。多模态感知跑在独立短上下文里，只回传紧凑、有依据的 Findings；7 个原语在统一多时钟表示上粗到细查素材、按模态核验需求、分时钟对比草稿与参考、局部测流信号；一个分阶段协议让 agent 先在最小预览上试最高风险的决定。
- 数字：239 个 VibeVideoBench 任务、匹配 agent runtime 与固定感知模型，Claude Opus 5.5 的整体音画质量 L3 从 4.03 升到 4.43（L2 rubric 合规 98.87%→99.35%），GPT-6 Astra 4.03→4.27，Claude Sonnet 5.5 3.97→4.10；音画同步单项最高 +0.56；轨迹审计显示代码编辑粒度决定「合规」与「观感」的取舍。
- 为什么值得看：它把「生成质量」拆成可被程序检查的中间量，且不训练模型——这是目前最像「给生成器配一个 QA 工程师」的做法。

### 26. I2VT（44↑）

[HF 论文页](https://huggingface.co/papers/2611.34941) · CMU · [代码](https://github.com/HorizonWind2004/i2v-transfer)

- 问题：图像编辑模型能跟很宽的指令，视频编辑器却落后，部分原因是配对的原视频-编辑后视频极难收集。
- 方法：Image-to-Video Transfer——不拍新视频、不改架构，让视频编辑器扮演图像编辑器：把一张图当成一帧视频来编辑，每个去噪步由图像编辑器指导视频编辑器的预测；训练只见单图，测试时把能力用到整段视频并保持时序一致。另扩 OpenVE++，新增动作改变、表情改变、肢体动作、场景重打光四类任务。
- 数字：三种不同视频编辑器上，原有编辑能力提升且扩到新任务；在 OpenVE-Bench 与 OpenVE++ 上都达到 SOTA。
- 为什么值得看：它把「视频编辑数据稀缺」转成「图像编辑能力迁移」，绕开了最贵的一环；代价是训练分布里没有真实运动，时序一致性只能靠测试时继承。

### 27. PixelMatte（19↑）

[HF 论文页](https://huggingface.co/papers/2611.34929) · [代码](https://github.com/White-YC/pixelmatte)

- 问题：图像抠图要高频精度，但现有扩散方法多在潜空间做，VAE 的压缩与重建和发丝级边界天然冲突。
- 方法：把预训练**像素空间** DiT 改造成抠图模型，复用骨干原生 patch embedding，把输入图、trimap、带噪 alpha 拼成空间对齐的 token，直接像素级预测，不加条件编码器或 adapter；只用文本到图像的预训练，不需要配对图到图预训练；再加 LayerShift 与 High-Pass Refiner 两个轻量校准模块，单次前向出 alpha。
- 数字：四个基准、两种像素扩散骨干，P3M-500-NP 与 AM-2K 上相对 RenderMatte 把 SAD 与梯度误差降 24–44%；AIM-500 与 RenderMatte-2K 上持平或更好。
- 为什么值得看：它证明「像素空间生成先验」在精度敏感任务上确实优于潜空间，而不是只在小图上好看。

### 28. Agentic LongLive（18↑）

[HF 论文页](https://huggingface.co/papers/2611.34907) · NVIDIA · [代码](https://github.com/NVlabs/LongLive)

- 问题：实时自回归视频生成能流式播几分钟、随时换 prompt，但长故事里人物、物体、地点的一致性守不住；离线多镜头 agent 会先读完整剧本、逐镜头规划、失败重生成，直播流等不起。
- 方法：异步 agentic memory。记忆 agent 在独立 GPU 上只读已经揭示的 prompt、不看生成视频，为每个实体维护文本状态与演化图像；据此合成全局图与单镜头记忆图，由辅助 GPU 预填进生成器的 attention sink；同时给点名实体的 prompt 写 entity card。视频不等记忆，视频错误也不回写。一个用 RL 训练的小语言模型（图像 reward 用下游视频结果校准）在下一个 prompt 未知时就决定记什么。
- 数字：新基准 LongStory-Online（25 个故事、857 个镜头，逐镜头揭示）上，持久状态准确率比基座 LongLive-2.0 高 26.3 点、主角身份高 44.9 点、重访地点一致性高 40.4 点，H100 上只多约 1% 生成时间；单台 8×B200、生成器 BF16 下 34.3 FPS 快于实时，14 分钟故事画质稳定；换两个 MiniMax-H3 生成器身份一致性也提升，其中 LongLive-H3 也能实时跑。
- 为什么值得看：把「记忆」放到生成器之外、且允许它滞后，是流式长视频能同时保实时与一致性的关键取舍。

### 29. SlidesWeaver（10↑）

[HF 论文页](https://huggingface.co/papers/2611.28010) · 香港科技大学

- 问题：生成 PPTX 同时要语义规划、视觉构图、精确排版与可编辑性：程序化方法可编辑但设计僵，图像方法好看但内容被拍平成难改的像素。
- 方法：混合多 agent 系统，语言与视觉 agent 通过共享的 deck/slide 两级状态协作；用分阶段多模态承诺、基于扩散的构图规划，以及两套生成日程分别偏向构图自由与文字保真，同时保留原生文本与几何。
- 数字：24 种系统-模型配置、1,728 次生成，在评测的每个维度上整体质量都更优，同时保持结构控制、可编辑性与实用生成效率。
- 为什么值得看：它没有在「可编辑 vs 好看」里二选一，而是把两者拆给不同 agent、用共享状态对齐——这是 agent 系统里少见的结构化协作。

### 30. Loupe（8↑）

[HF 论文页](https://huggingface.co/papers/2611.31895) · 北京大学 · [项目页](https://zengkaiya.github.io/Loupe/)

- 问题：知识密集型视频生成的 prompt 常缺事实、外观与时序关系；搜索工作流能补证据，但手写策略不会自适应规划，常规训练又被视频级反馈的高成本与轨迹级信用太粗卡住。
- 方法：视频生成 agent 检索并核验文本与视觉证据，构造有证据支撑的时序 prompt 与参考图；提出 Rubric-Based Credit（RBC），用 prompt 专属的事实、视觉、时序要求，在渲染前评估中间搜索与规划步骤；RBC-SFT 按步骤质量重加权 assistant token，RBC-GRPO 把步骤信用与最终规划奖励结合，RL 阶段完全不渲染视频。
- 数字：新基准 Search-VBench 150 个留出 prompt、7 类；三个视频生成器四个维度全涨，MiniMax-H3 总分 32.80→70.67，超过未训练的搜索工作流；完整 RBC 训练比「标准 SFT + 轨迹级 GRPO」高 5.27 点。
- 为什么值得看：把视频生成的 RL 成本从「渲染一次算一次」降到「评规划不渲染」，这是让 agentic 视频生成可训练的关键工程点。

### 31. LiveVAE（3↑）

[HF 论文页](https://huggingface.co/papers/2611.34912) · [代码](https://github.com/MeiGen-AI/LiveVAE)

- 问题：视频扩散越来越快、越来越可流式，但 VAE 仍是交互生成与编辑的主要延迟瓶颈；现有加速多靠重卷积或全帧注意力，且大多只优化解码，编码在流式条件生成里照样贵。
- 方法：先测预训练视频 VAE 的有效感受野，发现编解码一个 patch 几乎只依赖时空邻域；于是用因果窗口注意力做流式编解码，把每帧计算压下来、时序 KV 缓存保持有界；先解耦蒸馏编码器/解码器再联合微调，保住原 latent 空间，可直接替换原 VAE。
- 数字：MiniMax-H3 上编码快 5.2–6.2×、解码快 3.0–3.3×，PSNR 还更高；配上专用推理设施总加速到 13.4×，画质几乎无损。
- 为什么值得看：「全局时空建模并非必需」这个结论比加速比更有价值，它给流式 VAE 的设计定了局部性前提。

### 32. SIA（2↑）

[HF 论文页](https://huggingface.co/papers/2611.33894) · 西蒙菲莎大学 · [代码](https://github.com/alimohammadiamirhossein/selective-image-analogy)

- 问题：图像类比把 (A, A') 的变换迁到新图 B，但默认所有变化都该迁；用户常只想应用其中一部分编辑。
- 方法：提出 Selective Image Analogy 设定：一对示范里含多个编辑，推理时由用户选哪些应用到 B。构造带全编辑/部分编辑目标的数据集；模型先学迁移完整变换，再用 mask 对齐抑制获得选择控制——token 门控 LoRA 在去噪时只让被抑制的编辑 token 不更新，配合概念抑制向量在去噪前削弱选中 token 的文本嵌入。
- 数字：摘要未给量化数字；作者给出定量、定性与用户研究，称能压掉不需要的编辑、保留所选，且不必为每种组合重拍示范对。
- 为什么值得看：把「编辑选择」做成推理时的可控维度，而不是给每个组合训一个模型——这是编辑模型产品化必须迈的一步。

### 33. SPARC（1↑）

[HF 论文页](https://huggingface.co/papers/2611.34064) · 腾讯 · [代码](https://github.com/zju3dv/SPARC)

- 问题：长时相机控制视频生成要同时满足相机轨迹与场景记忆，现有方法常另加控制/记忆模块，注意力随历史长度爆炸。
- 方法：把预训练视频 DiT 的原生自注意力改造成统一机制——注意力连通性既当几何条件、又当地址做历史检索。已观测 token 只连几何对应的历史 token 与局部时空邻域，未观测区域保留稠密注意力；再用对应关系偏置与顺序无关的历史定位，跨长间隔稳定检索。
- 数字：不加可学习控制/记忆模块，相机贴合与重访一致性提升，注意力计算大幅下降；配合四步蒸馏推理加速超过 50×。
- 为什么值得看：它把「控制」和「记忆」都归约成注意力剪枝的副产品，是结构上最省的一支——1 票说明选题偏工程，但思路值钱。

## 四、3D 与世界模型：几何要显式，状态要持久

这一组 7 篇，两个共同诉求：**几何从稀疏点云变成连续曲面**，以及**相机转走再转回来时，世界还在原地演化**。

### 34. FoundSurface（17↑）

[HF 论文页](https://huggingface.co/papers/2611.34128) · 香港理工大学 · [代码](https://github.com/vLAR-group/FoundSurface)

- 问题：无位姿图像做 3D 表面重建，前馈 pointmap 方法免了相机位姿，却只能给出离散稀疏点，拿不到连续高保真曲面。
- 方法：把 pointmap 与 ray 表示接起来。先用预训练 pointmap 模型取显式几何先验；query 视角为中心的选择模块用稳健 surfel 投票挑几何相关参考视角；cross-attention 回归器把目标 query ray 与参考特征连起来，估连续粗曲面；最后 raylet 模块聚合局部 3D 特征，刻出高频细节与解析法线。
- 数字：9 个数据集训一个统一基础模型，6 个未见数据集零样本泛化，几何精度与细节保持明显超 SOTA。
- 为什么值得看：它证明 pointmap 不必停在点云——把「点」升级成「射线上的连续曲面」是更省的路径，比重新训一个 3D 生成模型务实。

### 35. Target-Part（16↑）

[HF 论文页](https://huggingface.co/papers/2611.30472) · [项目页](https://zishanqin.github.io/partdpo/)

- 问题：部件感知 3D 生成既要整体合理，也要部件完整、彼此分开；高质量部件标注太少，撑不起大规模 SFT。
- 方法：用 DPO 在少量部件标注上适配预训练生成器，不改架构。按几何指标对同 prompt 不同随机种子的候选排序，挑「跨种子质量差最大」的 (物体, 目标部件) 样本；每个样本存一对共享同一干净 GT 组合 latent、只在高斯噪声上不同的种子轨迹；从 FlowDPO 推一个 reference-relative 的目标块偏好损失，同时用目标块与完整部件集的 GT flow-matching 损失做绝对监督，只更新 DiT。另用人排控制与合成裁剪构造受控 loser。
- 数字：三档训练集规模里中等档最好，在留出 Objaverse 与多部件聚合上超过预训练生成器与直接 SFT 基线；跨数据集分布偏移下增益不稳定。
- 为什么值得看：把偏好学习用在「同一 latent、不同噪声」的受控对上，比人排偏好便宜且噪声可控；作者也诚实报告了跨域退化。

### 36. WorldBridge（4↑）

[HF 论文页](https://huggingface.co/papers/2611.34079) · 新加坡国立大学 · [项目页](https://davidyan2001.github.io/WorldBridge/)

- 问题：从几乎不重叠的散图生成连贯可探索 3D 世界：几何方法接不上，图像/视频方法能编未见区域但跨视角几何不一致。
- 方法：把散参考编码成全局场景上下文，指导各视角的几何与外观生成；时序/空间参考注意力分别增强目标轨迹上的时序参考与轨迹外的空间参考；一个即插即用的 latent-reference 一致性策略，用重投影引导的测试时优化提参考保真度；同时提出评测散图低重叠设定的 WorldBridge benchmark。
- 数字：定性定量都超现有 SOTA，作者称首次系统处理「散图、低重叠」的 3D 世界生成。
- 为什么值得看：它把评测缺口一并补了——低重叠散图是真实采集最常见的形态，之前的基准都回避了。

### 37. OmniPersist（2↑）

[HF 论文页](https://huggingface.co/papers/2611.32473) · 新加坡管理大学 · [代码](https://github.com/cszhilu1998/OmniPersist)

- 问题：动作条件世界模型要维持动态物体的持久性，但透视视频的视野有界：相机转开再转回，出画的运动实体常在潜空间里变异或消失。
- 方法：单阶段扩散模型里耦合透视视频生成与全景演化，不靠辅助模型、也不需要初始全景输入；全景流用更低帧率跑以控成本，GeoAnch 做空间对应、TemComp 做时间聚合；对相机控制架构不敏感，latent 级与 attention 级条件都支持。
- 数字：新构造的动态基准上，图生视频与视频续写任务的视觉质量、相机可控、重访一致性、动态持久性一致提升。
- 为什么值得看：用全景当「出画区域的记忆」，比外挂 3D 缓存更贴视频模型的接口；低帧率全景流是聪明的成本取舍。

### 38. 3D CoCa v3（2↑）

[HF 论文页](https://huggingface.co/papers/2611.33835) · 北京大学 · [代码](https://github.com/AIGeeksGroup/3DCoCav3)

- 问题：大规模 3D 城市场景要同时抓多尺度几何结构与复杂空间关系，现有 3D 视觉-语言方法偏全局语义对齐或物体级表示，结构化关系建模不足。
- 方法：场景图增强的对比+生成框架：金字塔视觉编码器学多尺度几何；语言模型解码器加问题引导的 caption 检索与视觉 cross-attention；引入 MSG 关系描述，把结构化空间关系加进 3D-语言对比对齐；另建 City3D-9.6K 多视角城市视觉-语言数据集，含对齐的视觉几何、场景 caption 与场景图。
- 数字：City-3DQA 句级/城市级 split 总体 top-1 88.35% / 64.79%，比 3D CoCa v2 高 20.88 / 3.57 点；GeoEval3D 上最佳。
- 为什么值得看：20.88 点的句级提升主要来自关系监督而不是更大模型，说明城市 3D 理解的瓶颈在「关系怎么标」。

### 39. MEMO（1↑）

[HF 论文页](https://huggingface.co/papers/2611.34939) · [代码](https://github.com/royorel/MEMO)

- 问题：动态高斯泼溅要么只建外观、要么只做前景 mask 的孤立物体；网格都靠 TSDF 融合或 Poisson 重建，固定网格限制了细节，也给不出每帧网格。
- 方法：给每个高斯一个受高斯过程启发的运动模型，把位置与旋转随时间写成一组时间高斯核的组合，使每个高斯在整个序列里始终是合法面元，并隐含动态几何，任意时刻都能从高斯定义的场里提网格；针对大而快的运动，用基于点轨迹的闭式初始化拟合每个高斯的初始轨迹。
- 数字：新建 Blender-Moments（9 个动画场景、每帧有 GT 网格）与两个真实数据集，几何精度最优，新视角合成与训练时间仍有竞争力。
- 为什么值得看：把「每帧网格」变成高斯场的直接读出，而不是后处理融合——这是 4D 重建里表示与交付物第一次对齐。

### 40. GOLD-SLAM（1↑）

[HF 论文页](https://huggingface.co/papers/2611.32335) · InSAI Lab · [代码](https://github.com/InSAI-Lab/GOLD-SLAM)

- 问题：全景相机一帧覆盖近整个球面，但 LiDAR 的视场对不上，靠 LiDAR 深度先验的全景高斯泼溅 SLAM 在无 LiDAR 覆盖区会崩。
- 方法：在球面域做跟踪与建图，用 LiDAR 覆盖区外的跟踪视觉特征改位姿；针对新观测表面覆盖不足与增量建图的漂浮伪影，提出 Depth-Aware Map Extension and Pruning（DAEP）；另采 WHOLE 数据集（UAV 平台，弱几何/高动态/全向/低光/简单五类场景）。
- 数字：相对现有全景基线，平均 PSNR 提升 5.56–9.10 dB，平均 Depth-L1 降低 71.9–83.9%；在 Jetson Orin NX（16 GB）上验证嵌入式在线运行，代价是重建质量。
- 为什么值得看：它把「传感器视场不匹配」当核心问题而不是噪声，DAEP 与 WHOLE 都是为这个不匹配设计的。

## 五、Agent 与自进化：从「能跑」到「知道自己该改什么」

这一组 14 篇，最集中的问题是**信用分配**：失败轨迹里哪一步该改、哪个候选该留、哪段上下文该压。答案普遍不是「换个更强的模型」，而是「换个更细的信号」。

### 41. Play2Evolve（20↑）

[HF 论文页](https://huggingface.co/papers/2611.33457) · Show Lab · [代码](https://github.com/showlab/Play2Evolve)

- 问题：coding agent 能从一句话生成可运行的游戏，但「能跑」不等于「好玩」：核心功能可靠、视觉吸引、玩法有探索与进度，这三件事 agent 都不会自己评。
- 方法：递归游戏开发框架，Initialization → Refinement → Evolution 三阶段；agent 以「可玩性」为反馈亲自试玩，诊断功能、视觉、玩法问题，反馈既驱动修 bug 与补素材，也驱动提出新玩法与美术目标；用视频生成模型加代码产出静态/动态素材并接进交互。
- 数字：GameCraft-Bench 得分 60.05，初始化后为 50.81，Play2Code 为 52.46；人类整体质量评分 3.67，对比 2.38 与 2.43。
- 为什么值得看：把「试玩」变成 agent 的评测回路，而不是等人来玩——这与今天视频生成那篇 VibeVideoAgent 是同一个套路在不同介质上的复现。

### 42. TT-RSI（15↑）

[HF 论文页](https://huggingface.co/papers/2611.30965) · 上海 AI Lab · [代码](https://github.com/uanu2002/TT-RSI)

- 问题：无标签问题上的测试时自改进主要靠 self-consistency：独立采样再多数投票；早先的推理在推理时被丢掉，训练时还可能把错误的多数固化成目标。
- 方法：两条互补路径。In-Context RSI 把上一轮完整解法当参考重解同一题，由模型自己决定用不用、怎么用，让推理算力建立在已有推理上；In-Weight RSI 把逐轮改进蒸馏进权重，理论上把第一次尝试推向模型的无限步改进极限，从而跳出「初始多数错误」的陷阱。
- 数字：平均准确率比基座 +13.89%，在相同测试时算力预算下比最强 self-consistency 方法高 +4.79%。
- 为什么值得看：它把「测试时」与「进权重」接成一个正循环，且给出「第一次尝试 → 无限步极限」的理论刻画，不只是工程 trick。

### 43. OOA（9↑）

[HF 论文页](https://huggingface.co/papers/2611.34147) · NVIDIA · [代码](https://github.com/nvidia-nemo/labs-OO-Agents)

- 问题：现在 agent harness 替模型管上下文：窗口满了就触发 compaction 摘要历史。另一种做法是模型自己通过 context API 决定何时压、压什么，但两种策略没被系统比较。
- 方法：在 NVIDIA 开源 harness nooa 里把上下文控制权交给模型，在文档研究与 ML 工程两类任务、8K–512K 的上下文预算上对比；并测推理引擎能否让模型驱动的编辑更便宜——编辑后复用未变后缀的 KV cache。
- 数字：会用 context API 的模型准确率更高、输入 token 常更少，紧预算下尤其明显：GPT 6.1 在 32K 预算的 OfficeQA Pro v2 上从 21% 到 56%（接近三倍）；Kimi 最多省 41% 输入 token；复用后缀 KV 让每请求 prefill 计算最多降 15%，准确率无可测变化。
- 为什么值得看：它把「上下文管理」从 harness 工程问题变成模型能力问题，并指出配套的推理引擎 KV 编辑是必要条件。

### 44. MLEvolver（5↑）

[HF 论文页](https://huggingface.co/papers/2611.28244) · 香港科技大学

- 问题：autoresearch agent 的 harness 堆了很多机制，但没人拆清每个组件各贡献多少；上下文管理与技能管理尤其混在一起。
- 方法：在统一 agent 框架里，以「最近性截断」为基线，沿两条轴做受控消融：上下文管理（保留什么）与技能管理（怎么存、怎么复用经验）；覆盖 MLE-Bench 与 KernelBench，三个模型 gpt-oss-120b、gpt-6-luna、gpt-6-sol。
- 数字：保留「可单独访问的历史尝试记录」优于滚动摘要，context folding 在六个设置里全部最好、比基线最高 +19.2%；技能侧「选择性删除长期没用的教训」平均优于合并或升格为常驻规则。组合成 MLEvolver 后，MLE-Bench Lite 奖牌率 72.7%、KernelBench Level 3 fast_1 94%，同推理预算下大幅超 AIDE 与 OpenEvolve。
- 为什么值得看：结论是反直觉的——加技能不如删技能，留摘要不如留原始记录；这类「负向维护」在 agent 工程里长期被忽略。

### 45. Speak When You See It（5↑）

[HF 论文页](https://huggingface.co/papers/2611.30895) · [代码](https://github.com/bhc6/speak-when-you-see-it)

- 问题：主动式任务助手每隔几秒就要判断步骤是否完成、有没有出错；但两个基准很大程度上在奖励「知道什么时候」而不是「看见什么」。
- 方法：先量化这个漏洞——一个从不看视频的计时器（25 秒报警、30 秒确认每步）在 Ego-MC-Bench 上错误 F1 0.373，超过所有已发表结果（最高 0.27）；把它形式化为 video-blind frontier，即仅凭经过时间、指令与训练统计能达到的最优权衡。再提出 Evidence-Contrastive Training：在基准自己的问题上微调，正例配同一录像、同一经过时间的负例，让时间无法区分一对样本。
- 数字：209 个 QICD 视频、约 15 GPU 小时训 2B 模型，四个种子在两个基准上都越过 frontier；不适配迁到 Ego-MC-Bench，及时确认无错步骤 59%，同骨干、用约 25k 合成反事实加真实录像训练的已发表模型是 30%；同一经过时间下区分完成/未完成 90–92%（指令典型时长只能到 65%），重标时间戳几乎不影响，换成另一段录像完成准确率掉三分之二。
- 为什么值得看：它先证明「榜单可能被时钟刷」，再用对照训练把视频证据逼出来——方法论比分数更值得抄。

### 46. ELITE（4↑）

[HF 论文页](https://huggingface.co/papers/2611.21056)

- 问题：自改进 coding agent 普遍「评估-选择」：用下游任务结果决定哪条 lineage 继续，评估成本随探索线性涨，还会过拟合固定评测分布。
- 方法：Explore-then-Integrate——每代提出多个聚焦改进、从同一父代独立实现，再检查程序找出互补、冗余、冲突的机制，把兼容子集重实现成一个连贯后代；进化回路里不用下游任务结果或轨迹，只做结构与可运行性的确定性检查。
- 数字：SWE-bench Pro 上初始 agent 60.0%→85.6%，对比 Darwin Godel Machine 86.7%、Huxley-Godel Machine 88.3%；候选任务评估为 0，观测到的 wall-clock 进化时间分别少 8.8× 与 3.2×；不做适配跨基准平均 SWE-bench Verified 73.3%、Polyglot 69.3%。
- 为什么值得看：它用「机制整合」替代「优胜劣汰」，证明没有下游评估也能接近有评估的效果——这对评测污染是个直接回应。

### 47. NOPO（4↑）

[HF 论文页](https://huggingface.co/papers/2611.17287) · 南洋理工大学

- 问题：RLVR 依赖可靠 verifier 判断对错，但现实里常只有「能证伪失败」的便宜检查：验证为负的是可信反例，验证为正的只是未被证伪，可能大量假阳。
- 方法：把这个设定形式化为 one-sided verifiability；提出 Negative-Only Policy Optimization——把验证为正的样本当无标签，只用可信负例抑制，具体是 reference-relative 负抑制损失，加一个按「未被证伪比例」缩放更新的 group-level adapter。
- 数字：在单元测试、约束检查、LLM 自验证三类 verifier 上，无 oracle reward 时在代码、逻辑、数学基准上 pass@k 均超基线；增益在推理时扩展与跨基准迁移下仍保持。
- 为什么值得看：它承认「正例不可信」并据此改目标函数，比在噪声正例上硬做 RL 更符合真实标注预算。

### 48. CARE-OPD（3↑）

[HF 论文页](https://huggingface.co/papers/2611.34756) · 上海交通大学

- 问题：长时 agent 的全在线 on-policy 蒸馏每次更新都要新 rollout，太贵；prefix replay 能从存下的历史里采学生回复，但教师轨迹缺少学生造成的历史，扩覆盖又会降低教师可靠性；固定按位置排的回放表也抓不住任意深度的关键决策。
- 方法：CARE-OPD 两手——学生 seed 的教师补全加回复级置信门控，扩大历史覆盖同时滤掉不可靠更新；hindsight 回放分配用下游执行证据挑「真正有后果」的轮次。
- 数字：软件工程与深度研究两类长时任务上超在线 OPD 与先前 prefix replay；SWE-bench Verified 任务成功率 59.5%，端到端训练时间相对异步在线 OPD 少 45%、环境动作少 44%。
- 为什么值得看：它把「回放哪里」从位置启发式换成结果证据，这是长时 agent 训练成本能不能打下来的核心。

### 49. SPLICE（3↑）

[HF 论文页](https://huggingface.co/papers/2611.34777) · 上海交通大学

- 问题：长时 agent 的 group-based RLVR 常出现全失败组：组内所有轨迹 reward 为 0，group-relative 方法拿不到策略梯度；用强模型补完整解又贵，还让学习器吃长段 off-policy 历史。
- 方法：对每个全失败组，proposal 模型在当前策略轨迹上选一个 splice 点，从该点生成若干有界 option；用重复的当前策略续写估每个 option 的价值，把正估计转成 return-weighted 局部目标，只在这些 option 上拟合当前策略。
- 数字：两个策略家族 × 两个长时任务（SWE-bench Verified、BrowseComp-Plus）四个设置全超 GRPO 与全轨迹引导基线，比 GRPO 高 2.8–9.8 点；初始失败的 SWE 任务「毕业率」比 GRPO 高 10.8 点；proposal 模型计算还更少。
- 为什么值得看：全失败组是 agentic RL 最常见的死局，SPLICE 用「局部嫁接」把死局变成有界监督，且不需要完整专家轨迹。

### 50. AIChipBench（3↑）

[HF 论文页](https://huggingface.co/papers/2611.33093) · [代码](https://github.com/frontiereval/AIChipBench)

- 问题：LLM 解码器在硬件里跨 step 保存状态，一次错的状态更新可能让当前 token 正确、几个 token 后才坏；设计能过输出测试却仍是错的。
- 方法：让 agent 用可综合 RTL 实现量化 Qwen3.5、Gemma 3、Gemma 4、Llama 3.2 解码器，对照一个可执行整数参考（规定每步输出与存储状态）；公开测试下有限预算调试，冻结设计后在留出 token 序列、复位、内存 stall 与综合上评分；第二赛道要求在面积近固定下加速正确设计。
- 数字：四个 coding agent 共 9,136 次尝试；指出「第一个状态不匹配」的反馈在 12 个 agent-任务格子里全部优于只给输出反馈，接受率 +25.0 到 +46.9 点，每个被接受设计的 agent 小时减半；69 个被接受设计里 45 个在新序列/条件下、测试要求的 32 步内失败；超过三分之一的加速尝试没交出设计。
- 为什么值得看：它把「状态」这个隐藏变量做成可诊断反馈，顺带证明硬件 agent 的 benchmark 必须用远超开发用例的最终测试。

### 51. Memanto（3↑）

[HF 论文页](https://huggingface.co/papers/2611.28231) · Moorcheh.ai · [代码](https://github.com/moorcheh-ai/memanto-benchmark)

- 问题：基于问答的记忆 benchmark 直接告诉 agent 该回忆哪条事实；真实职场请求是隐含的——要在团队频道发更新，agent 得从早先交互里推断是哪个频道，再用进工具调用。
- 方法：在 DolphinBench 上评 Memanto——一个用信息论相关性分数给记忆排序的记忆 agent；跑在 Hermes harness、GPT-6-Luna、每对话最多 6 轮。
- 数字：600 个职场任务完成 503 个（83.83%）；基准作者报告的最强配置 Mem0 + GPT-5.6-Luna、最多 60 轮完成 424 个（70.67%）；Memanto 总成本 10.86（最便宜已报告 run 为 61.48），中位延迟 15.32 s。
- 为什么值得看：它比的是完整系统而非单模型，成本与延迟也进了表——记忆系统的价值本来就在「少调几次模型」。

### 52. DetourBench（2↑）

[HF 论文页](https://huggingface.co/papers/2611.20844) · [代码](https://github.com/DatagridsAI/DetourBench)

- 问题：benchmark 只看 agent 是否到达正确终态，分不清「只取了决策必需的证据」与「读了大半个环境」，也分不清「差一步」与「乱走一通」。
- 方法：把环境约束成有限、部分可观测、单位代价的转移系统，资源被发现后全局可寻址，于是穷举可算出全信息最小动作数 L0 与可回放 witness；从图可恢复的终态还算精确剩余工作量 R_T，把「差一次访问」与「走错路」分开，不可逆错误承诺记为无有限剩余距离；成功、达成、剩余进度、归一化绕路分开报。
- 数字：375 个计分 episode（5 个模型端点 × 25 个集成任务 × 3 次重复），成功率 58.7%–96.0%，条件达成率 0.803–0.890，两者对模型排序不同；可恢复失败里剩余工作量能区分接近完成与高代价未完成。
- 为什么值得看：它给「轨迹质量」提供了精确参考下界，而不是又一个 LLM judge——这是评测能算账的前提。

### 53. EditRec（2↑）

[HF 论文页](https://huggingface.co/papers/2611.21155) · [代码](https://github.com/ntt-dkiku/llm-edit-recommendation)

- 问题：agent 产出 artifact 后用户常要发修改请求；能否在用户开口前预测这些请求，直接决定 review 成本。
- 方法：把任务形式化为 edit recommendation，从 WildChat-4.8M 真实对话建 EditRecBench；失败分析发现有些 case 本质上不可预测，于是加 decision model 做门控，预测不可靠就不展示；训练的模型超过现有 decision model。
- 数字：在门控阈值下，展示建议的 pass@5 提升 12–25 点。
- 为什么值得看：它不追求「全都猜」，而是先判断「该不该猜」——这比把建议一股脑塞给用户更接近可用产品。

### 54. 加密交易监控审计（0↑）

[HF 论文页](https://huggingface.co/papers/2611.29829)

- 问题：反非法加密资金流已出现「图检测器 + 规则 + RAG + LLM judge」的 agent 流水线，评估只看端到端准确率或理由质量，没人回答「到底是哪个组件做的决定」。
- 方法：在 Elliptic++ 比特币数据上做决策来源归因，三层追踪：逐案 actual causation、干预式 Shapley 信用、上游风险分数的中介分析；另单独测 judge：76 个证据包、4 个骨干、2 个 prompt。
- 数字：一个确定性钱包分数覆盖规则拿了约 94% 的 flag 信用；验证门取消了 judge 自己发出的大部分 flag（且落在合法交易上）；judge 会跟随注入的风险分数、上下文短到放不下 system prompt 时干脆不给结论、还会引用不适用的监管条款，而基于子串的引用检查照样通过；隐藏分数也没用，因为带分数时收集的证据已经编码了它。
- 为什么值得看：结论很硬——LLM 的理由不能当作「谁触发了告警」的证据；合规场景里，可解释性必须追到组件级归因。

### 55. Puzzling-Bench（4↑）

[HF 论文页](https://huggingface.co/papers/2611.34331) · [代码](https://github.com/a1bhinav/puzzling-bench)

- 问题：推理 benchmark 容易被污染，答案质量也参差；谜题类任务还常缺少可核验的出处与提示层级。
- 方法：从 Puzzling Stack Exchange 2014–2026 档案建 23,777 道谜题，含谜语、密码、逻辑格、横向思维、文字游戏、趣味数学，三分之一带图；每题附作者采纳答案、短参考解（评测集由 LLM 抽取并在 50 题人审）、作者提示、社区标签与创建日期，支持提示消融、类别分析与滚动 post-cutoff 切片（254 题在九个模型里六个的训练截止之后，含最强模型）。
- 数字：九个前沿/开放模型，两层评分（归一化精确匹配 + LLM judge），三个 judge（两个模型家族）95–97% 判定一致（kappa 0.82–0.96），无模型移动超过 1.6 点，无同家族偏好；GPT-6.1 在共享 255 题上 74.8%；17 道硬核题击败全部九个模型，失败高度相关，九模型 oracle 才 91%；100 题多模态试点里，去掉题图让两个最强模型掉 24 与 35 点。
- 为什么值得看：它同时给了污染切片、提示消融与 judge 校验，是「benchmark 该长什么样」的完整样板。

### 56. CONCOR（4↑）

[HF 论文页](https://huggingface.co/papers/2611.30460) · 新加坡管理大学

- 问题：对比解码（CD）靠对比不同条件下的 token 分布压幻觉，但现有生成/判别 benchmark 只看最终分数，会被候选过滤、生成轨迹变化与回答偏置混淆，说不清对比修正本身有没有效。
- 方法：CONCOR 直接测「真值候选 vs 不同类型幻觉候选」的竞争，用 Contrastive Grounding Margin 衡量，并分析修正的方向一致性、组成与可靠性；受控到能隔离对比调整的效果。
- 数字：现有 CD 方法行为分两类——有的稳定偏向真值候选，有的修正强但引入更多错误；这解释了它们对「加大对比强度」为何反应相反（有的涨、有的崩）。
- 为什么值得看：它把「幻觉有没有被压住」拆成逐 token 的方向问题，比最终准确率更能指导方法选择。

### 57. 多语言决策模型（4↑）

[HF 论文页](https://huggingface.co/papers/2611.33307) · 南洋理工大学

- 问题：决策模型（对每个选项返回概率、被路由器与 guardrail 直接阈值化）多语言底座训练，却几乎只在英文上排名。
- 方法：评 25 个头部开放权重决策模型，17 个任务、14 种语言，与英文平行项逐题比；再做 81 次受控微调，测任务技能迁移、目标语言数据量、全参微调能否补差；并比较人译与 LLM 翻译的测试集。
- 数字：每个模型在每种语言都掉点，高资源语言约 2 点、泰米尔语约 8 点；置信度只掉一半——英文设 95% 准确率的阈值，泰米尔语只剩 90%；损失大小由语言与底座决定，与排行榜名次无关；英文任务技能可迁移，几千条目标语数据能缩小大缺口，但加数据与全参微调都补不平；23 个「基准-语言」对里 LLM 翻译的题都答得更准，说明 LLM 翻译测试集低估了差距。
- 为什么值得看：阈值化系统里「准确率掉 8 点、置信度只掉 4 点」意味着线上会静默降级，这比平均分危险得多。

### 58. 反事实 SQL 奖励（4↑）

[HF 论文页](https://huggingface.co/papers/2611.34363) · [代码](https://github.com/RishiiGamer2201/counterfactual-sql-rewards)

- 问题：text-to-SQL 的 RL 只要查询在一个数据库上结果与参考一致就给奖励；但数据缺少暴露 bug 的行时，错查询会靠运气匹配。
- 方法：反事实数据库奖励——把最终查询再跑在几个隐藏的、代码生成的数据库副本上，全对才给（strict），或按匹配比例给（mean）；在 1,302 个合成审计题上测，另做 3.35B 模型、三 seed 的 GRPO 对照。
- 数字：strict 把「全款支付的错查询」占比从 29.5% 降到 16.8%，reward hack 从 54.1% 降到 1.9%，2,847 条正确查询零误拒；族盲生成器的副本效果相近；但 GRPO 里 mean 形式没提升域内准确率（8.4% vs 11.7%），因为两种奖励只在 5–7% rollout 上分歧，Spider 上 +1.6 点；有一个 seed 把两个符号都翻过来。
- 为什么值得看：奖励更可信不等于训练更好——5–7% 的分歧率与单 seed 反转，是对「换个 reward 就能涨」最直接的警告。

### 59. 小模型何时该推理（2↑）

[HF 论文页](https://huggingface.co/papers/2611.30334) · Telecom Paris · [代码](https://github.com/samyhaff/ed-study)

- 问题：推理 LLM 能做零样本实体消歧，但小模型上推理是否仍值它的成本，此前没拆开看。
- 方法：在经典 coarse-to-fine 实体消歧管线里比较 pointwise、listwise、reasoning 三种候选选择器，覆盖 in-domain、few-shot、true zero-shot 三种设定；推理范式用蒸馏与 RL 两套配方训练；再分析 reranker 不确定性与分布偏移各自的作用。
- 数字：推理的收益随域偏移增长——in-domain 可忽略，true zero-shot 决定性；两个因素分工明确：reranker 对候选的不确定性定位「两种范式何时分歧」，偏移决定「分歧时谁对」。
- 为什么值得看：它给出「何时值得推理」的可操作判据（看不度与偏移），而不是笼统说 reasoning 更强。

### 60. Lembas（2↑）

[HF 论文页](https://huggingface.co/papers/2611.32938) · UIUC

- 问题：长视频 RAG 靠选帧与 token 压缩省算力，但没算「多给一个 token 值多少」，帧与字幕还各自为政。
- 方法：把视频 RAG 写成帧与字幕共享预算的 token 分配问题；核心假设是 token 价值在条目内递减、相似证据拿越多 token 边际越低；用一个目标同时刻画两种效应，用带收敛保证的迭代注水求解；多轮对话复用已处理 token，并用 VLM 注意力免费细化相关性。
- 数字：同等算力下比 SOTA 基线最高 +7.2 点；多轮视频理解最高 +1.5 点，同时少 1.7–17.3× TFLOPs。
- 为什么值得看：把「选什么」换成「分配多少」，是视频 RAG 从启发式走向可优化目标的一步。

## 今天的三个观察

**一、具身智能的瓶颈正从策略移到数据生产线**，而且生产线开始自己闭环。今天票数第一的 Real2SimLab 不训练任何策略，只统一评测与造数据；DexEngine 把 retarget 变成可扩展的物理校正管线；DemoFoundry 用 coding agent 写交互程序、渲染器只管外观；SEEK 与 RoboEvo^2 则让执行反馈回到程序与策略。共同点是：**人类演示不再是唯一入口，代码、视频与仿真失败都成了数据源**。这也解释了为什么这一组平均票数最高——大家真正缺的是数据，不是又一个新的 VLA。

**二、参数效率分化成循环复用与稀疏激活两支**，而且开始正面交手。MoLT 把 KV 当跨 loop 记忆、U 形跳过无用遍历，在 700M 上换 1.7× token 效率、3B MoE 十任务 +2.1 点；DyLoMo-DiT 用权重共享循环 + 稀疏专家，在 DiT 上把 FID 降 11–24%、文生图 GenEval 超过 FLUX.1 而激活参数只有 1.05B。Sage-Med 则从另一侧证明：3B 激活可以打赢 235B 总参，前提是 322.7M 记录的数据课程。三条路的共同结论是——问题不再是「模型多大」，而是「哪部分参数在什么时候被用到」。

**三、评测继续往过程与反事实走**，而且开始反噬热门方法。Puzzling-Bench 用 post-cutoff 切片与 judge 交叉校验；DetourBench 算出精确最小动作数，把「差一步」和「乱走」分开；反事实 SQL 奖励把 reward hack 从 54.1% 压到 1.9%，却在 GRPO 里没涨点；多语言决策模型显示准确率掉 8 点、置信度只掉 4 点。最刺眼的是 AIChipBench：69 个通过开发测试的 RTL 设计里 45 个在新序列上失败。「通过测试」与「正确」之间的缝，正在成为评测论文的主战场。

## 数据与方法

- 数据抓取：`python3 code/ai-daily/fetch_papers.py --date 2026-11-26`，落盘 `~/tmp/ai-daily/2026-11-26.json`；本期 `count=60`，与 `papers` 数组长度一致。
- 排序口径：Top 10 按全榜 upvotes 降序，同票按 arXiv id 升序；正文按主题分组，组内同样按 upvotes 降序、同票按 id 升序。正文序号（1–60）与 Top 10 名次无关。
- 票数口径：upvotes 为抓取时刻 2026-11-26T21:00:08+08:00 的快照，HF 票数会继续变；同一天不同时间重抓数字会不同，不影响结论方向。
- daily 日与 arXiv 日：这里指 HF Daily Papers 在 2026-11-26 收录的论文，不等于 arXiv 提交日；个别更早的 id 也可能今天上榜。
- 数字来源：每篇 bullet 的数字都取自对应摘要；摘要没给具体数值的（CARE-3D、DemoFoundry、SIA、Look Back），文中明确写「摘要未给」，不做推测。
- 分组原则：按论文主张归类，不按机构；跨组的（如 ROAM-Bench 既可算具身也可算评测）归到其主要贡献所在组，避免同一篇出现两次。
