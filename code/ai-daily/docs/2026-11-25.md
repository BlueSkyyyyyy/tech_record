## 一、基座模型与架构：把控制写进结构

这一组 8 篇，共同点是「不再靠调参，而是改信息怎么流」：给每个 token 一条可重写的矩阵残差流、按层分配 FFN 容量、让训练剪自己的拓扑、在预训练就分开指令与数据通道。

### 1. Antom 3-in-1 Transformer（106↑）

[HF 论文页](https://huggingface.co/papers/2611.25403) · Ant International

- 问题：支付风控天然有三种结构——行为流水是序列、交易与商户属性是表格、账户-设备-商户关系是图。工业界通常三套模型拼装，换一个业务就要重学一遍表示。
- 方法：一个约 7B 的模型，按任务路由只激活约 1.7B；在蚂蚁国际内部支付数据上预训练，把行为表示与关系表示做成可复用底座，再按业务微调。
- 数字：跨业务迁移比同架构从零训练提升 34.5%；只用 25% 标注，就在多个商户域的 AP 与 Recall@0.5% 上超过全标注从零基线；十亿级平台四个月在线实验，整体损失率相对 XGB-Online 降 37.88%。
- 为什么值得看：这是「基础模型进风控」少见的完整账——有跨业务迁移、有标注效率、还有四个月线上损失率，而不是一个离线 AUC。

### 2. Loom Attention（90↑）

[HF 论文页](https://huggingface.co/papers/2611.30634) · [代码](https://github.com/Caiyun-AI/LoomFormer)

- 问题：每个 head 的 Q/K/V 都由同一层输入投影而来，电路训练完就固定；残差流只能纵向叠加，没法按 token 重新布线。
- 方法：loom attention 把两种注意力交织——纵向注意力对本层之前各 head 的输出做归一化门控线性注意力，写进 per-token 矩阵记忆，充当第二条残差流；横向注意力照旧对 token。LoomFormer 因此把控制放在向量流、内容放在矩阵流。
- 数字：只多 2% FLOPs、同样 300B token，LoomPythia-2.8B 的下游平均增益约为 mHC-Pythia-2.8B 的 1.6 倍，0-shot 追平 Pythia-12B、5-shot 反超；整体匹配用 3 倍以上算力训练的 Transformer，以及用 1.7–2.8 倍算力的 HC/mHC、MUDDFormer、AttnRes。
- 为什么值得看：把「超连接」从标量混合升级成矩阵记忆，等于每个 token 自带一个可重写的微型 KV 缓存——这是残差流竞赛里目前最像新架构、而不是调参的一支。

### 3. KMed-31B（21↑）

[HF 论文页](https://huggingface.co/papers/2611.28719) · NAVER

- 问题：医疗任务的目标函数根本不同：选择题与诊断预测有标准答案，临床问询没有唯一正确答案、只能按 rubric 评。混在一起训，提升一类就掉另一类。
- 方法：按「输出是否固定 + 反馈是否有参照」把任务分成四类，每类用与其反馈匹配的 reward 训一个专家，再用 MOPD²（多教师 on-policy delta 蒸馏）合成 31B 学生；另造 Synthetic Health Dialogue 补临床问询数据。
- 数字：相对基座，HealthBench Hard 22.95→41.87、Professional 37.92→50.20（非思考模式）；思考模式 23.80→51.48、41.97→59.18；四项医学选择题持平或小升。同一配方用在 Qwen3.8-27B 上也涨。
- 为什么值得看：结论是「reward 的形状必须对齐任务的反馈形状」，这条对任何多任务后训练都成立，不限于医疗。

### 4. FFN 内在维度（7↑）

[HF 论文页](https://huggingface.co/papers/2611.32782) · [代码](https://github.com/naver-ai/lidf)

- 问题：所有层 FFN 中间宽度相同，但机制研究说不同深度的层做不同的事；它们的容量需求是否也不均匀？
- 方法：对 58 个开源模型（14 个家族、70M–72B）每层 FFN down-projection 的输入做 PCA，用「重建到固定 cosine 相似度所需的主成分数」定义该层内在维度。
- 数字：普遍呈「中间厚、两头薄」，对校准语料（英/中）稳定，后训练后大体保留；按此分配宽度做知识蒸馏，Qwen3-8B +2.3、Qwen2.5-3B +2.5，Gemma-3-4B +0.9、LLaMA-3-8B +0.5，反向分配在四个教师上全最差；增益大小与教师分布的 σ99 相关。
- 为什么值得看：它没有停在「测出相关性」，而是用反向干预（按维度分配 vs 反向分配）证明这个信号能指导设计。

### 5. Steerable by Design（7↑）

[HF 论文页](https://huggingface.co/papers/2611.32199) · MIT · [项目页](https://mancelle.com/)

- 问题：next-token 预训练把「指令」和「数据」塞进同一个输入通道，模型分不清，于是既有刻意越狱，也有无意的 in-context alignment drift。
- 方法：预训练阶段就分开两条路：一个 encoder 编码后文的高层语义特征，经 cross-attention 注入，且 token 流不能写回该控制通道；模型从预训练起就依赖这个通道预测下一个 token，于是它成了可控的手柄。
- 数字：Mancelle-3B 在可比开源模型上比 prompt 与 activation steering 更强且保持流畅，能抵御黑盒与 soft-prompt 反操控；Mancelle-400M 在更受控的基线上复现了同一结论。
- 为什么值得看：对齐从「最后 1% token + 推理时干预」前移到预训练架构，是少数敢动预训练输入接口的工作。

### 6. Model Carving（2↑）

[HF 论文页](https://huggingface.co/papers/2611.27962) · Harvard University · [代码](https://github.com/KadenZheng/model-carving)

- 问题：每层都是同样的 attn+MLP，这个均匀性是惯例不是最优；剪枝和蒸馏都是训完再压，压缩时已经丢了「小模型本来该怎么长」的信息。
- 方法：给每个 sublayer 一个可学习标量门，训练损失直接把组件关掉，一次训练同时学权重与拓扑；被关掉的层不再运行。
- 数字：140M–2.7B 标准 Transformer 与 140M–1.3B looped 上，等算力下 carved 模型验证损失低于用最多 1.7 倍算力训的 dense；每 token FLOPs 最多少 34%、解码快 1.6 倍；优于同尺寸剪枝/蒸馏产物，且优势随规模变大。
- 为什么值得看：它和本组 FFN 内在维度那篇互为印证——容量该按层分配，而且分配可以发生在训练中，而不是训练后。

### 7. Factorized Context Attention（2↑）

[HF 论文页](https://huggingface.co/papers/2611.32423) · KAUST · [代码](https://github.com/mohammad2012191/FCA)

- 问题：长上下文一次前向既慢又掉精度、还卡在窗口；grid probing 靠把输入切成短片段反复提问恢复精度，但每个片段都要重新编码一遍。
- 方法：指出 grid probing 本质是「在模型外部用 prompt 模拟出来的注意力」，于是把同一模式做成原生 block-sparse attention：输入只编码一次进 KV cache，所有 span 作为 masked 序列一次批量前向，用 stair 位置表把每个 span 压回训练时的位置范围。
- 数字：长视频理解 +约 10 点、长篇小说 +9–14 点；能在 1000+ 帧视频和 4 倍窗口长度的文本里找到 needle；对同一输入追问的耗时最低只要 grid probing 的 1/10。
- 为什么值得看：它把「测试时技巧」还原成「注意力模式」，这类还原通常能直接进推理栈，且不用重训。

### 8. Fractal Neural Synthesis（1↑）

[HF 论文页](https://huggingface.co/papers/2611.32393) · WERR Lab · [代码](https://github.com/pCwOrM/fractal-neural-synthesis)

- 问题：边缘 MCU 的 Flash 占用随参数量线性增长，大一点的网络根本存不下。
- 方法：用 24 字节的复数坐标种子 (c_x, c_y, ℓ) 在 f_c(z)=z²+c 的分岔边界附近程序化生成隐层权重；配大 bailout 的平滑逃逸核与四种零开销几何采样口径。
- 数字：INT8 读出下比 0 隐层 Linear-INT8 高 3.6–10.8 点，Flash 比收敛的 Float32 MLP 少 10.7×–129×（隐层 725×–2773×）；Ionosphere 90.30% 只用 285 B，PenDigits 97.90% 用 2,598 B。
- 为什么值得看：激进但有边界——只在小表格基准上验证，别把它读成「大模型免存储」的证据；不过 285 字节跑出 90% 这个数量级本身值得记一笔。

## 二、Agent：判断证据、时机与分工

这一组 11 篇，几乎都在回答同一个问题：agent 变强之后，瓶颈从「会不会做」转到了「什么时候做、做多少、谁来做」。这也是今天最强的一组信号。

### 9. RLVB（98↑）

[HF 论文页](https://huggingface.co/papers/2611.32884) · Nanyang Technological University · [代码](https://github.com/declare-lab/RLVB)

- 问题：长任务 agent 常常「懒得找证据」就提交答案；而结果奖励只看最终答案，蒙对和真有证据同分，教不会「何时该停」。
- 方法：训练时模拟器能算出每步的精确后验，于是 RLVB 在后验仍含多个答案时奖励「继续走」、在后验收敛时奖励「提交」。奖励不需要 judge、critic 或 reward model，也从不读 agent 自己写的那行 belief。
- 数字：3 个 VLM × 3 个 benchmark（其中两个训练没见过）九个设置全部提升，平均 +17.1%；同样用结果奖励时 GRPO 与 PPO 平均反而低于基座；比用 LLM judge 给过程奖励的 PPO 高 9.3%，GPU 小时少 1.6 倍。
- 数字：证据充分时作答的比例为 51%/12%/74%，基座是 8%/0.4%/36%；证据不足却提交的回合只占 0.1–2.2%，基座为 3–68%。
- 为什么值得看：它把「过程奖励」从模型打分换成了环境可验证量——这是当前最可扩展的一条路，且 Pro Worlds 基准本身可复用。

### 10. NightWatch（97↑）

[HF 论文页](https://huggingface.co/papers/2611.28947) · [代码](https://github.com/SuJQ0722/NightWatch)

- 问题：CUA 靠离散截图感知，VLM 推理延迟叠加界面自身变化，导致动作真正执行时看到的状态已经过期——感知与动作之间有一道缝。
- 方法：外挂 NightWatch-0.8B，一个小型 System-1 模型做流式界面监控，把 agent 持续同步到当前状态；不改 agent 的模型、prompt 或动作空间，即插即用。
- 数字：OSWorld-Verified 上非推理墙钟时间 -33%、浪费的等待时间 -53%，任务成功率持平；DynaCU-Bench 上大模型 agent 从 39.5% 提到 44.2%；同等「只看截图」输入下优于 AOI、PUSV 等被动观察基线，也优于体量大 30 倍以上的 System-1 决策模型。
- 为什么值得看：它证明「感知的时机和内容一样重要」。0.8B 的外挂就能拿到这个收益，工程落地成本极低。

### 11. ACAP（62↑）

[HF 论文页](https://huggingface.co/papers/2611.31205) · MMLab@NTU · [项目页](https://projects.zxhezexin.com/acap)

- 问题：用一个 coding agent 控制整台机器人，会把本来可以并行的部件工作串行化，独立的部分互相等。
- 方法：把机器人拆成一组常驻 agent，各管一个控制组（臂+爪、躯干+底盘等），异步推理与执行；另设 hyper-agent 分配任务、协调物理依赖、在 lead 与 member 之间动态移交控制权，需要紧耦合操作时再收回来。
- 数字：72 次真机 rollout、25 种任务/平台设置，任务均衡时间成本比单 agent 的 Direct Policy 低 28.2%，Fully Parallel、Parallel-Sequential、Collaborative 三类任务都有改善；8 个协作设置全部低于 Fixed Delegation；另 90 次 rollout 在 6 个任务上均低于 Direct（30 分钟上限）。
- 为什么值得看：多 agent 在物理世界里少见的真机账，而且报的是时间成本而非成功率——这才是并行真正的卖点。

### 12. CUA-SEE（48↑）

[HF 论文页](https://huggingface.co/papers/2611.30962) · Tongyi-MAI

- 问题：CUA 基准是静态的：难度封顶、功能覆盖有限、只给聚合分，随着 agent 变强，判别力和诊断力一起衰减。
- 方法：闭环评测环境，让任务与可执行 verifier 一起进化，并拆成三个目标——基准进化按 cohort 校准难度与覆盖，诊断进化按 agent 能力边界生成探针，verifier 进化把变化的需求翻成状态级 checkpoint 并做对抗验证。
- 数字：摘要没给统一分数，报告的是跨多个 agent、应用与轮次都能持续产出有挑战且可测的任务，并保留过程级证据。
- 为什么值得看：评测开始和 agent 一起「自进化」。这和 RLVB 的可验证奖励是同一套基础设施思路——先有可执行验证，才谈得上自动加难度。

### 13. ICLWorld（20↑）

[HF 论文页](https://huggingface.co/papers/2611.32649) · [代码](https://github.com/ICLWorld/ICLWorld)

- 问题：前沿 agent 同时在电脑和机器人上工作，但 in-context learning 没被公平测过：现有基准大多离线、用文本或静态图、有训练数据污染风险，机器人侧只有方法级消融。
- 方法：在线基准加 UIverse harness，把每个环境都变成 UI；30 个环境、630 段演示视频（10+ 小时）、160 个任务，规则刻意反直觉，每个任务给文本/视频三种规则版本，按「复现演示→新实例→未见环境」三级测泛化。
- 数字：Claude Opus 5.5 与 GPT-6 Astra 在电脑使用上成功 82%/76%，机器人使用只有 27%/26%；去掉规则的对照最多 8%；GPT-6 Astra 在三种规则版本下全过仅 38%，是单一规则时的一半；机器人规则问答正确率 98%，任务却只完成 20%。
- 为什么值得看：「说得出规则」与「做得到」之间那 78 点缺口，是今天所有具身 agent 论文里最刺眼的一个数。

### 14. CoT-Proxy（14↑）

[HF 论文页](https://huggingface.co/papers/2611.33148)

- 问题：从强教师蒸馏长程 agent 通常要连 CoT 一起模仿，但最强教师的 CoT 藏在 API 后面，根本拿不到。
- 方法：只用教师的动作轨迹训学生，推理块留空，另加一个对自身生成 replay buffer 的 KL 约束防漂移。作者发现空推理块学到的策略能迁移到「开思考」推理，称为 cross-format transfer；再往空块后放教师推理的短摘要（CoT-proxy）还能再涨。
- 数字：蒸馏 Qwen3.6-27B 的动作，Qwen3-4B 在 AppWorld 从 7% 到 18%，Qwen3-32B 从 12% 到 25%；加 CoT-proxy 后 4B 到 35%；蒸馏 GPT-5.6 Luna 的可见输出与 API 返回的推理摘要，4B 到 48%，SWE-bench Verified 从 3% 到 28%。
- 为什么值得看：闭源教师也能蒸，而且「动作先于理由」这个反直觉结论有跨模型、跨基准的对照支撑。

### 15. SpecEngineeringBench（13↑）

[HF 论文页](https://huggingface.co/papers/2611.32973) · Tokenwave.AI · [代码](https://github.com/TokenWave-AI/SpecEngineeringBench)

- 问题：现有基准把 issue 描述、测试入口、待查文件都直接给了，等于替 agent 完成了「测什么、去哪查」这两步最难的工作。
- 方法：100 个实例、78 个开源 Python 仓库、16 类应用，每个实例埋多个缺陷；两个独立任务（生成测试套件 / 通过执行分析发现缺陷）；指标合并测试有效性、缺陷检出、覆盖率与定位 precision/recall。
- 数字：7 个前沿 agent 的 Head Pass Rate 达 91.47%、Change-focused Coverage 80.48%，但 Fail-to-Pass 只有 26.36%；定位 recall 从文件级 78.11% 掉到函数级 51.29%；自主生成测试比只用仓库现有测试，文件/函数/hunk 定位 recall 分别 +4.99/+2.77/+2.69。
- 为什么值得看：它量化了「测试写得多」和「缺陷找得到」的解耦——高覆盖率是假安全感。

### 16. Coding4Games（12↑）

[HF 论文页](https://huggingface.co/papers/2611.31974) · ARC Lab, Tencent · [代码](https://github.com/GVCLab/Coding4Games)

- 问题：把 LLM 当 CUA 打游戏要每步推理，实时游戏里环境不会等你；能不能让 coding agent 直接写一个不含 LLM 推理的独立程序来玩？
- 方法：15 款现代游戏；开发与测试分离——agent 在沙箱里用标准玩家接口迭代写程序，写完后冻结，在无 LLM 推理的条件下独立测试；同时评结果与开发过程。
- 数字：每款游戏的最佳程序在 13/15 上超过最强 GUI 基线、1 款打平；人类玩家在 10 款上仍高于所有 agent；论文还分析了开发预算对最终程序的影响。
- 为什么值得看：「agent 的产出是程序而不是动作」，推理成本一次性付清——这是实时场景里最现实的范式。

### 17. InstructReplay（3↑）

[HF 论文页](https://huggingface.co/papers/2611.32918) · Beijing Academy of Artificial Intelligence · [代码](https://github.com/xiaofengShi/InstructReplay)

- 问题：用新事实微调指令模型会侵蚀通用能力。作者测到标准微调平均掉 35 点，而且掉分与回答长度腰斩同步——回答越短、越容易失败。
- 方法：先让初始模型对一组通用指令各答一次，微调时把这些自答当锚，约束模型不要偏离；不改损失形式。
- 数字：三个模型家族、两个领域，五个通用基准的平均跌幅从 28.1 降到 2.4 点，回答长度基本保持，新事实学得和标准微调一样好；六种设置全部优于 7 种对照适配方法；对照实验把增益归因于「重放自己的答案」而非损失形状。
- 为什么值得看：灾难性遗忘的一个便宜解法，而且顺手给出了「回答长度」这个几乎零成本的早期监控指标。

### 18. OWE-Bench（2↑）

[HF 论文页](https://huggingface.co/papers/2611.30017) · Mercor

- 问题：工程任务缺长程基准：26 个专家写的任务横跨软件、物理、ML 与科学计算，从优化 kernel 到设计飞机、定位地震断层，单任务动辄上亿 token。
- 方法：按速度、成本、精度评，既有可自测的给定用例，也有按任务描述就该想到的隐藏用例；当前最佳 Claude Fable 5.2 得 54.6%，平均 211M token/任务。

### 19. RECAP（1↑）

- 问题：长程 agent 靠压缩历史进上下文预算，但摘要与策略联合学习很难——摘要的影响要在之后几十步才显现，信用分配跨得很远。

## 三、具身智能：空间、进度与反射

这一组 9 篇，从「模型看不看得懂 3D」一直排到「RL 该练哪一段」。共同点是把具身问题拆成可以单独测量的成分：几何内化、部件证据、反射鲁棒性、进度瓶颈。

### 20. S-Mind（41↑）

[HF 论文页](https://huggingface.co/papers/2611.28649) · Nanyang Technological University · [代码](https://github.com/KANABOON1/S-Mind)

- 问题：空间智能有两块基石——把多视角融成一个连贯 3D 场景、在推理中把场景在脑中转到新视角。作者的空间探针显示，MLLM 即使做过空间微调，这两项也基本都缺。
- 方法：用一小组 spatial tokens 把多视角几何内化：监督这些 token 承载融合后的 3D 场景，并在推理走到每个视角时重新发射、重述该场景。
- 数字：四个空间基准上比 Qwen3.5 骨干最高 +22.26 点；平均准确率超 GPT-6-Astra +0.45、Kimi-K3.1-Pro +1.97、GLM-5.3-Flash +7.80；融合与变换准确率 65.11%/82.17%，基线最多 16.02%/37.28%；推理比同骨干的工具型 agent 快约 100 倍。
- 为什么值得看：能力写进骨干后，即使撤掉 spatial token 仍在——这比外挂一个 3D 工具更接近「真的会」。

### 21. PartAgent（34↑）

[HF 论文页](https://huggingface.co/papers/2611.32554) · HKUST · [代码](https://github.com/yangcaoai/PartAgent_Agent_for_3D_Part_Seg)

- 问题：3D 部件分割要同时用几何（3D 专家的区域提议）与语义（2D 专家的多视角线索），两者难整合，切错了也很难逐步修。
- 方法：免训练 agent。结构-语义专家整合把 3D 区域与 2D 多视角证据经 image-to-surface 对应合成多粒度部件划分；观察驱动的闭环修正看当前划分与证据，选检查、补证据、重组或重选，并验证每次改动。
- 数字：PartObjaverse-Tiny-WT 上 68.41 mIoU，超最强对比方法 8.53 点；3DCoMPaT200、PartNeXt、PartNetE、PartObjaverse-Tiny 四个数据集全部最高，平均 69.36，比对比方法的最好均值高 7.28 点。
- 为什么值得看：免训练加闭环验证，说明 3D 任务的瓶颈常在「证据怎么用」，而不是「再训一个更大的模型」。

### 22. RoboDojo-Mirror（29↑）

[HF 论文页](https://huggingface.co/papers/2611.33010) · intelligence++ · [代码](https://github.com/iPPLab/robodojo-mirror)

- 问题：动物认知里有镜像自我识别测试。机器人策略在含自身倒影的场景里，还能可靠操作吗？
- 方法：在 RoboDojo 上建基准，保持任务目标、成功判据、策略 checkpoint 不变，对比无镜、单镜、双镜、镜面桌面四种条件；再用几何匹配的非反射板做对照，把「镜子是障碍物」与「镜子是反射面」分开。
- 数字：5 个策略（VLA、WAM、agentic）在所有镜子条件下都掉；三条件平均掉 10.8–56.7 点，镜面桌面最高掉 62.5 点；50–88% 的镜子特有失败没有记录到机器人与板接触，所以不是撞出来的；真机 π0.5 与 FastWAM 同样下降。
- 为什么值得看：这是一类此前没人系统测过的分布外失败，而且失败模式很具体——朝倒影里的假目标去、真实物体定位偏移。

### 23. LeadVLA（12↑）

[HF 论文页](https://huggingface.co/papers/2611.30149) · [项目页](https://louiszengCN.github.io/LeadVLA_PAGE/)

- 问题：机器人领走要边走边适配身后的人。用显式状态或规划器会把耦合切碎，端到端轨迹预测又把路线执行与人的反应纠缠在一起。
- 方法：把路线保留为显式 Path 参考，另学 Pace（沿路线的进度）与 Residual（局部对人、对场景的适配）；建 LeadInfra（UE 闭环数据生成，约 4M 样本）与 LeadBench（108 个完全留出的闭环 episode）。
- 数字：LeadBench 上任务成功率 39.6%，为所评策略最高，同时保持路线保真与跟随者响应；零真机微调即可迁移到未见真实环境。
- 为什么值得看：39.6% 说明这个任务远没解决，但「显式路线 + 学习残差」的分解至少让失败可归因。

### 24. LoopedWAM（5↑）

[HF 论文页](https://huggingface.co/papers/2611.25595) · University of Central Florida · [代码](https://github.com/anhdao69/LoopedWAM)

- 问题：世界动作模型要大的视频与动作 Transformer，部署效率差，而视频与动作的推理成本并不对称。
- 方法：每个专家用共享的 6-block 核心循环，执行 30 层只存 12 块；视频与动作专家按成本用不同深度；elastic self-distillation 训一个 checkpoint 覆盖多档动作深度与采样步数。
- 数字：0.58B 策略参数、无机器人预训练：LIBERO 96.1%、RoboTwin 2.0 91.9%、RoboCasaGR1 52.2%，峰值显存比 Fast-WAM 少 7.4 倍；LoopedWAM-E 在 H100 上 27.6 ms 得 96.0%、24.7 ms 得 95.2%；两步采样四层循环在三基准上距完整模型 0.5 点内；真机 AgileX PiPER 80 次 71.3%。
- 为什么值得看：把「循环深度」变成可调的延迟旋钮，是 WAM 落地最实际的一步——一个 checkpoint 给出整条精度-延迟曲线。

### 25. Foresight Forcing（2↑）

[HF 论文页](https://huggingface.co/papers/2611.30963) · [代码](https://github.com/anson2333/ForesightForcing)

- 问题：WAM 预测未来视频，但训练目标让物体怎么动、空间关系怎么变这些 3D 几何转移停留在隐式。
- 方法：用冻结 3D 基础模型提取当前与未来观测的 patch 特征差，作为稠密几何监督；蒸馏进 spatial transition queries，由当前观测、指令、本体状态逐步精炼，与当前视觉特征一起出动作；部署时不需要未来观测或 3D 教师。
- 数字：RoboTwin2.0 Full 平均 95.01%；LIBERO 与 LIBERO-Plus 表现强、鲁棒性提升；六个真机任务平均 85.8%。
- 为什么值得看：把 3D 教师当训练期脚手架、推理期丢掉，这条「蒸馏几何」路线比直接上 3D 输入便宜得多。

### 26. Point Dynamics（1↑）

[HF 论文页](https://huggingface.co/papers/2611.25946) · MBZUAI-IFM · [项目页](https://marsaki.github.io/point-dynamics-proxy/)

- 问题：机器人世界模型能跟随动作，但被操作的物体常塌陷或与动作不一致。作者把原因归到条件上：动作只说机器人去哪，没说场景怎么响应。
- 方法：把动力学与渲染分开，用 3D 点动力学作代理——首帧 lift 成点，学一个点动力学模型响应机器人运动，再把点渲染回像素对齐的视频，任何视频模型都能读。
- 数字：DROID 上换两种不同架构的渲染器，物体运动误差分别降 8.6% 与 6.2%，画质不降；真机双臂降 8.1%；动力学更准则物体运动更准，直接编辑点还能 steer 视频。
- 为什么值得看：它给「世界模型的瓶颈是动力学而非外观」提供了一个可干预的中间表示，而不只是一句诊断。

### 27. ReFocus（1↑）

[HF 论文页](https://huggingface.co/papers/2611.32639) · Zhejiang University · [代码](https://github.com/ReFocus-Robotics/ReFocus)

- 问题：长程操作 RL 只有稀疏的成功/失败，不知道瓶颈在哪；每次整段 rollout 既贵，又练不到真正卡住的那几步。
- 方法：Global 与 Local 交替。Global 阶段把任务分解成子任务 DAG，用 DAG progress reward 训练并诊断瓶颈；据此选 Adaptive Practice Windows（从入口阶段到目标阶段）在 Local 阶段多练，再整段评估进入下一轮。
- 数字：LIBERO-Long 97.8%、RoboCasa365 51.3%，π0.5 基线为 90.6%/39.3%；真机 BreadBaker 95% 对 30%。
- 为什么值得看：真机上 65 点的差距说明，把练习分配到瓶颈比换策略头有效得多。

### 28. RoMo Hands（1↑）

[HF 论文页](https://huggingface.co/papers/2611.31766) · Roblox Corporation · [项目页](https://romodataset.github.io/romo-hands/)

### 29. Nemotron-Labs-VisualCreation（82↑）

[HF 论文页](https://huggingface.co/papers/2611.31358) · NVIDIA · [模型](https://hf-mirror.com/nvidia/Nemotron-Labs-Image-30B-A3B)

- 方法：Pixel as Code——光栅图用学到的离散视觉 token，结构化产物用显式程序；共享的生成-渲染接口把两者接到图像、矢量、网页、文档的视觉反馈上；Nemotron harness 做规划与候选选择，并对可编辑的结构化/混合产物做定点修复。

### 30. ThinkMorph-SSL（21↑）

[HF 论文页](https://huggingface.co/papers/2611.32183) · [代码](https://github.com/ThinkMorph/ThinkMorph-SSL)

- 问题：交错多模态推理（先生成中间图再继续推）通常靠任务专属演示来训，而这类演示很难收集。
- 方法：两阶段，用图像本身当监督。第一阶段把上色、去噪等视觉 pretext 任务转成无指令的交错轨迹：描述损坏图→生成恢复图→解读结果；第二阶段用自动构造的演示做问题驱动的指令微调。

- 为什么值得看：把「中间图」的监督从人工演示换成自监督 pretext，数据成本一下降下来，而且不依赖更强的教师模型。

### 31. Qwen-Image-HD（21↑）

[HF 论文页](https://huggingface.co/papers/2611.32736)

- 问题：直接在全分辨率画布上微调生成器要长序列和大量算力，资源有限时局部还会出现不自然的重复条纹。
- 方法：改成局部训练加块自回归生成：每步预测 1K 尺度的一个 tile，条件是高分辨率的上/左邻块与一张压缩历史缩略图；把历史与目标映射到共享画布坐标系来表达空间关系与尺度差；推理用 Wavefront-AutoRegressive 在多卡上并行生成同一反对角线的 tile。
- 数字：Qwen-Image-Bench 4K 上总体优于 FLUX-3-Image-Klein 的直接 4K 生成；比同骨干全图 4K SFT 画质更好、训练算力更低、推理更高效，原分辨率对比下重复条纹更少。
- 为什么值得看：把 4K 生成的平方级成本拆成线性 tile，并用画布坐标解决了「邻块尺度不一致」这个实打实的工程难点。

### 32. iTDM（14↑）

[HF 论文页](https://huggingface.co/papers/2611.30986) · HKUST · [代码](https://github.com/Luo-Yihong/iTDM)

- 问题：前向扩散 RL（确定性 ODE 采样、不回传轨迹）看着新，其实等价于带符号的 reward-weighted regression；baseline 相减隐含「策略速度 = 行为边缘速度」，在 CFG rollout、离线/离策略、在线自一致性不完美时都不成立，会注入 baseline 漂移。
- 方法：对 Trajectory Distribution Matching 取无穷小极限，经 posterior-score 恒等式得到锚在行为速度上的样本级梯度，不学额外的 reward-tilted 目标分数；用在线辅助 denoiser 追踪该速度，在辅助最优处保证精确的 baseline 不变性。
- 数字：组合生成、文字渲染、偏好对齐上取得 in-domain 与 out-of-domain 双 SOTA；GenEval2 收敛快近 3×，可平滑扩到 0.87 不崩；扩到 5.6B 的 FLUX.3 仍有效。
- 为什么值得看：这是一篇「掀开已有方法隐含假设」的论文，结论对所有 diffusion RL 实现都成立，不只是图像生成。

### 33. MAGPIE（13↑）

[HF 论文页](https://huggingface.co/papers/2611.32462) · KlingAI Research

- 问题：多参考图生成要保主体外观、又要按指令摆位置；现有组合引导没有在合成前把关系显式实例化，错了只能看结果猜。
- 方法：把目标构图表示成可执行 Blender 程序定义的简化 3D 场景；coding agent 把每个实例链接到参考图，对照指令检查几何与渲染视角并改程序；最终 proxy 渲染作为图像生成器的视觉计划；用 MAGPIE-Instruct-3K 训生成器跟随计划。
- 数字：DreamOmni2 与 SconeEval 上同时提升 Qwen 与 FLUX；FLUX 在 DreamOmni2 的总体成功率 +28.21 点；SconeEval 上总体分最高。
- 为什么值得看：「先构造可检查的 3D 计划，再渲染」把多参考生成的错误从像素空间前移到可 debug 的程序空间。

### 34. CodecOPSD（12↑）

[HF 论文页](https://huggingface.co/papers/2611.31184) · [代码](https://github.com/Kiteretsu77/CodecOPSD)

- 问题：统一视频生成把所有条件（身份、涂鸦、深度、运动）都 token 化拼进序列，条件 token 很快主导算力，而其中大部分时空信息是冗余的。
- 方法：借经典视频编码的思路做条件 token 剪枝，丢掉冗余 token；再用 on-policy self-distillation 训一个 DiT adapter，让它学会这种剪枝模式而不掉画质。
- 数字：16 种条件模态上平均剪掉 66% 的条件 token，几乎无质量损失；去噪快 2×，KV cache 模式显存最多降 73%；条件越多、帧越长、分辨率越高，收益越大。
- 为什么值得看：「条件即成本」问题的一个干净解，而且能外挂到已有生成模型上。

### 35. RoomTokens（11↑）

[HF 论文页](https://huggingface.co/papers/2611.30219) · 3D Language & Generation Research Group · [代码](https://github.com/3dlg-hcvc/RoomToken)

- 问题：3D 室内场景生成要么把场景当物体向量序列（碰撞与越界只能靠损失或后处理），要么用语义图（丢掉实例与朝向）。
- 方法：切片结构化 token，每个 token 存语义类、实例-颜色身份、朝向场；用 MDIRT（RoomTokens 上的 masked 离散扩散）联合去噪三个通道，共享跨切片骨干；建筑 token 作为显式平面图约束被 clamp。
- 数字：3D-FRONT 上布局保真与物理一致性均优于序列/向量法与 map 法；摘要未给具体 mIoU 或碰撞率。
- 为什么值得看：把实例分组、朝向估计、3D 范围都编码进 token 而不是留给后处理，是离散场景生成的正路。

### 36. VenusOCR2.0（9↑）

[HF 论文页](https://huggingface.co/papers/2611.32617) · Tencent · [代码](https://github.com/flow3rdown/VenusOCR)

- 问题：文档解析要同时高精度与高吞吐，而自训练数据引擎很容易把模型训崩。

### 37. Residual Guidance（9↑）

[HF 论文页](https://huggingface.co/papers/2611.32820) · KAIST AI · [代码](https://github.com/nahyeonkaty/residual-guidance)

- 问题：流式视频生成逐 chunk 出图，用户中途改 prompt 后模型仍跟着旧 prompt。作者定位为 context inertia：上一 chunk 是强先验，压住了新 prompt；而且即使 cache 只留上一 chunk 仍会惯性，丢掉 cache 又断视觉连续性。
- 方法：不改 cache，而在 cache 外测一个修正量——把上一 chunk 重噪后、在无 cache 条件下用新 prompt 去噪一次，把残差加到下一 chunk 的早期去噪步，也就是内容基本定型、新 prompt 被压制最狠的阶段；免训练，每 chunk 只多一次前向。
- 数字：从单次切换到长序列多次切换，显著提升已有流式模型的切换能力（包括自带切换机制的模型），画质基本保持；无需 per-model 调参。
- 为什么值得看：「测在 cache 外、加在决定期」这个修正极简，工程上几乎零成本就能接进现有实时管线。

### 38. LoopDVR（9↑）

[HF 论文页](https://huggingface.co/papers/2611.32067) · GVC Lab, Great Bay University · [代码](https://github.com/Intellindust-AI-Lab/LoopDVR)

- 问题：稠密视觉识别模型参数大，但直接减宽或减深会破坏不同深度学到的不同变换。
- 方法：把 ViT 骨干与 Transformer 解码器的 block 跨层复用；按层间表示差异选共享组，最后一个骨干 block 保持独立以构造多尺度特征；每个共享 block 用组内末层预训练权重初始化；每层加独立 Loop Adapter 保留深度特异变换；再把视觉表示蒸馏进循环骨干。
- 数字：参数减约 28% 而精度有竞争力；LoopDet-S 仅 7.0M 参数达 50.9 box AP；在稠密识别任务上取得最佳精度-参数权衡。
- 为什么值得看：循环深度在检测/分割上也开始算得过来，而「按表示差异分组」比均匀共享合理得多。

### 39. PINE（7↑）

[HF 论文页](https://huggingface.co/papers/2611.29389) · The University of Melbourne · [代码](https://github.com/AIGeeksGroup/PINE)

- 问题：几何（点图、法向）与语义（实例）通常由不同网络或不同 pass 得到，慢且不一致。
- 方法：一步 Omni Diffusion Transformer，一次前向出点图、表面法向与实例图；每张图是一个 token 流，用 stream mask 控制哪些流交互；相机感知的 ray encoding 按光线而非像素定位 token；grounding attention 把 DINOv3 特征的亲和度加进 attention logits。
- 数字：仅用 139K 合成图训几何，给定或不给定内参都达 SOTA 点图、法向平均排名第一；大物体实例超 SAM，而训练图不到其 1%；三图联合预测比 MoGe-3 + SAM 快 5.7×。
- 为什么值得看：「一次前向、多流、按光线定位」是把几何与语义合流的正确接口，而不是再拼两个模型。

### 40. AdProducer（4↑）

[HF 论文页](https://huggingface.co/papers/2611.31466) · University of Central Florida · [代码](https://github.com/lky-ang/AdProducer)

- 问题：广告视频不只是画面合成，还要理解产品、决定卖点怎么呈现；产品调研与创意设计互相牵制。
- 方法：端到端 agent：多模态 agent 用网页与图像搜索调研产品，转成卖点驱动的 storyboard，指导冻结的视频生成器；造 AdProducer-SFT/RL 数据，先 SFT 再 RL，联合优化 storyboard 与视频级奖励；提出 AdCreation-Bench（305 个 brief、8 个领域、PG-Score + Ad-Score）。

- 为什么值得看：它说明当前广告视频质量的主要瓶颈在「调研→卖点→分镜」这段 agent 工作，而不是生成器本身。

### 41. Distill to Loop（4↑）

[HF 论文页](https://huggingface.co/papers/2611.31977) · Virginia Tech · [代码](https://github.com/WinterCCC/Distill-to-Loop)

- 问题：循环 diffusion transformer 多是从零训，把完整预训练成本又付一遍，而强预训练的非循环模型已经存在。
- 方法：把预训练 DiT 蒸馏进循环学生，block 用教师初始化；把蒸馏写成朝教师的不动点迭代，每次循环都朝教师输出训，每次循环是深度方向的一步 ODE；因此一个模型测试时可跑任意循环数，还能把高阶 ODE solver 用到深度维；另构造 loop guidance（不同循环数输出之间引导）。
- 数字：SD3-medium 上约 37% 参数的学生，2–4 次循环在 GenEval/ImageReward/PickScore/HPSv2.1 平均追平教师；2 次循环只用约 58% 教师算力；四步 SD3-medium 上 loop guidance 把四指标均值从 88.2 提到 99.2。
- 为什么值得看：循环深度从「重训一个架构」变成「蒸馏即可得的推理旋钮」，这条路对已有大模型最友好。

### 42. Align the Pair（3↑）

[HF 论文页](https://huggingface.co/papers/2611.29547) · [代码](https://github.com/Mingxiao-Li/RePrime)

- 问题：一步生成器的表示对齐该加在哪条训练路径？加在生成路径（纯噪声样本）是自然选择，但那里没有实例对应。
- 方法：在 Priming（先重建损坏图、再用最优传输匹配特征分布）框架上系统对比两条路径；发现对齐生成路径在 17 种配置里全部让 recall 崩（0.45→0.15–0.25），而对齐「损坏图-干净图」的配对重建路径、用冻结 DINOv2，在所有设置都有效；并给出解释——目标不含实例信息时，最优对齐特征是类内常数，损失会把样本拉向类原型。
- 数字：ImageNet 256×256 上 priming epoch 减半即追平 160-epoch 基线，后训练更新少 4× 还超过其最终质量；FID 1.30（B）/1.155（L）；单阶段变体 115M 参数 FID 1.22；配对路径对齐形成的 interface block，其语义可预测 16 个模型的样本质量。

### 43. Escriba-OCR（2↑）

- 问题：教育反馈需要保留学生原文的错误（拼错、换行、划掉、插入），而 VLM 天生倾向把字改写正确。
- 方法：在 BRESSAY（1000 篇手写巴西葡语作文）上建基准，除 CER 外加错误保留、凭空纠错、编辑标记 P/R、行结构，用配对 bootstrap；只用可校内自部署的开源模型；在 647 页训练集上微调 LightOnOCR-3-1B，单卡 85 分钟。

### 49. Split LM Privacy（5↑）

[HF 论文页](https://huggingface.co/papers/2611.31752) · Setloop · [代码](https://github.com/setloop-io/Separating-Measurement-Failures-from-Defence-Failures-in-Split-Language-Model-Privacy)

- 问题：split-learning 隐私评测会以多种方式失败：漏看梯度通道、把重建对齐到错位标签、未校准探针就测防御。把测量失败当成防御失败，结论会完全变。
- 方法：对四个 split-LLM campaign 做回溯性证据再分析，加两项范围检查（host key custody、变分互信息界）；把每条主张映射到五种可采性状态；19 个配置的探索加七格防御重设计试点；1522 项检查、122 个 SHA-256 固定产物可复跑。
- 数字：24 个必需探针只有 4 个合格，但这 4 个校准探针仍在 13 个配置里确认了合格 breach；其余 6 个被效用或学习增益失败排除；七格试点中 2 个量化配置未过效用门，校准 next-byte 结构探针在 7/7 格突破 0.02 门（0.097–0.112），标点属性探针达 0.79–0.89，最终 4 个失败、3 个未定。
- 为什么值得看：隐私论文里的「攻击成功」常混着测量错误，这篇给了一套可采性分类学，值得当审稿清单用。

### 50. Caption Metric 审计（4↑）

[HF 论文页](https://huggingface.co/papers/2611.30488) · [代码](https://github.com/morninghut/ic-dataset-audit)

- 问题：学习式图像描述指标在人评上训练又在人评上测试，报告的相关系数其实是一个泛化声明，但没人审过。
- 方法：对 Polaris、Nebula、Spica 三套最新人评做像素级匹配审计；控制重训；把 Kendall τ 拆成「检出最低分样本」与「其余排序」两项；提出新协议——只用不含测试样本训练的模型来排名，同时报两项，并用配对检验比较。
- 数字：Spica 训练集约含 Polaris 测试集的三分之二，人评分完全相同；Pearl 的虚高只出现在重复样本上且随 epoch 增大，DENEB 不到 1 点；τ 的第一项贡献了大部分相关性且接近饱和；冻结特征上的 ridge 回归追平或超过三个学习指标；按新协议，零样本 VLM judge 在三套新测试集上排第一。
- 为什么值得看：它把「指标涨了」拆成「记住了测试集」与「真会排序」，这套审计对任何用人评训练的评估器都适用。

### 51. Clinical3D-Bench（4↑）

[HF 论文页](https://huggingface.co/papers/2611.32094) · clinicalspace · [项目页](https://clinicalspace.github.io/clinical3d-bench/)

- 问题：医院空间推理要跟踪长得一样的设备、理解病人相对方向、判断通道宽度，现有基准覆盖不足。
- 方法：3368 题、8 种题型，基于 373 个病房布局的第一视角漫游；布局按医院设计规范生成、答案由 3D 场景算出、成对场景状态检验模型是否随证据改变答案；10 位医生筛查布局；另给 Clinical3D-45K 训练集与 GeoJeV（让 MLLM 真正做 3D 计算而非只看图）。
- 数字：35 个 MLLM 中最好的开源/闭源为 45.7%/53.6%，答案先验 40.8%，医生子集 79.0%；32 个开源模型中 27 个在病人相对方向二选一上低于 40%；微调后两个 MLLM 超最好闭源 16–20 点；直接把 3D 图当输入几乎不被使用——换成另一段视频的 3D 图，准确率也几乎不变。
- 为什么值得看：「给了 3D 输入却不用」是很硬的诊断：接口不等于能力，这一点对多模态具身研究普遍适用。

### 52. GRAPE-Bench（4↑）

[HF 论文页](https://huggingface.co/papers/2611.33020) · [代码](https://github.com/zhangce01/GRAPE-Bench)

- 问题：视频推理模型在视觉退化下是否可靠？现有基准多靠合成退化或难题，缺自然退化，也缺「简单但安全相关」的判断。
- 方法：联合评退化条件与问题难度：合成集覆盖 12 种 corruption（日常与驾驶视频），另加夜间、雨雪雾的真实驾驶；每段视频配三个递进难度的问题；再用 preference steering 连续控制安全判断与难题推理之间的取舍。
- 数字：合成与真实条件下模型排名出现反转；合成数据微调把 Qwen3.5-9B 的真实准确率从 76.7% 提到 81.1%；clean-privileged on-policy distillation 在另一推理设置到 80.4%；偏好引导可调取舍而总体准确率几乎不变。
- 为什么值得看：排名反转意味着「在合成退化上选模型」会选错，这对落地是直接风险。

### 53. PyraFault / ZoomTrace（3↑）

[HF 论文页](https://huggingface.co/papers/2611.29150) · [代码](https://github.com/Yan2266336/PyraFault)

- 问题：视觉 agent 在整张病理切片上按倍率游走，但一个看起来合理的观察未必来自它声称的位置，尤其跨倍率、组织相似的区域。
- 方法：形式化 cross-magnification provenance verification：判断证据是否支持声称的空间关联、能恢复就恢复源、证据不足就 abstain；PyraFault 含 306 万坐标监督样本、2200 例、5 个 TCGA cohort；ZoomTrace 先估观察来源再评与声称位置的一致性，结合物理尺度对齐、视觉检索、几何精修与可靠性估计。
- 数字：503,320 个测试样本上 AUPRC 0.969 / AUROC 0.987，Efficient LoFTR 为 0.789 / 0.903；接入 agent 工具链能减少被污染的观察与静默失败，但下游增益取决于 agent 与阈值。
- 为什么值得看：把「agent 的观察可信吗」做成可验证任务，是医疗 agent 落地绕不过去的组件。

### 54. SpatialArena（3↑）

[HF 论文页](https://huggingface.co/papers/2611.32816) · [代码](https://github.com/mvp-ai-lab/SpatialArena)

- 问题：几何基础模型的进展没法可靠比较：各论文采样帧、分辨率、split 都不同；up-to-scale 对齐的误差可能比模型间差距还大（深度拟错空间误差近 3 倍，轨迹对齐把失败方法的误差低估最多 2.6 倍）；还缺长视频、动态场景与航拍。
- 方法：统一指标与规则的开放竞技场，用稳健且确定性的对齐；5 个任务（单目深度到 SLAM）、23 个公开数据集共 418,929 图，加自采的 Spatial Arena；评了 52 个模型。
- 数字：单目深度在公开基准上接近饱和、在大规模非受控场景远未饱和；进步现在来自跨帧跨视角的一致性，前馈 3D/4D 模型追平或超过单目专家，并超过视频深度模型。
- 为什么值得看：它先说「以前的数不可比」，再给一套可比基线——这类基准比再刷一个 SOTA 有用。

### 55. GeoDecisions（1↑）

[HF 论文页](https://huggingface.co/papers/2611.30564) · CRUISE, UNSW · [代码](https://github.com/cruiseresearchgroup/GeoDecisions)

- 问题：决策模型（输出候选标签上的概率分布）越来越多被当作分类器或评估器，但它们能否利用空间上下文、是否有地理偏差，并不清楚。
- 方法：两个任务——地理感知图像分类、对客观/主观话题的地点评分；6 个决策模型对比监督任务模型；另提一个免训练的地点先验融合方法。
- 数字：空间感知需要视觉，只给文本坐标不足以分类日常照片与卫星图；开放权重决策模型准确率更高，但错误在空间上更聚集；5 个主观话题上，所有决策模型都给社会经济条件更低的地点更低评分；地点先验能提升空间感知，且不显著增加偏差。
- 为什么值得看：它把「地理偏差」从数据偏差议题变成模型评分行为的可测问题。

### 56. FATCAT（1↑）

[HF 论文页](https://huggingface.co/papers/2611.31129)

- 问题：对齐被当成模型安全的主机制，但已有对抗评测都默认硬件是完整的。
- 方法：首个物理故障注入攻击：非侵入式电磁故障，针对有物理接触的 GPU SoC，不需要软件权限或模型层访问；用自主 RF 侧信道触发，把故障同步到 prompt 的 prefill 阶段，破坏 LPDDR5 DRAM 与片上 LPDDR 接口上的安全关键内存事务，而不让系统崩溃、仍保持模型连贯。
- 数字：Jetson Orin Nano 与 AGX Thor 上，Llama 3.2 1B 与 Gemma 3 1B 被稳定逼出受限请求；在 SmolVLA 控制的 6-DoF 机械臂上，攻击静默破坏模型导致突跳，两次试图夹住论文作者。
- 为什么值得看：结论很硬——没有硬件容错，模型层对齐给不了安全保证。这是今天最该被认真对待的「边角」论文。

### 57. Semantic-Reversal 检索镜片（1↑）

[HF 论文页](https://huggingface.co/papers/2611.31442) · Pelloran Inc. · [代码](https://github.com/pelloran-inc/pelloran-safety-lens)

- 问题：稠密检索会被「语义反转陷阱」骗：文档 B 与正确答案 A 只差一个改变意思的小编辑，E5-Large-v2 的原始 cosine 在 5000 池子里把 B 排进 top-10 的比例达 82–100%。
- 方法：学一个小投影 W: R^1024→R^d（d=11 或 32），在声明案例集上按确定性配方训练；再用边界值求解替代稠密特征分解的谱图检索加速器，在 10 万池上服务该投影。
- 数字：四个域（法律/医疗/专利/金融）、十二个（域, 池大小）设置、池到 10 万，声明案例上 HN@10=0.0000，正确复述保留 93–99%；10 万池每域 HN@10 仍为 0.0000，约 300 条查询的套件 0.6–1.1 s（约 2–4 ms/查询）；每文档只存几个 float，索引小约 90×；但改写查询对未变语料的正确率会降到约 0.79。
- 为什么值得看：结论有明确边界（只在声明案例与测量池上、无概率界、跨域只部分迁移），这种自我限定反而比夸大更可信。

### 58. EEGJev（1↑）

[HF 论文页](https://huggingface.co/papers/2611.32100) · [代码](https://github.com/dengzhe-hou/EEGJev)

- 问题：一段 EEG 可以支持多种解码任务，固定标签测试看不出模型能否随问题与选项变化而切换。
- 方法：一次前向给候选答案打分的快速决策模型；EEGJev-Bench 覆盖 6 类问题、19 个公开 EEG 源；固定记录与选项、只换问题（包括训练时配对的属性，如表情与受试者被要求用哪只手）。
- 数字：13 个测试源上按请求属性选标签的准确率 99.70%（均匀选择为 49.20%）；具体答案的平衡准确率 62.04%；95 分位响应时间短于 NeuroLM 在匹配验证题上逐题作答。
- 为什么值得看：99.70% 与 62.04% 的落差正好说明「选对属性」和「选对答案」是两件事，评测不该只报后者。

### 59. 受控负载下的语言模型退化（0↑）

[HF 论文页](https://huggingface.co/papers/2611.27404) · [项目页](https://hf-mirror.com/collections/kutomanovhennadii/iec-passports-6ae3ad9fe2c798814eb8a3dc)

- 问题：负载上升时模型错误变多，但背后是不同过程：跟丢原文、守住位置却执行错规则、改了规则根本不管的词。
- 方法：用「按规则替换词」的无意义文本控制负载，分别设定文本长度、答案中词的位置、替换密度、规则数、规则在表中的位置；对齐答案与参考做逐词追踪，用考虑「请求间难度离散度随负载变化」的统计模型，分离出 synchronization、rule execution、misfires 三条负载依赖律，组成模型 passport；给出七个模型的 passport。
- 数字：摘要未给具体数值，贡献是分离方法与七份可对比的 passport。
- 为什么值得看：它问的是评测的正确粒度——把「变差」拆成可归因的分量，比一个总分有信息。0 票大概是因为标题太素，不是内容太浅。

## 今天的三个观察

**一、agent 的竞争点已经从「能力」移到「元决策」，而且元决策可以被可验证信号训练**，今天票数最高的三篇 agent 论文恰好对应三个元问题：RLVB 决定「证据够不够、要不要停」，NightWatch 决定「什么时候该重新看一眼」，ACAP 决定「哪部分交给谁做」。三者都不改基座模型的能力，只改决策时机与分工，收益却分别是 +17.1%、-33% 墙钟时间、-28.2% 时间成本。这比再刷一个 benchmark 分数更接近可部署的进步。

**二、评测正在从「排行榜」变成「诊断仪」，而且诊断出的缺口比分数更难造假**：ICLWorld 的 82% vs 27%、RoboDojo-Mirror 的 62.5 点、Clinical3D 的「给了 3D 图却不用」、SpecEngineeringBench 的 80.48% 覆盖率对 26.36% 检出率，都是同一个方向：把「看起来会」拆成「哪一步不会」。这类工作票数往往不高（4–29 票），但它们的结论保质期比 SOTA 长。

**三、架构侧的共识是「非均匀」：容量、深度、条件 token 都该按需分配**：Loom 给每个 token 一条矩阵残差流、FFN 内在维度显示中段更宽、Model Carving 让训练剪掉整层、CodecOPSD 剪掉 66% 的条件 token、LoopDVR 与 Distill-to-Loop 把深度变成可复用的循环。它们的方法不同，但都在反对同一个默认值——「每层一样、每个 token 一样、每个条件都留着」。这条线目前还没有统一的评测，可能是接下来半年最值得跟的方向。

## 数据与方法

- 数据抓取：`python3 code/ai-daily/fetch_papers.py --date 2026-11-25`，落盘 `~/tmp/ai-daily/2026-11-25.json`；本期 `count=59`，与 JSON 中 `papers` 数组长度一致。
- 排序口径：Top 10 按全榜 upvotes 降序，同票按 arXiv id 升序；正文按主题分组，组内同样按 upvotes 降序、同票按 id 升序。正文序号（1–59）与 Top 10 名次无关。
