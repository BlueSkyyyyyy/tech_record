今天最热的两个都是模型报告，但卖点不在权重。Sage S2.1 Flash（64↑）把 320B MoE 的 agent 能力压在可验证环境上——工具、搜索、编码、ML 实验与科学软件，任务是否完成按执行结果、环境状态变化或提交物判定；K2-Horizon（56↑）一次放出 0.9B 到 375B-A23B 六个全开源模型，连预训练数据管线和每一阶段的中间 checkpoint 一起给，还顺手把 attention 的 value 投影也做成 MoE。两条合起来说明：前沿模型的竞争点正在从「榜单分数」转向「环境 + 可复现管线」。

## 一、前沿模型与训练/推理账本

### 1. Sage S2.1 Flash（64↑）

Sage S2.1 Flash Technical Report · Intern Large Models · [2611.21072](https://huggingface.co/papers/2611.21072) · [code](https://github.com/InternLM/Sage-S2.1-Flash) · [项目页](https://internlm.github.io/Sage-S2.1-Flash/)

- 问题：科学证据和交互环境是两种输入——分子图、生物序列、谱图要专用编码，工具/搜索/编码又要求模型在环境里动手；通用 MoE 能否用一个 backbone 同时吃下。
- 方法：320B 参数的通用 MoE。Sage Sci-Perception 用独立编码器处理分子图与生物序列，谱图表示成按测量顺序排列的 patch；模态专用 projector 把这些表示投进共享 backbone，与文本、图像一起处理。
- 训练环境：为 tool use、search、coding 以及 ML 实验、科学软件搭可验证环境；完成与否看执行结果、环境状态变化或提交的产物，而不是看模型自述。
- 数字：33 个 benchmark、7 个领域，对 5 个 baseline 的主比较里，OfficeQA Pro 72.2、MLE-bench Lite 90.3 HumanRank、Harvey LAB、SpreadsheetBench-2 排第一；OSWorld-Verified 85.2、WebArena-Verified 67.6、DeepResearch Bench-II 54.2 排第二。
- 为什么值得看：它的强项是「用文档证据、产出可核验的 workbook」，这恰好是 agent 最容易被自评糊弄的部分。标题写 S2.1 Flash、摘要正文写 S1.5 Flash，版本号对不上，但数字按摘要记。

### 2. K2-Horizon（56↑）

K2-Horizon: A Frontier Fleet of Open Source Language Models · Institute of Foundation Models · [2611.21003](https://huggingface.co/papers/2611.21003) · [项目页](https://ifm.ai/k2/)

- 问题：开源模型通常只放权重和模型卡，「怎么造出来的」仍是黑盒；同时推理模型的注意力计算越来越贵。
- 方法：六个模型，从 0.9B dense 到 375B-A23B MoE，覆盖数学/科学、软件工程、深度研究、办公自动化。建模上引入 Mixture-of-Value Attention（MoVA），把 MoE 用到 attention 的 value 投影上，再加 softplus attention gating，让门控更灵活。
- 效率与数字：36B-A4B 同时用 MoVA 与 softplus gate，在同数据上几乎追平 32B dense，active 参数只有七分之一；Uno 是无损扩散适配器，不需要单独 draft model，解码最高 2.2×。四个模型共享同一份 22T token 语料与配方，因此能做受控的 scale/sparsity 对比；造数据管线产出了约 10T 合成预训练 token。
- 开放程度：按 LLM360 的定义放全流程——每个训练阶段的中间 checkpoint、预训练数据、训练日志，以及 xLLM（dense/MoE 生产训练）和 RL360（RL 栈）的代码；连造数据的管线也逐条文档化。
- 为什么值得看：这份发布里最值钱的不是权重，是 22T 配方 + 10T 合成管线 + 中间 checkpoint。对训练系统，这是少见的可复现全链路样本。

### 3. Calpha（11↑）

Calpha: Toward Native Biomolecular Intelligence in a General-Purpose Language Model · Shanghai Jiao Tong University · [2611.20986](https://huggingface.co/papers/2611.20986) · [code](https://github.com/yliust/Calpha) · [项目页](https://calpha-ai.com)

- 问题：生物分子基础模型会折蛋白，通用 LLM 会用自然语言推理，但两者互不相通——前者的能力不在 LLM 里，后者的推理也进不了结构预测。
- 方法：第一步只做单链。Qwen3.5-9B 读一条用 ESM2 residue 特征增强的序列，可以文本回答，也可以吐一个 token 调用预训练 SimpleFold 结构头；结构头只能通过 Qwen 的 residue states 获得蛋白信息。
- 数字：固定折叠请求下，TM-score 均值 0.808（FoldBench-334 dev）、0.635（CASP16 domains）、0.900（CAMEO 风格 PDB 集）。对 ESM2-3B 编码 + 微调 SimpleFold-3B 头的 baseline：100–299 残基的三个配对置信区间都含 0；300–600 残基平均差 −0.044、−0.160、−0.025。
- 代价：四种英文请求每次都能触发折叠；但蛋白训练把 350 题 MMLU-Pro 子集从 77.4% 降到 70.3%。多链复合物、结构理解、语言推理对坐标的影响都还没做。
- 为什么值得看：把 LLM 当「调度器 + 状态提供者」是可行路线，但长链掉点和通用能力退化是明账。这类「通用模型兼职专业头」的账，应该都按这两项报。

### 4. Latent Feedback（5↑）

Latent Feedback Is a Compute and Data Amplifier · Institute of Foundation Models · [2611.20404](https://huggingface.co/papers/2611.20404) · [code](https://github.com/ifm-ai/LoRM)

- 问题：高质量数据用完时，常见做法是多刷几个 epoch，但每一遍的边际价值递减。Latent feedback 把每个 token 的顶层状态喂进下一个 token 的输入，是另一种花算力的方式，但此前没和「同算力多刷几遍」的 vanilla Transformer 正面对比过。
- 方法：在模型尺寸、unique data、epoch 三个维度做网格，每个点两边都调参；再把两个模型拟进同一条 scaling law，latent feedback 相当于「参数更多的 Transformer」。
- 数字：最多省 48% 算力、47% 的唯一数据；law 用 60M–271M 模型拟合，在留出的 778M 上 loss 预测误差在 0.3% 内、两模型 gap 在 0.05% 内。唯一数据相对模型规模稀缺时收益消失——而今天的模型远没到那个区间。
- 为什么值得看：数据墙下的另一条轴，而且给出的是可外推的 scaling law，不是单点提升。对训练系统，这等于用结构上的 recurrent 反馈去换数据重复。

### 5. LoopFill（3↑）

LoopFill: Pipelined Multi-Token Speculative Decoding for Looped Transformers · UIUC · [2611.19649](https://huggingface.co/papers/2611.19649)

- 问题：looped Transformer 反复用同一组层，参数省，但每生成一个 token 都要串行走多轮，解码延迟高。已有的 pipelined self-speculative 方法用浅层 loop 的预测做 draft，可下一个 token 必须等前一个到达 drafting depth 才能进管线。
- 方法：training-free。把 multi-token suffix draft 与 shallow-loop 预测合到同一棵 draft tree：suffix lookup 可以立刻延长一个浅层预测，于是多个未来 token 能一起进管线；shared block 一次算出不同 loop depth 上的最高分候选，full-depth verification 保住自回归分布。
- 数字：7 个 benchmark 上，相对 greedy 自回归平均加速 5.85×（Ouro-2.6B）与 5.13×（Huginn-3.5B）；比最强 baseline LoopAhead 再高 40% 与 25%。
- 为什么值得看：looped 模型「层数可复用」的承诺，一直卡在解码延迟上；training-free 意味着可以直接套到已发布权重，不用重训。

## 二、Agent：注入防御、组织交付与程序优化

### 6. SPILLWAY（44↑）

SPILLWAY: Separating Target Admission from Sanitization to Defend Tool-Using Agents against Prompt Injection · SAINT Machines · [2611.07222](https://huggingface.co/papers/2611.07222) · [code](https://github.com/saintmachines/spillway) · [项目页](https://saintmachines.github.io/spillway/)

- 问题：工具 agent 会发邮件、改文件、付款，网页或共享文档里藏一句指令就能让它把钱和数据送给攻击者。现有 runtime 防御常把「放不放行」交给 LLM——这个判断会读到攻击者文本，还给每一步加模型调用；provenance 防御虽把模型挡在最终检查外，却要先让模型规划或路由任务。
- 观察：动作「去哪」其实写在工具的 typed returns 里——邮件的 sender、付款的 account 都在类型化字段里，而注入指令只能是自由文本。
- 方法：确定性 floor，不需要 per-task plan。只有当工具输出里出现、但用户任务里没有的 target value，是由只读工具在 typed field 返回、或被固定 delegation rule 覆盖时才放行；确定性 sanitizer 在模型读之前删掉规则命中的 instruction-like 区域，并保留被删片段作证据；local judge 只能恢复被拒的调用，不能恢复 target 落在被删文本里的调用。
- 数字：3 个 backbone，其中一个跑 7 个 task suite；标准模板注入无一能把动作重定向到攻击者 target，mean utility 与 composite（NRP、ERS）在所受防御里最高；伪造 chat template 直接得 0；开源 RL attacker 下 in-scope ASR 为 0.007；全程没有 defense-triggered backbone 重跑，模型调用几乎不增加。
- 为什么值得看：它把「能不能放行」从模型判断变成类型系统加固定规则，拒绝是可审计的。对 agent 工程，这比再训一个注入分类器更接近可部署的形态。

### 7. SWE-CoWork（34↑）

SWE-CoWork: Benchmarking Coding Agents as Digital Employees in Organizations · Tokenwave.AI · [2611.20218](https://huggingface.co/papers/2611.20218) · [code](https://github.com/TokenWave-AI/swe-cowork-bench) · [项目页](https://tokenwave-ai.github.io/swe-cowork-page)

- 问题：组织里的 coding agent 不是拿到一个完整 issue 就开写。它要先搞清楚「要建什么」，跟同事协作，再验证交付；需求往往分散在人脑和工作记录里，还互相冲突。
- 方法：101 个开发任务，覆盖 101 个真实仓库、11 种语言、12 个应用域。每个任务把 agent 放进一个有 26 个同事的模拟工程组织，同事职责不同、知识有界、协作行为受控；agent 从一段简短的 handoff 出发，要自己找回需求、调和证据，改动由私有可执行测试判分。
- 数字：评了 11 个模型。前两名满足约 63% 的 fail-to-pass 测试，完整完成的任务却不到 8%。把完整需求提前给，Seed Evolving 与 GPT-6 Astra 的 F2P 提高约 16 个百分点，但完整成功率不动。
- 失败解剖：Claude-Opus-5.5 平均把 93% 的首个问题指向了被问卡片的负责人，最终只拿到 64% 的同事持有需求；被推迟的问题没人跟进；需求拿到了实现仍不完整；31% 被报告为完成的需求测试失败。
- 为什么值得看：会写 patch 和会交付之间，差的是一个需求状态机。对 agent harness，这比再换一个更强的模型更值钱，因为 63% 与 8% 的差距不是代码能力造成的。

### 8. Accelerate Bench（14↑）

Accelerate Bench: Evaluating Agents for Application-Level Program Optimization · Tencent Hunyuan · [2611.20882](https://huggingface.co/papers/2611.20882) · [code](https://github.com/AdAstraAbyssoque/accelerate-bench) · [项目页](https://acceleratebench.com/)

- 问题：应用级优化不是改一个热点函数，而是要在完整程序里找到有用的改动，并让它们互相配合，同时保持计算语义不变。
- 方法：32 个 CPU 优化任务，改编自科学应用与超算竞赛。每题给一个能跑的程序，外加 workload、正确性要求、时间边界、允许改动的范围；agent 自己决定改哪、怎么改。public test 支持迭代，独立 verifier 给最终提交打分。
- 数字：benchmark 1.1 上评 16 个 agent（模型 + harness），Score@1 从 25.5% 到 67.4%。大多数程序是正确的，真正拉开差距的是加速比：前两名在 32 个任务里至少 22 个做到 2×，其余 14 个只有 8–17 个，412 个正确结果里有 125 个低于 1.25×。
- 受控回放：同一份源码只改 build 与 runtime 设置，就跑出 0.29×–2.12×；一个改动的价值取决于另一个改动，可能是 1.01×，也可能是 6.4×。
- 为什么值得看：优化 agent 的分数会被 harness 与环境放大或抹平。对做 kernel 的人，这篇的潜台词是：报 speedup 必须锁构建和运行配置，否则数字没有意义。

### 9. Termination Lag（1↑）

Termination Lag: Coding Agents Solve Early but Stop Late · Pennsylvania State University · [2611.14960](https://huggingface.co/papers/2611.14960) · [code](https://github.com/musacim/termination-lag)

- 问题：coding agent 可能早就解对了，却继续干活——多花的步数不只是成本，还可能把对的改错。
- 方法：定义 termination lag 为「首次正确 patch 到 run 结束」之间的步数；覆盖 5 个模型、2 个 agent 框架、3 个 SWE-bench 数据集，记录并测试执行过程中出现的每一个不同 repo patch，而不是只看最终提交。
- 数字：38–82% 的成功 run 在第一次源码编辑就拿到正确解；这些 run 里，解后步数中位数占 35–37%（Qwen3-Coder）与 54–60%（Laguna-XS.2）；1–8% 的 run 在后续活动中把正确 patch 改坏，最终答案反而错。
- 为什么值得看：早停是几乎免费的收益，但前提是能在 patch 级判定正确，而不是等最终态。和 SWE-CoWork 一起看，agent 的成本一头在需求，一头在停止条件。

### 10. Craftax Goal Compiler（1↑）

Continuation-Guided LLM Evolution of Program Policies and Goal Compilers in Craftax · [2611.19537](https://huggingface.co/papers/2611.19537) · [code](https://github.com/vicgalle/craftax-program-policies)

- 问题：coding agent 能用模拟器反馈合成代码策略，执行时零推理调用；但长程任务里局部改进会伤最终成功率，换一个目标又得重跑一次昂贵的合成。
- 方法：先用 feedback cascade 建立能力，把反馈从 episode return 推到 hierarchical goals 再到 belief updates，每一层都能由模拟器稠密打分；再把控制器拆成 environment interpreter I（models、memory、skills）与 rule program p_0，让 coding agent 去优化一个可复用的 goal compiler C_θ，把结构化任务 g 映射成新程序 p_g。
- 数字：在部分可观测、程序生成的 Craftax 里，只用 episode 级反馈会卡在 <1% 的最终关到达率；用 cascade 后到最终关 50%、击败最终 boss 28%。5 次独立的 compiler search 只用短任务训练，零样本迁到更长任务，既不做任务微调，也不在推理时调 LLM。
- 为什么值得看：「一次合成、多次复用」的编译器形态，比每次让 LLM 现场决策便宜得多。今天的 termination lag 讲何时停，这篇讲复用什么，两个合起来才是 agent 的成本结构。

## 三、具身智能：552B、跨本体与 4D 规划

### 11. ScaleVLA（39↑）

ScaleVLA: Scaling Vision-Language-Action Models to 552 Billion Parameters · galbot · [2611.21607](https://huggingface.co/papers/2611.21607) · [项目页](https://galaxygeneralrobotics.github.io/scalevla/)

- 问题：前沿 VLM 已经能控机器人，但绝大多数 VLA 策略仍用小得多的 VLM backbone，这部分潜力没被用上。问题是：前沿规模的表征能不能直接当机器人学习的地基。
- 方法：把 552B 的 DeepSeek-V4.1-Flash backbone 接到可训练的 action DiT 上，在共享训练设置下系统比较 2B 到 552B 的 VLM，评三项能力：样本效率、泛化、精细操作。
- 数字：样本效率上，10 个 demo 就超过用 50 个 demo 的 2B backbone（87.8% vs 85.6%）；泛化上 LIBERO-PRO 成功率 45.1%，小 backbone 最高 31.3%；真机插充电器从 4/10 提到 9/10，增益集中在接触敏感的对齐段。
- 延迟：尽管有 552B，每个 action chunk 的中位延迟是 216 ms。摘要没给显存占用与部署拓扑。
- 为什么值得看：规模买到的是「更少 demo + 更准的接触」，不是全面碾压；216 ms 说明前沿 VLM 能进控制环，但前提是 action chunk + DiT 这层接口设计对。

### 12. SALA（12↑）

SALA: Semantically Aligned Latent Actions Enable Dual-Axis Scaling of Embodied Foundation Models · [2611.17110](https://huggingface.co/papers/2611.17110) · [项目页](https://sala-vla.github.io/)

- 问题：机器人交互数据贵，第一视角人类视频是补充；latent action model（LAM）比 world-action model 省训练与推理，但多数 LAM 只靠视频重建学 latent action，表征会按外观聚类而不是按动作，人类动作和机器人动作对不齐。
- 方法：不需要配对数据。用无配对人类/机器人片段的语言描述估语义相似度，转成 soft neighborhood 结构，把人类的 latent action 拉向语义相关的机器人 latent；机器人动作重建则把 latent space 锚在控制上。得到的共享 latent action space 同时监督人类与机器人视频。
- 数字：摘要没给绝对指标，给的是两条 scaling 轴——预训练人类视频增加，下游机器人动作预测误差持续下降；后训练加入任务相关人类视频，真机任务成功率显著上升。
- 为什么值得看：跨本体对齐从「像素重建」转到「语言语义邻域」，而且不需要配对数据。对具身数据飞轮，这决定人类视频到底能不能算数。

### 13. Ego Guidance（3↑）

Ego Guidance: Enhancing Robot Policy Learning with Action-Free Human Egocentric Videos · Ant Group · [2611.13685](https://huggingface.co/papers/2611.13685) · [code](https://github.com/llong-cs/EgoGuidance) · [项目页](https://llong-cs.github.io/EgoGuidance/)

- 问题：没有动作标注的人类第一视角视频，怎么用来训机器人策略。
- 方法：基于预训练 VLM 的 SPAR（Shared Prediction on Action and Representation），一个 MoT 架构，让未来视觉状态预测与动作预测共享表征、又提供独立互补的学习信号。
- 数字：摘要没给具体数值。结论是 ego video 学到的表征能提升 OOD 机器人任务，而且随视频数据量继续涨；论文还比较了目标函数选择与数据 curation 的影响。
- 为什么值得看：和 SALA 同一天，两篇都在回答「人类视频怎么变成监督」。这篇的答案是拿「预测未来视觉状态」当辅助任务，路线更偏世界模型。

### 14. JEPA4R（3↑）

JEPA4R: Embodied JEPA World Models with 4D Point Planning · AI Geeks · [2611.19771](https://huggingface.co/papers/2611.19771) · [code](https://github.com/AIGeeksGroup/JEPA4R) · [项目页](https://aigeeksgroup.github.io/JEPA4R)

- 问题：JEPA 世界模型预测未来 embedding 而不是像素，在 latent 里规划；但 2D 图像让操作真正依赖的度量几何变成隐式、和外观纠缠，而且模型「想象」了什么看不见，多数只在仿真里做短程 latent planning。
- 方法：输入单深度相机的点云，在点云 latent space 里预测与规划，policy head 跑在冻结 latent 上，作者称之为 4D point planning；再在冻结 world model 上加一个 decoder，把想象还原成 4D 点云。
- 数字：decoder 在 200 步上的平均点误差 ≤1.1 cm；OGBench 的 Cube-Single/Double/Triple/Scene 都超过 pixel JEPA；MetaWorld 98.4%、Adroit Relocate 88.0%，第二名 R3M 是 96.0% 与 65.3%。
- 真机：只在 digital twin 里训练，JEPA4R 与 policy head 零样本跑在真实机械臂上，夹爪和灵巧手都行。
- 为什么值得看：把世界模型的想象变成可检查的 4D 点云，是评测世界模型最缺的一环；1.1 cm / 200 步是可以拿去做闭环的精度。

### 15. VR 纠正抓取（2↑）

Correcting Persistent Failures in Point-Cloud Grasping Policies using Human Demonstrations in Virtual Reality · HCLTech Robotics · [2611.18919](https://huggingface.co/papers/2611.18919)

- 问题：Contact-GraspNet 这类离线抓取生成器按学到的「像不像能抓」排序，不保证真的能抓起；RL 能直接优化成功率，平均更好，但总有一些抓取长期失败。
- 方法：自动挖掘 RL 持续失败的场景，送到 VR 应用里让人用手抓一次，回传两个抓取点进训练。人只提供「抓哪」，接近路径由机器人自己选。
- 数字：仿真里 RL 把未见物体成功率从 Contact-GraspNet 的 55% 提到 83%；再加 58 条人类演示，hard case 从 24% 提到 45%，接近翻倍；未演示过的相似 case 也恢复了 RL 单独会丢的性能，同时未见物体成功率不降。
- 为什么值得看：人只补最难的那一小撮，数据效率极高。「失败挖掘 + VR 纠正」比全量遥操作便宜得多，是可以直接接进现有 RL 抓取流水线的补丁。

## 四、评测：医疗、审稿、物理与长程经营

### 16. InclusionMed（52↑）

InclusionMed: Benchmarking AI for Inclusive Healthcare · [2611.21218](https://huggingface.co/papers/2611.21218) · [code](https://github.com/panuvi/inclusionmed) · [项目页](https://inclusionmed.ai/)

- 问题：医疗 AI 要在不同角色、任务、照护场景下都可靠，但 benchmark 覆盖很不均匀，一个总分掩盖了场景差异。
- 方法：InclusionMed Atlas 按 3 个医疗角色 × 3 种 AI 能力组织；首版从 388 个候选 benchmark 里做结构化审计与独立复现，选出 4 个公开基准，加上私有的诊断推理基准 DxFiles，共 5 个，覆盖 9 个 role-capability 格子中的 3 个；结果聚合成 InclusionMed Index。
- 数字：总榜 17.5–49.1（满分 100）；分数按角色与能力分别报，同一个模型的排名会随角色/能力变化；用 task-level tag 做基准内分析，Index 前 10 的模型在 patient communication 上全都高于 clinical decision-making。
- 成本：Index 接近的模型，估计推理成本差异很大。
- 为什么值得看：「一个医疗分数」不成立。对评测工程，角色×能力矩阵加成本列，比再刷一个平均值有用；反过来说，只有 3/9 个格子有覆盖，也说明这块基建还早。

### 17. PaperCritic（22↑）

PaperCritic: Training AI Reviewers to Assess the Soundness of Papers · Carnegie Mellon University · [2611.17834](https://huggingface.co/papers/2611.17834)

- 问题：投稿量涨得快，AI 审稿被当成替代方案；但直接模仿人类审稿有问题——审稿同时评 soundness、interestingness、clarity，后两个是主观的。
- 方法：只评 soundness。学习目标同时最大化 precision（review point 是否扎实、有实质）与 recall（覆盖多少高质量参考点）；据此构造 PaperSound-23K：1K 篇 ICLR 投稿、23K 条人类与 LLM 写的 review point，带质量标签；用 precision/recall 的 F1 作 reward 做 RL。
- 数字：in-domain 测试集上超过前沿模型与其他 AI reviewer 训练方法（摘要没给具体分数）；更意外的是迁移——学审 ICLR 论文，能迁到 Nature 系论文，甚至代码审阅、法律合同审阅、故事写作反馈。
- 为什么值得看：把「审稿」拆成可验证的 soundness 点，才谈得上用 RL。迁移结果说明「找漏洞」是可迁移技能，而不是背 ICLR 的行文风格。

### 18. DominoBench（3↑）

DominoBench: Evaluating Multi-Step Physical Reasoning from Still Images · University of Southern California · [2611.20385](https://huggingface.co/papers/2611.20385) · [数据集](https://hf-mirror.com/datasets/emilioferrara/DominoBench)

- 问题：多模态模型能流利描述场景、也能解课本物理题，那它能不能看一眼静图就判断连锁反应的结果。
- 方法：2D 刚体场景的静图，结果由物理模拟器算。854 个 item 组成 427 个最小配对，一个量改 1–3 个网格步就决定「人是否幸存」；每题配四级 hint ladder，最后一级给出决定结果的具体计算。
- 数字：30 个模型、10 个家族。无辅助时，Anthropic、Google、OpenAI 的前沿模型最多答对 72% 的「命运翻转者」，一对双胞胎全对最多 34%；指出决定步骤帮助很小，用文本给精确几何也几乎没用；一旦把决定计算和所需量（包括静图看不到的速度）写出来，同一批模型到 82–92%，小开源模型仍接近随机。
- 为什么值得看：失败点在定量那一步，不在感知。对要规划或行动于物理世界的模型，「说得清场景」不能当作「算得对下一步」的证据。

### 19. OutfitterBench（2↑）

OutfitterBench: Evaluating LLM Agents on Long-Horizon Resource Allocation and Commitment Coordination · [2611.17933](https://huggingface.co/papers/2611.17933) · [code](https://github.com/adminblackjack/OutfitterBench)

- 问题：长程经营里，agent 自己的选择会制造未来约束——承诺了有限产能，就背上未来义务、也关掉了后来的机会。要持续表现好，既得让计划一直可行，又得比较资源分配与被它挤掉的替代方案。
- 方法：经营一家户外装备租赁店 200 天，从 46 个产品的目录采购，处理约 1,100 个预订请求；资本上限固定，预订与不确定的 walk-in 需求争抢可复用装备，可用性随时间变化。
- 数字：7 个前沿 LLM 里，多个 agent 不如一个简单的规则 baseline，只有领先的那个稳定超过它。轨迹分析显示，一些 agent 对已知约束应用不一致，新决策与既有承诺冲突；履约更可靠的 agent 也可能从相当的承诺里拿到低回报，或拖延资源再分配。
- 为什么值得看：长程 agent 的失败常常不是算不动，而是不守自己立下的约束。这需要一个承诺账本，而不是更长的上下文。

## 五、决策与金融：从组合权重到欧洲语言

### 20. AllocFlow（60↑）

AllocFlow: End-to-End Portfolio Trading Action Generation from Raw Market Data · Nanyang Technological University · [2611.19937](https://huggingface.co/papers/2611.19937) · [code](https://github.com/allocflow/AllocFlow) · [项目页](https://allocflow.github.io/)

- 问题：传统组合管理把信号预测与组合构建拆开，学习目标与配置、执行目标对不齐；真实约束是共享资本下多资产的同时配置。
- 方法：端到端 flow matching，直接从原始多资产历史生成联合仓位。cross-asset flow Transformer 以时间市场表征为条件，一次生成所有标的的连续、带符号权重；训练分两阶段——strategy-supervised imitation 先塑造候选组合分布，再用 group-relative RL 结合组合级金融奖励与冻结策略参考做精修。
- 数字：小时级加密永续合约上，RL 精修把 imitation 策略的年化净收益从 27.79% 提到 51.38%，Calmar 从 0.955 提到 4.043，各项指标全面超过 teacher；在额外 6 个月未见的 2026 数据上不重训，Calmar 仍有 4.90。
- 为什么值得看：收益来自「联合生成权重」而不是「先预测再优化」。对做 agent 的人，这是一个把 RL 精修接在模仿之后的干净配方，且验证集是真正的时间外样本。

### 21. Zuse（0↑）

Zuse: A Decision Model for European Languages · Bineric AI · [2611.06238](https://huggingface.co/papers/2611.06238) · [项目页](https://bineric.com/zuse)

- 问题：decision model 读文档、对固定选项返回概率，不生成文本。2026 年出了几个，但没有一个公布英文之外的结果。
- 方法：4B、9B、27B 三个模型，在冻结的开源 base 上训一个 low-rank adapter 加 pointer head，覆盖 27 种欧洲语言。
- 数字与校准：11 个训练外来源、9 个任务组、27 种语言；27B 得 87.5% 准确率，pooled ECE 0.016，按来源加权 0.035。误差按任务结构化而不是按语言——知识任务过度自信、可接受性判断自信不足，三个尺寸都一样，所以一个拟合 temperature 修不了两边；5% 错误预算下能自动化的比例，与 chance-corrected skill 的相关性（Spearman 0.97）高于 raw accuracy（0.91）。

- 为什么值得看：「小模型 + 指针头」在封闭选项任务上极便宜，但能力边界由 base 的语言覆盖决定。对评测，校准必须按任务分层报，一个 ECE 会骗人。

### 22. SMEFT RL（0↑）

A Reinforcement Learning Method to Navigate SMEFT Operator Space · Université de Montréal · [2611.21439](https://huggingface.co/papers/2611.21439) · [code](https://github.com/ReinforcePhysics/ReinforceSMEFT)

- 问题：SMEFT 算子空间是组合爆炸——多个算子同时贡献不同 observable，效应彼此相关，不同的算子组合可以同样好地描述数据。
- 方法：把算子空间探索写成序列决策，用一个轻量 actor-critic，总共约 40K 可训参数；目标不是找单一 best-fit，而是发现一组多样化的高质量理论假设。
- 数字：环境含 132 个 observable，横跨多个粒子物理扇区，其中 24 个测量偏离 SM 超过 1.5σ；学到的策略能构造多算子理论并显著改善 global fit；与 random-subset、random-sequential 两种搜索对比，说明策略确实在导航这个组合空间。
- 为什么值得看：40K 参数就能在巨大组合空间里找出多样解，说明 RL 在这里的价值是「采样结构」而不是模型容量。科学发现类 agent 可以借鉴这个「多样性优先于单一最优」的目标。

## 六、生成模型：语音、长视频与手控世界模型

### 23. VoxMel（20↑）

VoxMel TTS Technical Report · VoxDance-Lab · [2611.20254](https://huggingface.co/papers/2611.20254) · [code](https://github.com/VoxDance-Lab/VoxMel) · [项目页](https://voxdance.github.io/voxmel-demo/)

- 问题：连续自回归 TTS 需要一个既让 next-latent 预测稳定、又保住细粒度声学细节的目标。用学出来的 VAE latent 要复杂神经编码器，往往压住保真度上限；mel 频谱无需编码器，但直接自回归很难稳。
- 方法：tokenizer-free。用一个固定、可精确逆变换的两轴 Haar 变换：先沿频率把 mel 分成局部均值与频率残差，再把均值沿时间分成 Coarse-Mel 与时间残差；LM backbone 加 flow-matching head 自回归生成 Coarse-Mel，两个残差层非自回归，且都不回灌自回归历史。
- 数字：10 万小时 Emilia 训练。0.6B 监督模型 test-en 1.51% WER、0.738 SIM，test-zh 1.29% CER、0.755 SIM；GRPO 后到 1.15% WER / 0.753 SIM 与 1.17% CER / 0.776 SIM。
- 效率：把 guided flow head 蒸馏成 2 步与 4 步学生，每个 coarse frame 只需 2 或 4 次 head 评估；4 步学生 SIM 有竞争力，WER/CER 接近监督模型。
- 为什么值得看：用可逆变换替代学习式 tokenizer，是把「表示设计」从训练里拿出来的好例子；4 次 head 评估/frame 是可以直接算进推理预算的数字。

### 24. MovieRoll（7↑）

MovieRoll: A Systematic Framework for Rolling Out Long-Form Videos · Tencent Hunyuan · [2611.21339](https://huggingface.co/papers/2611.21339) · [code](https://github.com/Tencent-Hunyuan/MovieRoll) · [项目页](https://tencent-hunyuan.github.io/MovieRoll/)

- 问题：流式视频生成要撑过训练时长还保质量，同时处理自己生成的历史和不断涨的 cache。
- 方法：先用 Window-wise Teacher Forcing（WinTF）建多步 base——窗口内双向注意力、对历史因果，按渐进噪声联合去噪 chunk；HieraKV 按层注意力模式做分层压缩，浅层留全历史、深层只留 sink 与最近历史；再用 CuLT-DMD 做长 rollout 蒸馏，自 rollout 中冻结参数、平均局部梯度后更新，一次更新覆盖多个时间位置但只保留一个局部计算图。
- 数字：HieraKV 把 cache 最多降 78%，同时生成质量还提升；HeliosBench 上，base 只训过 ≤15s 视频，在 30s 处仍有竞争力；distilled 在单事件与多事件、最长 60s 的评测里总分最高。
- 工程件：KV recomputation 给两个模型限住上下文，AnnealCFG 在接近干净端点时退火引导以稳住 base；FBCA attention 与 PS-VAE 解码支撑流式输出。
- 为什么值得看：长视频的账本是 KV cache 与训练时长。「浅层全历史、深层 sink+recent」是可以直接抄的取舍，78% 的 cache 节省也是少见的实打实数字。

### 25. UMM-JEPA（2↑）

UMM-JEPA: Generative Pretraining via Masked Next-Scale Representation Prediction for Unified Multimodal Models · [2611.18668](https://huggingface.co/papers/2611.18668)

- 问题：统一多模态模型同时做理解与生成，但生成训练不必然提升理解。作者认为原因是生成目标与理解所用的感知表征不匹配——前者优化离散 visual code 或 generative latent，后者消费的是连续感知表征。
- 方法：把生成改写成对连续「理解表征」的渐进预测；模型由粗到细构造多尺度表征层级，像素渲染与表征预训练解耦，最后才接上。
- 数字：16 个 benchmark 的视觉均值 51.71，对比只看理解的 Qwen-VL baseline 46.36；文本均值也升。受控比较里，表征预测目标解释了大部分理解增益，data-matched 对照组均值几乎不动；相比 discrete-code 与 latent-flow 目标，迁移更强也更一致。
- 机制：线性探针与视觉证据干预显示，模型学到更丰富的物体/空间结构，也更依赖图像特有信息。
- 为什么值得看：「生成能不能帮理解」取决于监督在哪个空间。对统一模型训练，这比再加一个生成 head 更根本。

### 26. LynnReal-Hand（1↑）

LynnReal-Hand: Unlocking World Interaction with Hand Control · [2611.21479](https://huggingface.co/papers/2611.21479) · [code](https://github.com/LynnReal-AI/LynnReal)

- 问题：交互式视频世界模型已经能用文本和相机控制，但直接操作物体需要更细的控制。手是自然接口，难在手-物动力学复杂、还要实时。
- 方法：10 万条交互 clip，真实与合成环境都有，配 hand-aware 监督；学一个 causal flow map 做少步生成；region-aware score distillation 融合视频与图像先验，修交互动态与外观；Ultra-Fast-VAE 用更紧凑的视频解码器降推理成本。
- 数字：全序列模型 FVD 181.67、MANO Dice 93.02；三步 causal 模型 MANO Dice 92.49；540p 单卡 H200 流式 18.03 FPS、741 ms 延迟、峰值显存 34.89 GB。
- 为什么值得看：手控是世界模型最难的交互接口之一。18 FPS / 741 ms 说明「实时可交互」开始进入射程，但 34.89 GB 仍是部署硬门槛。

### 27. GlyphAtlas（1↑）

GlyphAtlas: Disentangling Stroke Detail from Layout for Scene Text Synthesis · [2611.20192](https://huggingface.co/papers/2611.20192) · [code](https://github.com/Fr0zenCrane/GlyphAtlas) · [项目页](https://fr0zencrane.github.io/project-glyphatlas/)

- 问题：场景文字合成要笔画准确、布局正确、还要与场景协调。常见做法把目标文字预渲染成 glyph image，同时指定布局与字形；但这样每个字的分辨率被目标区域大小绑死，小字、密集排版、复杂结构就拿不到足够笔画细节。
- 方法：保留 glyph image 作空间锚，另加一个 glyph atlas——每个字或词在独立 cell 里渲染编码，把参考分辨率与目标区域大小解耦；atlas-anchored attention 让每个文字区域只从对应 cell 取笔画细节，去修 glyph image 给出的粗结构。
- 训练：mask-weighted flow matching 目标加 timestep-weighted text perceptual loss，兼顾书写准确与背景一致；atlas cell 做随机分辨率增强，推理时可调 atlas 预算。
- 数字：摘要没给 FID 或准确率。结论是小、密、复杂结构都能笔画准确，能零样本迁到任务训练未见的语言，多文字区域场景领先。
- 为什么值得看：「参考分辨率与目标尺寸解耦」是通用技巧，任何需要局部细节的生成任务都能搬。

### 28. Dataset Distillation via Drifting（0↑）

Dataset Distillation via Drifting · [2611.16642](https://huggingface.co/papers/2611.16642)

- 问题：数据集蒸馏要学一小组合成样本替代大真实集；现有方法多在分类器上优化蒸馏数据，不直接逼近数据分布。
- 方法：在特征 extractor 的 latent space 里「漂移」蒸馏样本——同时向真实数据靠、彼此远离，完全不用分类目标；提出基于分布的度量作为补充评测，并把它当可视化工具解释模型，扩展到图像之外的模态。
- 数字：摘要没给具体数值，结论是漂移后的数据覆盖真实分布显著更好，同时仍是强训练样本。
- 为什么值得看：把蒸馏目标从「分类器损失」换成「分布匹配」，评测口径也跟着换。对 data-centric 训练，这是更可解释的压缩，也顺带成了一个看模型内部空间结构的工具。

## 七、表示与可解释性：方向消融与视觉锚点

### 29. Centered Ablation（1↑）

Centered Ablation: Why Last-Layer Directional Ablation Under-Fires or Collapses, and a Closed-Form Fix · Knovel Engineering · [2611.20148](https://huggingface.co/papers/2611.20148) · [code](https://github.com/knoveleng/centered-ablation) · [项目页](https://knoveleng.github.io/centered-ablation/)

- 问题：方向消融——把 hidden state 沿某个「行为方向」的分量去掉——是关掉拒答等行为的标准手段，但很不稳：有的模型几乎不触发，有的文本直接崩成重复。
- 分析与修法：在最后一层 residual stream 上，消融精确等价于一个 logit bias：固定词表 footprint 乘以 gate，而 gate 是 hidden 与 direction 的 cosine。问题在于 gate 从原点量，最后一层状态却共享一个远离原点的大 common mode；方向一旦与 common mode 重叠，就会在良性文本上误触发、在目标上反而打不中。Centered Ablation 闭式地把 common mode 从 direction 里投影掉，不改生成流程。
- 数字：8 个模型上，标准配方 under-fire 的地方，CA 把攻击成功率提高 29 与 46 点；Gemma-2-9B 的 collapse 从 50% 降到 1%；高重叠模型多保住 12–40 点良性回答，比先前工作的 affine offset 多 39–46 点。两个生成前就能算出的数，能在没见过的模型上预测它是涨 faithfulness 还是涨攻击成功率；另有一个 collapse index 标记文本退化。
- 警告：两个标准安全 judge 对崩坏文本的打分方向相反，足以凭空造出 46 点效应。
- 为什么值得看：安全干预的失败模式被写成几何问题，并给了闭式解。更值得记住的是最后那条：用 LLM 当安全评委的流水线，可能一直在给退化文本发奖励。

### 30. RAPO（0↑）

Reflection Anchors for Propagation-Aware Visual Retention in Long-Chain Multimodal Reasoning · [2605.09614](https://huggingface.co/papers/2605.09614) · [code](https://github.com/coder-gx/RAPO) · [项目页](https://coder-gx.github.io/RAPO/)

- 问题：长链 CoT 提升 LVLM 推理，但视觉信息会在生成中衰减。现有做法要么在推理时重注入视觉，要么训策略加强 grounding，可是「在哪干预」靠感知启发式，「局部视觉影响如何往下传」也没被显式建模。
- 分析：从信息论推出一步干预的下游视觉增益下界，它取决于两个量——局部 branching room（token 熵）与下游视觉传播潜力（后缀相对 vision-marginalized 参考的 divergence）。
- 方法：RAPO，基于 GRPO 的策略优化，选高熵的 reflection anchor，优化 chain-masked finite-window KL surrogate 来增强下游对视觉的依赖。
- 数字：摘要没给具体数值。推理密集与通用 benchmark 上，多个 LVLM backbone 都显著超过强 baseline；机制分析显示 anchor 富集在视觉敏感的决策点，RAPO 提高了生成轨迹上的 contrastive visual-dependence 信号。
- 为什么值得看：把「何时再看图」变成两个可计算的量，比固定间隔重注入更有依据。对长 CoT 多模态，这是干预点选择第一次有了可解释的判据。

## 补遗：晚间才进榜的 12 篇

首轮 23:30 抓取只看到 30 篇，次日复核上游为 42 篇。

- **[EBR](https://huggingface.co/papers/2611.08977)**（5↑）：loop 模型靠反复迭代同一个 recurrent block 加有效深度，但没有显式的「进度」度量，什么时候停、怎么改当前状态都没依据。EBR 在 latent reasoning state 上学一个能量函数，把 loop 更新写成对这个能量的梯度下降：能量给状态打分，梯度指精修方向，同时给出停止信号。训练上加了 exploration-based training，去发现更多 mode、把能量面在更大的状态集上塑形。四个算法推理 benchmark 上追平或超过此前的 recurrent 推理模型，Sudoku-Extreme 到 99.9% 准确率，推理算力比次优模型少 345 倍，训练算力相当。多解 benchmark 上它对「不同合法解」的覆盖是 SOTA，单样本准确率仍接近 100%。
- **[Marimba](https://huggingface.co/papers/2611.18330)**（4↑，Charcot AI）：语音应用真正要的是三类判断——音频窗口里有没有某个词、话轮有没有说完、说的是哪种语言；Marimba 把它们做成基于冻结 Qwen3-ASR 0.6B 特征的 typed decision 接口。词法问题对 ASR 转写做零样本打分，非词法问题走 question-conditioned head 加第 18 层的 turn-end readout，语种识别直接借 ASR 自己的 language score。私有对话测试集上 decoder AUROC 0.80–0.92，公开朗读语音 0.92–0.97，Speech Commands 四分类 0.93，二元词法 ECE 不超过 0.08。个人信息检测把 greedy transcript 交给私有 PII 管线，合成巴西葡语上 item-level F1 0.904（参考转写 1.000）；第 12 层 speaker readout 在 AMI 与 VoxConverse 上以 0.966–0.980 的 AUROC 超过 ECAPA baseline，数说话人（0/1/2/3+）也比 pyannote 3.1 准。短板摘要里也写了：turn-end readout 0.930，低于 Smart Turn v3.2 在自家测试集上的 0.982。ICSI 会议子集上按下一说话人标注的 AUROC 0.716 对 0.712，配对置信区间含 0，等于没差别。
- **[BitDecoding-FP4](https://huggingface.co/papers/2611.09825)**（3↑，University of Edinburgh）：长上下文服务里 KV cache 吃满显存与带宽，NVFP4/MXFP4 能在 FP4 Tensor Core 上跑 attention，但量化算法与系统加速之间有条缝——系统侧用朴素量化掉点严重，精度侧用向量码本又被查表开销拖慢解码。作者逐个处理三处误差：Dual-Residual Query Quantization 把 query 拆成两个 FP4 张量、把 query logit 误差从 60% 降到 1%，Underflow-Aware Probability Scaling 防止 E4M3 scale 把长上下文概率舍成 0，Outlier-Aware Key Quantization 用静态平滑、Hadamard 旋转加 scale 搜索压 key outlier；系统侧再用 transposed softmax 配 fused probability quantization 与 stacked query MMA 消掉 softmax 瓶颈。dense 与 MoE、GQA 与 MLA 上 NVFP4 与 BF16 KV 的精度差在 0.5 分以内（MXFP4 1 分），RL rollout 也跟得住；B300 上跑 Qwen3-4B 与 Qwen3-30B-A3B，峰值服务吞吐是 BF16 KV 的 2.4–3.0 倍。
- **[Expert Disagreement](https://huggingface.co/papers/2611.16694)**（3↑，Georgia Institute of Technology）：模型被另一个 agent 反驳后改答案，光看翻转率或最终准确率分不清它是在纠错还是在放弃正确答案。作者固定问题、证据与模型初始答案，只改 revision context——中性反思、匿名分歧、或挂上领域专家名头的分歧——在五个模型、1,989 个有证据支撑的医疗/科学/法律决策上做两遍审计。二元决策的账可以精确算：只有错答被翻的比例超过对答的 a/(1-a) 倍（初始准确率 90% 时是 9 倍）时改写才提分，而没有一个模型在专家分歧下越过这条线，准确率最多掉 16.1 分。专家标签这个 prestige cue 让五个模型里的四个更爱翻转，但对准确率的影响从 −5.2 分到 +2.4 分都有，所以翻转次数不能当伤害的代理；同样论据下仅换来源标签，三个闭源模型仍更爱翻，revision 流水线得用配对、条件化的指标逐模型逐协议评。
- **[More Agents](https://huggingface.co/papers/2611.17610)**（3↑）：多 agent 论文常拿通信架构对单次 greedy 采样，这把 coordination 与采样次数、推理算力混在了一起。作者合成九项实证评测、516 个多 agent 配置，按六维资源向量 R 与四类 baseline 阶梯重新对齐：对样本数对齐（B 类）与预算对齐（C 类）的 baseline，多 agent 平均准确率是 −0.042，log-odds 上的多层随机效应模型在敏感性检验里仍为负。这类可比对照里 74% 的多 agent 结果等于或低于 baseline，同时报两种 baseline 的研究中把 greedy 换成采样 baseline 就让差值平均移动 −0.038。结论很可操作：agent 共享同一份证据时通信不带来新信息，要正收益就得切分证据、加外部验证，或让模型之间真有错误多样性。
- **[Correct Labels](https://huggingface.co/papers/2611.04395)**（2↑，Cornell University）：微调数据里常有能预测正确答案的 metadata，比如 reward-model 分数或质量标签；作者问的是每个训练标签都正确时，模型会不会照样学会依赖这层 metadata。做法是在多选题上微调三个家族、7–9B 的开源模型，让 `(Reward: 5)` 一直标在正确选项上；测试时把标注挪到错误选项，模型在 97–100% 的 CommonsenseQA 题目上就选了那个错项，而把标注去掉后大部分答案又是对的——所以不加标注的评测测不出这种依赖。cue-following 随训练时标注的可靠性上升，用中性甚至无意义的标注词也会长出来，只是测试时措辞会影响强度；Qwen3 上做 DPO 后，选项字母分数里同样有 cue 依赖。作者给的审计很便宜：任务与正确答案不动，只挪动或删除可见标注。
- **[SilentGuard](https://huggingface.co/papers/2611.20595)**（2↑，Genentech）：agent 靠调 API 拿答案，而 API 会静默失败——忽略请求的一部分（比如写错名的 filter），仍返回 HTTP 200 和一个看着合理的错结果；作者在 15 个公开研究 API 里找到 11 个有这种失败，计数最多被放大 691 倍。现有 checklist、reviewer model、LLM judge 这类「让模型自己抓」的补法仍留下超过 70% 的错答案，judge 标出的计数里 agent 有 77.4% 照样报出去；SilentGuard 把决定从模型移到跑 tool call 的 harness，用任何正确 API 都必须满足的不变量检查每个结果，破坏不变量的值就不下发。7 个开源模型上目标故障的错答案从 74.0% 降到 1.7%、无故障任务不掉分，3 个前沿模型上从 70.2% 降到 0.5%，而同一检查只给警告仍有 70.1% 错——起作用的是强制而不是提示。碰到新故障类型，单靠 harness 也能把错答案从 61.1% 压到 24.5%，代价是用 abstain 换正确率。
- **[ViRA](https://huggingface.co/papers/2611.21605)**（2↑）：高分辨率视觉 agent 靠放大局部读证据，但现有 agent 常凭常识作答，而对最终答案做 RL 修不了这一点——猜对与读出来拿一样的奖励。作者提 Cross-Input Relative Policy Optimization（CrossRPO），在 contrast set 上训练：同一个问题问几张只有一小块区域不同、答案也不同的图，只有真去读那块证据才能整组答对，他们并证明整组奖励不会强化「靠常识就能答对」的组。训练集 ViRA-Train 与评测集 ViRA-Bench 都是在 21–120 MP 的图上改一个小物体造出来的，另拍 ViRA-Bench-Real 用真实变化排除编辑痕迹；每篇只用约 3,500 条训练，最高分辨率下整组准确率 63.3%，GRPO 是 59.3%。ViRA-9B 是同尺寸里最准的开源模型，ViRA-27B 在多数 benchmark 上超过最高 thinking 档的 Claude Haiku 5.5 与 GPT-6-Luna。
- **[MS-HVED](https://huggingface.co/papers/2611.21412)**（1↑）：临床脑 MRI 常是快速、各向异性的 2D 采集，方位、对齐与覆盖范围各不相同，几套 stack 只部分重叠，现有超分方法要么只吃单输入，要么假设理想的多 stack 几何。MS-HVED 是 sequence-agnostic 的多 stack 超分：轴位、冠位、矢状位各自编码成多尺度高斯后验，再用 field-of-view-aware 的 Product-of-Gaussians 融合，让没覆盖到的区域不参与，训练时用 physics-informed domain randomisation 模拟斜切、部分覆盖与伪影。合成 benchmark 上重建保真度不差于或优于对照，下游组织分割也优于低分辨率输入；外部队列是尼日利亚 30 例常规脑 MRI，构成 44 例、7 位神经放射专家盲评的主要部分。该队列 210 次配对评估里 187 次偏好 MS-HVED，全部临床队列总体质量分 5.93 对 4.49（p<.001），去掉轴位或冠位输入偏好仍在（p<.001）。
- **[Inside the Trading Loop](https://huggingface.co/papers/2611.11657)**（0↑，Cornell University）：一个混合多 agent 交易系统——LLM 分析师把公司新闻与宏观报告交给 coordinator，由它定股票权重与现金比例，再由动量组合构建与规则化执行落地。评估用券商记录的 paper account（带确定性 fallback），并用回溯 replay 比较不同 LLM 配置：2026 年 3 月 11 日到 8 月 28 日账户收益 34.5%，同期 SPY 是 14.4%，但这个原始收益优势伴随更大的最大回撤。把评估放在同 session 或推迟到次日，重建出的策略都高于对应的 SPY 与 QQQ 参照。设计对比还看了现金决定权、选择性调用与响应契约：constant-cash 控制给出的收益估计与按 stance 定仓接近，更短的报告契约改善解析、却可能改掉推荐。
- **[GPBam](https://huggingface.co/papers/2611.18981)**（0↑，AAIRE - Agents, AI and Retrieval Lab）：大陆法系的法律推理不是查条文——德国国家考试要的是 Gutachten：点名适用规范、涵摄事实、论证到结论。GPBam 收 81 个公法考试案例与参考解，配一个覆盖 200 条法条的背诵任务，案例来自备考、覆盖面广且很少重复，且不公开，作者在评测模型里没找到背过标准答案的证据。因为参考解引用的规范天然是检索 gold set，它能在这同一批实例上同时评检索与长文生成，回答「一份法律意见到底需要多好的检索」：32 个开源与闭源模型无检索时得分跨 4.81–76.42（满分 100）。给法条帮助有限——七个模型 × 八种检索配置下检索指标差近三倍，最多只换到 4.1 分、七个里有三个不显著，91% gold-norm recall 的 oracle 也只提 2–6 分；真正相关的是先验知识，法条逐字背诵与作文质量的相关系数 ρ=0.92（32 个模型）。
- **[Abstention Direction](https://huggingface.co/papers/2611.20441)**（0↑）：abstention（不确定或涉安全时不给回答）有三个来源——query 本身歧义、模型知识边界、与人类价值不对齐，但此前对内部表征的分析只做了第三类，用有害/无害 query 算 refusal direction。作者把框架扩到三类：每类构造共享模板、只改诱发 abstention 那一因素的反事实对，用两极平均激活之差归一化得到 abstention direction。activation steering 显示在中间层干预能跨三类升降 abstention，且有效果跨类，说明三条方向共享一个公共分量。摘要未给具体数值：层号、干预强度与成功率都没有。

## 今天的三个观察

**一、评测开始把「部分正确」和「交付」分开记账**。SWE-CoWork 的 63% F2P 对 <8% 完整交付是今天最刺眼的一组数；Accelerate Bench 的 412 个正确结果里有 125 个加速不到 1.25×；InclusionMed 的前 10 名在患者沟通上全面强于临床决策；DominoBench 的 72% 单题正确对 34% 双胞胎全对；OutfitterBench 里多个 agent 还不如规则 baseline。这些指标以前都能被一个 solve rate 盖住，现在被拆成「实现了 / 验证了 / 交付了 / 守住承诺了」。对写 agent 的人，这意味着 harness 里必须有一份显式的需求与承诺状态，否则涨的是前半段，不是后半段。

**二、规模红利还在，但支付方式变了**。ScaleVLA 用 552B 买到的是 10 个 demo 顶 50 个（87.8% vs 85.6%）和接触敏感段的精度（4/10→9/10），代价是 216 ms/chunk；K2 的 36B-A4B 用七分之一 active 参数接近 32B dense；Sage 的 320B 换来 OfficeQA Pro 72.2 与 MLE-bench Lite 90.3。另一面，Latent Feedback 明说数据相对模型稀缺时反馈失效，LoopFill 说明 looped 模型的延迟要靠 draft tree 补。今天真正的工程问题是「用多少 active 参数、多少 demo、多少毫秒，去换那几点」，而不是「谁更大」。

**三、安全与可解释性在往「把判断从模型手里拿走」走**。SPILLWAY 用 typed returns 加固定规则做确定性 floor，开源 RL attacker 下 ASR 0.007，且不额外跑 backbone；Centered Ablation 把方向消融写成 logit bias，闭式投影掉 common mode，collapse 从 50% 到 1%、攻击成功率 +29/+46。两篇的共同点是：与其再训一个 judge，不如把不变量写进系统。而 Centered Ablation 顺手证明两个标准安全 judge 会对崩坏文本给出相反打分、伪造 46 点效应——这对任何「用 LLM 评安全」的流水线都是直接警告。和前几天比，方向很清楚：从「加一个模型来判断」转向「把判断条件变成可验证的结构」。

## 数据与方法

- 抓取命令：`python3 code/ai-daily/fetch_papers.py --date 2026-11-17 --out ~/tmp/ai-daily/2026-11-17.json --brief ~/tmp/ai-daily/2026-11-17.md`
- 数据源：HF 官方域名在本机不可达，脚本走 hf-mirror；本次 `latest` 返回 42 篇，`?date=2026-11-17` 返回 0 篇，最终取 latest 的 42 篇（并集仍是 42）。42 篇的 `submittedOnDailyAt` 都是 2026-11-17，按这一期成稿。首抓时间 2026-11-17T23:30:26+08:00，复核抓取时间 2026-11-18T21:01:49+08:00。
- 快照：42 篇、619 upvotes；13 篇上双，29 篇在 0–9 票，其中 4 篇 0 票；前三名合计 227 票，占 36.7%；Top 10 合计 499 票，占 80.6%。正文章节与 Top 10 表内的逐篇 upvotes 保留 23:30 首抓值，未随复核改写。
- 补遗：首抓 30 篇（23:30 快照），次日复核上游为 42 篇，补 12 篇。
- 排序口径：组内按 upvotes 降序，同票按 arXiv id 升序；Top 10 取全榜前 10；正文序号按分组顺序编排，与 upvotes 排名无关。
- daily 日 vs arXiv 日：42 篇的 daily 收录日都是 2026-11-17；接口的 `publishedAt` 跨 2026-10-26 到 2026-11-16。RAPO 的 arXiv 号是 2605 号段（5 月），但接口给的 `publishedAt` 是 2026-11-15，这里按接口值计，不自行推断重投时间。
- 数字口径：所有数字取自 JSON 里的论文摘要原文；摘要没给的（如 SALA、Ego Guidance、GlyphAtlas、RAPO、Dataset Distillation 的具体指标，PaperCritic 的分数）明确写「摘要没给」，不做外推。upvotes 会随发布继续变化，后续重抓数字不同属正常。
