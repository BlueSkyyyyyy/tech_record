## 一、科学计算与时序基础模型

### 1. PROLA（14↑）

PROLA: Principal-Orthogonal Low-rank Adaptation for Predictive Spatiotemporal Weather Downscaling · [2611.11318](https://huggingface.co/papers/2611.11318) · arXiv 2026-11-08 · daily 2026-11-19 · [代码](https://github.com/yms020615/PROLA)

- 问题：全球粗网格预报会漏掉局地大气结构；把预训练气象 backbone 迁移到「从近期粗状态预测未来高分辨率场」，既要同时提高空间与时间分辨率，又很贵。
- 任务：作者把它形式化为 PSWD（Predictive Spatiotemporal Weather Downscaling）。这不是单帧超分，而是联合细化空间/时间分辨率并预测未来高分辨率轨迹。
- 方法：空间、时间两阶段共用预训练 backbone、固定数值 scaffold 与轻量 residual head；PROLA 把固定低秩预算分给预训练权重的主方向与正交补，再用梯度信号重标定 rank-1 优化器更新，不增加可训练 rank。
- 数字：摘要只说在 PSWD 上优于代表性低秩适配 baseline，并在多个数据集与任务上有效；**没给 RMSE、目标分辨率、加速比或低秩预算的具体数值**。
- 为什么值得看：低秩预算如何在「保住预训练知识的主方向」与「学新任务的正交补」之间分配，是可迁移到任何大 backbone 微调的问题；气象只是压力测试。读这篇时要记住证据是相对比较，不是可复现的绝对指标。

### 2. PACT（2↑）

Recurrent Domain Incremental Adaptation of Time-Series Foundation Models · [2611.24075](https://huggingface.co/papers/2611.24075) · Nanyang Technological University · arXiv 2026-11-18 · daily 2026-11-19 · [代码](https://github.com/Sachithx/PACT)

- 问题：时序基础模型换工况后要持续适应，但不能忘掉旧工况；标注校准集很小，推理时还不知道当前是哪个工况。
- 观察：工况漂移下嵌入空间不是整体平移——一些局部区域变化很大，另一些几乎不动；全局适配会把本来就分对的嵌入也推走。
- 方法：把冻结的源嵌入空间切成 local charts，为每个新工况影响到的区域学轻量 residual transport；始终保留 identity path，用学到的 gate 在 identity 与累计 transport 之间软选择；encoder、分类头与旧 transport 全部冻结。
- 数字：每个新工况只用 **5%** 标注校准数据，测试时不给工况身份，四工况轴承故障流上平均 macro-F1 保持 **>0.95**；在任务与标签空间同构的公开基准上也观察到类似的「保留 + 适应」行为。
- 为什么值得看：这是「不重训、不遗忘」的模块化适配，和 LoRA 同源但作用在嵌入几何上；5% 校准与无工况标签两个约束都很工程化。摘要没给各基准的具体分数。

## 二、Agent：自进化、环境与量化设计

### 3. The Resolution Hypothesis（11↑）

The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements · [2611.23068](https://huggingface.co/papers/2611.23068) · ShanghaiTech University · arXiv 2026-11-17 · daily 2026-11-19 · [项目页](https://lineshogan.github.io/resolution-hypothesis/)

- 问题：agent evolution 的常见闭环是 proposer 写候选（prompt、skill、memory），selection 留下分高的；但不同论文的方法互有胜负，某些任务上根本 bootstrapping 不起来。
- 假设：瓶颈不在「提不出更好的候选」，而在「噪声评测认不出哪个更好」——作者称为 Resolution Hypothesis，并在候选选择与方法排名两个层面检验。
- 规模：**7** 种 evolution 方法、**6** 个模型、超过 **1,000 万**次 LLM 调用。
- 结果：候选层面，确有有帮助的候选存在，但 selection 区分有用/有害的能力**不比随机好**，误差逐轮累积；方法层面，常见几个百分点的领先小于同一方法两次独立运行的差异，已发表的排名很多靠运气。
- 为什么值得看：这直接把「评测分辨率」变成 agent 自进化的第一性约束。对做 harness 优化的团队，先做配对比较、重复运行、置信区间，可能比再换一个 proposer 更划算。

### 4. Game2Player（8↑）

Game2Player: Scaling Gameplay Experience for Visual Agents through Environment-Player Co-Development · [2611.24154](https://huggingface.co/papers/2611.24154) · University of Illinois at Urbana-Champaign · arXiv 2026-11-18 · daily 2026-11-19 · [代码](https://github.com/game2player/Game2Player)｜[项目页](https://game2player.github.io/)

- 问题：游戏是视觉 agent 的好测试床，但人类 gameplay 贵、从视频学要反推动作；现有数据集覆盖游戏少，往往没有显式任务与可验证结果。
- 方法：环境与 player 共同开发。Builder agent 改造现成网页游戏、暴露内部状态、用基于状态的 progress measure 与 success check 定义任务；Coding Player 与 VLM Player 去尝试，并把问题报给 Builder 修，玩既是环境验证也是数据采集。
- 规模：**568** 个已验证网页游戏、**3,436** 个任务、**15.7K** 条轨迹（**307** 小时 gameplay）；另留 **50** 个游戏做 PlayerBench。
- 训练与结果：用 progress-weighted SFT，对推进任务的步骤加权；Game2Player-9B 在 PlayerBench 上 progress **14.3%→31.2%**，外部 GameWorld 上 **30.0%→53.1%**。
- 为什么值得看：可验证 reward 不是「再标一批数据」，而是让 Builder 把游戏状态和成功条件一起造出来；9B 的增益说明环境质量比模型规模更靠前。

### 5. QDA（4↑）

QDA: Closed-Loop LLM Quantization Design with Agents · [2611.23388](https://huggingface.co/papers/2611.23388) · MIT HAN Lab · arXiv 2026-11-17 · daily 2026-11-19

- 问题：PTQ 的最优 recipe 随模型与精度变，专家要为每个新模型重设计；评估一个量化推理模型要几十 GPU 时，跨代码库拼方法还得手工移植。
- 方法：让 agent 闭环设计 recipe。候选先用「原模型在 agent 没见过的 reasoning traces 上的输出 KL」在几分钟内打分，promising 的再用长生成检查重复循环等失败；同时提供互相兼容、适配新架构的公开 PTQ 方法库。
- 数字：四个推理模型上，W4A16 / W4A8 / W3A16 平均比最强公开 recipe 高 **0.9 / 1.4 / 2.2** 个百分点，每次搜索 **64 GPU 小时**；320B MoE GLM-5.3-Flash 的 NVFP4 W4A4 恢复 FP8 准确率的 **98.3%**，最强厂商 checkpoint 是 **96.9%**。
- 工程性：所有 QDA checkpoint 直接跑现有 serving kernel，**无推理额外开销**；作者表示将开源库、evaluator 与 harness。
- 为什么值得看：把「评估太贵」拆成「代理指标 + 少量长生成复核」，是 agent 做系统设计时最实际的一招；KL 代理选的是行为一致性，不只是 perplexity。

### 6. LogT（1↑）

LogT: Logically Think with Images for Visual Search · [2611.19200](https://huggingface.co/papers/2611.19200) · AI at Meta · arXiv 2026-11-14 · daily 2026-11-19

- 问题：让 VLM 用 Zoom-in 工具「用图像思考」时，现有工作堆 SFT + RL 和工具专用设计，逻辑推理与准确、高效地用工具仍难兼顾。
- 转向：作者不再加 RL 复杂度，而是把 SFT 数据质量当瓶颈，做一个全自动数据引擎，强制 logic-chain-guided reasoning，产出视觉 grounded 的问题与结构化工具调用轨迹。
- 数字：在 Qwen2.5-VL-7B 与 InternVL3.5-8B 上微调，评测覆盖七个 benchmark 测试集；Qwen2.5-VL-7B 的 LogT-SFT 超过「SFT + RL」训出的 SOTA，用的数据少 **3.1×**、GPU 小时少 **>120×**。
- 叠加：在 LogT-SFT 上跑一个不带工具专用设计的简单 RL，就比此前复杂 RL 方案高 **9.59** 个百分点；工具调用准确率/效率与推理轨迹结构也更好。
- 为什么值得看：又一次「数据引擎 > RL 技巧」的实证；对 agent 训练，先把轨迹的逻辑链写对，再谈信用分配。

### 7. Shopping Agents（1↑）

Thinking Harder Doesn't Lead to Better Choices: Reasoning Effort Increases the Confidence but Not the Correctness of LLM Shopping Agents · [2611.22033](https://huggingface.co/papers/2611.22033) · University of Chicago · arXiv 2026-11-17 · daily 2026-11-19

- 问题：LLM 被当自主购物 agent，输入是多模态商品列表；直觉上「想得更多」应该选得更好，报告的置信度也该能预测对错。
- 设置：**10** 个前沿模型、**3** 个商品选择基准（WebShop、Amazon SQID、Wayfair WANDS）。
- 结果：提高 thinking effort 在三个基准上都没有统计显著的质量提升，但同一改动显著抬高自报置信度——多想买来的是 confidence，不是 correctness；多数模型在每个 effort 档位都校准不好。
- 错误结构：错误高度共享——一个模型在某题错，另外几个也容易错；在多个模型都错的题上，很大比例会选同一个错误商品。
- 为什么值得看：test-time compute 的收益不是免费的，且「模型集成」在相关错误面前收益有限；做 agent 评测必须同时报校准与错误相关性。

## 三、生成模型：交互视频、像素解码与预测目标

### 8. ALIVE（10↑）

ALIVE: Making Streaming Video Models Interactive · [2611.21366](https://huggingface.co/papers/2611.21366) · Tsinghua University · arXiv 2026-11-16 · daily 2026-11-19 · [代码](https://github.com/lijinzhao30/ALIVE)｜[项目页](https://lijinzhao30.github.io/ALIVE/)

- 问题：流式视频 LLM 能持续看世界，但通常把用户请求孤立处理：不会主动监控、不会协调多轮任务、该追问时不追问。
- 数据与训练：ALIVE-SFT-288K 与 ALIVE-RL-3K 两阶段；对比式 SFT 教「何时、如何回应」，RL 用 Behavior-Aligned Credit Assignment（BACA）把 trajectory-level 与 local advantage 结合，细化多轮里的决策、回答与**沉默**。
- 评测：提出 FSI-Bench，专门评「反馈寻求 + 后续任务完成」；在四个公开 benchmark 与 FSI-Bench 上综合分最高。
- 数字：摘要没给各项具体分数；可确认的是 288K SFT、3K RL 两个数据规模与「四个公开榜 + FSI-Bench 综合最高」。
- 为什么值得看：把「不说话」当动作来学，是流式交互和普通 VQA 的分水岭；BACA 的局部/全局 advantage 组合也可直接借到多轮 agent RL。

### 9. DWD（6↑）

Decoding Without a Decoder: Direct Pixel Prediction from Diffusion Transformers · [2611.22287](https://huggingface.co/papers/2611.22287) · Stanford University · arXiv 2026-11-17 · daily 2026-11-19 · [项目页](https://hanshengchen.com/dwd/)

- 问题：潜扩散模型最后要用 decoder 把 denoised latent 映回像素，多一个模块、多一份推理成本，还可能引入解码失真。
- 方法：把「去噪」和「出像素」两个角色拆开。原 denoising head 继续驱动采样；新增 DWD linear head 只在最后一步预测像素。只微调最后几个 transformer block，DWD head 用像素质量损失训，denoising head 锚到预训练模型以保持采样轨迹。
- 数字：在 Wan 视频生成上明显减少细节扭曲与闪烁，warping error **−23%**；在像素流模型上把 ImageNet FID 从 **1.55** 降到 **1.43**，作者称是 pixel flow models 的新 SOTA；去掉 decoder 的同时维持甚至提升像素质量。
- 范围：latent 图像与视频生成器都适用；对本来没有 decoder 的 pixel diffusion 也有增益，说明「最后一步单独出像素」不只是为了省 decoder。
- 为什么值得看：decoder 往往被当成生成模型的外设，这篇把它变成可拆的最后一步；对推理栈，少一个 VAE 解码就是少一块显存与延迟。摘要没给端到端加速比。

### 10. AnisoFlow（4↑）

Learning Anisotropic Prediction Targets for Flow Models · [2611.17767](https://huggingface.co/papers/2611.17767) · Stanford University · arXiv 2026-11-13 · daily 2026-11-19 · [项目页](https://hanshengchen.com/anisoflow/)

- 问题：flow matching 的预测目标（velocity、noise、clean data）是手选的，这个选择强烈影响训练与样本质量，但通常被当成超参。
- 方法：把目标变成可学的：对 noise 分量做各向异性缩放，在联合学习的一组基上给每个方向一个非负权重；用闭式映射从网络输出恢复 velocity，架构、flow-matching loss、采样器都不变。
- 理论：分析预测误差后预测「每个方向偏好的 noise 权重随数据方差近似线性增长」，与像素空间学到的权重一致；因为恢复是精确的，训练可以纯粹为「让网络好预测」优化目标。
- 数字：ImageNet 256×256 上只学预测目标，FID 从 JiT baseline 的 **1.90** 降到 **1.55**，没有 representation alignment、没有改架构；像素空间 T2I 质量提升，并在降精度推理下基本消除 patch-seam。
- 为什么值得看：这是「不改模型只改目标」的免费改进，且给出了可检验的理论；对训练系统，目标变换不增加参数与采样步数。

### 11. Code World Model 2.0（4↑）

Code World Model 2.0: Towards Infinite Controllable Video Generation · [2611.22925](https://huggingface.co/papers/2611.22925) · inclusionAI · arXiv 2026-11-17 · daily 2026-11-19 · [代码](https://github.com/inclusionAI/CodeWorldModel)｜[项目页](https://www.inclusion-ai.org/CodeWorldModel/)

- 问题：用 visual proxy 把世界状态模拟与真实感视频合成解耦，能同时服务离线片段与实时交互流；但 proxy 从粗布局到细粒度关节几何不等，流式推理又只有几步因果去噪，容易沿自生成历史累积漂移。
- 方法：Invoker-Render 用一个共享条件接口（结构 proxy、外观参考、语言）把双向创作模型与因果**四步**流式模型配对；在约 **200 小时**对齐的多粒度语料上训练，细几何给得少时也能补出合理局部运动，运行时可选输入细节。
- 抗漂移：ProForcing 先用训练视频历史把 causal predictor 蒸馏成四步 renderer，再切到连续自生成 rollout，避免「步数压缩」与「rollout 漂移」叠加；配 pipelined serving。
- 结果：跨 proxy 家族、粒度与相机路径的可控性，稳定优于近期 streaming baseline；**30 分钟**赛车 rollout 保持场景与主体外观。
- 为什么值得看：世界模型落地的关键不是单帧好看，而是长 rollout 不崩；四步因果 + 渐进 forcing 是可直接对照的推理/训练协同设计。

### 12. Jeveration（0↑）

Jeveration: System One Models Now Generate · [2611.24738](https://huggingface.co/papers/2611.24738) · National University of Singapore · arXiv 2026-11-18 · daily 2026-11-19

- 问题：System One 模型（如 Jev）用一次并行预测出决策；能不能用同一范式直接生成图像，且保持全局一致？
- 方法：基于冻结 VLM，复用其视觉-语义知识做整体图像生成；让所有位置共享一个随机状态来协调并行预测，每次采样得到不同但 coherent 的图；由于直接图像监督下模型会忽略该状态，先学离散图像码的分布来引导单步生成。
- 统一：同一架构同时做 text-to-image、image-to-image 与 dense prediction，一个 checkpoint 三个任务，各一次前向。
- 数字：生成 **512×512** 图像 **78 ms**，比现有 unified models 最多快 **122×**，图像质量与 dense prediction 保持竞争力。
- 为什么值得看：0 票但方向有意思——如果生成也能单步并行，扩散的迭代成本就不是唯一路线；不过摘要只给了速度与「competitive」，没给 FID。

## 四、安全、检测与鲁棒性

### 13. CHORD（2↑）

Let Samples Sing in Chorus: Mitigating Spurious Correlations via Cross-view Consensus · [2611.22668](https://huggingface.co/papers/2611.22668) · arXiv 2026-11-17 · daily 2026-11-19 · [代码](https://github.com/davelee-uestc/chord_debiasing_public)

- 问题：模型靠 spurious correlation 走捷径，在 underrepresented group 上崩；现有方法要么纠正人工指定的 bias attribute（可能不是模型真用的捷径），要么从单一表示里猜 bias（不完整且噪声大）。
- 思路：一个特征空间里被遮住的 bias，在另一个空间里可能更清楚；让样本在多个表示空间里「合唱」，做 cross-view consensus。
- 方法：CHORD 在每个 view 里聚合类内划分，作为候选 bias 的 proxy，在没有 bias supervision 的情况下同时去偏目标表示与分类器。
- 数字：视觉、语言、语音、医学影像共 **7** 个 benchmark 上 worst-group accuracy 一致提升；摘要没给具体点数。
- 为什么值得看：不依赖 bias 标签、也不假设单一表示够用；对评测，worst-group 比平均分更能暴露捷径。

### 14. VAE Rhythm（1↑）

VAE Rhythm: Temporal Decoding Traces for AI-Generated Video Detection · [2611.21114](https://huggingface.co/papers/2611.21114) · Show Lab · arXiv 2026-11-16 · daily 2026-11-19 · [代码](https://github.com/showlab/vae-rhythm)｜[项目页](https://showlab.github.io/vae-rhythm/)

- 问题：靠可见伪影检测 AI 视频不可靠，新生成器会学会抹掉；但生成管线本身会留下痕迹。
- 观察：多数视频生成器用 3D causal VAE 解码 latent，连续帧按时间分组，帧的保真度随组内位置周期性起伏——VAE Rhythm；真实视频逐帧拍摄，没有这个周期。
- 方法：免训练的 phase scan：用现成 VAE 从不同起始 offset 重建片段，测重建误差随 offset 的周期性；可做 zero-shot 分数、现有检测器插件，以及配对真实视频与 VAE 重建的数据引擎（训 CaDet）。
- 数字：在 **31** 个生成器的 **39** 个变体里发现该节奏，包括闭源 Sora、Kling 3.0、Seedance 2.0；DF26 上免训练分数超过 **15** 个重训 baseline，作为插件把 **19** 个检测器全部提升 **6.7%–23.7%** AUROC；CaDet 在 AIGVDBench、DF26 与三个 2026 闭源模型上 AUROC 最好，无生成视频训练的变体在 AIGVDBench 仍 **>90%**。
- 为什么值得看：检测生成视频不必追可见瑕疵，可以直接测管线的「时间指纹」；对数据侧，这也是一个几乎零成本的真假配对引擎。

### 15. IDEA（1↑）

IDEA: Intent-Dominance Evidence Audit for Inference-Time Backdoor Detection in GUI Agents · [2611.24102](https://huggingface.co/papers/2611.24102) · HUAWEI Noah's Ark Lab · arXiv 2026-11-18 · daily 2026-11-19

- 问题：组织部署下载来的 open-weight GUI agent，后门模型能过干净数据验收，只在屏幕出现视觉 trigger 时乱来，等于供应链风险；现有检测器多是 sample-level、面向图像分类器/CLIP encoder，缺 GUI 的 step-level 检测。
- 签名：干净步骤由指令驱动动作；被未引用屏幕区域劫持时，指令失去对 decision state 的控制，或该区域反过来决定它——作者称为 intent–evidence dominance inversion。
- 方法：Intent Counterfactual Probing（ICP）量「改写指令能把 decision state 推多远」，Region Causal Audit（RCA）量「消融候选区域能推多远」；gated conformal score 把两个位移与干净流形同距离的干净步骤比，给有限样本假阳性保证；不需要 trigger 知识或攻击数据。
- 数字：Qwen2.5-VL-3B、**5** 个攻击家族；在受控 FPR 下稳定检出并优于 SOTA，每次报警都能定位 trigger 区域，推理开销不大（摘要没给具体毫秒或百分比）。
- 为什么值得看：把后门检测从「看输入像不像」变成「看决策被谁主导」，且带 conformal 保证；这是 agent 供应链安全少见的 step-level 方案。

## 今天的三个观察

**一、Agent 的瓶颈从「提议」转向「分辨**」。Resolution Hypothesis 的 7 种方法、6 个模型、超过 1,000 万次调用给了一个很不客气的结论：候选里有好东西，但 selection 分不出来，误差逐轮累积；方法排名那几个百分点的差距，还不如同一方法两次独立运行的波动。同一天的三篇是同一逻辑的不同侧面：Game2Player 用基于状态的 success check 把「任务完成」变成可验证信号，QDA 用 KL 代理把「这个 recipe 好不好」压到分钟级，购物 agent 的研究则说明「多想」只抬高置信度、不提高正确率。共同点不是提出更强的 proposer，而是先把「更好」定义成可测量、可复现的东西。

**二、生成模型在同一天拆了三个接口**。DWD 拆的是解码器：denoising head 继续采样，最后一个线性头专门出像素，Wan 上 warping error −23%，像素流 FID 1.55→1.43。AnisoFlow 拆的是预测目标：架构、损失、采样器都不动，只学各向异性的 noise 权重，ImageNet 256×256 FID 1.90→1.55。ALIVE 与 Code World Model 2.0 拆的是交互与流式：前者把「何时说、何时沉默、何时追问」学进多轮策略，后者用四步因果渲染 + ProForcing 把 30 分钟 rollout 的漂移压住。三件事的共同收益都不来自更大的 backbone，而来自「把某一环从主模型里拿出来，单独定义损失与接口」。

**三、低票区的方法学比票数更值得读**。VAE Rhythm 在 31 个生成器的 39 个变体里找到 3D causal VAE 的周期指纹，免训练分数超过 15 个重训 baseline，作为插件把 19 个检测器提升 6.7%–23.7% AUROC；IDEA 用 ICP + RCA + conformal 把 GUI agent 的后门检测做到 step-level，还能定位 trigger 区域；PACT 只用 5% 标注校准就把四工况 macro-F1 稳在 0.95 以上；CHORD 在七个基准上不靠 bias 标签提升 worst-group。它们票数都在 0–2，但共同点是「机制清楚、约束明确、失败模式可检验」。反过来，今天票最高的 PROLA 摘要只给相对提升、没给绝对误差，读的时候要把热度和证据强度分开看。
