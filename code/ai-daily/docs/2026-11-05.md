## 一、Agent：把信用、上下文和接口拆开

### 1. TurnWise：信用分配到回合（49↑）

Turns Matter: Advancing Streaming Video RL via Turn-Level Credit · 机构未标 · [2611.06728](https://huggingface.co/papers/2611.06728) · [code](https://github.com/XD111ds/turn-wise-rl)

- 问题：流式视频理解要求模型在每个回合决定「现在回答」还是「继续观察」。现有 GRPO 工作主要在改 reward，但 advantage 仍然是整条轨迹共用一个值——前面答对会强化后面的冗余回答，前面答错又会压掉后面本可以补救的追问。
- 方法：**turn-level credit assignment** 用 silence-completed prefix scoring，从每个决策之后的剩余回报构造 group-relative advantage，把早先回合的奖励从当前信号里剥掉；**turn-mean policy optimization** 先在回合内平均 token loss、再跨回合平均，让「回答」和「等待」按决策数而不是输出长度加权。
- 代价：不需要 learned critic，也不增加 rollout，属于对现有 GRPO 管线改动较小的方案。
- 数字：摘要只写了「优于 prior RL approaches」，没有给具体指标；价值主要在 credit 的粒度与交互粒度对齐，而不是某个榜单涨点。
- 对 agent 工程的意义：流式 agent 的数据本来就是回合制的，trajectory-level advantage 是一种结构性错配。

### 2. 多轮 agentic RL 到底提升了什么（39↑）

What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents? · 中科院自动化所 · [2611.06483](https://huggingface.co/papers/2611.06483) · [code](https://github.com/GaryStack/Rethinking-Agent-RL) · [项目页](https://rethinking-agentic-rl.github.io/)

- 用 **Pass@ 指标**同时扫采样宽度 K 与交互深度 T，而不是只报一个固定预算下的分数。
- 发现一：trajectory-level RL 的收益依赖足够的回合预算，预算一收紧就显著衰减——部署时给的步数上限会直接改变结论。
- 发现二：agentic RL 不是均匀提升单步决策质量，增益集中在**错误恢复**和**长程韧性**；换句话说，它更像「学会补救」，而不是「每步更聪明」。
- 给出 **BudgetMix RL**：训练时变化交互预算，让策略见过不同预算；也讨论了 process supervision 的收益与局限。
- 数字：摘要没有给具体数值，结论是定性的；但这篇的评测协议值得直接抄进 agent RL 的实验设计。

### 3. HCU：程序、语义、视觉三条通道（17↑）

Hybrid Computer Use: A Unified Programmatic, Semantic, and Visual Interface for General Agents · Microsoft Research · [2610.41432](https://huggingface.co/papers/2610.41432) · [code](https://github.com/microsoft/Hybrid-Computer-Use) · [项目页](https://microsoft.github.io/Hybrid-Computer-Use/)

- 批评「截图 + 鼠标键盘」的单一 CUA 接口：它把人类交互先验强加给 agent，每一步都要重新读屏，而电脑本身的程序接口和语义接口基本没被用上。
- HCU 统一三条通道：**code / CLI**（程序）、**accessibility AX**（语义）、**GUI**（视觉）；AX 工具返回紧凑观测、批量执行动作、用 **AX diff** 报告效果，减少往返；切换通道时还会防 stale-state 动作。
- 结果：OSWorld 2.0 上 Partial 与 Binary 都是对比系统最高；所有被测模型换用 HCU 都有提升，但各模型在三通道上的工作量分配明显不同。
- 数字：摘要只给了「最高」，没有给具体分数。
- 工程意义：CUA 的瓶颈不只在模型能力，接口设计直接决定步数、成功率和 token 成本。

### 4. TAC-CoT：只让工具调用说人话（17↑）

TAC-CoT: Tool-Empowered Implicit Chain-of-Thought via Interleaving Explicit Tokens · Data Intelligence System Lab · [2611.01926](https://huggingface.co/papers/2611.01926) · [EMNLP 2026](https://aclanthology.org/2026.emnlp-main.1436/)

- 矛盾很具体：显式 CoT 生成开销大；隐式 CoT 用连续 token 替代 rationale，但 agent 的工具调用需要一个离散、可解析的文本接口。
- 做法是**分段**：推理段换成 compact latent reasoning segment，只有 tool call、observation、final answer 保留文本 token，两者交错。
- 数字：agentic math 与 QA 基准上准确率最多 **+8.8 点**，模型前向次数最多降 **6.8×**；单工具和多工具设置下工具使用质量都变好。
- 看点：它不是「全部搬到潜空间」，而是精确划出哪一部分必须保持可读——这比「潜空间通信」的口号更接近可部署的方案。

### 5. 重写推理历史来省 token（13↑）

Why Pay for Long Reasoning When Rewrite Do Trick? Causal Effects of Reasoning History Compaction on Future Generation and Agent Cost · 独立作者 · [2611.03852](https://huggingface.co/papers/2611.03852) · [项目页](https://debeltoni.github.io/ShortReasoning/)

- 不改权重，在工具结果揭晓前把之前的推理**重写成 compact state record**，再让模型基于压缩后的历史继续生成。
- 结果：被接受的压缩历史通常会缩短后续推理；代码 case 里减少了对同一个候选解的重复验证；软件 agent 部署中可以降低总花费。
- 代价说得很清楚：任务质量和「包含重写时间」的端到端时间取决于目标任务与压缩器，不是无条件赚。
- 数字：摘要没有给具体百分比。
- 工程意义：context engineering 可以从「截断 / 摘要」再往前一步——**改写模型自己的思路**，而且不改模型参数。

### 6. 监控准确率不等于决策价值（4↑）

Monitor Accuracy Isn't the Answer: A Decision-Value Framework for Evaluating AI Agent Restart Monitors · Intuit · [2610.36544](https://huggingface.co/papers/2610.36544)

- 论点：一个固定 **90% 准确率**的 restart monitor，对成功率的实际影响可以从 **-5 点**摆到 **+35 点**，只取决于重试时剩余预算下的成功概率。
- 两个工具：**decision-sufficiency criterion**（Blackwell 实验比较的二动作特化），判断某种进度表示 / context 压缩是否保留了做「重启还是继续」决策所需的信息；以及无模型的 **decision audit**，用同时二项区间在已有轨迹上认证偏好，证据不足就 abstain。
- 实验：SWE-bench Verified 的 19 个 SymPy issue、194 次外部评测执行、130 条回溯审计；2.29 点的表面 restart 收益来自单个幸存的失败尝试，另一个模型上是 **-42.29 点**；103 次在线比较没有一次达到认证门槛。
- 结论：评估监控器应该看 recovery opportunity、decision value 和统计支持，而不是分类准确率。

### 7. KernelSeek：用问题而不是工具堆（4↑）

Ask, Don't Equip: Question-Driven Coding Agents for Deep Kernel Optimization · Snowflake · [2611.03517](https://huggingface.co/papers/2611.03517)

- 批评两个极端：scripted agent 在配方适用时省样本、不适用就卡死；开放式 agent 让模型自由变异 kernel，用成千上万次评测换自由度。两边都靠「加工具」——profiler、反汇编、文档检索、经验库——但都缺一个**方向**：剩余差距到底在哪。
- 做法：通用 coding agent + 最小 harness（强制可验证目标）+ 在决策点提问；先由人提问，后来用一个问题库让 agent 自问。问题不缩小下一步的动作空间，只改变它看系统的层。
- 数字：同任务、同评测、同硬件、同一周内，工具丰富的自主 agent 在 **133** 个模型驱动步骤后停在 **0.50× FlashAttention-3**；KernelSeek 到 **1.13×**。随后产出 Hopper 与 Blackwell 上无依赖的 FlashAttention 前向，单 CUDA 文件、不用 CUTLASS/CuTe/cuBLAS/cuDNN，每个架构 **182** 个场景全对，几何平均 **1.16× FA-3**、**1.46× FA-4**。
- 分析：162 条人类消息、11.5K 次 agent 工具调用中，所有大增益都跟在「换一层看问题」或「否定一个自称极限」的问题之后，而不是跟在补充信息之后。

## 二、评测：完整科研、视频记忆与跨游戏解说

### 8. FrontierPhysics：让 agent 做完整物理研究（58↑）

FrontierPhysics: Evaluating Agents for End-to-End Physics Research · BenchFlow · [2611.06910](https://huggingface.co/papers/2611.06910) · [项目页](https://www.benchflow.ai/frontierphysics)

- 现有物理 benchmark 只考固定题、孤立子任务、或给定解法的论文复现，很少同时检查研究质量与正确性。
- FrontierPhysics 有 **56** 个任务，由 **42** 位物理学家按自己的研究设计，覆盖理论、计算、实验共 **9** 个领域；每个任务要求 agent 做文献调研、研究计划、实验、结构化输出和论文写作。
- 评分把**确定性 verifier** 与**专家 rubric** 结合，判断研究是否既正确又可发表。
- 数字：**22** 个模型、**26** 种配置，没有一种通过超过 **46/168** 次 rollout。
- 人工看轨迹后的结论：前沿 agent 的主要弱点是推理不够严谨、专家直觉不足，而不是物理知识缺口或执行错误。

### 9. VideoMemBench：记住看过与说过（31↑）

VideoMemBench: How Well Do MLLMs Remember in Video Conversations? · 机构未标 · [2610.40131](https://huggingface.co/papers/2610.40131) · [code](https://github.com/Oliiveralien/VideoMemBench) · [项目页](https://videomembench.github.io/)

- 提出 **in-context video memory**：多轮视频对话不仅要答当前问题，还要取回之前**看到**的内容和**自己说过**的话。
- 数据：**326** 个视频、**2,476** 个回合，其中 **1,387** 个回合依赖更早的回合；依赖分两类——Episodic Dependency（回指之前描述过的视觉片段）与 Answer Dependency（建立在模型自己之前的回答上）。
- 构造时逐条验证两个性质：**necessity**（没有前文就答不出）与 **non-leakage**（当前问题不复述前文信息）；用 planner / generator / judger 三个 LLM 角色加人工审核。
- 数字：20 多个开源与闭源 MLLM 中，Claude Opus 5 最好，整体也只有 **45.7%**。
- 意义：多轮视频的失败不一定是单题 VQA 能力，而是跨回合状态维持——这和 agent 的记忆问题是同一类。

### 10. StreamDuo：不会解说就去查 wiki（21↑）

StreamDuo: A Live Commentator and a Research Agent for Unseen Games · Alaya Lab · [2611.01120](https://huggingface.co/papers/2611.01120) · [code](https://github.com/ZixianGao/StreamDuo-code) · [项目页](https://zixiangao.github.io/StreamDuo/)

- 问题：现有直播解说模型训练和测试都在同一款游戏上，跨游戏时只迁移了「什么时候说话」的节奏，没有迁移游戏世界知识。
- 做法：可训练 commentator + 冻结 research agent。commentator 看到叫不出名字的东西就发当前帧，research agent 读该游戏 wiki，**2 秒后**返回几条条目，直播继续；只训练 commentator，且只在单一游戏（Baldur's Gate 3）上训。
- 训练两段：information-gain labels 教它只在「答案能帮它说出人类解说词」时提问；on-policy self-distillation 用一个能看到理想答案的自身副本，教它使用有噪声的检索结果。
- 数字：10 个未见游戏上 entity recall 从 **0.082** 提到 **0.116**（对比同数据训练的 Proact-VL）；source-game leakage 从 **9.9%** 降到 **1.0%**；timing 与人工评的生动性、整体质量都是 streaming 模型里最高。

### 11. SleuthVLM：不听音频也能做 omni（7↑）

SleuthVLM: Do We Really Need Audio-in-Video for Omni Video Understanding? · Ant Group · [2611.06083](https://huggingface.co/papers/2611.06083) · [code](https://github.com/WPR001/OpenOmniHarness) · [项目页](https://wpr001.github.io/sleuthVLM/)

- 问题：omni 模型通常把采样帧和音频放在一次前向里联合处理，进展主要靠模型规模与 omni 数据；但「必须直接听」这个前提本身没被检验。
- 做法：SleuthVLM 建立在 VLM 上，**从不直接听音频**——语音先转文本，再由 agent harness 自主查证视频，不预设 workflow。
- 数字：4 个 omni benchmark、视频最长 **90 分钟**，平均准确率 **75.0%**，比 Gemini 3.8 Flash 高 **2.6 点**；Video-MME-v2 以 **77.8%** 登顶；开源 **27B** VLM 超过所有开源 omni 模型。
- 结论：hearing 不是瓶颈，agentic ability 才是；omni 理解需要更好的 agent，而不只是更多模态对齐数据。
- 注意边界：这证明「音频可以用转写 + 主动查证替代」，不等于音频信息无用。

## 三、具身：VLA 去编码器，数据来自仿真与人类

### 12. NEO-VLA：动作策略不该只看到编码器终点（61↑）

From Pixels to Actions - Towards Native Vision-Language-Action Policies · MMLab@NTU · [2611.06918](https://huggingface.co/papers/2611.06918) · [项目页](https://www.lmms-lab.com/posts/neo_vla/)

- 问题：VLA 的默认前提是「视觉先被编码器压成固定表征，动作推理再开始」。但操作恰恰依赖最容易被这个抽象丢掉的信号：局部几何、边界、深度、细微状态变化。
- 做法：**structurally encoder-free**。图像由轻量 patch 卷积 tokenize，与语言一起在 backbone 中演化；flow-matching action expert 从不同深度抽取 instruction-conditioned 的视觉表征。
- 三个发现：受控比较下 native 架构优于 encoder-based；全参微调能缩小差距但消不掉；单纯加 scale 也补不回来。逐层 probing 进一步显示，**action-critical 信号经常在最终视觉表征之前就达到峰值**。
- 数字：摘要没有给具体数值，只有跨多种操作设置与分布偏移的一致趋势。
- 意义：视觉编码器的信息瓶颈是可测的结构问题，不是「模型不够大」；这对 VLA 的 backbone 设计是直接反例。

### 13. GameVerse：分钟级游戏视频（37↑）

GameVerse: A Minute-Scale Gameplay Dataset for Long-Horizon Interactive World Modeling · Alaya Lab · [2610.37257](https://huggingface.co/papers/2610.37257) · [code](https://github.com/kangverse/GameVerse) · [项目页](https://kangverse.github.io/GameVerse/)

- 问题定位很硬：交互世界模型 rollout 超过约 **1 分钟**就失去一致性，原因不是模型容量，而是长程训练数据稀缺——现有 gameplay 数据集 clip 普遍 **不到 10 秒**，caption 还是整段粗描述。
- 数据：**69.7K** 个 clip、**1,655 小时**、**3.496 亿帧**，覆盖第一/第三人称；其中 **1,358 小时**是连续两分钟序列，比之前的数据集长一个数量级。
- 管线：场景一致的分段、质量过滤、相机位姿估计、事件级 caption；caption 把静态场景上下文与动态前景事件分开，并按事件边界而不是固定时间窗对齐。
- 结果：规模、多样性、标注质量超过现有公开数据集；在其上训练能明显延长交互世界模型的时间跨度（摘要没给具体指标）。
- 意义：长视频生成的数据单位从「clip」变成「带稳定相机轨迹的分钟级事件序列」。

### 14. PyRUA-DataFarm：coding agent 当遥操作员（25↑）

PyRUA-DataFarm: LLM Agent as a Cost-Efficient Teleoperator for Real-Ready Robot Data · DAGroup-PKU · [2611.05320](https://huggingface.co/papers/2611.05320) · [项目页](https://dagroup-pku.github.io/PyRUA-Lean/DataFarm/)

- 问题：遥操作仍是采机器人 demo 的默认方式，每个 episode 都烧机器人和操作员时间，新任务从零开始。
- 做法：coding agent 收到数据请求和一条目标场景的校准 episode，就在仿真里重建任务——写场景、写专家控制器、写成功判据；仿真提供精确 action，视频模型以真实图像为条件把 rollout 渲染成照片级视频，多相机视角一致。独立 judge 先认证专家与每个渲染 episode。
- 数字：5 个真机任务上，只用 farm 数据训练的策略与等量遥操作数据打平——**100 次试验 93 胜 vs 84 胜**；在未见桌布和彩光下保持 **87 胜**，遥操作策略掉到 **46**。
- 成本：任务适配一次性约 **21 美元** API + **5 美元** render contract，之后每个 episode 平均 **0.80 美元**；一小时三视角数据约 **107 美元**，低于中国遥操作报价 **117 美元**、北美纯人工 **290 美元**。
- 意义：数据采集的成本结构从「人 + 机」变成「API + 渲染」，瓶颈转到仿真保真度与 judge 可靠性。

### 15. H2RB：用人类 demo 桥接新机器人（15↑）

Human-to-Robot Transfer via Bridging Representation and Action Space in VLAs · KAIST AI · [2611.04391](https://huggingface.co/papers/2611.04391) · [code](https://github.com/jun-brro/h2rb-code) · [项目页](https://junhyeong-park.me/h2rb/)

- 问题：预训练 VLA 适配新机器人仍要昂贵的本体数据；人类 demo 好采，但 human-robot embodiment gap 大，尤其当 VLA 主要在机器人数据上预训练时。
- 做法：**unpaired** 人类 / 机器人联合训练。**geometry-anchored alignment** 把两边观测落到兼容表征；**decoupled-decoder tokenizer** 共享 action latent，但不强迫两个域走同一个 action mapping。
- 数字：真机任务上 object transfer 从 **8.0** 提到 **51.8**；skill transfer 得到 **62.7**，而 co-train baseline 完全无法迁移人类示范技能；物体摆放偏移下 OOD transfer 从 **6.0** 提到 **45.3**。
- 意义：人类视频/动捕可以成为 VLA 的规模监督，前提是把「观测表示」和「动作头」分开桥接，而不是硬对齐。

### 16. PyRUA-REAL：把真机探索沉淀成技能（11↑）

PyRUA-REAL: Robot Exploration and Adaptive Learning through RSI in the Real World · DAGroup-PKU · [2611.06768](https://huggingface.co/papers/2611.06768) · [项目页](https://dagroup-pku.github.io/PyRUA-Lean/real/)

- 问题：coding agent 能把空间推理接到可执行机器人行为上，但这种改进能不能在物理交互后**持久保留**，而不是一次性脚本？
- 做法：embodied recursive self-improvement——agent 把交互经验存成 persistent memory 和可复用 executable skill，用执行反馈改代码，再部署；部署阶段不需要在线 agent 参与决策。
- 数字：8 个真机任务平均成功率 **91.1%**；RoboDojo 的 **42** 个任务上平均 **84.4%**。
- 意义：和 DataFarm 正好一对——一个负责「造数据」，一个负责把交互沉淀成「可复用程序」。

### 17. DRAP：按轨迹放大风险决定可塑性（0↑）

DRAP: Dynamics-Risk Adaptive Plasticity for Continual Learning in Physical AI · 独立作者 · [2611.05029](https://huggingface.co/papers/2611.05029) · [code](https://github.com/oswaldoludwig/DRAP-Dynamics-Risk-Adaptive-Plasticity)

- 问题：physical AI 的持续学习和普通 CL 不同——每一步的小误差会沿轨迹放大，把 agent 推出训练分布，最终导致闭环失败。
- 做法：replay-free。用 action gradient 乘以局部**轨迹放大风险**估计 tensor 的历史重要性；对一个 ridge 正则的局部线性模型，取状态转移矩阵最大奇异值，作为与策略无关、Lyapunov 式的一步扰动放大估计；每个任务后把风险加权平方梯度累进 tensor 级 importance memory，再用归一化累计重要性缩放各 tensor 的 AdamW 学习率。
- 实验：在 OpenVLA 的固定 KappaTune 子网上，对 LIBERO Spatial / Object / Goal 做无 replay 顺序适配；相比 AdamW 与 EWC，旧行为保留明显更好，同时新套件仍能学。
- 数字：摘要没有给具体成功率。
- 看点：把「灾难性遗忘」换成「闭环稳定性」的语言，重要性由动力学风险定义，而不是参数距离。

### 18. EmoReward：奖励权重从训练轨迹里学（25↑）

EmoReward: Self-Evolving Reward Calibration for Emotional Video Generation RL · Tencent Hunyuan · [2611.06518](https://huggingface.co/papers/2611.06518) · [code](https://github.com/Tencent-Hunyuan/EmoReward) · [项目页](https://emoreward-project.github.io/)

- 问题：情感表达没有唯一正确答案。固定 visual / motion / text 奖励抓不住情感意图，还容易被 reward hacking；RLHF 又难扩展，个体审美差异让面部、肢体、色彩的校准更麻烦。
- 做法：从**实际训练 run 的 reward traces** 里蒸馏 evidence reliability。先由情感 prompt 规划 grounding cues，再用异构信号 primitives 给生成视频打分；**Reflective Reward Gating** 用 phase、face confidence、conflict、subtlety 的 instance gate 校准各信号贡献并归一化；**RewardMemory** 在每个情感 regime 内估计 primitive 可靠性，下一轮训练用有界乘子校准融合权重，不更新 reward model。
- 实验：HunyuanVideo 1.5 上跨多个 RL 算法提升；在 SAGE-GRPO 下与其他 agentic reward 方法比较；SD 3.5 与 FLUX 上做迁移验证。
- 数字：摘要没有给具体数值。
- 看点：奖励权重不是人工调的，而是从「自己训练过程中哪些证据可信」估出来的。

### 19. VA-TDM：用速度场做少步蒸馏（12↑）

VA-TDM: A Unified View for Improving Few-Step Diffusion Models by Velocity Adversarial Distillation · 机构未标 · [2611.06796](https://huggingface.co/papers/2611.06796) · [code](https://github.com/Luo-Yihong/VA-TDM) · [项目页](https://luo-yihong.github.io/VA-TDM/)

- 问题：少步蒸馏依赖跟踪 student 不断变化的分布，但中间步的 student score 很难估，常用 estimator 描述的可能已经不是当前 student 分布。
- 方法：**Velocity Adversarial Distillation** 用 learned critic 比较 student 与 teacher 的速度场，把分歧变成学习反馈；它统一了 score distillation、Fisher-based matching、moment matching，并解释了已有的启发式 MMD 更新。
- VA-TDM 进一步做 trajectory distribution matching：沿 student 自己的采样轨迹给部分去噪监督，再加 transition-aware online velocity learning 与 dual-form VAD。
- 数字：四步文生图与文生视频上达到 SOTA，扩到 **33B MiniMax-H3**；VA-TDM-H3 的人类偏好明显超过少步 Fast-H3，靠近原始多步 H3。
- 意义：把蒸馏目标从「分数匹配」换成「速度场匹配」，监督位置可以落在轨迹中段，而不是只在端点。

### 20. VidDub：换语音后别再重建源嘴型（9↑）

VidDub: Replacement-Aware Distillation for Two-Step Video Dubbing · Tencent · [2611.03404](https://huggingface.co/papers/2611.03404) · [code](https://github.com/LAW1223/VidDub) · [项目页](https://law1223.github.io/viddub-project-page/)

- 问题：视频配音编辑器普遍用原音频做自重建训练，但驱动语音被替换后，源视频嘴型就是**冲突目标**，模型会往错误方向回归。
- 做法：**replacement-aware cross-audio supervision**。配对音频样本做全帧重建；替换音频样本遮掉源嘴区域的重建 loss，嘴只由音视频同步监督，未遮的面部和背景照常保留。
- 蒸馏：replacement-aware teacher 先学准确 lip sync 且不回归源嘴；matched trajectory regression 把 teacher 的 CFG 引导轨迹搬到两步 student；distribution matching distillation 补回画质。
- 数字：三个训练 seed 上，遮掉冲突源嘴使 cross-audio **Sync-C 提升 0.833**；最终两步模型在四个 benchmark 上同时保持同步、画质、身份和视觉语音识别。
- 意义：训练目标必须与「推理时输入会被替换」这件事一致，否则越训越会重建错误目标。

### 21. NitroFusion2：在文本流上做对抗蒸馏（8↑）

NitroFusion2: Bringing Adversarial Loss to the Text Stream of Multimodal Diffusion Transformers · SketchX · [2611.05648](https://huggingface.co/papers/2611.05648) · [code](https://github.com/ChenDarYen/NitroFusion2) · [项目页](https://chendaryen.github.io/NitroFusion2.github.io/)

- 观察：MMDiT 的 text stream 通过 joint attention 已经读过图像，同时仍绑定文本条件；所以改文本条件，会改变它从图中提取什么信息。
- 方法：**Text-Stream Adversarial Distillation** 用中间 text-token state 作为新的对抗表示，而不是只用图像特征；**Aspect-Cued Discrimination** 按 typography、objects、style 等 aspect 条件化判别器，控制对抗训练强调哪些属性。
- 数字：把少步蒸馏从常规 **4–8 步**压到 **1–2 步**且质量可比；1 步就能生成清晰文字与细粒度细节，2 步在评测上仍有竞争力。
- 看点：对抗蒸馏的判别特征不必来自图像；对多模态 DiT 来说，文本流本身就是一个可 steer 的判别空间。

### 22. LiveFoley：实时视频转音频（7↑）

LiveFoley: Dynamic Real-Time Video-to-Audio Generation for Immersive Interactive Worlds · 机构未标 · [2611.05988](https://huggingface.co/papers/2611.05988) · [code](https://github.com/dalision/livefoley) · [项目页](https://dalision.github.io/livefoley-page/)

- 问题：实时 streaming V2A 落后离线模型有两处硬伤——视觉前端为降 look-ahead 缩小感受野，损害音画对齐；causal AR diffusion 后端逐 patch 独立去噪，损害音质。
- 前端：**Trailing Sliding Window** 把非因果 segment encoder 直接变成 streaming 模块，无需重训；只重新对齐窗口就保住对齐，可配置 hop 把 look-ahead 压到人类感知阈值以下；**Unified Varhop** 适配不同延迟/算力预算。
- 后端：**History LocDiT** 加过去上下文，零延迟代价，作为默认；**Future-Warmup LocDiT** 用近似未来条件打破 AR 死锁，用可接受的后端 look-ahead 换质量。
- 数字：时间对齐匹配离线模型，生成质量领先 streaming 系统；摘要没有给具体毫秒数或分数。
- 意义：实时生成的关键是「窗口怎么滑、历史怎么带」，不是简单换一个更小的模型。

### 23. TaoMate-HD：渐进分辨率流式数字人（2↑）

TaoMate-HD: Progressive-Resolution Autoregressive Audio-Video Generation · TaoLive AIGC · [2611.03394](https://huggingface.co/papers/2611.03394) · [code](https://github.com/TaoLiveAIGC/TaoMate-HD) · [项目页](https://taoliveaigc.github.io/TaoMate-HD/)

- 问题：高分辨率去噪贵；文本更新会导致语音重复或中断。

- 训练：**continuation training** 使用非对称文本条件，生成与蒸馏各用不同文本窗口。
- 数字：同模型同硬件比直接高分辨率生成快 **1.6×**；stage-parallel 部署再快 **1.9×**；continuation training 把字符错误率降 **11.18 个百分点**；支持小时级音视频生成。
- 看点：分辨率与时间都被做成渐进式，历史按 stage 对齐——这是流式音视频能长时间不崩的关键结构。

### 24. UniRestorer++：按退化粒度扩专家（2↑）

UniRestorer++: Scalable Universal Image Restoration with Multi-Granularity Degradation Modeling · 机构未标 · [2611.06042](https://huggingface.co/papers/2611.06042) · [code](https://github.com/mrluin/UniRestorer_plusplus)

- 问题：通用图像修复缺少可靠 scaling 策略——加深加宽会饱和；degradation-aware 专家依赖准确估计，在 OOD 和真实输入上容易路由错。

### 25. Solv3R：从当前状态继续解几何（18↑）

Solv3R: 3D Looped Transformer as a Multi-view Solver · 机构未标 · [2611.02857](https://huggingface.co/papers/2611.02857) · [code](https://github.com/ubc-vision/solv3r) · [项目页](https://ubc-vision.github.io/solv3r/)

- 问题：经典 SfM 是迭代的，可以增量扩图、逐步细化；多数几何基础模型却是一次前向出全量，或按帧更新 recurrent state，扩图和细化都很别扭。
- 做法：looped transformer 学习**从当前状态继续解**多视图几何。update operator 与迭代次数无关，已解好的视角和新加入的视角可以联合更新，不管各自「解到什么程度」。
- 能力与训练：继续迭代时保持准确重建、能纠正不准确状态；固定图像集合可细化、新观测可接入、支持重定位与 streaming reconstruction；已解视角表征可缓存复用，形成 compact KV cache；论文还分析了 solver 动力学。
- 数字：摘要没有给具体数值。
- 意义：3D 基础模型也需要「可续算」的接口，而不是一次性预测；这一点和长上下文 / streaming 推理是同构的。

### 26. AnchorComplete：补全但保住已看见的几何（11↑）

AnchorComplete: Recovering Complete Scene Meshes from Partial Point Clouds · 机构未标 · [2611.03228](https://huggingface.co/papers/2611.03228) · [项目页](https://wrchen530.github.io/anchor-complete/)

- 问题：图像 3D 重建主要恢复可见表面，得到的是有大洞的部分点云，未观测几何没人负责。
- 做法：基于 **TRELLIS.2**。partial-point conditioning 把 global scene token 与 local spatial evidence 结合，把生成锚定在输入上；metric-scale coarse-to-fine 在固定大小窗口内逐步细化，同时保持全局结构一致。
- 结果：Replica 与 SCRREAM 上，完整场景重建稳定优于强 baseline，稀疏视角尤其明显；保留已观测几何，并支持不同尺度的场景。
- 数字：摘要没有给 PSNR / Chamfer 具体值。
- 看点：补全的目标不是「生成一个看起来合理的场景」，而是**在保住已看见部分的前提下**补未观测区域。

### 27. GaussianRenderFormer：不用光栅化器渲染 3DGS（3↑）

GaussianRenderFormer: Transformer-based Rendering of 3D Gaussian Splats · The Hebrew University of Jerusalem · [2611.05593](https://huggingface.co/papers/2611.05593) · [code](https://github.com/SVLwoof/gaussianformer) · [项目页](https://svlwoof.github.io/gaussianrenderformer/)

- 问题：能不能让 transformer 自己学会渲染 3D Gaussian splats，renderer 里完全不要 rasterizer？
- 做法：每个 Gaussian 作为一个 token，过 view-independent encoder；view-dependent decoder 把相机射线的小 patch 变成像素，通过 attend 这些 token 取信息。
- 数字：在 **26,820** 个 Objaverse 物体上训练，每个剪到 **20,000** 个 Gaussian；对 **300** 个未见物体，输出相对完整未剪枝 splats 为 **38.08 dB PSNR**，而同一剪枝输入用 rasterizer 是 **44.02 dB**。
- 诊断：差距不是泛化问题；把每个 Gaussian 的投影 footprint 告诉 decoder（它本可自己推断）能加 **1.4 dB**，指向 view decoder 瓶颈；作者也承认不能排除欠训练。
- 意义：神经渲染与显式表示的边界还在，但约 6 dB 的差距说明 rasterizer 的先验仍然很强。

### 28. Halley：光网络的预测控制面（33↑）

Halley: A Predictive Control Plane for Optical AI Data Center Networks · 机构未标 · [2611.04408](https://huggingface.co/papers/2611.04408)

- 背景：前沿模型在数万加速器上训练，每步结束所有卡同时交换数据；机架间是光网络，从 laser 到 switch 四层大多跑固定或事后策略。共享 enclosure、冷却、供电的 laser 会一起坏，固定 spare ratio 下 correlated failure 可证明地封顶 pool availability，pool 再大也没用。
- 做法：预测控制面，读每个资源的下一状态、在故障前动作。四个组件各带形式保证：**LightReserve** 给 laser pool 定覆盖界；**FoldFit** 的 switch 调度在最优的 **11/9** 以内；**ThermaLead** 对 microring 做一步前馈；**TriageGuard** 先保护最高风险模块。不确定时退回已部署策略。
- 数字：丢一个耗尽 spare 的窗口时，effective goodput 从 **65.2%** 提到 **76.5%**；只丢 dark channel 带宽时到 **67.4%**；每 MW 是训练的 **1.03–1.17×**；同训练量最多省 **3.3–14.7%** 数据中心容量。
- 工程细节：fallback circuit 经过形式验证，在商用 FPGA 上时序接近，过 **130 nm** signoff。
- 意义：训练集群可靠性要从「多买冗余」转向「预测 + 分层控制 + 形式保证」。

### 29. OPD 的泛化盲点（24↑）

On the Generalization Limitation of On-Policy Distillation for Post-RL Consolidation · ByteDance · [2611.05609](https://huggingface.co/papers/2611.05609) · [项目页](https://yichenzw.com/opd-generalization.github.io/)

- 现象：多教师 on-policy distillation 在分布内几乎完美——达到教师 IND 分数的 **96.04–102.73%**，但这会掩盖分布外的不完整合并：OOD 分数比 base model 还低 **2.45–16.25%**。
- 组合泛化更差：三个组合设置里，MOPD 提升了 IND，但 composed OOD 比最好教师低 **18.19–24.34%**。
- 原因定位到两个瓶颈：teacher capability 与 data coverage；两者同时缓解后，实验里的 OOD forgetting 消失。
- 更新几何：OPD 的更新平均更小、谱更集中，MOPD 的共享更新结构更多；据此提出 geometry-based patching 与 base-preserving replay，在基本保住 IND 的同时改善 OOD。
- 意义：蒸馏「看起来学会了」可能只是覆盖了监督分布；post-RL consolidation 必须单独测 OOD，不能只看 IND 平均分。

### 30. Muon-RT：用教师位移替掉动量缓冲（22↑）

MUON-RT: Reusing the Teacher's Trajectory for Momentum-Free Muon for LLM Self-Distillation · IIT Kanpur · [2610.41104](https://huggingface.co/papers/2610.41104)

- 观察：带 EMA teacher 的自蒸馏已经保留了学生更新历史，Muon 却还额外存一份 momentum buffer，增加长期训练内存。
- 做法：用 **teacher-student displacement** 替代 hidden weight matrix 的 momentum。作者证明这个位移编码了施加更新的指数加权历史，并在局部模型下平滑时间不相关噪声；实现上去掉径向分量、做谱归一化，再在 Newton-Schulz 正交化后与当前梯度混合。
- 数字：Qwen2.5-7B-Instruct 的 SDFT 上，比 AdamW 平均准确率 **+2.6 点**且持久内存 **-42%**；比 momentum Muon **+5.4 点**且 **-27%**；Olmo-3-7B-Instruct 的 SDPO 上比 AdamW **+2.0 点**。
- 意义：优化器状态可以复用蒸馏里已经存在的 teacher，省下的是长期占用的显存，而不是一次性的计算。

### 31. D3D：草稿不必等验证（18↑）

D3D: Decoupled Diffusion Drafting for Asynchronous Speculative Decoding · Fudan University · [2611.06425](https://huggingface.co/papers/2611.06425) · [code](https://github.com/fudan-generative-vision/D3D)

- 问题：target-conditioned diffusion drafter 虽然能一次前向出一个 block，但每个新 block 都要等更新后的 target hidden state，draft 与 verify 只能串行，端到端加速被锁死。
- 做法：standalone diffusion drafter，去掉 inter-round 依赖；blockwise denoising + auxiliary autoregressive supervision，在**不看 target hidden state** 的情况下得到长 accepted prefix；验证时用一个 packed pass 同时草拟后续 block，实现异步投机解码。
- 工程：按对 acceptance length 的影响逐层剪枝，**36 层剪掉 5 层**仍在三个 benchmark 上保留 **99% 以上**平均接受长度。
- 数字：7 个 benchmark 上，Qwen3-8B / 32B target 平均 **5.00× / 5.71×** 解码加速，DFlash 是 **4.03× / 3.67×**；GSM8K + Qwen3-32B 达到 **7.48×**。
- 意义：投机解码的瓶颈从「草稿模型多大」变成「草稿能不能不等验证」。

### 32. SpecOPD：把 on-policy 蒸馏也并行（15↑）

SpecOPD: Branch-Parallel On-Policy Distillation for Speculative Decoding · Qwen · [2611.02846](https://huggingface.co/papers/2611.02846) · [code](https://github.com/QwenApp/SpecOPD) · [项目页](https://qwenapp.github.io/SpecOPD/en.html)

- 关键观察：on-policy 监督不必继承 draft-and-verify 的串行依赖；一个 draft block 只用 reference prefix 和 draft-sampled history 就能被监督。
- 做法：branch-parallel OPD，在 reference anchor 上从演化中的 drafter 策略并行采多个分支；把这些分支 pack 成 proposal tree 共享 target-prefix 计算。full attention 用 tree mask，sparse attention 用 branch-consistent indexer group，linear attention 用 indexed state replay 保留各分支历史。
- 训练目标与规模：**E2E-TV surrogate** 直接优化 acceptance length，而不是代理的 token 准确率；实验覆盖 8B full-attention（GQA）、27B full-linear（GQA-GDN）、125B sparse-linear（QSA-GDN），三种并行 drafter（DFlash、DSpark、DFlash V2），以及对话、代码、数学、agentic 四类任务。
- 数字：平均 acceptance length 最多 **+41.45%**；native 配置下 supervised-token throughput 是 sequential-rollout OPD 的 **16.09×**；相对自回归解码最多 **3.56×**。
- 意义：蒸馏训练的吞吐本身也可以并行化，不只是推理阶段。

### 33. LoopVQ：looped 模型的 KV cache 按 loop 轴压（11↑）

LoopVQ: Sub 1-bit KV Cache Quantization for Looped Transformers · Seoul National University · [2611.05304](https://huggingface.co/papers/2611.05304) · [code](https://github.com/mscheong01/LoopVQ) · [项目页](https://mscheong01.github.io/loopvq/)

- 问题与观察：looped transformer 用重复层换参数效率，但每个 loop step 都存自己的 K/V，KV cache 随 loop 数线性增长，成为主内存瓶颈；同时 loop 轴上的 KV 高度冗余，不同 loop step 对量化的敏感度差别很大。
- 做法：跨多个 loop step 联合编码通道，并微调 codebook 去对齐全精度模型输出；设计与标准 LLM 的 KV 量化正交，可与 TaSQ 组合。
- 数字：**0.5 bit/element** 下，在 Ouro 与 Huginn 上的通用、长 CoT、长上下文检索任务都超过标准 LLM 的 KV VQ 方法；与 TaSQ 组合在 **0.25 bit/element** 仍保留大部分 BF16 精度。
- 系统数字：SGLang 实现下，**32K** context 解码延迟近乎减半；1.4B / 2.6B Ouro 的峰值服务吞吐分别最高 **4.3× / 6.1×** 于 BF16 baseline。
- 意义：looped 架构的显存账要按 loop 轴算，不能照搬标准 KV cache 的量化方案。

### 34. SIMPLE：把推理能耗写成四参数定律（9↑）

The SIMPLE Law for Energy Cost of LLM Inference · ECS Lab · [2611.03330](https://huggingface.co/papers/2611.03330) · [项目页](https://hf-mirror.com/spaces/ecs-lab/SIMPLE)

- 问题：token 按个计费，但每个 token 的能耗不同；每个 token 进入 KV cache 都会抬高后续 token 的成本。现有最准的能耗模型是拟合，不是定律——把架构吸进系数里，需要逐模型标定。
- 做法：从计算与访存复杂度推闭式表达式，覆盖 MHA 与 GQA；得到 **SIMPLE**，四个参数，分离 prefill 与 decode，decode 再分为 KV cache 成本与 next-token 计算。
- 精度：**13** 个 dense LLM、**6** 个家族、NVIDIA H100 上，**R² = 0.969**、**MAPE 11.97%**，比 SOTA 低 **3.1–3.5×**，且无需逐模型校准。
- 解释力与 agentic serving：prefill 能耗随 hidden dimension 二次增长；更激进的 GQA KV 分组比 MHA 每 token 最多省 **3×**；reasoning budget 拉到 **4.0×** 时，Intelligence per Joule 在中段达峰后最多降 **3.14×**；agentic 每请求能耗是 non-agentic 的 **13.0×**，prefix caching 去掉 **93%** 的 prefill 成本，但 KV cache 项不变，缓存后仍贵 **4.8×**。
- 意义：推理优化要报「每焦耳智能」，而不只是 tokens/s。

### 35. Multi-layer Indexer：让 indexer 与 attention 并发（5↑）

Multi-layer Indexer: Overlapping Selection and Attention in DeepSeek Sparse Attention · Writer · [2611.03768](https://huggingface.co/papers/2611.03768) · [code](https://github.com/ArjunKrishnak/dsa-multi-layer-indexer)

- 问题：DSA（DeepSeek-V3.2 与 GLM-5 家族）每层前都有一个 lightning indexer 扫全 cache、保留 **k=2048** 个 token；长上下文下 decode 时间花在 indexer 扫描上，而不是它喂给的稀疏 attention。
- 观察：相邻层选中的 token 几乎一样，所以某层可以直接用上一层 indexer 的选择，解除「本层必须先算 indexer」的依赖，让 indexer 与当前层 attention 并发。
- 实现：MLI 不需要重训、不增加权重；默认实现不改 kernel，直接跑在 SGLang 生产 decode graph 里；可选 fused decode kernel 在 DeepSeek-V3.2 上再加速；还能与 IndexCache（GLM-5.2 的 IndexShare）组合。
- 数字：相同 retention 下，1/2 时比 IndexCache 快最多 **14.5%**（DeepSeek-V3.2）/ **9.8%**（GLM-5），1/4 时 **7.9% / 5.1%**，上下文越长差距越大；128K、1/4 retention 达到未修改模型 **1.32×** 的 decode throughput，高于 IndexCache 1/8 的 **1.28×**，同时保留两倍的新鲜选择，LongBench、RULER、LongBench v2 准确率在几个点内。
- 意义：稀疏 attention 的瓶颈常在「选哪些 token」，不在「算 attention」。

### 36. MSafeTemp：多语言安全不能只翻译英语数据（8↑）

How I Aligned Your Model: Scaling Up Multilingual Safety Training with Templates · Swiss AI Initiative · [2610.40516](https://huggingface.co/papers/2610.40516) · [code](https://github.com/swiss-ai/msafetemp) · [项目页](https://swiss-ai.github.io/msafetemp)

- 问题：安全对齐高度偏英语，低资源语言覆盖不足；现有开放数据要么规模小，要么缺少地区本地化的有害话题。
- 做法：模板增强管线——从有害 prompt 抽安全模板，翻译后用文化上真实的实体填槽，有害与良性样本都填；发布 **MSafeTemp**，覆盖 **60** 种语言，经过验证。
- 发现：只用英语评测会误判多语言安全——一些在英语里失败的攻击，翻译后成功；文化本地化变体还能暴露翻译本身漏掉的失败。
- 结果：模板增强提高了英语以外的安全表现（摘要没给具体分数）。
- 意义：多语言安全不是把英语数据翻译一遍，实体、话题和评测都要本地化。

### 37. VeriSpoof：一个音频 LLM 做五件取证的事（5↑）

VeriSpoof: Beyond Real or Fake with One Audio LLM · The University of Melbourne · [2611.04634](https://huggingface.co/papers/2611.04634) · [code](https://github.com/swagshaw/verispoof) · [项目页](https://swagshaw.github.io/verispoof/)

- 问题：语音 deepfake 检测器只回答真/假，但取证还要问：哪个生成器、两段录音是否同源、证据是什么。
- 做法：一个 audio LLM 共享权重做五个任务——检测、生成器归因（generator / acoustic model / vocoder）、录音条件分析、合成片段定位、来源验证；每个判断附可独立核验的 rationale，用 sentence likelihood 打分，检测与来源验证不需要单独 head；反事实样本训练「按证据决策」。
- 数字与成本：14 个 Speech-DF-Arena 测试集上，VeriSpoof-Plus pooled **EER 2.14%**，28 个系统里第三、开源第一；Base 只用 8 个语料官方训练集，**EER 4.43%**，不到次优开源检测器的一半；同权重下来源验证 **6.2% EER**；只更新 **2.85B** 参数中的 **29.7M**，单张 **24GB** GPU 加 gradient checkpointing 可训。
- Rationale 的效果：PartialEdit 上 **99.6% vs 78.4%**；面对训练中没见过的编辑仍能 **99.5%** 做对。
- 意义：取证模型要输出「可核验的句子」，而不是一个黑箱分数。

### 38. KGO：单步生成的概率时序预测（3↑）

Koopman Generative Operators for Efficient Probabilistic Time-Series Forecasting · The Sequential Learning Group · [2611.04760](https://huggingface.co/papers/2611.04760) · [code](https://github.com/azencot-group/KGO)

- 问题：概率时序预测要同时有结构化的时间动力学、表达性不确定性和高效推理；latent dynamics 太死，diffusion / flow matching 又太慢。
- 做法：**Koopman Patch Embedding** 做时间一致的 latent 轨迹外推；**Koopman Flow Matching** 用 Koopman latent 空间里的闭式矩阵指数做单步生成，绕开迭代采样；**Adaptive Uncertainty Gate** 按变量与预测步长自适应分解 aleatoric 不确定性，不用手工调。
- 数字：ProbTS 的 **17** 个 benchmark 中，**13** 个 CRPS 第一、**16** 个 NMAE 第一；推理时间比迭代生成模型至少 **25×** 降低。
- 意义：单步生成不必牺牲不确定性，关键是把动力学结构放进 latent，而不是把采样步数硬压到 1。

### 39. HERIT：用检索造伪标签翻译历史档案（1↑）

HERIT: Enabling Global Access to Hanja-to-English Historical Translation by Mitigating Temporal Bias · DAMI Lab · [2611.04949](https://huggingface.co/papers/2611.04949) · [code](https://github.com/dandamdandam/HERIT)

- 问题：Hanja-Korean 历史档案因语言壁垒难以全球使用；人工翻译太贵，直接套现成 MT 又处理不了语言细节，以及稀缺人工标注带来的**时间偏差**。
- 做法：用 RAG 从大量 Hanja-Korean 语料生成高质量伪标签，扩大训练集，缓解数据稀缺与跨历史时期过拟合，再做领域适配。
- 结果：自动与人工评测都稳定优于 baseline；并用该模型翻译了档案中此前未翻译的部分。
- 数字：摘要没有给 BLEU / COMET 具体值。
- 意义：低资源历史文本的可行路线是「检索造数据 + 领域适配」，而不是从零硬训一个翻译模型。

## 今天的三个观察

1. **长程能力的问题被拆成了「信用分配」和「状态携带」两件事**。 TurnWise 把 GRPO 的 advantage 从整条轨迹拆到每个回合，多轮 RL 那篇证明收益依赖回合预算，VideoMemBench 则说模型连「自己上一轮说过什么」都记不住。三条线指向同一个工程结论：**先把 credit 和 state 的粒度对齐到交互回合，再谈更大的模型**。

2. **Agent 的进步越来越像系统工程，而不是模型能力**。 HCU 的三通道接口、TAC-CoT 的文本/潜空间分段、推理历史重写、KernelSeek 的提问策略、restart monitor 的决策价值——这些工作的涨点都来自**接口、预算、控制点**，而不是换一个更强的 base model。反过来说，做 agent 产品时，这些「外围」才是可积累的护城河。

3. **推理系统开始算物理账**。 Halley 报的是 goodput 和机柜容量，SIMPLE 报的是每焦耳智能，D3D / SpecOPD 报的是 acceptance length，LoopVQ / MLI 报的是 KV cache 驻留与 decode 吞吐。共同的转向是：**效率不再等于 tokens/s**，而要看在真实约束（功率、容量、显存、延迟）下能交付多少有效训练或有效回答。OPD 那篇则从另一侧提醒：合并能力时如果只盯 IND，OOD 可能悄悄退化——**省下来的账，可能在分布外还回去**。
