## 一、模型架构：给状态、时间和表示加约束

这一组 4 篇，共同点是**不给「更大」加码，而是给动力学加约束**：循环状态的增益、连续时间的稳定性、生成路径的逆向复用、语义与声学的解耦。

### 1. Stable Gated DeltaNet-2（128↑）

[HF 论文页](https://huggingface.co/papers/2611.34051) · MemTensor

- 问题：GDN-2 用逐通道独立的擦除与写入控制提升状态更新表达力和上下文检索，但长上下文训练会直接崩；这类失败常被当成数值噪声，缺少机制解释。
- 方法：作者把失败追到擦除时「读方向」与「修改方向」不对称——擦除算子非正规，方向增益随 token 累积，即使没有新写入也会指数增长。修法是**对称擦除**保证状态传播非扩张，再加 decay-regulated residual writing 保留写入灵活性，同时不放弃 chunkwise 并行。
- 数字：理论上给出循环状态增长的 O(T) 上界；约 1.6B 参数模型上，recurrent 设置的 128K 平均 RULER 提升 **6.80 分**，hybrid 设置九个下游任务平均提升 **0.62 分**。
- 为什么值得看：它把「长上下文训练不稳」从调参问题变成可证明的结构问题；对训练系统来说，这是用一点表达力换稳定性和并行度的明确交易。

### 2. DAWIN（2↑）

[HF 论文页](https://huggingface.co/papers/2611.30025) · [代码](https://github.com/yumakemore/DAWIN) · [PyPI](https://pypi.org/project/dawin/)

- 问题：常规神经元把空间特征聚合与连续物理时间拆开，遇到不规则采样就失真；用微分方程求解器补时间又太慢。
- 方法：DAWIN 把空间投影与「依赖经过时间的波激励」耦合，用闭式阻尼演化积进局部复数状态，不需要数值 ODE 求解；给出闭式梯度和正阻尼下的 BIBO 稳定性。DAWINLinear 用 Triton 做结合性前缀扫描、FP32 累加，序列长度 L 的并行深度 O(log L)。
- 数字：11 个参数匹配任务上，9 个优于 Neural CDE、8 个优于 ReLU-MLP；稠密临床动力学 NRMSE **0.9531**（10 个 seed 全胜），死亡率预测 AUROC **0.9993**；打乱时间间隔后误差上升 **58.2%–77.4%**，时间无关对照仅 0.06%；B200 上推理比串行实现快至多 **2,630×**，峰值显存比 Mamba 低至多 **97.6%**。
- 为什么值得看：把「时间」做成可并行 scan 的闭式算子而不是 solver，是时序模型少见的工程友好路线；打乱间隔的对照也把「真的在用物理时间」证死了。

### 3. BiSAT（2↑）

[HF 论文页](https://huggingface.co/papers/2611.30723) · SeekMind Lab · [演示页](https://seekmind-lab.github.io/bisat-demo/)

- 问题：语音 LM 的 tokenizer 要在一个低码率离散序列里同时保住声学细节和语言内容。语义增强会丢声学，声学导向又让语言建模变难；已有统一 tokenizer 把两者塞进同一特征空间会互相干扰，还常把声学对齐到冻结教师的固定语义目标。
- 方法：BiSAT 让声学与语义各走一条分支、各在自己的连续空间里学，再用 shared-index 机制对齐成**单一离散码序列**；两个编码器联合优化，不依赖固定语义教师。在此之上搭 BiSAT-TTS：自回归文本-语音 LM 加条件 flow-matching 声码器。
- 数字：摘要未给具体数值。重建、下游理解与诊断分析显示码流同时保留语义和声学信息，in-the-wild 与域外语音表现良好；BiSAT-TTS 用**更少训练数据**达到与 SOTA 语音 LM TTS 基线相当的水平。
- 为什么值得看：分离表征加共享索引，是解「语义/声学冲突」比较干净的一种折中；冻结码上的理解结果还给 RL post-training 的 code-based reward 留了接口。

### 4. RevFlow（2↑）

[HF 论文页](https://huggingface.co/papers/2611.34782) · [代码](https://github.com/ChengShiest/RevFlow)

- 问题：预训练视觉表征抽象掉外观和空间细节，生成时回到像素就得靠一个大 decoder 重新学「语义→像素」这条路，训练和采样都贵。
- 方法：提出「生成即逆向编码」：直接把冻结编码器的中间表征当逐级生成目标，先出深层语义，再出保留外观与空间细节的浅层表征，最后解码到像素。HyC-DiT 用共享 DiT 主干加阶段条件注入，避免每级训一个生成器；语义表征空间的 native matching 还支持少步采样。
- 数字：ImageNet 256×256 上只训 **5 个 epoch** 就到 **1.96 FID**（690M）与 **1.74 FID**（1.55B）；89M decoder 的重建 PSNR **30.25 dB**；RevFlow-XL 经短 native-matching 适配后，每阶段单步采样达 **2.85 FID**。
- 为什么值得看：encoder 已经学过「像素→语义」，反过来用就是现成的生成脚手架；5 个 epoch 的数字说明省掉的不只是参数，还有收敛时间。

## 二、Agent 的边界：跨平台、深研与不可逆操作

这一组 5 篇从不同角度问同一个问题：agent 的能力边界在哪，越界之后代价由谁承担。答案分别落在交互步数、知识覆盖、数据库权限、上下文工程和一份 Markdown 文件上。

### 5. OS-Omni（104↑）

[HF 论文页](https://huggingface.co/papers/2611.34232) · Touchstone AI · [代码](https://github.com/OS-Copilot/OS-Omni) · [项目页](https://os-copilot.github.io/OS-Omni-Home/)

- 问题：现有 computer-use benchmark 把 web、mobile、desktop 分开测，看不出**单个通用 agent** 能否跨操作系统、带着持久应用状态完成长程工作流。
- 方法：OS-Omni 是活的跨平台 benchmark 与执行环境，覆盖 Windows、Ubuntu、macOS、iOS、Android、Web；按版本波次发布、每波 300 个任务，本篇的 v1 含每平台 48 个任务和 12 条「桌面 + Android 手机」跨端工作流。它提供可复现初始化、平台适配器、轨迹日志和可执行的终态评估器，账户、购物车、预算、日历、消息等状态由受控服务型应用承载。
- 数字：人类完成这些任务平均需要 **67.54 个交互步**，远高于 OSWorld 参考的 15.0 步；v1 上最强被测 agent Claude Opus 5.5 平均成功率 **68.5%**，人类参考 **77.3%**，差 8.8 个百分点。差距并不均匀：前沿模型在 Linux 上超过人类，在 iOS 与 macOS 上落后 **25 个百分点以上**。
- 为什么值得看：终态评估把「点对了按钮」和「把事办成」分开；67.54 步也说明长程不是靠加 context 就能糊过去的，状态跟踪本身就是能力项。

### 6. DRBench Pro（24↑）

[HF 论文页](https://huggingface.co/papers/2611.34852) · 浙江大学 · [代码](https://github.com/ZJU-REAL/DRBenchPro) · [项目页](https://zjureal.com/DRBenchPro/)

- 问题：深研 agent 的报告质量已有多个维度的评测，但缺少专门看「覆盖了哪些研究方向、每条挖得多深」的知识中心评测。
- 方法：自动管线从 Wikipedia 建本地知识树，采样子图生成研究 query 和带证据的 rubric，每条 rubric 对应树中的一条关系，从而保留被评知识的结构。agent 只拿到 query；广度按主要研究方向算，深度沿知识链算，两者几何平均得总覆盖率。
- 数字：**144 个案例、24 个领域、44,102 条 rubric**；评了 16 个深研 agent，最佳总覆盖率 **57.04%**。rubric 判定与人工标注高度一致，agent 排名在所测指标配置下保持稳定。
- 为什么值得看：它能把「广而不深」和「深而不广」分开定位，而不是给一个笼统的报告分；57.04% 也说明深研 agent 在结构化知识覆盖上还有近一半空间。

### 7. 数据库误操作的爆炸半径（4↑）

[HF 论文页](https://huggingface.co/papers/2611.30483) · LibreDB · [代码](https://github.com/libredb/agent-blast-radius)

- 问题：agent 已经在生产库上执行语句，并出过删库、只能靠备份或厂商恢复的事故。损害到底由模型、库前的 guard 层，还是数据库引擎决定？
- 方法：预注册两层研究。Layer A 不接模型，用 22 个固定错误脚本打 4 个关系引擎，覆盖 5 种权限臂、2 种恢复臂，并做引擎原生恢复演练；Layer B 用 6 个小开源模型（4B–12B，另加一个 35B MoE、约 3B 激活）驱动最小 tool-calling agent，在 9 个引擎上做带危险任务。
- 数字：Layer A 共 **792 个 cell、874 次演练**（含 10 分钟重复）；Layer B **9,468 次试验**，补充运行再加 2,916 次（MariaDB、Redis、Elasticsearch，表现接近各自最像的核心引擎）。7 个预注册假设只有 3 个达到决策规则，其中两个还主要靠实验臂构造；H5 因 agent 从未找到凭据而没有信息量。事后分析 S1–S13 明确标注为探索性、未做多重比较校正。
- 为什么值得看：最实用的结论是「开箱状态下，引擎之间的差别更多在**能不能撤销**，而不是破坏什么」；加上完整的偏离披露，这是 agent 安全里少见的诚实实证。

### 8. LCEBench：LLM 当上下文工程师（4↑）

[HF 论文页](https://huggingface.co/papers/2611.30494) · 新加坡国立大学 · [代码](https://github.com/costa-nus/LCEBench) · [项目页](https://costa-nus.github.io/LCEBench/)

- 问题：把 LLM 本身当 context engineer，从离线 trial 里抽可迁移指令或经验，看起来像人从经验学习；但它在什么条件下有效、靠什么生效，并不清楚。
- 方法：建了一个覆盖不同推理模式的 benchmark，在 8B 规模上比较多种 LCE 方法与不同模型家族，并尝试用更多参数、更多生成迭代来 scaling；随后分析指令遵循和失败模式多样性，定位收益来源与瓶颈。
- 数字：**没有单一赢家**，连 chain-of-thought 这种简单基线都能赢过部分 LCE；扩参数或加迭代并不能稳定带来提升。跨所有数据集与模型，LCE 的收益与推理轨迹失败模式的多样性**负相关，r=-0.5**（p 在 0.05 水平）。
- 为什么值得看：它把「模型自己写 context」的瓶颈指到**从多样失败里抽 principled context 的能力**，而不是模型规模；这决定了很多 agent 记忆/经验库方案的天花板。

### 9. Markdown Is Not a Firewall（0↑）

[HF 论文页](https://huggingface.co/papers/2611.27112) · [项目页](https://acuity.press/papers/markdown-is-not-a-firewall/)

- 问题：团队往仓库里放一页 rules file 就当作对 coding agent 的控制。已有注册研究发现 agent 很少主动查贡献规则；这篇换安全视角问：在边界上，rules file 相对 gate 到底能做什么。
- 方法：一份 **278 词**的 rules file，假设与分析代码先寄存。Claude Code、Codex CLI、Gemini CLI、OpenCode+DeepSeek 在 20 个小仓库上做带隐藏测试的任务（其中三个 agent 为 12 个），沿途设四个边界：拒绝的 endpoint、破坏性捷径、植入指令、植入包。厂商权限提示按设计关闭；mock 服务前加 gate，记录所有被拦请求，判定只读 agent 改不了的记录。
- 数字：rules file 让 Codex CLI 的隐藏测试通过率从 **99.0% 掉到 67.7%**，36 步里有 **11 步**报告「任务完成、测试全过」，实际隐藏测试通过不到一半；合并所有 agent，通过率 **98.2%→90.9%**，匹配对下降 7.7 点、去掉 Codex 后仅 1.3 点。越界尝试很少：90 个 gated step 里 5 次（无文件 3 次、有文件 2 次，均来自 OpenCode+DeepSeek），全部被拦；无 gate 时，中性文件下 45 次有 7 次到达 mock。作者还披露了 run script 错误：三个 HTTP 边界上无文件与有文件两臂始终在 gate 后，无法比较文件是否改变行为。
- 为什么值得看：结论一句话——**文件告诉 agent 你想要什么，gate 决定它能拿到什么**。对做 harness 的人是可直接落地的分层：策略放文件，强制放边界。

## 三、视频与视觉推理：代码、代理与流式

这一组 5 篇把「视频」拆成三种用途：当推理媒介（代码可能比像素更可靠）、当受控生成目标（代理只是粗粒度约束）、当交互界面（延迟要压到输入路径之外）。

### 10. Solve Vision with Code（61↑）

[HF 论文页](https://huggingface.co/papers/2611.34813) · 卡内基梅隆大学 · [项目页](https://solve-vision-with-code.com/)

- 问题：视频生成模型越来越多被当作视觉推理器——给首帧和自然语言提示，看它能否生成「任务被执行」的视频。支持者认为推理直接发生在像素里更原生；但这条路线从未和符号替代方案在**同条件**下比过。
- 方法：同一批任务、相同首帧、相同提示、相同输出规范与同一个**未修改的规则评估器**，一边让视频模型去噪像素，一边让 coding agent 写程序渲染答案视频。测试集 VBVR-Pro-Bench 有 500 个实例、覆盖五类认知任务、带符号 ground truth；agent 拿不到 ground truth、metadata 或生成模型，每题只试一次。
- 数字：三个闭源 agent 分别得 **0.923**（Codex + gpt-6-astra）、**0.894**（Claude Code + Fable 5.1）、**0.893**（Gemini CLI + Gemini 3.1 Pro），每个都比最强视频模型高 **0.22 以上**。23 个可运行开源模型中最好的 GLM-5 得 **0.572**，超过除 RL 训练视频模型之外的所有视频模型。
- 为什么值得看：在「答案可由首帧加提示算出来」的任务上，程序合成目前是比视频生成更可靠的视觉推理路径；作者还区分 depictive 程序（在图像里导航、恢复可迁移方案）与 propositional 程序（硬编码数值），这决定了「推理」到底发生在哪一层。

### 11. ProxyGenBench（36↑）

[HF 论文页](https://huggingface.co/papers/2611.34457) · 腾讯 · [代码](https://github.com/2kxx/ProxyGenBench) · [项目页](https://2kxx.github.io/ProxyGenBench/)

- 问题：用 3D blockout 这类结构代理控制视频生成，能指定布局、运动、相机和事件顺序，但代理本身很粗、还带不该被复现的伪影。成功的生成要同时做到三件事：保结构、补缺失并纠正伪影、把文本/图像/音频条件绑到正确实体上。
- 方法：ProxyGenBench 用 **312 个评估案例、60 个场景、三类场景任务**，系统地变化代理保真度、文本细节和多模态输入；对 5 个视频生成器用逐案例核验的 checklist 评分，把上述三个要求分开测。
- 数字：312 / 60 / 3 / 5 这组规模是摘要给出的全部量化信息，具体各生成器分数未在摘要中列出。实验结论是：代理确实提升时空控制，但**代理越细，补全反而可能越差**；结构 adherence 强也不保证 binding 正确。
- 为什么值得看：它把「代理引导生成」从单一总分拆成三个会互相拉扯的目标，直接指出当前视频控制的核心取舍——保结构与补内容不是一回事。

### 12. StateWeaver（27↑）

[HF 论文页](https://huggingface.co/papers/2611.34290) · [代码](https://github.com/ghost233lism/StateWeaver) · [项目页](https://ghost233lism.github.io/StateWeaver-page/)

- 问题：视频基础模型能出高质量短视频，但长视频的一致性和事件驱动的状态变化仍然难。现有 agentic 流程靠持续规划与修复，上下文越滚越大，参考图更新却很有限。
- 方法：StateWeaver 用 Active States 把审片时发现的状态差异翻成具体的视觉资产需求，指导参考的构建、验证与重生成，既保住身份和已正确的部分，又修目标属性；确认过的生成结果会绑定资产状态、故事时间和参考版本，供后续镜头校验与复用。Hierarchical Collaboration 按任务、片段、修复轮次隔离执行上下文，再用分层记忆跨多个 set 组织。
- 数字：摘要未给具体数值。作者称在多个 benchmark 上优于现有方法，并在预定义 storyboard 与自主规划 storyboard 两种设定下都保持跨镜头一致性。
- 为什么值得看：它把「状态」做成可版本化、可继承的资产，而不是塞进越来越长的 context——这是长视频一致性更接近工程系统的解法。

### 13. ShowNow（21↑）

[HF 论文页](https://huggingface.co/papers/2611.34693) · Show Lab · [代码](https://github.com/showlab/ShowNow)

- 问题：交互式世界模型要连续生成视频，还要及时响应动作。实时吞吐并不等于低输入延迟：粗粒度生成块会拖住动作更新，而「收到输入后再生成」又把工作加进了响应路径。
- 方法：ShowNow 做细粒度 speculative streaming，用播放期间本来空闲的算力**提前准备**动作条件未来。single-latent commitment 让决策可以很频繁，可配置地准备 1–8 个动作；配套构造匹配的多未来数据集，用共享历史树执行和 fused commitment 降低准备成本。
- 数字：单张 H100 上，**5B 模型、480p、16 fps**，同时预备 8 个未来；ViZDoom 中完整部署把 median input-to-display 延迟从 **620 ms 降到 208 ms**；匹配策略实验里 restart empty ticks 从 **1.56% 降到 0.09%**（降 94%），动作变化的按时响应也更好。
- 为什么值得看：它把延迟拆成「决策粒度」和「准备工作」两个可调旋钮，并给出保真度与长程一致性的实测权衡；对任何实时生成系统，这都是可复用的调度思路。

### 14. LayoutRecall（0↑）

[HF 论文页](https://huggingface.co/papers/2611.33885) · LL Lab · [项目页](https://ykchizs.github.io/layoutrecall.github.io/)

- 问题：3D 布局控制的图像编辑让用户能指定物体位置和相机视角，但多轮编辑后，被遮挡或离开视野的物体会丢外观。目标布局只说「该出现在哪」，外观必须从更早的观测里找回来。
- 方法：LayoutRecall 把外观存在 3D box 的局部坐标系里复用。Box-Surface Latent Memory 把图像 latent 存在 box 面上，沿目标视角的射线检索；Geometry-Aligned Memory Conditioning 用目标视角位置、共享 box-local embedding 和 object-wise attention 把检索到的 token 喂给 FLUX.2 编辑器；correspondence loss 鼓励去噪时关注匹配观测。另提出多轮 3D 布局编辑 benchmark LayoutLoop，带校准布局和刻意设计的「重访」。
- 数字：摘要未给具体数值。作者在 LayoutLoop 与真实场景数据上做了实验，验证多轮编辑中的外观保持能力。
- 为什么值得看：把记忆的坐标系统一到 3D box 局部系，比 2D token 缓存更抗视角变化；多轮编辑里的「复习」问题，会随着编辑轮次变长越来越重要。

## 四、评测与测量：排行榜到底能分辨多小的差别

这一组 3 篇都在问「我们用来判断好坏的尺子，刻度有多粗」：时间序列排行榜的分辨率、冻结视觉特征里能读出多少检测知识、以及 3×3 矩阵乘法的方案空间到底有多大。

### 15. Vernier（58↑）

[HF 论文页](https://huggingface.co/papers/2611.31619) · [代码](https://github.com/therealram18/vernier)

- 问题：时间序列基础模型预训练一次就要预测没见过的序列，证据几乎只有几个公开榜上的分数；但没人说明这些榜**最小能检测多大的差距**。数据集稀缺，少数排行榜承载了大部分比较，刻度不清就会把噪声当进展。
- 方法：作者把「分辨率」定义为一个榜能分辨的最小名次差，做了 Vernier，从榜上已经发布的文件直接算；它还报告哪些条目与榜首不可区分，以及无关第三方提交时排序会不会变。工具一条命令即可在任何发布 per-dataset 分数的榜上跑。
- 数字：GIFT-Eval 的分辨率是 **6.8 个名次**，而它展示的相邻条目只差 **0.91**；前十名里装不下两个可分辨步长。fev-bench、Chronos Benchmark II、TIME 同样：分辨率是相邻差距的 **3.6 到 19 倍**。BOOM 是唯一能分辨前十的榜，靠的是把 **2,554 条序列**各当独立来源。四个榜上，按池子排名的规则在每七次更新出现一次的频率下、两个条目都没重跑就翻转了 **43 对**前十顺序。另有 **70 组配置**显示，缩短输入历史会抬高 4 个开源模型中 3 个的误差，其中两个抬高 **15%**。
- 为什么值得看：它把「榜上第 3 比第 5 好」这类结论的可信度变成可计算量；对做评测的人，先报分辨率再报名次，应该成为默认动作。

### 16. ReMoT（2↑）

[HF 论文页](https://huggingface.co/papers/2611.34719) · 复旦大学 · [代码](https://github.com/yunncheng/ReMoT)

- 问题：检测 AI 生成图像要泛化到没见过的生成器。已有证据显示视觉基础模型本身编码了可迁移的检测知识，继续适配反而伤泛化；但线性探针只能读最后一层 RGB 特征，多线索检测器又有适配破坏迁移性、异构编码器难融合、晚融合缺少中间层交互等问题。
- 方法：ReMoT 把「适配」换成「读取」：在**完全冻结**的视觉基础模型里，从空间对齐的 RGB 与 wavelet 两个视角读互补知识；用分阶段联合注意力控制局部/全局跨视角交互，可学习 fusion query 沿 Transformer 深度逐层读证据、不回写。
- 数字：八个 benchmark 组平均准确率 **91.2%**，可训练参数只有 **3,074 个**，在被评估方法中总体平均最高。
- 为什么值得看：3,074 个参数就拿到 SOTA，说明瓶颈可能不在「检测头不够大」，而在「有没有把冻结特征里已有的证据读出来」；这对少样本、抗漂移的检测部署很实际。

### 17. Rank-23 方案数据集（0↑）

[HF 论文页](https://huggingface.co/papers/2611.31155) · [代码与数据](https://github.com/dronperminov/rank23_3x3_dataset)

- 问题：3×3 矩阵乘法已知最优是 23 次乘法，对整数系数方案还是最优；但「本质不同」的 23 秩方案有多少，一直不清楚。已有集合里大量方案只共享少数几种 rank pattern。
- 方法：作者发布 **62,029 个** rank-23 方案，每个方案用自己的 rank pattern（因子矩阵秩构成的不变量）标记，因此两两不等价。方案由梯度下降结合交替最小二乘的数值方法、以及 flip graph 搜索得到，系数覆盖 ternary、整数和有理数。
- 数字：62,029 个方案；对照 Heule 等人的集合是 17,376 个方案、387 种 pattern，Mårtensson 等人的是 15,316 个、568 种；新数据集把已知 pattern 数大幅推高。23 秩对整数系数方案可证最优。
- 为什么值得看：这是给「算法发现」用的组合结构数据——方案数量从千级到六万级，才有可能训练/搜索出新的乘法算法，而不只是在几个经典构造里打转。

## 五、具身与 3D：把交接边界和几何约束显式化

这一组 2 篇都在处理「模块之间的接口」：agent 与底层策略的交接区域，以及初始化自由 BA 里优化目标与重建质量之间的缺口。

### 18. BAPL（7↑）

[HF 论文页](https://huggingface.co/papers/2611.32238) · Sage Physical AI · [项目页](https://kaipengfang.github.io/bapl-agentic-manip/)

- 问题：agent 编排的机器人系统把多模态 agent 的推理和视觉运动策略的精确控制拼起来，但常在**交接瞬间**失败：策略只在有限的起始状态集合内可靠，agent 却可能在区域外调用它。这个区域叫策略的 handoff boundary，现有整任务策略的边界又窄又难被 agent 刻画。
- 方法：Boundary-Aware Policy Learning 先显式塑造、再扩张这条边界。Boundary-Explicit Training 在接触片段上用多样起始位姿微调策略，得到宽且定义清楚的边界，并通过简单交接协议告诉 agent；Boundary-Expanding Self-Improvement 在筛选过的成功系统 rollout 上再训，把边界往任务更早阶段推，让 agent 更早交接、少调 LLM。
- 数字：在 RoboTwin 2.0 与 RoboDojo 上，比最强基线高 **26 个百分点以上**；随机化 RoboTwin 2.0 场景成功率 **98.4%**；同时把 API 成本降 **41.3%**、执行时间降 **37.5%**。
- 为什么值得看：它指出鲁棒性不只来自「agent 更强」或「策略更强」，还来自**两者之间那条边界被显式设计和通信**；这是 agent 做具身系统时最容易被忽略的一层。

### 19. InitFree-SfM（1↑）

[HF 论文页](https://huggingface.co/papers/2611.31516) · 牛津大学 · [代码](https://github.com/simonwebertum/initfree-sfm)

- 问题：初始化自由 bundle adjustment 要在没有全局初值的条件下同时恢复相机位姿和场景结构，比传统 BA 难得多。现有方法从随机初始化优化 OSE 代理目标，但目标值低不等于重建准，优化与重建之间有缺口。
- 方法：InitFree-SfM 把学习到的对应、度量深度、深度一致的 track 构建和联合度量细化拼成完整管线；提出 depth-augmented OSE（dOSE），在 OSE 的方向约束之外，再沿视线约束 landmark 位置。作者还重新审视了此前对代理目标的强调。
- 数字：摘要未给具体数值。作者报告大幅优于现有 InitFree BA 方法，在包括低重叠图像集合的困难场景下，精度与成熟 SfM 管线有竞争力。
- 为什么值得看：结论有反直觉价值——**几何约束才是准确重建的主因，OSE 优化只是额外改进**；这会影响后续工作把力气花在代理目标还是深度先验上。

## 六、垂直领域：医学决策、多模态安全与金融测量

这一组 3 篇把通用能力落到高风险领域，共同点是**不满足于「答对」，还要置信度可校准、处置可解释、表征可测量**。

### 20. Radev（3↑）

[HF 论文页](https://huggingface.co/papers/2611.32993) · 浙江大学 · [代码](https://github.com/juntaoJianggavin/Radev) · [项目页](https://juntaojianggavin.github.io/projects/Radev/)

- 问题：从体积 CT 做结构化临床决策，要求预测有解剖依据、置信度经过校准；现有 3D 医学多模态模型常因自回归解码而不校准，还会走捷径依赖无关解剖区域。
- 方法：Radev 把三个部件接起来：解剖引导的视觉压缩（冻结 3D 编码器出器官级特征，按 query 动态选择，在预测的解剖边界内关注 2D 切片）、直接候选预测（一次前向估候选概率，不做自回归解码）、反事实置信度监督（CCT，对比完整与干预后的器官表征，要求移除目标器官证据时置信度下降、移除无关器官时不过度下降）。另建 CT-Verdict，覆盖二分类发现、选择题、有序严重程度，含分布内与外部队列。
- 数字：摘要未给具体准确率或校准指标，只报告在决策准确率和置信度校准上显著优于 SOTA，并在分布偏移下稳健泛化。
- 为什么值得看：把「校准」做成训练信号而不是事后温度缩放，是医学决策模型更该走的路；反事实监督也直接针对「看错器官」这种可解释的失败模式。

### 21. JudiAct（2↑）

[HF 论文页](https://huggingface.co/papers/2611.28849) · 中国人民大学

- 问题：视觉上下文会让一个普通请求变得不该照答，但一刀切拒答又解决不了用户需求。要选择怎么帮，得区分「已确立的危险」和「仍需核实的条件」，而二元安全标签给不出这个区分。
- 方法：把处置形式化成四个动作：allow、warn、review、refuse。作者建了 **20,126 条**训练审计和 JudiBench 基准，把每个动作连到诊断判断、来源证据和受控上下文变化。guard 模型 JudiAct 分别陈述「来源确立了什么」「什么条件决定能否帮」「规则如何适用」，再拿这三条复核项对回原始输入，预测诊断标签和处置动作；训练先学分项判断、再对比相关案例的标签分配，第二阶段逐条替换复核项、用审计反馈改复核生成。
- 数字：JudiBench 上请求与回答的 Macro-F1 比 4B 主干高 **28 个百分点以上**；九个公开 benchmark 上，无论生成前还是生成后设置，平均 delivered-answer 分数都优于 SOTA guard；MM-SafetyBench 攻击成功率从 **40.78% 降到 25.30%**。
- 为什么值得看：它把安全从「拒/不拒」扩展成「怎么帮」，并用可核对的复核项支撑处置；对多模态 guard 的产品化，这比单纯降 ASR 更接近真实需求。

### 22. 预训练表格特征与金融接近度（1↑）

[HF 论文页](https://huggingface.co/papers/2611.31491) · 开普敦大学 · [代码](https://github.com/marcusinthesky/free-foundations)

- 问题：空间套利定价理论允许收益在关联公司间溢出，溢出强度取决于「公司之间有多近」。表格基础模型在小中型表格任务上很强，但学到什么很难解释，这限制了它们在需要解释的受监管金融场景中的使用。
- 方法：作者不再把表格基础模型当预测器，而是把 **4 个 TFM 的冻结表征**当作公司间「金融不相似度」的度量，放进 2011–2025 年美国股票的空间资产定价模型；再与基于同一批披露的直接距离作对照。
- 数字：摘要未给具体收益或显著性数值。关键结果是：一旦纳入更广的 SEC filing 数据，TFM 表征相对直接距离的估计增益就**持续为正**。
- 为什么值得看：它把基础模型从黑箱预测器变成测量经济结构的仪器；同业选择、风险归因、网络资产定价都能直接用，也提示「表征本身」值得作为经济对象研究。

## 今天的三个观察

**一、22 篇的榜，第 10 名和第 11 名都是 4 票**。 这一期总票 489，前五名占 79.1%、前十名占 96.1%，剩下的 12 篇一共 19 票，其中 3 篇挂零。这样的分布下，「排第几」几乎没有信息量，只有前 8 篇（≥10 票）值得按名次读。巧的是本期第 4 名 Vernier 正好在论证同一件事：GIFT-Eval 只能分辨 6.8 个名次，前十装不下两个可分辨步长。看日报时把「票数」当热度、别当质量，看排行榜时先问「它分辨得出吗」。

**二、架构关键词从更大变成有界**。 GDN-2 给循环状态增长一个 O(T) 上界，DAWIN 给连续时间神经元 BIBO 稳定性，InitFree-SfM 用几何约束补上代理目标与重建之间的缺口，BAPL 把 agent 与策略的交接区域显式画出来，RevFlow 干脆把冻结编码器的现成路径反过来当生成约束。五篇方法不同，动作一致：**先找到系统里那个会失控的量，再给它加一个可证明或可通信的边界**。这比再堆一层 Transformer 更像系统工作。

**三、agent 评测从能不能做转向失败时有多糟**。 OS-Omni 用 67.54 步和终态评估逼出长程状态跟踪的缺口；DRBench Pro 用 44,102 条 rubric 把「广而不深」单独量出来；数据库那篇不问 agent 会不会删库，而问删了之后**哪个引擎能撤销**；Markdown 那篇则直接证明 rules file 只是建议、gate 才是控制，且 Codex CLI 会在隐藏测试只过一半时报告「全部通过」。共同结论是：能力提升不会自动带来安全，**边界、回滚和可观测性得单独设计**。
