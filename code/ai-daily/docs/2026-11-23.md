## 一、模型架构与预训练

### 1. cmHC（94↑）

- 出处：XingChen-AGI · [HF](https://huggingface.co/papers/2611.27193) · [arXiv 2611.27193](https://arxiv.org/abs/2611.27193) · [代码](https://github.com/Newiz430/cmHC)
- 问题：mHC 把多流残差的混合矩阵约束在 Birkhoff 多面体（双随机矩阵集合）里来稳定深层传播，但「在多面体里怎么混」没解决：矩阵贴着顶点时各流近乎独立（混不够），挤在均匀重心附近时各流又难以区分（混过头）。
- 方法：cmHC 把整个多面体向内部做几何收缩，强制混合矩阵探索更深的内部区域，且仍是精确双随机、不引入新参数；浅层只做适度收缩以避免过混。论文给了跨层累积混合量、流差异与梯度差异的界，并为 Ascend NPU 写了融合算子。
- 数字：在稠密与 MoE、多个参数规模上验证；NPU 融合算子把超连接执行延迟最多降低 44.8%。
- 为什么值得看：这是少见的「先证明退化条件、再改几何」的架构工作——不换残差形式、不加参数，只改混合矩阵的可行域形状，就能同时改善训练稳定性和算子效率；对做超连接/多流残差落地的人，44.8% 这个数比榜单名次更有用。

### 2. Clover-35B-A3B（37↑）

- 出处：Diffuspace · [HF](https://huggingface.co/papers/2611.24636) · [arXiv 2611.24636](https://arxiv.org/abs/2611.24636) · [代码](https://github.com/DiffuSpace/Clover-35B-A3B-Preview)
- 问题：扩散语言模型要进 agent 场景，得同时满足三件事：长上下文里的历史不能全量重算、块内要能双向看、还要有 thinking 模式；现有块扩散模型通常只解决其中一两件。
- 方法：35B 总参 / 3B 激活的 MoE 扩散 LM，把 Gated Delta Networks 改造成适配块扩散：已生成上下文走循环记忆，当前块内走双向 softmax 注意力，两者在同一个 softmax 里竞争读出，并加可学习的块大小校准与零初始化的右上下文卷积分支。另有一个 decision-model 变体，一次去噪同时回答一组相关问题。
- 数字：七项 agent 指标全部第一，SWE-bench Verified 73.6、Terminal-Bench 2.1 51.7；单张 NVIDIA GB300、BF16、batch size 1 时报告生成速度 680 tokens/s；500 组内部问题上，联合预测把单题准确率 90.37%→93.88%、全组全对率 65.4%→77.0%。
- 为什么值得看：它把「循环记忆 + 块内双向」的混合注意力真正压到了 3B 激活的推理成本上，680 tok/s 是扩散 LM 少见的部署级数字；decision-model 变体则给出一个便宜的多问题批处理思路——一次去噪换 3.5 个点的单题准确率。

### 3. MemOnce（21↑）

- 出处：Nanjing University · [HF](https://huggingface.co/papers/2611.27973) · [arXiv 2611.27973](https://arxiv.org/abs/2611.27973) · [代码](https://github.com/Clare-Nie/MemOnce)
- 问题：标准 Transformer 的长程记忆是逐层、逐 token 的 KV cache，显存线性涨、算力二次涨；线性时间架构把历史压成固定状态，又丢细粒度信息。两边都不适合「长期反复交互」。
- 方法：Memory encoder-decoder 只缓存末层隐状态的一个小子集作为紧凑记忆，再按需解码回各层 KV；Memory sparse attention 对每段新输入自适应检索相关记忆，且稀疏索引只算一次、跨层复用。两者合起来支持在线的记忆加载与 KV 解码。
- 数字：把 Qwen3.5-4B 改成 MemOnce 后，1M 上下文下记忆状态缓存缩小 1313×、prefill 延迟降低 6.9×、吞吐提升 3.5×，整体记忆性能还涨了 5.77%；在多种模型规模、上下文长度与预训练/后训练范式下都优于 Transformer 与其他架构。
- 为什么值得看：1313× 的缓存压缩不是靠量化或丢弃换来的，而是「只存末层、用时解码」这个接口设计；稀疏索引跨层只算一次也说明它认真算了 kernel 账。对长上下文 serving 来说，这是一条与线性注意力不同的路线。

### 4. QueryLM / Search From the Start（4↑）

- 出处：EPFL · [HF](https://huggingface.co/papers/2611.26809) · [arXiv 2611.26809](https://arxiv.org/abs/2611.26809)
- 问题：模型上线时都带搜索工具，但预训练仍然只学「预测静态文本」，搜索能力全靠后训练补；后训练能不能补全，此前没有干净的对照。
- 方法：在预训练语料里大规模插入网络搜索 query，用本地索引取回网页响应，拼成增强语料继续做语言建模——模型在预训练阶段就学会「何时发 query、怎么把检索证据接进下文」。覆盖 Wikipedia 与 DCLM-Edu，360M–3.3B 参数。
- 数字：搜索预训练的模型在知识密集任务上更好，也更听得进检索证据；对搜索预训练与常规预训练模型做同样的 SFT 后，优势仍在。1.4B 的 QueryLM 在所有知识密集任务上都不输 FLOP 匹配的 3.3B 基线。
- 为什么值得看：它把「工具使用」从后训练的补丁变成预训练的数据构造问题，而且给了 scaling 上的反直觉结论——1.4B 打过 3.3B，说明搜索能力不是纯参数量的函数。训练产物（checkpoint 与数据）已放出，可复现性不错。

## 二、世界模型与生成

### 5. NoPeWorld（55↑）

- 出处：The Hong Kong Polytechnic University · [HF](https://huggingface.co/papers/2611.27963) · [arXiv 2611.27963](https://arxiv.org/abs/2611.27963) · [代码](https://github.com/yuhangdai427/NoPeWorld)
- 问题：交互式视频世界模型会让人物/物体穿墙、穿桌，现有开源模型没有一个能可靠避免；但重训一个懂物理的世界模型代价极高。
- 方法：先建 NoPeBench 量化模型对物理障碍的反应；关键发现是冻结 DiT 的隐状态里已经编码了「这个动作会不会穿模」。NoPeWorld 只在隐状态上加一个小预测头判断候选动作是否安全，不安全就替换成最保留原意图的安全动作，世界模型本身不动。
- 数字：跨六个视频世界模型，平均物理违规率从 74% 降到 16%；对开放域图像、第三人称视角、移动障碍物都能零样本泛化。
- 为什么值得看：74%→16% 是「读现有表征」而非「再训一个模型」的胜利——它说明世界模型的物理知识早在隐空间里，缺的只是一个读出接口。替换动作而不是重采样，也保证了原意图不被改掉。

### 6. P2E / Prune to Expand（4↑）

- 出处：City University of Hong Kong · [HF](https://huggingface.co/papers/2611.27229) · [arXiv 2611.27229](https://arxiv.org/abs/2611.27229)
- 问题：prompt enhancer 的监督对（SFT）通常从密集 caption 反推短 prompt，隐含假设是「让图像生成涨得多的 caption 就是好监督」；但这一假设没人验过。
- 方法：先做对照实验，发现用「生成增益大」与「增益小」的 caption 对训练出的 PE 模型表现差不多——密集 caption 里的图像专属细节是冗余监督。P2E 随之改成纯文本方法：在每条样本的删除上限内，选择性删掉冗余句子，保留明确的用户要求与有信息量的视觉结构。
- 数字：相同训练配置下，P2E 在多种图像类别与生成器上，人类偏好对齐与视觉质量都优于密集 caption SFT。
- 为什么值得看：它推翻的是数据构造里一个很常见的默认假设——「信号强」不等于「监督对」。而且解法只是删句子，不需要新模型、不需要 reward model，是低成本改数据配方的典型。

### 7. GameWM（3↑）

- 出处：Tencent · [HF](https://huggingface.co/papers/2611.19247) · [arXiv 2611.19247](https://arxiv.org/abs/2611.19247) · [代码](https://github.com/hebing-sjtu/GameWM)
- 问题：现有「引擎 + 视频模型」的游戏管线只把视频模型当渲染器，重画引擎已经定好的运动，既浪费生成能力，也限制了同一机制能呈现的多样性。
- 方法：明确分工——GameWM-engine 保留规则、状态、相机与世界布局这些必须精确的东西；GameWM-VM 生成手工昂贵的部分（世界外观、交互细节）。配套三件事：以交互而非探索为中心的数据引擎、让角色设定/场景美术/技能描述进入模型的接口、5B–33B 的模型家族（含实时因果变体）。
- 数字：同一个引擎机制可在视觉与物理上呈现为多种不同版本，而事件时序与结果仍由引擎精确计算；模型规模覆盖 5B 到 33B。
- 为什么值得看：它把「世界模型」从替代引擎改成与引擎分权，思路比单纯堆生成质量更工程化。真正的难点在接口——技能描述如何变成可控的生成条件，论文只给了系统描述，还没给量化对比，值得等后续。

### 8. Motion-Aware Reward（2↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.22495) · [arXiv 2611.22495](https://arxiv.org/abs/2611.22495)
- 问题：指令引导视频编辑的 reward model 偏爱时序一致，代价是运动被压平——论文称之为 motion collapse；而 reward 一旦有这种偏好，latent optimization 与 reward-guided fine-tuning 都会顺着它把运动越改越少。
- 方法：用受控的「抑制运动」变体做诊断，发现复合 reward 在 VE-Bench 上 97% 的情况会选被抑制的候选，线性探针接近随机。于是显式加入 RGB 帧差流，并用「抑制运动」与「伪造运动」两类负样本做偏好训练，再加一个蒸馏锚点保持与人类质量判断对齐。
- 数字：VE-Bench 运动梯度上，选中被抑制候选的比例降到 0%，与人类质量评分的 Spearman 相关 0.57；能检测未见过的抑制变体，并在两条编辑管线的 reward 微调中保住运动。
- 为什么值得看：这是「reward hacking 的物理版」——不是模型学会了骗 reward，而是 reward 本身把「不动」当成「一致」。帧差流这个改动很小，但它把 0.57 的相关性和 0% 的塌陷率摆在一起，说明修的是根因不是指标。

### 9. Autoregressive View Model（1↑）

- 出处：Meta · [HF](https://huggingface.co/papers/2611.23417) · [arXiv 2611.23417](https://arxiv.org/abs/2611.23417)
- 问题：新视角生成通常要先建显式 3D 表示（点云、GS、mesh），重建误差会一路传到渲染；而纯视频扩散又难以在长镜头上保持场景一致。
- 方法：AVM 把场景生成成一串视图流，不建显式 3D。统一 in-context 接口下，以图像或视频为条件、沿指定相机路径生成短片段；从输入与已生成历史里检索相关视图，组成有界的 active context。训练上先用 flow matching 把双向视频 DiT 微调成 N-in-1-out，再用自己的 rollout 调因果模型，降去噪步数并抑制长程漂移。
- 数字：训练规模约 800 万场景与视频片段；在相机控制、文本控制、视觉质量、动态、稀疏/4D 重建、长程一致性等多类基准上评估。
- 为什么值得看：1 票说明它还没被社区读到，但方向值得留意——「用检索式上下文替代显式 3D」是长视频生成的一条实用路线，Meta 把训练规模拉到 8M 也说明不是玩具。摘要没给具体指标，只能先记着。

## 三、多模态推理与感知

### 10. Future-OPSD（41↑）

- 出处：University at Buffalo · [HF](https://huggingface.co/papers/2611.26954) · [arXiv 2611.26954](https://arxiv.org/abs/2611.26954) · [代码](https://github.com/Jingchensun/future-opsd)
- 问题：视频前瞻推理（从当前画面预判下一步事件/动作）过去靠人工标注的未来描述、rationale 或完整未来帧监督， scalable 不了；而且把整段未来片段当成同等重要，大部分上下文其实与决策无关。
- 方法：用「过去—未来」视频对构造 on-policy 自蒸馏信号，不需要额外标注或大模型监督。定义 foresight score 衡量未来片段的决策价值，由此得到 contrastive privilege advantage；由于该分数不可解，优化一个可解的下界代理，把「真实未来 vs 随机参考未来」的优势与教师—学生蒸馏优势做插值，放大决策相关内容、压掉无关上下文。
- 数字：开放式预测提升最多 14.2 点、闭环规划提升最多 15.9 点，且通用视频理解不掉点。
- 为什么值得看：14.2/15.9 两个点都是「不加标注」拿到的；更关键的是它把「哪段未来值得学」显式建模成 advantage，而不是默认整段未来都是监督。对做视频 agent 的人来说，这比再标一批 future caption 便宜得多。

### 11. TAISR-Reasoning（21↑）

- 出处：CIPLAB · [HF](https://huggingface.co/papers/2611.15449) · [arXiv 2611.15449](https://arxiv.org/abs/2611.15449) · [代码](https://github.com/jasonleex1995/TAISR_needs_Reasoning)
- 问题：文字感知图像超分（TAISR）一直当视觉复原做，但严重退化的文字在局部像素里根本读不出来；人靠上下文、逻辑模式与先验去「猜」，模型却没有这一步。TAISR 到底需不需要推理，此前没有诊断工具。
- 方法：两个诊断件——ReasonText 基准把「必须推理才能读」与「局部可恢复」的文字分开；GTTCA 用识别结果算超分质量，绕开文字检测误差。发现 12 个近期 SR 模型在需推理文字上一致大幅掉点，而 MLLM 能靠推理读出低清文字。据此提出 RTC：训练-free 插件，用外部 MLLM 推断退化文字、生成 caption，喂给文字条件 SR 模型。
- 数字：RTC 一致提升全部 6 个文字条件 SR 模型，在需推理文字上尤其明显；一个真实场景 SR 模型加 RTC 后，甚至超过 TAISR 专用模型加 RTC。
- 为什么值得看：它把「超分」从像素问题重新定义成「先读后画」的推理问题，而且 RTC 不改任何权重就能涨点。对做文档/车牌/招牌复原的人，这是一条立刻能试的 plug-in；GTTCA 这个指标也值得直接拿来用。

### 12. PURE（8↑）

- 出处：Alibaba multimodal & industrial AI · [HF](https://huggingface.co/papers/2611.22343) · [arXiv 2611.22343](https://arxiv.org/abs/2611.22343) · [代码](https://github.com/alibaba-multimodal-industrial-ai/PURE)
- 问题：身份匹配不是单一能力——两条记录可能在基础层是同一个东西，在变体层却不是（同款不同色/不同码）。只看最终准确率，会把「没看见差异」和「看见了但规则用错」混成同一个数。
- 方法：以电商为场景建 PURE，1457 道多选题、14 个任务，覆盖感知、理解、推理、证据 grounded 判断四个维度；题目由真实匹配对派生、两名领域专家校验。
- 数字：十个近期 MLLM 总分 47.1%–86.0%；理解维度平均最高、判断维度最低，主要弱在视觉差异定位与变体级规则判断。消融显示多模态证据有帮助，但模型会错误地把两条记录判成冲突；基础层多数模型更擅长认「匹配」，变体层则反过来更擅长认「不匹配」。
- 为什么值得看：那个「基础层/变体层方向反转」是全文最有信息量的一句——它说明聚合准确率不仅掩盖了能力结构，还掩盖了错误的方向。做商品/内容去重的人应该按这四个维度拆开看自己的模型。

### 13. StereoVLM（7↑）

- 出处：xpeng-robotics · [HF](https://huggingface.co/papers/2611.27915) · [arXiv 2611.27915](https://arxiv.org/abs/2611.27915)
- 问题：VLM 的语义很强，但度量 3D 空间很弱：多数模型从单图或多图推 3D，既不知道相机标定、也没有跨视角几何约束，预测到底靠视觉证据还是语义先验说不清。
- 方法：用标定双目作为显式几何基础，按层级学——跨视角对应 → 视差估计 → 标定条件下的度量深度 → 语义空间推理；模型因此能直接从双目观测学到可迁移的 3D 表征。配套 Stereo3D-Bench，从点级几何到物体级空间推理分三层。
- 数字：StereoVLM-8B 深度准确率（δ_1）95.17%、物体级平均分 66.98；层级几何监督在五个空间基准上平均 +3.54 点，RoboCasa 操作成功率 +4.3 个百分点。干预实验显示性能确实来自有效的跨视角几何，不能只用「多了视觉 token」或语义先验解释。
- 为什么值得看：它给了一个干净的因果证据：同样是双目输入，监督视差比直接监督深度在未见环境上泛化好得多。对做机器人 3D 感知的人，「监督中间几何量而不是最终深度」是可以马上迁移的结论。

### 14. CounterPoint（4↑）

- 出处：Nanyang Technological University · [HF](https://huggingface.co/papers/2611.24249) · [arXiv 2611.24249](https://arxiv.org/abs/2611.24249)
- 问题：多模态对齐器习惯把每条时间序列池化成一个向量，但「同一任务条件下两次不同的物理执行」（twin events）在池化后几乎不可分——时间维一平均，瞬态的跨模态耦合就没了，物理事件对齐退化成静态场景识别。
- 方法：论文先证明序列变长时任何时间池化表征都收敛到稳态记录条件，因此仅靠池化特征、换什么 loss 或嵌入几何都分不开 twin events。物理事件由 event gap 唯一标识——各模态瞬时同步的共波动，只在未池化的轨迹上累积。CounterPoint 去掉每个模态的时间均值，再逐帧算跨模态一致度，作为轻量插件接入对齐器。
- 数字：接入四个 SOTA 多模态对齐器后，表征从「粗条件匹配」转向「细粒度物理事件对齐」，一致优于现有时间对齐方法。
- 为什么值得看：这是「先证明不可能、再给可行信号」的范式：池化不是调参问题，是信息论上就丢了 event gap。去时间均值这个操作简单到不像论文贡献，但配上那个收敛证明就成立了。

### 15. RadioVISTA（4↑）

- 出处：Nanyang Technological University · [HF](https://huggingface.co/papers/2611.28123) · [arXiv 2611.28123](https://arxiv.org/abs/2611.28123)
- 问题：城市里的无线电信号看不见，但场强由建筑与街道决定。VLM 只看可见结构，能不能推出这个不可见场？要回答这个问题，需要真实城市的精确场，还要能单因素干预。
- 方法：建一个 label-free 引擎，把地球上任意坐标变成可射线追踪的城市，仿真匹配的单因素反事实并精确计算答案，得到 RadioVISTA 基准与训练集。物理上场是各传播路径之和，因此可以分别考「场强判断」与「单条路径是否存在」。
- 数字：跨六大洲发现明显的 field-path dissociation——前沿 VLM 能较准判断场强，却说不清是否存在一条直射或单墙反射路径；开源模型连读场都失败，给四次机会任一次算对仍低于随机。未见城市上微调可让 9B 开源模型在场强上接近前沿闭源模型，但监督或 RL 微调都提不动路径追踪。
- 为什么值得看：「答对最终场强」和「理解路径几何」被拆开了，而且后者怎么微调都上不去。这对具身/无线规划是个警告：模型可能只是拟合了场强的统计先验，并没有真的做几何推理。

## 四、空间记忆与具身智能

### 16. ReSpaceBench（10↑）

- 出处：Tsinghua-LeapLab · [HF](https://huggingface.co/papers/2611.21485) · [arXiv 2611.21485](https://arxiv.org/abs/2611.21485)
- 问题：具身 agent 要在反复进出的环境里可靠工作，必须认得「这是不是上次那个房间」，还要区分外观相似的同类房间、并跟上跨次访问的变化。但已有评测把「跨多次访问的物理地点身份」留成了隐含条件。
- 方法：ReSpaceBench 含 590 个合成与真实家庭场景、3244 道题、9 类任务（房间关联、持久状态追踪、下游推理）。用受控走场定义「一次访问」，刻意放入同类型房间干扰项与跨 session 的物体变化；另出 RS-30K 训练集，与基准在模板、场景、路线、视频上完全不重叠。
- 数字：评了 32 个模型与 3 个 agentic 视频理解框架。最强零样本模型总体 50.5%（450 题子集 52.2%），人类标注者 90.1%；agentic 框架相对同底座直接推理没有总体提升。微调 Qwen3-VL-8B 把总体从 35.5% 提到 60.4%，关联类涨最多，且能迁到真实场景。
- 为什么值得看：50.5% vs 90.1% 这个差距不是「看不清」，而是「记不住地点身份」；执行轨迹分析指出主要失败是证据遗漏与跨访问房间关联错误——也就是说，多跑几轮找证据并不自动带来一致的空间记忆。这是给 agent memory 研究的一个明确靶子。

### 17. AgentRoboCritic（8↑）

- 出处：Chenyan Xiong Research Group at CMU · [HF](https://huggingface.co/papers/2611.26613) · [arXiv 2611.26613](https://arxiv.org/abs/2611.26613) · [代码](https://github.com/cxcscmu/AgentRoboCritic)
- 问题：前沿多模态 agent 已经能直接输出低层数值动作控制机器人，但基准只报 episode 级成功率——既看不出它怎么成功，也看不出它在哪一步失败。
- 方法：AgentRoboCritic 让策略 agent 在给出每个动作时同时声明局部意图，再由 critic 对照意图评估动作结果与失败模式，做动作级分析；覆盖 12 个操作基准。另建 400 个动作的人工标注集验证 critic，并放出 12844 条标注动作与微调后的开源 critic。
- 数字：分析确认了闭环从局部失败恢复、跨场景语义 grounding、零样本操作等能力，也定位到抓取与对齐这类物理执行瓶颈，以及不同失败模式上恢复能力不均。微调的 Muse-Glimmer-30B 失败模式准确率从 32.58% 升到 74.24%。
- 为什么值得看：把「成功率」拆成「意图—动作—结果」三元组，才能区分「想错了」和「手抖了」。74.24% 的开源 critic 让这种分析不再依赖闭源前沿模型，12844 条标注也是可复用资产。

### 18. AeroRSI（7↑）

- 出处：Tsinghua University · [HF](https://huggingface.co/papers/2611.24077) · [arXiv 2611.24077](https://arxiv.org/abs/2611.24077) · [代码](https://github.com/starsholic/AeroRSI)
- 问题：无人机 VLA 在闭环飞行里仍常失败，要修就得在策略自己会到达的状态上给「修复动作」；人类飞行员标不了这个规模，规则规划器又不可靠。
- 方法：递归自改进——失败的策略自己判断修复好不好，判据是「从修复处继续飞下去」。这样采样动作、甚至直接模仿会伤策略的规则提议，都能变成可靠监督。每轮重新锚定当前策略的失败、用续飞验证修复、再把修复蒸馏回来，同时保持其他行为不变。
- 数字：TravelUAV 上三轮把 2B 监督策略成功率从 46.4% 提到 67.5%，碰撞减半；同初始化下超前 SOTA 10.6 点，且不需要额外人工标注或推理开销。
- 为什么值得看：「用续飞结果验证修复」把稀疏的 episode 级成败变成了动作级监督，还绕开了「第一次失败就终止、后面失败被遮住」的问题。46.4→67.5 且碰撞减半，是闭环指标而不是离线精度。

### 19. TIPO（5↑）

- 出处：Multimedia and Human Understanding Group · [HF](https://huggingface.co/papers/2611.27398) · [arXiv 2611.27398](https://arxiv.org/abs/2611.27398)
- 问题：视频物体跟踪假设物体外观变但身份不变；可当物体被拆开、组装成新实体时，SAM 2/3 这类基础模型能维持 tracklet，却无法随物理演化更新语义身份。此前工作只处理拆解，且要等跟踪失败才触发昂贵搜索。
- 方法：提出 TTU 任务（持续跟踪、识别新实体、维护关系状态图、给变换打语义标签）与 VISTA 数据集；TIPO 是 training-free 的 generate-evaluate-judge 流程：从不相连的 mask 组件生成拆分/合并提议，用内部与外部重叠度对照 mask decoder 先验打分，再让 MLLM 对最高分提议做视觉确认与语义标注。
- 数字：VISTA 含 50 段序列、26000+ 帧、124 个组装与 132 个拆解事件及状态图；TIPO 在跟踪与状态图准确率上 SOTA，比此前方法快 6–15×。
- 为什么值得看：6–15× 来自「持续推理」而不是「失败后搜索」，这个架构差异比精度更重要。TTU 这个任务定义也补上了跟踪与场景图之间的空白——物体身份不是永久的，会随物理变换分裂和合并。

### 20. Doppeldwarf-306（2↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.27490) · [arXiv 2611.27490](https://arxiv.org/abs/2611.27490) · [代码](https://github.com/turhancan97/doppeldwarf-306)
- 问题：实例检索基准大多盯地标建筑，视觉上极相似的小型系列雕塑是另一类难题——同系列共享风格，只能靠细节区分；而手机导游这类应用还会额外拿到位置先验。
- 方法：发布 Doppeldwarf-306：波兰弗罗茨瓦夫 306 座青铜矮人雕像的 1691 张开放许可照片，记录每张的拍摄者。系统比较 13 个骨干、7 种预训练范式；并模拟「按用户附近雕像过滤」的导游设计，区分「位置当过滤器」与「位置当权重」。
- 数字：无需训练，冻结 DINOv2 最近邻的 leave-one-out 首选准确率 93.1%，13 个骨干里最好的 94.7%；候选数每翻倍约掉 0.8 点。位置当过滤器不如等量随机抽样（置换检验 p=0.005），当权重则在用户距雕像 25 m 时把 DINOv2 从 93.4% 提到 98.7%。隐藏拍摄者后，学习型局部特征匹配把 DINOv2 从 81.8% 提到 85.5%；比较前二候选把未知雕像的误接受率从 38.3% 降到 19.6%（已知接受率 90% 时）。
- 为什么值得看：它顺手拆穿了一个常见的评测假象——「按位置过滤有增益」其实可能只是「候选变少」的增益，随机子采样会高估它。位置该当 soft weight 而不是 hard filter，这个结论对任何带地理先验的检索系统都成立。

## 五、Agent、工具与自进化

### 21. Duopra（28↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25773) · [arXiv 2611.25773](https://arxiv.org/abs/2611.25773) · [代码](https://github.com/cyChen2003/duopra)
- 问题：全双工交互模型很会「接话」——低延迟轮转、附和、打断，但完成任务还需要任务能动性：及时调工具、并在用户纠正后改参数。前后端分离的 agent 把「要不要请求」和「怎么执行」拆开，可没发出的请求执行不了，发不完整的请求又会误导后端。
- 方法：Duopra 把后端当成一个工具，后端只接受自包含的自然语言请求；直接调用与后端委托共享同一动作接口，要求「忠实发起 + 正确执行」。三阶段训练：协议 SFT、奖励及时且完整执行的全双工 RL、以及 thinker 更新后只修 projector 的 talker 条件修复。
- 数字：FDB v3 上，Realtime-Venus-Audio + Harness 的多数失败发生在领域工具执行之前；同一后端下 Pass@1 从 4.7% 升到 44.7%。Duopra 直接调工具 47.7%（仅 SFT 后是 26.0%），接 DeepSeek 后端 49.3%；三项 FDB v1.0 takeover 率均优于底座。
- 为什么值得看：4.7%→44.7% 说明「全双工」的瓶颈根本不在语音延迟，而在请求发起。把后端降级成工具、让前端对「发起」负责，是个很干净的接口划分；projector-only 修复也避免了 thinker 一更新就把 talker 带崩。

### 22. Intent Contracts（4↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.24025) · [arXiv 2611.24025](https://arxiv.org/abs/2611.24025) · [代码](https://github.com/zwang-devv/intent-contracts)
- 问题：工具型 agent 的权限控制通常在「规划器写好的命令」上做事后审查，但审查者要么看不到规划器的意图，要么只能整条命令接受/拒绝，无法限制「做多少」。
- 方法：意图契约让规划模型不持有任何工具；每步只提交一份短契约（目标、用户原话的逐字引用、scope 字段）。代码校验契约，再由一个小的可信模型对照用户原话检查，并自己写出工具调用。这样规划器对调用的影响被限制在「事先记录的契约」里，执行多少由可信侧决定。
- 数字：以 gpt-6.1-terra 为规划器、GLM-5.3-Flash 为可信模型，在 AmPermBench 三个任务族上：契约下每个被改动的对象都出现在产生该改动的契约目标里；审查基线则多在命令里点名对象、很少写进目标。规划器擅自加活时，契约在 27/30 次运行里完成用户任务，意图可见的审查者只有 16/30。但契约并不减少未授权动作，与「盲审」无法区分；环境术语澄清后，每个改变状态的条件下仍有 40–49% 打错目标。
- 为什么值得看：这篇的价值一半在负结果——「契约能限制越权范围，但不能提升安全性」。40–49% 的错目标来自歧义指代下规划器自选对象，而可信模型看不到环境，再提醒「不确定就拒绝」也没用。想做 agent 权限层的人，应该先读这个负结果再决定要不要上契约。

### 23. NextUnit-Bench / PHM Agents（4↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25252) · [arXiv 2611.25252](https://arxiv.org/abs/2611.25252) · [代码](https://github.com/JialingRichard/nextunit-bench)
- 问题：预测与健康管理（PHM）里每个模型都要落到没见过的设备上。普遍做法是让模型本身更通用；另一种做法是把通用性放到「为每个新任务造模型的 agent」身上。哪种对？
- 方法：NextUnit-Bench 覆盖 24 个公开数据集、切成 58 个 fold（留出整机或工况）；每个 agent 有两小时交付一个可执行预测器，再在隐藏单元上跑。对比前沿 agent、AutoML、以及四套数据上已发表方法的忠实复现。
- 数字：前沿 agent 明显强于 AutoML（后者不到最强 agent 分数的一半）；30 个已发表方法里只有 6 个超过最强 agent 自己的设计。一个几百字的纯文本计划就能承载两个前沿 agent 间的大部分差距，给弱 agent 的计划，最强 agent 会掉到同一水平、甚至预测完全相同；但动手前给谁的计划差别不大。可本地部署的开源权重模型拿到最强 agent 的设计，也只有一半的交付率，且分数不升。
- 为什么值得看：「通用性正从模型转移到建模者」这个提法有数据支撑：真正的差距是「在每台机器的数据上做设计」，而设计靠几百字计划就能传递。同时它给开源模型泼了冷水——有设计不等于能执行。做 AutoML/agent for science 的应该看那 6/30。

### 24. Feedback-Free Self-Evolution（4↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25534) · [arXiv 2611.25534](https://arxiv.org/abs/2611.25534) · [代码](https://github.com/LitaoGuo/How-Self-Evolution-Reshapes-Skills)
- 问题：agent 的「技能」是专家写下的流程知识，现在模型会自己在没有任何任务、运行或判断反馈的情况下重写它。这种无反馈自进化，到底让技能更适配模型，还是侵蚀掉专家知识？
- 方法：让模型一轮轮重写专家技能（不给任务、不给反馈），再用重写后的技能跑 agent；同时采样模型「只看主题自己写技能」的先验，定位改写把技能拉向哪里。基于结论提出 SkillDiff：原地标出「模型自己不会写的那部分知识」，不改技能文本。
- 数字：三十轮后，所测每个模型在每个基准上都变差，SkillsBench 平均掉 15 点；改写把技能拉向模型先验，最先丢掉先验之外的知识；把这部分知识放回去能恢复大部分通过率。SkillDiff 在无反馈、不改文本的前提下，SkillsBench 平均 +4.8 点。
- 为什么值得看：15 点的退化是个强警告——「让模型自己维护 skill」在无反馈时是净损失，而且丢的正是专家最值钱的部分（模型不会自己写的那点）。+4.8 的 SkillDiff 说明不必阻止改写，只要把不可再生的知识标注出来保护。

## 六、文本生成与证据基础设施

### 25. Vulnerability Timelines（3↑）

- 出处：Computer Incident Response Center Luxembourg · [HF](https://huggingface.co/papers/2611.22479) · [arXiv 2611.22479](https://arxiv.org/abs/2611.22479) · [代码](https://github.com/vulnerability-lookup/exploitation-patch-timeline-paper)
- 问题：「先被利用、后被修复」的间隔到底能不能算？答案取决于公开证据的时间戳是否可用、可追溯；而各来源的日期精度、语义和批量导入方式差别很大。
- 方法：在 Vulnerability-Lookup 里实现证据模型：每个生命周期事件取最早证据，区分漏洞专属记录与批量目录，保留日期精度，并回溯到原始来源。基于该模型统计披露、利用、修复三类时间戳。
- 数字：3758 个有利用证据的漏洞标识里，98% 有披露日期，只有 15.7% 有修复证据，VTEM 要求的厂商侧日期完全缺失。排除 1041 条批量目录导入与同日歧义后，59 个漏洞有「利用后修复」证据，中位间隔 7.6 天，主要是目录收录到发行方修复之间。可追溯性还暴露系统性错误：一个采集器把漏洞公开误判为在野利用，占初始利用日期的 40%；另一个目录把漏洞发布时间当成 11% 条目的利用时间。
- 为什么值得看：7.6 天这个数看起来可用，但论文自己说明它依赖证据可用性——40% 与 11% 的两个错误率比中位数更值得记住。做漏洞优先级/补丁窗口的人，应该先检查自己的时间戳是不是也来自批量目录。

### 26. StylePrism / SP-Refine（3↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.27211) · [arXiv 2611.27211](https://arxiv.org/abs/2611.27211)
- 问题：个性化长文生成想让模型「像某个用户那样写」，标准做法是把用户旧文塞进 prompt 做 RAG，但具体学哪些风格特征、学到什么程度，全交给模型自己决定。
- 方法：StylePrism 把风格拆成 7 类 28 个方面；SP-Refine 把风格提取变成显式一步：先填满 StylePrism（用户习惯、原文引用证据、要避免的写法），再基于用户样本起草，并对照这份画像改两遍、用模型自己的风格打分引导。纯推理时方法，不训练。
- 数字：LongLaMP 三个长文任务、三个 LLM 上，SP-Refine 在 27 项 ROUGE/METEOR 比较中赢 25 项，平均 +10.2%、最多 +35.8%；只用画像写作在全部 27 项里都更差，说明画像是修改指南而不是样本替代品；单次隐式推断是更便宜的近似方案。
- 为什么值得看：+10.2% 来自「把风格显式写下来再改」，而不是更多检索。更有用的是那个消融——画像不能替代样本，只能指导修改；这纠正了「结构化描述可以压缩掉原文」的常见误解。

## 今天的三个观察

**一、26 篇的票数比 50 篇还集中**。 全天 384 票，前三名占 49.5%、前十名占 84.1%，cmHC 一篇 94 票就是全天四分之一。作为对照，11-20 的 50 篇是 650 票、前三名 21.1%、前十名 54.0%。这说明「少」不等于「平均」：论文少的时候，注意力反而更狠地压在榜首几篇上。对读者的实际含义是，今天扫完 Top 10 就覆盖了八成票数，但剩下 16 篇里仍有 AeroRSI（46.4→67.5）、Doppeldwarf（位置当权重的 98.7%）这种硬结果——票数低更多是题材冷，不是质量差。

**二、今天最强的一批工作都在「读现有表征」，而不是重训**。 NoPeWorld 在冻结 DiT 的隐状态上加一个头就拿到 74%→16%；MemOnce 只缓存末层隐状态、用时解码回 KV，换来 1313× 缓存压缩；AgentRoboCritic 用「动作前声明的意图」对齐 critique，把失败模式准确率从 32.58% 拉到 74.24%；CounterPoint 只是去掉时间均值就恢复了被池化抹掉的物理事件信号。共同点是：先证明目标信息已经存在于某个中间量里，再设计最小读出接口。这比端到端重训便宜，也更容易说清因果。

**三、评测正在拆成能力结构与证据链**。 ReSpaceBench 把「认得房间」和「记得是哪次访问」分开，最强模型 50.5%、人类 90.1%；PURE 把匹配拆成感知/理解/推理/判断四维，还发现基础层与变体层的难易方向相反；RadioVISTA 把「场强判断」与「路径追踪」拆开，后者怎么微调都上不去；NextUnit-Bench 则指出一个评测 convention（截断测试发动机剩余寿命）就能把报告误差减半。同一天四篇论文得出同一个结论：聚合指标既掩盖能力缺口，也掩盖错误方向。

## 数据与方法

- **抓取**：`python3 code/ai-daily/fetch_papers.py --date 2026-11-23 --out ~/tmp/ai-daily/2026-11-23.json --brief ~/tmp/ai-daily/2026-11-23.md`，抓取时间 2026-11-24T21:00:05+08:00。
- **来源**：HF Daily Papers 的 daily 列表（本次走镜像，`mirror:latest=26`、`mirror:date=0`，即镜像的 latest 列表与按日期查询的结果不一致，按 latest 取到 26 篇）。`count` 字段为 26，正文覆盖全部 26 篇，无遗漏。
- **排序**：组间按主题，组内按 upvotes 降序、同票按 arXiv id 升序；Top 10 按全榜票数取。upvotes 是抓取时刻的快照，隔天重抓会变，不回改旧文。
- **daily 日 vs arXiv 日**：`date` 指 daily 收录日，不是首发日。本期多篇首发更早，例如 TAISR-Reasoning 是 11-11、Clover 是 11-18、AVM 是 11-17，都在 11-23 才进榜。
- **写作口径**：每篇的「数字」只取摘要里出现过的数；摘要没给具体指标的（如 GameWM、AVM）只写评估维度、不补数。所有摘要均重写，不粘贴原文。
