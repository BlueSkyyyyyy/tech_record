## 一、Agent、评测与方法论

### 1. WeVisForensics（50↑）

- 出处：Tencent · [HF](https://huggingface.co/papers/2611.21373) · [arXiv 2611.21373](https://arxiv.org/abs/2611.21373)
- 问题：AI 生成视频的检测要么靠单次 chain-of-thought（漏掉短促、局部的伪影），要么靠预先写死的多 agent 流程（无法按需选择检查手段）；而且只优化「查什么」不提升「检查员本身」的能力。
- 方法：主调查员 agent 调度一个可自进化的取证检查员库（视觉 + 音频），自己学「查哪类伪影、查多长的窗口、何时收尾」；两层 agent 共享交互反馈，DTPO 用双时间尺度策略优化闭环——调查员快更新、检查员慢精修。另建 ForenCue-30K（角色级取证标注 + 交互轨迹 + RL 池）。
- 数字：跨 in-domain / out-of-domain / agentic 三类基准平均检测准确率 95.2%，比最强前作高 9.0 个百分点；结论带局部证据定位。
- 为什么值得看：它把「工具库」当成可训练对象而不是固定菜单，DTPO 的快慢双环是 agentic RL 里少见的、把「用工具的人」和「造工具的人」一起优化的写法。

### 2. AltRA-Test（21↑）

- 出处：Technion · [HF](https://huggingface.co/papers/2611.26073) · [arXiv 2611.26073](https://arxiv.org/abs/2611.26073)
- 问题：LLM 当裁判/打分器越来越普遍，但「什么时候统计上可以替代人类标注」缺少检验；原有 Alt-Test 要求所有条目由同一批标注者标，而大规模标注常常是不同子集。
- 方法：对条目做 bootstrap 重采样，每个条目抽 k 条人工标注、把其中一条替换成 LLM 标注，构造「全人工」与「人 + LLM 混合」的配对面板；若混合面板的标注者间一致性（IAA）统计上不劣于全人工面板，则认为替代成立。论文证明该检验在渐近水平 α 上一致。
- 数字：在 20 个数据集、文本/图像/音频/视频四种模态上测了 18 个 LLM × 5 种提示技巧；约 100 个条目通常就够；真实数据里 LLM 大约在一半的设置中通过检验，主要取决于任务。
- 为什么值得看：它把「LLM 裁判靠不靠谱」从拍脑袋变成可执行的非劣性检验，而且明确告诉你「替代不是普遍成立」——做数据标注预算的人应该先跑这个检验再砍人。

### 3. Twice-Told Critiques（10↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.26286) · [arXiv 2611.26286](https://arxiv.org/abs/2611.26286)
- 问题：同行评审的价值来自「不同读者发现不同问题」，但 LLM 辅助写作可能让评审意见趋同；此前没有跨会议、跨年份的量化。
- 方法：用 claim 级重合度度量同一篇论文多份评审的批评重叠；再用 LLM 文本检测器 MELD 标记评审，比较「被标记者之间」与「未被标记者之间」的重合度差异。
- 数字：ICLR 同阶段评审的重叠度从 2026 年的 12.0% 升到 2027 年的 21.3%，NeurIPS、ICML、F1000、PLOS 也逐年上升；2027 年第三份 ICLR 评审相对前两份只新增 5.46 个问题（2026 年是 6.12 个）；同一篇论文内，两份被 MELD 标记的评审比两份未标记的重合度高 3.0 点（ICLR 2024–2025）、4.5 点（2026–2027）、5.4 点（五个期刊来源）。
- 为什么值得看：这是「LLM 让评审同质化」的第一组硬数字。对写评审的人是个提醒：如果你的意见和另一位评审高度重合，可能不是英雄所见略同，而是同一个先验在说话。

### 4. Embeddings vs. Grep（8↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.20455) · [arXiv 2611.20455](https://arxiv.org/abs/2611.20455)
- 问题：代码检索榜上 dense encoder 远超 BM25，但 coding agent 实际用 grep 也干得不错——这个「dense 优势」到底测的是什么？
- 方法：自建 Repo-Premium：真实仓库的文件级检索，Python/JavaScript/TypeScript/Go/Rust/Java 六种语言，2022–2026 的 PR，91 个仓库的预注册测试池；同时给 BM25 公平配置（不切 chunk）、不把「被改过的测试文件」算相关，并对比「LLM 先生成稀有标识符再 grep」。
- 数字：dense 的优势主要来自两处评测偏差（BM25 被切块、相关判定宽松）与查询缺少代码里的稀有标识符；用 LLM 扩写标识符后，BM25 在每个 Python 池都追平 dense，包括 LLM 发布之后才开的 PR。没有任何方法能预测某条 query 上谁会赢。
- 为什么值得看：给「RAG 一定比关键词检索强」泼了盆冷水，还给了三条可执行建议：跟公平的词法基线比、dense 与 BM25 融合、查询里缺词就补代码里的词。

### 5. TwinLab-Bench（5↑）

- 出处：Zhejiang University · [HF](https://huggingface.co/papers/2611.26248) · [arXiv 2611.26248](https://arxiv.org/abs/2611.26248)
- 问题：现有 AI scientist 评测只考「按给定流程做」和「从给定候选里选下一个实验」，不考最开放的第三层——自己设计实验；而设计实验必须真的能执行、读数要落在真实实验室记录上。
- 方法：52 个来自物理、生命科学、工程的任务，支持 100 多种实验动作；每个任务配一个 TwinLab agent 当「实验室数字孪生」，执行被测 agent 设计的实验、读原始材料、调用由真实记录构建的计算器；报告与隐藏的真实实验答案比对，另有闭卷探针排除「背答案」。
- 数字：最强模型 Claude Fable 5.2 平均分只有 45.0；TwinLab agent 几乎消除了偏离真实记录的读数与重复请求的不一致回答。
- 为什么值得看：把「AI 做科研」的评测从终端里的代码题推进到「设计—执行—读数」闭环，45.0 分说明这一层还远没解决。

### 6. DailySafe（4↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.26298) · [arXiv 2611.26298](https://arxiv.org/abs/2611.26298)
- 问题：多模态模型的安全评测多是一次性有害请求或对抗场景，但真实生活里风险是随对话与画面**逐步显形**的：单看每轮都合理，连起来才危险。
- 方法：195 组自然的多轮、多图交互，覆盖 10 个日常领域、42 类任务；安全关键证据分散在后续轮次与图像里，用逐例安全标注判断模型能否在支持用户正当目标的同时识别并处理演化中的风险。
- 数字：195 组交互、10 个领域、42 类任务；摘要没给各模型的通过率。
- 为什么值得看：它定义了「动态安全意识」这个可测构念，补上了静态红队测不出的那一类失败。

### 7. System 1 agents（4↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.21053) · [arXiv 2611.21053](https://arxiv.org/abs/2611.21053)
- 问题：临床等敏感数据不能上云，本地 LLM 又会幻觉；更糟的是工具调用里编造的一个参数会沿着后续每一步传播。
- 方法：不生成文本，直接做选择。确定性编译器把每个工具的 schema 与请求翻成多选题（选项来自请求与 schema），再一次前向的决策模型作答；工具调用被约束成闭集选择，从结构上消灭「编造」。
- 数字：1,952 个请求、157 个生物医学工具，最佳 System 1 agent 选对工具或正确拒答的比例 97.0%，高于 18 个本地 LLM agent 设置的最好成绩 95.2%；6,056 个参数值填对 97.0%；System 1 调用中编造内容为 0，LLM 调用是 5.5%–19.7%。
- 为什么值得看：「把生成换成受限选择」在 agent 工具调用上是条被低估的路线，尤其是本地、合规、可审计的场景。

### 8. Squoosh Bench（2↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25200) · [arXiv 2611.25200](https://arxiv.org/abs/2611.25200)
- 问题：增长团队要决定「哪个改版值得上全量流量」，能不能用模拟用户来预判 A/B 结果？
- 方法：筛了 412 个历史网站 A/B 实验，取运行超过 21 天的 318 个；四个系统只看到改版前后页面（页面角色被遮蔽、结果不外泄），预测「原版赢 / 改版赢 / 不确定」。
- 数字：在人类浏览数据上微调的 Squoosh UX-1 每条臂模拟 1,000 个购物者，318 个里判对 267 个（84.0%，95% Wilson 区间 79.5–87.6%）；最强通用配置 Qwen3 Next 80B 判对 196 个（61.6%）。UX-1 看好改版的 126 个实验里，线上真有 118 个改版赢（93.7%），4 个输、4 个不确定；其余 192 个实验里还有 19 个改版赢。
- 为什么值得看：这是「模拟用户做决策」少见的、有 318 个真实线上结果兜底的验证；93.7% 的 precision 比 84.0% 的总体准确率更有商业含义。

### 9. PlayCraft（2↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.26624) · [arXiv 2611.26624](https://arxiv.org/abs/2611.26624)
- 问题：agent 已经能生成可玩的游戏，但「可玩」不等于「好玩」；让人产生掌握感需要大量真人试玩与调参。
- 方法：让一个看画面的玩家 agent 反复玩、每局后报告进度/结果/决策/反思；再由 crafter agent 读报告，估计玩家能力、预测不同熟练度的表现、与目标学习曲线对比，据此改关卡，给玩家「靠更好的决策与操作变强」的机会。
- 数字：在三种智能档位上用全新玩家 agent 复测，多数游戏的学习增益与学习斜率都变大，且每个档位的宏平均都优于基线；摘要没给具体提升幅度。
- 为什么值得看：把「游戏难度曲线」变成可优化的目标函数，思路也能搬到课程学习与 agent 训练环境设计上。

### 10. Optics as code（2↑）

- 出处：Stanford University · [HF](https://huggingface.co/papers/2611.23875) · [arXiv 2611.23875](https://arxiv.org/abs/2611.23875)
- 问题：光学神经网络每个器件都偏离设计，必须用硬件本身训练；现有做法要么依赖专家逐台标定的数字模型，要么做无梯度试错。
- 方法：coding agent 只从测量出发训练光学网络——harness 返回探针的相机图像，并要求每次请求附带一个假设；agent 由此形成对光路的物理理解，用可解释的光学元件重新参数化网络并在硬件上调。
- 数字：在分类与图像编码上优于无梯度方法，逼近「通过标定模型反传」的效果，成本只是后者一小部分；不需要逐器件标定、不需要对硬件求梯度；换更强的模型还能继续涨。
- 为什么值得看：这是「LLM 改权重」从数字网络走向物理器件的一步，而且它把「提出假设」写进了接口——可解释性成了采样效率的一部分。

### 11. S1CogBench（2↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.00911) · [arXiv 2611.00911](https://arxiv.org/abs/2611.00911)
- 问题：System One 决策模型（快、结构化输出）的认知能力边界不清楚，聚合分数看不出「哪一类认知环节坏了」。
- 方法：24 个经典认知任务 × 27 种评测模式，测 7 个开源模型与 API 模型 Jev；同时做人类反应预测、自主执行与受控任务操纵，并加共享 readout 对照与延迟对比。
- 数字：模型间行为轮廓明显不同——某些学习任务很强，却不会主动收集信息或随反馈调整；高准确率也不保证对任务需求变化作出类人反应。模型排名部分取决于「如何从模型里读出选择」；与生成式模型比，长回答慢得多，而匹配的单 token 生成几乎不增加开销。
- 为什么值得看：它把「读法」（readout）当作变量而不是细节，提醒所有决策模型的评测：你测的可能是抽取方式，不是能力。

## 二、具身智能与 VLA

### 12. Mind2Act World（46↑）

- 出处：Mind2Act-World · [HF](https://huggingface.co/papers/2611.26444) · [arXiv 2611.26444](https://arxiv.org/abs/2611.26444)
- 问题：现有基准要么在同一批任务里同时考推理与执行，要么把两者分开考，于是失败时说不清是「不会想」「不会做」还是「不会把两者接起来」。
- 方法：30 个仿真操作任务、5 个真实应用域，每个任务 3 个难度 × 2 种场景（Clean / Random），共 180 种配置；设三个视图——Mind（基于历史观测做决策）、Act（精确及时执行）、Mind2Act（动作结果反过来指导后续决策的闭环）。另配诊断 harness，把失败 episode 归因到 Mind / Act / 组合，并给每个系统出画像卡。
- 数字：最强 agent 在 Mind 上成功 52.7%、Act 上 39.0%，到 Mind2Act 只剩 12.0%；它保得住任务状态但撑不住持续接触，端到端策略则能执行练过的动作却几乎不保留任务状态。
- 为什么值得看：12.0% 是今天最刺眼的一个数——单项能力不自动迁移到组合任务。它把「组合」从口号变成了可归因的评测维度。

### 13. TuringSpace（22↑）

- 出处：Meta · [HF](https://huggingface.co/papers/2611.25387) · [arXiv 2611.25387](https://arxiv.org/abs/2611.25387)
- 问题：MLLM 能否像人一样从 2D 画面推断 3D 布局、预测动作后果、看到结果后自我纠正？现成 CAPTCHA 基准大多已被刷满且不考空间，空间基准又很少要求真的动手。
- 方法：125 个可交互 CAPTCHA 的合成网页环境，覆盖五种空间能力，必须靠点击与拖拽完成；每个任务是一个程序，能生成新实例并自带 checker 与 oracle，因此同时是可扩展的训练 gym。用它对 Qwen3.5-9B 做微调，再测 7 个 OOD 基准。
- 数字：人类解出 94.1%；最好的模型 GPT-6 Astra 仍失败 25.9%，最好的开源权重模型 Kimi K3 失败 68.0%。微调后 Qwen3.5-9B 从 1.6% 升到 33.1%（超过 Kimi K3），7 个 OOD 基准全部提升，VSI-Bench 真实室内视频上 +9.9 点。
- 为什么值得看：失败分析比分数更有价值——多数错误来自看错截图，而模型推理很少纠正错误信念，反而编造证据替它辩护。这是「空间智能」与「自我纠正」两个问题的交汇点。

### 14. ZeroVLN（21↑）

- 出处：ZYT AI Team · [HF](https://huggingface.co/papers/2611.26414) · [arXiv 2611.26414](https://arxiv.org/abs/2611.26414)
- 问题：主流 VLN 把 VLM 当「大脑」、接一个可学习动作头，并在导航数据上微调大脑去预测几何目标；这会实质改动基座权重、削弱通用视觉能力。
- 方法：慢快分离。大脑完全不做导航域 SFT，只提供语义工具调用接口，用自然语言把移动决策交给动作专家；先让专家学会执行这些请求，再用闭环 RL 联合优化「大脑的决策」与「专家的连续执行」。
- 数字：在相同导航 episode 上训练，ZeroVLN 在标准 VLN-CE 上明显优于代表性 SFT 分层方法，同时只对大脑权重造成很小改动、基本保住通用能力；摘要没给具体成功率。
- 为什么值得看：它是第一个「大脑零导航 SFT」的慢快 VLN 框架，也是第一个在 VLN-CE 上用闭环 agentic RL 联合优化慢快策略的工作——保通用能力这件事终于被当成约束而不是事后补救。

### 15. WAM-Policy（16↑）

- 出处：Maincode · [HF](https://huggingface.co/papers/2611.24011) · [arXiv 2611.24011](https://arxiv.org/abs/2611.24011)
- 问题：无臂四足机器人可以用三条腿走路、前腿操作，但没有策略能听懂语言指令；世界动作模型（WAM）是好起点，却都是为机械臂预训练的，采样还慢。
- 方法：两阶段。先把以臂为中心的 WAM 迁移到四足，并用 on-policy 自蒸馏（OPSD）把策略蒸成「1 个视频步 + 2 个动作步」的学生；再用 RL 调教师、用多教师 on-policy 蒸馏（M-OPD）把多个慢专家合并进一个少步学生。
- 数字：QLM-Bench 十个仿真任务、1,000 条无遥操作合成示范；迁移策略 77.0%，OPSD 学生保持 76.7% 且采样快 14×；任务级 RL + M-OPD 把它抬到 85.0%。OPSD 学生已部署到真实 Unitree Go2 Air。
- 为什么值得看：14× 加速只掉 0.3 个点，说明「世界模型当教师」在四足 loco-manipulation 上第一次算得过账；真机部署也让它不止是 benchmark 数字。

### 16. VSpark（9↑）

- 出处：KAIST AI · [HF](https://huggingface.co/papers/2611.22666) · [arXiv 2611.22666](https://arxiv.org/abs/2611.22666)
- 问题：自回归 VLA 一次一个 token 出动作，慢；投机解码本可无损加速，但机器人控制里很多不同 token 编码几乎相同的运动，草稿「接近正确」仍会被拒。
- 方法：三个设计——用带校准动作噪声的 rollout 让草稿见到更广的机器人状态；做特征对齐，让草稿匹配 VLA 的隐特征而不只是输出 token；复用被拒草稿上 VLA 已算出的预测，作为下一次验证的候选。
- 数字：4 种不同动作 tokenizer 的 VLA × 4 个操作基准，加速 1.28×–2.10×，且保持解码无损。
- 为什么值得看：把 LLM 的投机解码搬到动作空间，关键洞察是「动作 token 的等价类」——不解决这个，草稿接受率上不去。

### 17. Accord（9↑）

- 出处：BE2R Lab · [HF](https://huggingface.co/papers/2611.25279) · [arXiv 2611.25279](https://arxiv.org/abs/2611.25279)
- 问题：单目 + IMU 的稠密度量建图两难：VIO 给度量运动但几何稀疏，前馈深度模型给稠密结构却不保证米制尺度。
- 方法：VIO 滤波器发布度量位姿；深度基础模型以位姿为条件、在短关键帧窗口内预测深度；用 VIO 位姿三角化的度量 3D 点锚定每个窗口，再利用共视图像间的双向稠密深度一致性估计并校正逐图尺度误差（保住锚定的度量尺度）；最后因子图融合子图。
- 数字：一套配置、五个公开 camera-IMU 平台加一个新的手机 rig / GoPro 数据集，不做任何按数据集的调参、地图只用 Accord 自己的轨迹对齐，在每个平台上都拿到 5 cm 平均 F-score 的最好或次好。
- 为什么值得看：「多视图一致性」被当作几何自洽的监督源，而不是后处理技巧；配套开源手机 rig 数据集也降低了复现门槛。

### 18. Online Mistake Detection（9↑）

- 出处：University of Haifa · [HF](https://huggingface.co/papers/2611.25567) · [arXiv 2611.25567](https://arxiv.org/abs/2611.25567)
- 问题：辅助人做流程操作的助手，最有价值的时刻是「还来得及补救时」发现错误；现有在线检测器不用指令文本，用指令的方法又都是离线的。
- 方法：只用已观测视频、任务指令与历史预测，识别并定位已完成的动作尝试，分类为正确 / 修改 / slip / 纠正 / 多余；遗漏步骤等视频结束后再判。对比「模块化流水线（识别—定位—验证分开）」与「一步出全部输出的联合模型」；并把 EgoPER 重新划分，让所有 split 都含错误视频。
- 数字：步骤分割 F1@0.5 接近（联合 92.1%，模块化 93.6%），但联合模型的二分类错误检测 F1@0.5 更高（84.1% vs. 80.7%），slip 上差距最大（56.4% vs. 37.5%）；组件分析指向模块化方案的阶段间误差传播。
- 为什么值得看：结论反直觉——在在线场景里「联合」比「拆开」更稳，因为中间步骤没有机会把错误放大；slip 检测仍是短板。

### 19. Phantom Success, Silent Failure（4↑）

- 出处：MBZUAI · [HF](https://huggingface.co/papers/2611.25179) · [arXiv 2611.25179](https://arxiv.org/abs/2611.25179)
- 问题：仿真操作基准用手写 success checker 判成败；专家示范只能证明 checker 接受一种完成方式，而学出来的策略可能做一半就停、或用另一种方式完成——checker 会误判成功（phantom success）或误判失败（silent failure）。
- 方法：SimAudit，用 LLM 审计 checker 与任务指令，找出两者可能不一致的场景，在仿真里重建并跑原 checker，再用多视角渲染确认实际行为是否满足指令。
- 数字：RoboTwin 2.0、RoboCasa365、RoboDojo 上 183 个测试用例全部复现了预测的判定；视觉核验与去重后得到 49 个任务里的 61 个不同缺陷，其中 40 个 phantom success、21 个 silent failure。RoboCasa365 的缺陷多是接受了不完整执行，RoboDojo 多是拒绝了合法执行。
- 为什么值得看：40 个「假成功」意味着一些榜单分数是不可信的。做具身评测的人应该把 checker 当成被测对象，而不是裁判。

### 20. Teaching VLA to Stop Safely（3↑）

- 出处：University of Notre Dame DM2 Lab · [HF](https://huggingface.co/papers/2611.26239) · [arXiv 2611.26239](https://arxiv.org/abs/2611.26239)
- 问题：已有工作让 VLA 拒绝任务或抑制任务，但从执行中途接管时，原本「会拒绝」的策略仍可能把任务做完；即便没做完，机器人也可能把手里物体摔了——「没完成」不是安全。
- 方法：State-Aware Fallback Imitation（SAFI）：先构造 fallback 目标——在禁止任务的示范全程给静止手臂指令与一致的夹爪目标；再联合策略适配，把这些目标与保留任务的原动作一起学，让中间状态有明确的替代行为。
- 数字：OpenVLA-OFT 在 LIBERO 与 BadLIBERO 上，接管后的目标成功率降到 1.3%，无记录到的物理事故、无动作饱和，同时保留任务成功率仍高。
- 为什么值得看：把安全从「拒绝」推进到「安全地停住」，而且是用模仿学习而非额外安全分类器实现的，工程上更容易落地。

### 21. PAD（2↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25604) · [arXiv 2611.25604](https://arxiv.org/abs/2611.25604)
- 问题：端到端自动驾驶靠堆示范数据，但数据多不等于策略好；同一条示范对一个规划器有用，对另一个可能冗余甚至有害。现有筛选看样本内在属性或与训练相关的代理，不测下游策略效用。
- 方法：给每条候选示范打一个「针对目标策略」的效用：场景级校准反馈 + 投影后的策略梯度 + 对局部训练几何的正则近似，得到可扩展的 influence 型估值。
- 数字：受控的整组移除实验验证了估值方向正确；同一候选池在不同规划器家族上排序差异明显。DiffusionDrive 上，EPDMS 比纯真实数据训练在 NavTest 高 3.5 点、NavHard 高 5.0 点，且在 diffusion / regression / flow-matching 三类规划器上都优于全池训练。
- 为什么值得看：数据估值从「样本好不好」变成「对这条策略好不好」，这是数据飞轮真正需要的那一刀。

### 22. Inhabitant（2↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25005) · [arXiv 2611.25005](https://arxiv.org/abs/2611.25005)
- 问题：长程人-场景交互（比如把玩具捡起来扔进篮子）需要 agent 规划并执行一串动作，但现有 agent 缺空间控制、也缺对执行偏差的定量反馈，常常做不完。
- 方法：免训练框架：agent 用位置、路径、姿态指定每个动作，执行后测量实际交互与意图的偏差，据此修改控制规格；另建 Inhabit 基准——31 种公寓家具布局、75 个家务任务，每个任务串 1–3 个可移动物体目标，全身参与（不含手指）。
- 数字：Inhabit 上，Claude Opus 5.5 完成 98.7% 的任务，Sonnet 5.5 为 93.3%，Gemini 4 Argon 为 82.7%；消融显示去掉空间控制多数任务失败，去掉定量反馈动作精度下降。
- 为什么值得看：98.7% 说明「规划器 + 可量化的执行反馈」能把长程 HSI 做成工程问题；它也暴露了瓶颈在反馈接口而非模型规模。

## 三、视频、世界模型与 3D 感知

### 23. WeMM-Video（40↑）

- 出处：Tencent · [HF](https://huggingface.co/papers/2611.26409) · [arXiv 2611.26409](https://arxiv.org/abs/2611.26409)
- 问题：带音频的视频理解是全模态智能的核心难题：既要看画面、又要听声音，还要在中文与英文之间都成立。
- 方法：2B / 4B / 9B / 35B-A3B 四档中英双语全模态基础模型，统一文本、图像、音频、视频；混合思考范式同时支持非思考的快速直答与逐步推理。训练约 1.2T tokens，渐进预训练 + 多阶段后训练（多教师 OPD、抗重复的 MrDPO、专家 RL）。
- 数字：120 多个基准上评测；旗舰 35B-A3B 在全模态视频评测上刷新开源 SOTA，明显超过 Qwen3.5-Omni-Flash 与 Seed2.0-Mini-0428，并缩小与 Gemini-3.0-Flash 的差距；9B 版超过更大的开源 Qwen3-Omni-30B-A3B-Instruct。
- 为什么值得看：开源侧少有的「音频 + 视频」全家桶，而且 9B 打赢 30B-A3B 说明数据配比与后训练流程的杠杆比参数更大；评测与复现流水线也一并放出。

### 24. Coda-DaVinci（32↑）

- 出处：KlingAI Research · [HF](https://huggingface.co/papers/2611.26595) · [arXiv 2611.26595](https://arxiv.org/abs/2611.26595)
- 问题：Code2Video 用 agent 写的 3D 代理引导视频生成，能显式控制结构与动态；但代理该怎么建、提示该怎么写、这套范式的边界在哪，都没被系统研究过。
- 方法：先做受控实验 + 盲评，扫代理粒度、物理仿真、提示三个因素；再据此搭 Coda-DaVinci——按任务在「代理引导」与「直接生成」之间选，按实体自适应建模粒度，协调仿真与代理对齐的提示；多 agent harness 保留场景资产，并通过视觉检查与独立复核来修。
- 数字：VTR 上指令跟随领先、R2M 上场景一致性领先；物理合理性优于直接生成，视觉真实感优于对比的 Code2Video 基线；长视频评测里事件结构与跨交互一致性有提升，但转场稳定性与场景设定遵循仍是短板。
- 为什么值得看：它没有把「代码中间层」当万灵药，而是给出「什么时候该用、用多粗的代理」的取舍表——这比再刷一个指标有用。

### 25. Depth Pro 2（28↑）

- 出处：Apple · [HF](https://huggingface.co/papers/2611.26603) · [arXiv 2611.26603](https://arxiv.org/abs/2611.26603)
- 问题：单目深度里，多帧方法时序稳但边界糊，单帧方法边界锐但抖——两者长期是取舍。
- 方法：训练一个可扩展的单一网络，同时吃图像与视频，在原生分辨率上预测度量深度；图像与视频共用同一套权重，不靠多模型拼接。
- 数字：在度量精度、锐利度、时序一致性、运行时四个维度上同时优于前作，给出一族模型定义新的 Pareto 前沿；摘要没给具体误差指标。
- 为什么值得看：把「取舍」直接做成「同时满足」是这类基础模型最值钱的进展；对视频生成、SLAM、机器人感知都是上游收益。

### 26. HiUni（25↑）

- 出处：ernie-research · [HF](https://huggingface.co/papers/2611.26107) · [arXiv 2611.26107](https://arxiv.org/abs/2611.26107)
- 问题：统一多模态模型通常为理解与生成各留一套视觉表示或骨干计算，统一程度有限；能不能让预训练 VLM 直接长成一个统一模型？
- 方法：复用同一个语言对齐 ViT 与 dense Transformer 骨干，任务专用计算只放在输出侧；针对两个障碍——像素空间生成难优化、预训练 ViT 的语义抽象丢掉合成所需的细节——分别加 Pixel Diffusion Head（直接像素空间优化）与轻量 HiGate 通路（在输出附近补细粒度空间信息）。
- 数字：平均理解分数与预训练 VLM 接近，图像生成与编辑有竞争力；受控对比显示单个 dense 骨干足以支撑两种能力，不需要任务专用骨干计算。
- 为什么值得看：它赌的是「统一」不必靠两套参数，而靠输出侧的轻量适配；如果成立，多模态模型的训练与部署成本会显著下降。

### 27. EgoCaptioner（24↑）

- 出处：KlingAI Research · [HF](https://huggingface.co/papers/2611.26380) · [arXiv 2611.26380](https://arxiv.org/abs/2611.26380)
- 问题：第一视角视频描述需要细节与精确计时，但 MLLM 常漏掉短动作、搞错顺序、误解佩戴者自身的运动；现有 caption 格式也难以同时承载细粒度叙述与时间戳。
- 方法：视频级总览（场景、参与者、佩戴者整体活动）+ 带时间戳的步骤叙述，叙述按感知需求自适应、在关键时刻打点；粗到细标注流水线先定事件结构再扩写步骤，产出 8 个第一视角来源的 5 万条训练样本；用 GRPO 优化，奖励分别管事实准确、覆盖度、步骤级时间对齐，并惩罚碎片化与冗余；有传感器时用姿态导出的运动事实补充监督。
- 数字：五个第一视角基准上，在开源模型中 caption 质量、caption 条件问答、时间对齐均领先；PhysCapBench 上超过 Gemini 3.1 Pro，Minerva-Ego 的 caption-to-QA 协议下超过所有评测的闭源基线。
- 为什么值得看：「粗到细标注 + 双奖励」是一套可复用的长视频标注配方；姿态事实补监督也提示了传感器与视频模型的低成本结合方式。

### 28. AFFECT（13↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25980) · [arXiv 2611.25980](https://arxiv.org/abs/2611.25980)
- 问题：世界模型生成的视频越来越真，却常常抓不住「动作稍微一变，未来会怎样」；而策略评估与基于模型的规划恰恰依赖这种敏感性。
- 方法：辅助训练目标——对任务无关的人类遥操作策略注入时间相关的动作噪声，要求世界模型生成的视频对这种噪声的响应与真实录像一致；不需要从同一初始状态反复真机执行。
- 数字：OGBench 仿真与真实 DROID、ALOHA-2 上 rollout 更贴近真实；DROID 上「世界模型里的策略成功率」与真机成功率的 Pearson 相关从 0.47 升到 0.79，FVD 最多降 23%；用于规划时任务成功率最多 +8.3%。
- 为什么值得看：0.47→0.79 是「世界模型能不能替真机做策略筛选」的关键门槛，它把评测从「画面像不像」推到「动作响应对不对」。

### 29. Direct3D-V3（4↑）

- 出处：Nanjing University · [HF](https://huggingface.co/papers/2611.26511) · [arXiv 2611.26511](https://arxiv.org/abs/2611.26511)
- 问题：原生 3D 生成几乎都走 latent diffusion：先把几何压进 vecset、triplane 或稀疏体素，再让生成器建模；重建瓶颈与潜空间设计成了主要复杂度来源。
- 方法：干脆去掉 VAE，在原生 SDF 体素域上直接训练/采样 DiT；用邻域体素的隐式流形正则抑制不闭合表面，Marching Cubes 转网格后用渲染法线损失直接监督预测的 SDF；再把条件图像的相机参数作为辅助任务预测，强化「图像→3D」的映射。
- 数字：摘要没给定量指标；定性上局部细节明显更丰富，且同一套权重可扩展到生成式重建（扩散与法线引导细化交替，补全未观测区域）。
- 为什么值得看：去掉 VAE 意味着少一个需要单独训练、且会丢细节的环节；「原生体素 + 可微渲染监督」是一条值得继续压的路线。

### 30. SpecWM（2↑）

- 出处：Huazhong University of Science and Technology · [HF](https://huggingface.co/papers/2611.26211) · [arXiv 2611.26211](https://arxiv.org/abs/2611.26211)
- 问题：流式世界模型的投机推理用「解码后帧上的奖励」做验证，只覆盖外部打分的维度，还多付解码与打分成本；更关键的是分数不提供修正，被拒就得让大模型重算。
- 方法：用目标模型的隐速度场验证草稿 chunk，验证同时产出可复用的修正量；两个阈值分流 Accept / Refine / Reject，一步细化提画质、三步细化强化相机跟随与轨迹一致；整个框架免训练。
- 数字：WBench Navigation 上比目标模型快 1.63×，NavScore 从草稿的 75.99 升到 85.63；LongSpecBench 上长程多轮 rollout 的画质与控制能维持；Hy-Nomas 上跨骨干、跨去噪预算均有效。
- 为什么值得看：把「验证」变成「修正」是投机推理在世界模型上的正确抽象——拒绝不是终点，残差里就有可用的梯度方向。

### 31. One Prior, Two Dynamics（2↑）

- 出处：National University of Singapore · [HF](https://huggingface.co/papers/2611.26617) · [arXiv 2611.26617](https://arxiv.org/abs/2611.26617)
- 问题：视频里有世界如何变化，却很少有「什么动作导致变化」；潜动作学习能从视觉转移里恢复监督，但往往从零学动力学。
- 方法：一个先验、两个动力学。逆动力学用带可学习动作 query 的前馈转移编码器，正动力学用因果的、动作条件的视频生成器，两者都从同一个预训练视频 DiT 初始化；通过控制信息访问与紧凑瓶颈端到端优化。
- 数字：导航与机器人操作上，few-shot 动作探测刷新 SOTA，跨视觉上下文与跨本体的零样本动作迁移更强；把先验换成 V-JEPA2 这类预测表征也有效。
- 为什么值得看：预训练视频模型不只当生成器，还可以同时当逆动力学与正动力学的共享先验——这比单独训一个编码器省得多。

### 32. AURA（2↑）

- 出处：Kyutai · [HF](https://huggingface.co/papers/2611.26540) · [arXiv 2611.26540](https://arxiv.org/abs/2611.26540)
- 问题：音频驱动说话人视频质量上来了，但通常要对多秒 chunk 做几十步去噪，无法流式；语音助手/虚拟人需要低延迟、因果生成。
- 方法：逐 chunk 生成 + 滚动 KV cache，只需当前 chunk 的音频即可开生成，不像双向模型要提前看几秒音频；两阶段蒸馏——先让因果学生用更少步数与 chunk 级滑动窗口因果掩码对齐教师轨迹，再用带反向模拟的 DMD 补质量差。
- 数字：1.3B 单卡实时流 576p（16 Hz 播放率下 20.7 fps），比自己的双向教师快 23×，质量与较低分辨率的 TalkVerse 相当；5B 流 720p 9.7 fps，与 TalkVerse 教师质量相当、快 17×。开源两个权重 + 3 万条合成视频及预计算教师轨迹。
- 为什么值得看：20.7 fps 意味着真正实时；「当前 chunk 音频即可开生成」这个因果约束比堆蒸馏步数更能决定流式体验。

## 四、训练系统、推理加速与可解释性

### 33. Probing the "Conscious" Mind（41↑）

- 出处：University College London · [HF](https://huggingface.co/papers/2611.26590) · [arXiv 2611.26590](https://arxiv.org/abs/2611.26590)
- 问题：VLM 的输出看不出内部概念表示；全局工作空间理论（GWT）认为信息从并行脑过程里被选中、整合进共享工作空间、再提供给专门过程——这套功能在 VLM 里能否被观测和干预？
- 方法：Multimodal Concept Lens（MC-Lens），一个多模态 Jacobian lens：视觉编码器 lens 与语言解码器 lens 都把中间状态映射到由解码器输出词表定义的共享语义空间，从而跨模态比较概念可访问性；支持内部概念干预。把「readout carrier」从单个名词 token 扩成 token 集合，以更好表达概念并支撑反事实实验。
- 数字：概念信息在中间状态可读、且按任务需要被选择性访问；反事实实验显示被访问的概念确实参与下游计算与推理；两个 J-space 指标比隐状态余弦更清楚地跟踪跨模态对齐的发展，且可靠的选择性访问比概念可访问性更晚成熟；跨 VLM 家族与规模发现共享模式。
- 为什么值得看：它给「GWT 在人工系统里是否成立」搭了可操作实验台，也顺手给跨模态对齐提供了一个比余弦相似度更细的诊断量。

### 34. Posterior Matching Distillation（34↑）

- 出处：NVIDIA · [HF](https://huggingface.co/papers/2611.26629) · [arXiv 2611.26629](https://arxiv.org/abs/2611.26629)
- 问题：扩散蒸馏把教师的迭代采样压成几步，但基于分布的蒸馏多用 reverse-KL，mode-seeking 偏置会偏向教师的主要模态、牺牲样本多样性。
- 方法：PMD 把「采样」写成后验匹配：零总体损失时，它在每个训练噪声水平上恢复教师的完整干净图像后验；学生是随机的，因此在训练过的时间步网格内支持任意步数预算而无需重训。学习方式是匹配「以固定噪声状态为条件的、指数重加权后的学生样本均值」与教师对应的后验均值；在高斯破坏下，指数倾斜的后验均值等于在偏移输入上做一次教师评估。论文证明在一开邻域上匹配倾斜均值可唯一确定完整后验，因此无需辅助的学生 score 网络。
- 数字：SDXL 与 FLUX.2 [klein] 4B 上，4 步方法里 FID 最好，同时提示对齐与感知质量指标保持竞争或领先；摘要没给具体 FID 数值。
- 为什么值得看：mode-covering + any-step 这两点同时成立很少见；「一次教师评估就够」让训练成本没有随理论精致度爆炸。

### 35. LightningMoBA（17↑）

- 出处：Tencent · [HF](https://huggingface.co/papers/2611.26268) · [arXiv 2611.26268](https://arxiv.org/abs/2611.26268)
- 问题：MoBA 按 query 选 KV block 降长上下文成本，FlashMoBA 实现高效但保留固定 Top-k 预算与 query 中心的调度：固定预算不适应不同分数分布、还把路由绑死在任务粒度上；query-range 所有权让多个 range 选中同一列时无法复用 K/V。
- 方法：选择与执行协同设计。动态路由对每 query 的 block 分数设阈值，直接产出变长稀疏元数据；KV 中心所有权按（query head, KV block）列分组，把高扇出列切成有界任务并复用每任务加载的 KV tile；Hopper 上用运行时流水线把规则 K/V 传输与不规则 query gather 同 Tensor Core 计算重叠。
- 数字：在五个 checkpoint 上匹配 Top-16 保留率，端到端生成加速 1.20×–1.60×，平均 RULER 从 74.42 升到 75.28。
- 为什么值得看：加速没拿质量换（RULER 还涨了），关键是「把保留率从 GPU 调度粒度里解耦」——这是 kernel 与算法协同设计的典型收益。

### 36. RL Post-Training in DiT Is Activation Steering（14↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.26627) · [arXiv 2611.26627](https://arxiv.org/abs/2611.26627)
- 问题：RL 后训练能提升 DiT 的画质、文字渲染与组合准确率，这些能力都依赖 prompt，所以直觉上需要学复杂的、输入相关的变换。但其中有多少只是「与输入无关的整体偏移」？
- 方法：用极简参数化去探：在冻结基座的每个 block 输出上加一组固定 steering 向量；把向量拟合到公开 RL checkpoint 的速度预测上，目标里没有任何 reward；向量对所有 prompt、token、采样种子都相同。再做「零初始化 + 在线 RL」只训这组向量。
- 数字：SD3.5-M 上向量比 RL 训出的 LoRA 少 65× 参数（0.29M vs 18.8M），却恢复了 6 个 RL 图像模型 90.0%–96.3% 的 reward 增益，两个 RL 视频模型上分别是 89.8% 与 111.9%；只用向量做在线 RL，在文字渲染（OCR）与人类偏好（PickScore）上超过基于权重的 RL。
- 为什么值得看：如果大部分收益是一个常数偏移，那 RL 后训练的信号可能比想象中低维——这对训练成本、可合并性与「模型合并」都是好消息，也提醒我们别把「输入相关」当默认假设。

### 37. WM^MLLM（14↑）

- 出处：OpenEnvision · [HF](https://huggingface.co/papers/2611.24193) · [arXiv 2611.24193](https://arxiv.org/abs/2611.24193)
- 问题：视频世界模型把世界状态放在生成器的上下文里，重访同一地点要重新合成，之前的编辑会漂移甚至消失。
- 方法：把世界状态放到所有生成器之外——一张全景图 + 修订历史；MLLM 负责「写」这个状态：把每个请求翻译成对状态的操作、选择局部编辑写在哪、在候选成为下一状态前逐一检查。图像生成器只提议视角，视频只负责呈现。
- 数字：MBench-A 上四个环境恢复指标均值全部最高（Epipolar 91.5，基线 0.1–74.0），完成的相机往返最多（85.3%，基线至多 50.9%）；CompBench 15 列全部对 15 个基线取最优；112 个盲评局部编辑里，「生成后再选写入区域」把完成率从 34.8% 抬到 83.0%；258 个 WBench/MBench-A 条目中 46 次重访全部恢复原视图，97 个通过检查的局部编辑全部未改动区域外像素。
- 为什么值得看：用「外部可编辑状态 + MLLM 写操作」换取精确重访与局部不变性，是绕开生成器漂移的一条干净路径；91.5 vs 0.1 的 epipolar 差距也说明旧基线在这项上几乎没做对。

### 38. FlashMorph2（13↑）

- 出处：ByteDance Seed · [HF](https://huggingface.co/papers/2611.24809) · [arXiv 2611.24809](https://arxiv.org/abs/2611.24809)
- 问题：把预训练 Transformer 转成「全注意力 + 线性注意力」混合模型，要在预算下决定哪些层保留全注意力；FlashMorph 的层选择有两处 off-policy 失配——连续分支插值与教师强制隐状态不同于离散混合计算，冻结权重也反映不了后续恢复期的参数适配。
- 方法：on-policy 层选择：用采样出的离散混合架构、以它们自己的隐状态端到端评估；在恢复目标下联合优化层选择分数与模型权重，让评分反映「适配之后」的性能。
- 数字：跨 Qwen3 多个规模与多种线性注意力变体，平均分比 FlashMorph 在 RULER 上 +2.42、LongBench +1.08、召回密集型任务 +0.76；层选择在 0.6B–8B 上只要 0.72–3.57 GPU 小时。
- 为什么值得看：3.57 GPU 小时以内完成架构搜索，意味着「把已有模型改造成混合注意力」可以变成一次常规后处理，而不是重训项目。

### 39. Edit-Ready Training（13↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.26408) · [arXiv 2611.26408](https://arxiv.org/abs/2611.26408)
- 问题：已有证据表明 LLM 能在某些设定下做「权重空间编程」直接改网络权重，但没人系统研究过：专门训练被编辑的网络，能否让这种编辑更容易成功？
- 方法：建一个视觉模型权重编程基准——5 个 LLM 在 Waterbirds、CIFAR-100、PACS、Entity-30 上对 CNN 与 ViT 做重标注与纠错编辑；对比标准训练、label smoothing、基于梯度的可编辑训练，以及作者提出的 ERT（排练 LLM 实际执行的那种直接、闭式权重编辑）。
- 数字：累计 2,600 多次编辑过程，每次都在留出图像上评成功、副作用与精度损失；在标准网络难以编辑的地方，为编辑做准备显著提升成功率；ERT 在 GPT-6 Astra 与 Claude Opus 5.5 上取得所有基线中最高的平均分。
- 为什么值得看：它把「模型可编辑性」当成一个可以训练进权重的属性——如果 LLM 要长期维护模型权重，这可能是比「更大的编辑器」更划算的方向。

### 40. CompoundingKernel（11↑）

- 出处：Amazon Science · [HF](https://huggingface.co/papers/2611.19230) · [arXiv 2611.19230](https://arxiv.org/abs/2611.19230)
- 问题：让 agent 写 GPU kernel 的搜索系统，通常依赖参考实现或官方分数；能不能从零开始，只给 PyTorch 定义？
- 方法：每个问题只给 PyTorch 定义，不给参考 kernel、不给官方分数；模型外维护每题的归档，保存所有正确 kernel 及其谱系；LLM 控制器读归档，选一个父代或新设计，给每个并行子 agent 一个方向；正确性由模型外的检查决定。
- 数字：截至 2026-11-11，生成的 kernel 在 SOL-ExecBench（NVIDIA B200）的 L1、L2、Quantization 三个公开榜排第 1，L1 自 2026-10-27 起保持第一（11-07 短暂丢失）；235 个问题全部有站点验证的正确 kernel，209 个公开榜问题上比参考基线快 4.40×；同等 wall time 下在 38 个问题中的 35 个胜过 coded UCB 式树搜索，正确尝试次数多 2.4×；峰值一千多个 agent 并行，一次热重启修复把评测速率提升 3.6×。
- 为什么值得看：结论很硬——限制搜索规模的是「可靠测量的速率」，不是 agent 数量。这句话对所有 self-improving 系统都成立。

### 41. AutoMaster（11↑）

- 出处：RUC-AIBOX · [HF](https://huggingface.co/papers/2611.26510) · [arXiv 2611.26510](https://arxiv.org/abs/2611.26510)
- 问题：任务成功本身并不指定「该强化哪些行为」；即便成功的教师轨迹里也会有没根据的假设、无效重复、表面验证。
- 方法：Skill-FT 用自然语言「技能」在教师 rollout 中压制坏习惯、引出被低估的有效行为，再拿这些轨迹微调目标模型；AutoMaster 让一个 LLM agent 通过轨迹分析、技能设计、数据选择、以及 rollout 与目标模型评测的反馈来自主开发这些干预。
- 数字：Terminal、Search、软件工程任务上，4B 与 9B 目标模型相对「成功但无引导的教师轨迹」做 vanilla SFT，平均提升 1.42–8.99 个百分点，教师、任务池、训练集大小、SFT 配方全部固定；六个设置里，SFT 时保留技能指令都比去掉它更好，尽管评测时没有指令、监督输出完全相同。
- 为什么值得看：它说明「教师的关键不只是对不对，而是行为被怎么塑形」；保留技能上下文能提升内化效果，这个反直觉发现值得在自家 SFT 流水线上验一遍。

### 42. Self-Rewriting（6↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.21885) · [arXiv 2611.21885](https://arxiv.org/abs/2611.21885)
- 问题：模型训完就冻结，想变好只能再训一轮；prompt、脚手架、推理期算力在任务结束后都留不下。模型能否靠自己的推理改自己的权重？
- 方法：不给梯度、不给训练。给模型自己的权重、带评分的答案、以及运行自己的能力，27B 模型诊断失败并编辑对应权重；只在自测支持时才提交编辑，每次编辑替换上一次。
- 数字：一次编辑让它在 490 道从未见过、事先固定的题上准确率 +6.6 点；另一个 session 的编辑也显著变好；前八次自编辑 accuracy 单调上升；修复被损坏的自身副本时，只从文本数学题上学到的修复让该副本在六个未见图像基准上从 7% 升到 70%（达到未损坏模型的 83%）；能力随规模涌现——2B 不做编辑，4B/9B 把自己改坏，只有 27B 像人一样工作。
- 为什么值得看：收益写进权重、每次回答零额外成本，且不需要训练基础设施——这是「推理期自我改进」与「训练」之间被忽略的第三条路。但 4B/9B 改坏自己是明确警告：这能力有规模门槛。

### 43. Probing vs. Steering（5↑）

- 出处：Fraunhofer IAIS · [HF](https://huggingface.co/papers/2611.19499) · [arXiv 2611.19499](https://arxiv.org/abs/2611.19499)
- 问题：隐状态里的一个方向既能用来「探测」概念是否存在，也能用来「操纵」模型朝向该概念；但最能检测概念的方向，未必最能改变它。实践中却常把 probe 方向直接拿去 steering。
- 方法：在三个不同家族的指令微调模型上，构造从「协方差调整判别方向」到「均值差」的单参数方向族，在固定副作用下评探测与加性操纵；再做层扫描、文本匹配、旋转操纵算子与跨模型迁移。
- 数字：真理性与情感两个概念、每个模型里最佳 probe 都不是最佳 steering 方向，steering 一致偏好更接近均值差的方向；层扫描 60 个「层-模型-概念」组合中 59 个成立；线性映射迁移的 probe 保留目标模型 81%–91% 的超随机探测性能，而迁移的均值差在 12 对模型中的 11 对里保不住操纵效果；PopQA 上朝「unknown」操纵让不确定错误的弃答率 +18–44 点，确定错误只 +2–5 点。
- 为什么值得看：probe ≠ steering 有了系统性证据，且给了可操作的替代（要操纵就用均值差）；「弃答只对不确定错误有效」也说明 steering 不是万能纠错。

### 44. NarrowSpec（4↑）

- 出处：NVIDIA · [HF](https://huggingface.co/papers/2611.23835) · [arXiv 2611.23835](https://arxiv.org/abs/2611.23835)
- 问题：读目标模型隐状态的草稿模型（DFlash、EAGLE-3）通常继承目标的隐宽度，显存与带宽都跟着目标走；窄一点会不会掉接受率？
- 方法：让草稿的整个残差流以目标的一半或四分之一宽度运行；对借用目标词表投影的 DFlash，把训练好的输出适配器折进去，得到更窄的单一投影，logits 在浮点舍入误差内不变。
- 数字：DFlash 与 EAGLE-3 两族草稿、Qwen3-8B（NVFP4）与 GPT-OSS-20B（MXFP4）两个目标，在 B200 与 DGX Spark（GB10）的 SGLang 上：batch 1、温度 0 时端到端加速 1.06–1.12×（B200）与 1.13–1.44×（GB10）；batch 32 到各卡最大 batch 最多 1.21×，没有窄草稿比全宽更慢。
- 为什么值得看：这是一条「免费」的加速——不改接受率、不改输出，只削草稿宽度；在 GB10 这类带宽紧张的设备上收益最大。

### 45. A CPU Inside an LLM（4↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.26450) · [arXiv 2611.26450](https://arxiv.org/abs/2611.26450)
- 问题：预训练 LM 不做梯度微调、不接外部解释器时，多位数精确算术仍不可靠。
- 方法：零梯度、零样本的「电路嫁接」原语，把确定性计算编译进预训练权重，同时约束逐层归一化漂移、保住自然语言能力。三个机制：对无偏置 SwiGLU/GeGLU 做两层 Mellin-GLU 求积，把未知的逐 token RMSNorm 缩放变成对数间隔门网格上的平移（>250× 动态范围，带 IEEE 754 误差界）；用带符号 Chebyshev 不定 RoPE 自汇注意力与无记忆 SiLU 反对称 GatedDeltaNet 位移做跨 token 尺度抵消；轴对齐宽度扩展 d→d+K、d/(d+K) 范数补偿、Base-1000 规范 BPE 输出、差分（+254,−256）绑定反嵌入。
- 数字：自动五阶段编译器在常数 TC⁰ 深度合成 4–8 位带符号加减乘电路；三文字布尔电路 100%（N=1,728，另做 42 层 Gemma 4 E4B 审计），5-bit Majority/Parity 100%。6 位算术（N=1,200，BF16）：IBM Granite 4.2 3B 达 99.17%，Qwen 3.5 4B 达 100.00% 的 ALU 前缀准确率（加 FP32 sidecar 均 100%），句中续写 98%–100%；对照 12.8K 样本 LoRA 只有 42.2%/61.7%、句中续写 0%。侧车把 A100 显存压在 7.89/10.65 GiB（INT8/INT4 + FP32 sidecar 为 4.60/8.14 GiB），14/14 个预注册 >2K token Tango split 全过（N=4,392；11,134 个 OOD 触发中 0 个）。
- 为什么值得看：它证明「精确计算」可以作为结构编译进权重，而不是靠更多数据或工具调用；代价是工程复杂度极高，适合当「权重可编程」的上界参照。

## 五、3D、安全与其它

### 46. VODA（31↑）

- 出处：Yonsei University · [HF](https://huggingface.co/papers/2611.21383) · [arXiv 2611.21383](https://arxiv.org/abs/2611.21383)
- 问题：3D Gaussian Splatting 的分割方法大多通过渲染视图来训练与评测；这种错配会让「渲染出的 mask 很准」掩盖「3D 选择并不完整」——alpha 混合的特征监督把学习集中在主要贡献者上，被遮挡或贡献小的高斯几乎没监督。
- 方法：VODA，一个即插即用的监督目标：利用局部深度结构把逐像素贡献者分组，直接监督被选中深度簇里的所有高斯，绕开按贡献加权的梯度投递。同时提出 Removal-3D 合成物体移除基准与 Removal Depth Error（RDE）指标，比较预测与真值的深度变化来量化体素完整性。
- 数字：四个基于渲染的基线在 Removal-3D 上都被 VODA 稳定提升，LERF 与 ScanNet 上保持或提升；进一步分析显示 VODA 找回了低贡献高斯，而简单的梯度重加权与空间传播复现不出同等收益。
- 为什么值得看：「mask 对 ≠ 3D 选对」是 3DGS 编辑流水线里一个安静的正确性 bug；RDE 这个指标比渲染 mask IoU 更接近下游任务真正在意的东西。

### 47. VETO（4↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25776) · [arXiv 2611.25776](https://arxiv.org/abs/2611.25776)
- 问题：VideoLLM 的 SFT 会学到从训练数据的文本规律直接作答，绕过视频；这个捷径在数据层面难以定义，且无论训练轮数、数据规模、骨干如何都会形成——它藏在同分布准确率上涨的背后，在分布偏移下反而吃掉视频带来的增益。
- 方法：不在数据上干预，而在「捷径被写进去的地方」干预更新：先校准基座激活中「纯文本」占据的子空间，再把 SFT 更新投影到其正交补。
- 数字：7 个 VideoLLM 上，VETO 保住同分布 SFT 增益、抑制捷径；6 个偏移基准上增益超过 SFT，且答案来自完整输入而非捷径。
- 为什么值得看：把「模态捷径」从数据清洗问题改写成参数更新几何问题，是一种更可扩展的干预点；对所有「多模态 SFT 后变笨」的抱怨都值得一试。

### 48. Lang-SVG（1↑）

- 出处：Clemson University · [HF](https://huggingface.co/papers/2611.15941) · [arXiv 2611.15941](https://arxiv.org/abs/2611.15941)
- 问题：图像矢量化大多优化像素级渲染保真，产出的 SVG 缺少人类感知的物体-部件层级，难以编辑。
- 方法：用显式树结构组织 SVG 图元，带语义标签与父子关系；用粒度可控、开放词表的细分先验初始化物体-部件层级，再用带 SVG 树上下文的 MLLM 给未标注节点打语义标签；深度自适应简化降形状复杂度，Tree-Guided Pruning and Merging 去冗余节点，L1-SAM-Prompting 补缺失区域；另提一套衡量结构质量与语义部件对齐的评测协议。
- 数字：摘要说在渲染保真与结构质量上均达 SOTA，没给具体数值。
- 为什么值得看：把「可编辑性」变成可评测的结构指标，比再刷一版 LPIPS 更贴近矢量图的实际用途。

### 49. TwinD（1↑）

- 出处：机构未给 · [HF](https://huggingface.co/papers/2611.25935) · [arXiv 2611.25935](https://arxiv.org/abs/2611.25935)
- 问题：人脸 deepfake 检测器多在「混合伪造」上训练——生成的脸被贴回真实帧、留有混合痕迹；新生成器直接合成整张脸，没有混合痕迹，旧检测器失效。
- 方法：只用 FaceForensics++ 的伪造 + 两类「双胞胎」训练：重建双胞胎是自编码器重建真实帧、再把真实像素随机贴回一块区域（针对解码器的神经痕迹）；斑块双胞胎是把真实帧的修改副本与原帧混合（针对混合伪影），不需要生成器、也不需要人脸形状的 mask。两类线索互补，泛化到未见操纵。
- 数字：2019–2026 年 19 个数据集的基准上，此前最好的检测器在 10 个混合数据集上平均 AUROC 96.2%，但在 5 个整脸合成（EFS）数据集上无一超过 78.1%；TwinD 平均 96.3%，比此前 SOTA 高 8.9 点，混合集 98.1%、EFS 95.6%；只用双胞胎、不用任何 deepfake 数据集训练，三个种子平均仍有 94.3%。
- 为什么值得看：78.1%→95.6% 是这条赛道最大的一个洞被补上；更妙的是「不需要真伪造数据」也能训，说明伪造线索可以从真实图像的自洽性里人造出来。

### 50. ITPD（1↑）

- 出处：Abel AI · [HF](https://huggingface.co/papers/2611.26232) · [arXiv 2611.26232](https://arxiv.org/abs/2611.26232)
- 问题：时间序列上的因果发现要面对自相关、分布漂移、维数灾难；通用算法计算与样本复杂度都高。
- 方法：Iterative Temporal Parent Discovery，一个在「因果非平稳」多元时间序列上 sound and complete 的约束式算法；局部到全局，逐个变量发现父集来拼出全局图，利用时间结构先验、图划分与局部 Markov 条件，把高阶条件独立检验换成低阶的。
- 数字：有精确 oracle 时，测试次数最少、平均条件集最小；仿真中在 F1 与 wall-clock 上位于 Pareto 前沿；大图（≥1,000 节点）上更快，2,000 节点时比 IAMB、DF-PC、PCMCI 分别快 2.3×、9.1×、40.9×。
- 为什么值得看：40.9× 来自「用时间先验把高阶检验降阶」，这个思路对任何时序因果/特征选择流水线都可借鉴。

## 今天的三个观察

**一、「自进化」开始有分工，而不是一句口号**。WeVisForensics 把进化拆成快环（调查员学查什么）与慢环（检查员学看得更细），DTPO 的两个时间尺度各有明确的监督信号；CompoundingKernel 把记忆放在模型外的归档里，让控制器读谱系、给并行子 agent 派方向；AutoMaster 让 agent 设计「技能」去塑形教师行为；Self-Rewriting 则干脆让 27B 模型自己诊断、自己改权重，八次自编辑 accuracy 单调上升。四篇的共同结构是：**改进回路不在一次前向里，而在「谁评估、谁记住、谁决定下一次试什么」的分工里**。这也解释了为什么 CompoundingKernel 的瓶颈是「可靠测量的速率」而不是 agent 数量——进化系统的吞吐由评估器决定。

**二、今天最硬的一组数字，测的都是能力之外的东西**。Mind2Act 的最强 agent 在 Mind 上 52.7%、Act 上 39.0%，闭环只剩 12.0%；SimAudit 在 49 个任务里查出 61 个 checker 缺陷，其中 40 个是把不完整执行判成成功；TuringSpace 发现模型推理很少纠正错误信念、反而编造证据替它辩护；AltRA-Test 说 LLM 只在约一半的设置里够格替代人工标注；Squoosh Bench 的 84.0% 总体准确率背后，是「看好改版」时 93.7% 的 precision。这些工作没有提出更强的主干，但它们在回答一个更前置的问题：**你测到的分数，到底对应现实里的哪一件事**。对做训练系统的人，这比再刷一个 SOTA 更有复用价值。

**三、效率这条线，收益都来自少做一点而不是做快一点**。PMD 的 any-step 让一个学生覆盖整个步数预算；LightningMoBA 用动态路由把保留率从 GPU 调度粒度里解耦，1.20–1.60× 的同时 RULER 还从 74.42 涨到 75.28；NarrowSpec 把草稿残差流削到 1/2 或 1/4 宽，接受率基本不变，GB10 上 1.13–1.44×；FlashMorph2 用 0.72–3.57 GPU 小时完成混合注意力的层选择；DiT 的 RL 后训练被证明 0.29M 个常数 steering 向量就能拿回 90.0%–96.3% 的增益。它们改的都是「必须付出多少参数/步数/搜索」这个约束，而不是把同一个计算压得更紧——这也意味着这类收益更容易叠加。
