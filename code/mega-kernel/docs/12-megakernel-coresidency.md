# MegaKernel 的 SM 资源分配与异构 task 共驻成本手册

> 压缩成一张**可操作的成本手册**——回答「把许多**不同类型的 task** 塞进同一个常驻 grid 后，
> SM 资源怎么分、异构共驻会付出什么税、哪些旋钮是自由的、哪些被物理约束锁死」。
>
> 全部数字引自本专题已在**目标卡**（H100 / sm90、sm90a）上跑出的 `harness/*.out.txt`，逐条给出
> `docs/04` 的节号坐标；MPK 论文引用其快照行号，DeepGEMM 引用源码坐标（`docs/02`）。
> 与两份既有汇总的分工：`docs/05-summary.md` 是**整专题一页纸**（动机/判据/适用边界）；`docs/11`

## 0. 一句话：第二层成本是「异构 task 抢同一台机器」

`docs/11` 把调度器拆成六个部件时，task 被抽象成「一条条要执行的活」；但真实 megakernel 里这些活
**资源画像完全不同**：MoE 的 dispatch/gather 是**稀疏访存**、专家 GEMM 是**计算/带宽受限**、
attention 的 KV 读是**大块流式**、归一化是**纯发射受限逐元素**（`docs/02` §1 的 DeepGEMM 三案例）。
它们**共享同一台机器**（判据 C3/C4：单 kernel、设备内协调），于是诞生第二层问题：

> **不同类型的 task 放进同一个常驻 grid，会互相拖慢吗？拖慢多少？该按 SM 分区还是共享？**

本专题从 P83 起，用四种**可精确控制访存画像**的合成模式（下表）把这个问题逐旋钮量到底。

| 代号 | 访存模式 | 物理约束 |
|---|---|---|
| `coalesced` (`m0`) | 连续 `uint4` 流式读 | HBM 带宽 |
| `sparse8x` (`m1`) | 每 8 个读 1 个（物理 4× 流量） | HBM **物理流量墙** |
| `scalar4B` (`m2`) | 4 B 无向量逐元素 | **指令发射 / LSU** |
| `l2res16M` (`m3`) | 16 MiB 数据常驻 L2 | **L2 延迟**（几乎不碰 HBM） |

四种模式在**同一逻辑字节数**下跑，故「谁的吞吐低」直接对应「它撞的是哪堵墙」。§71 先用它们把
`docs/11` §5 的「数据面只认每 SM 总线程 `O·T`」这条合量**拿到四种画像上复检**，§72 起把它们塞进
同一常驻 grid。

## 1. 通用旋钮 `O·T` 与它的天花板（§70 / §71）

`docs/04` §70（P82-1）已给出「数据面吞吐由**每 SM 总线程 `O·T`**（`O`=每 SM block 数、`T`=每块
线程数）支配」；§71（P83-1）把它推广到四种访存模式：

- **合量 `O·T` 普适**：`coalesced`/`scalar4B`/`l2res16M` 的吞吐**都在 `O·T≈1024` 附近进入平台**
  （与模式无关的通用旋钮）；低 `O·T` 起始效率差别大——`coalesced` 在 `O·T=256` 已到自身 90%，
  而 `scalar`/`l2res` 只 39–45%，抬到 1024 各补 **2.22×/2.43×**。
- **但峰值差一个量级**（同逻辑字节）：`coalesced` **3056**、`scalar4B` **2597**、
  `l2res16M` **23448** GB/s（L2 驻留，`docs/04` §71.3）；`sparse8x` 逻辑吞吐仅 **713 GB/s**
  （等效物理 2848，已撞 HBM 流量墙）。
- **`sparse8x` 是唯一例外**：从 `O·T=256` 起即平——**`O·T` 不是它的旋钮**，它被物理流量墙锁死。
- **合量有裂缝**（§71.5 headline）：在**同一 `O·T=1024`** 下扫 `(T,O)` 拆分，`coalesced` 极差仅
  **1.04×**（复现 §70），但 `l2res16M` **1.47×**（`T=256/O=4` 22385 vs `T=1024/O=1` 15217）——
  **L2/延迟受限的模式要「多而小的 block」**（隐藏 L2 延迟），与 `coalesced` 的「少而大」相反。

> **设计含义**：把机器「按 `O·T` 铺满」是**通用**旋钮，但**非万能**：稀疏 task 先撞物理流量墙
> （只能靠 coalescing / TMA multicast / DSM 降物理流量，见 `docs/11` §8 与 `docs/04` §18–§22），
> L2/延迟受限 task 要「多而小的 block」（影响 worker 划分），发射受限 task 靠更多 warp。

## 2. 异构共驻税：大体加和，两处真裂缝（§72）

§72（P84-1）把四种模式按份额 `f_p` **交错分配**到同一常驻 grid（每 block 按 `assign[]` 选模式，
host 用误差扩散保跨 SM 共驻），与「各模式**轮流独占整机**的时间切片期望」（调和平均）比：

- **共驻大体加和**：九种混合的 `measured/expected` ∈ **[0.867, 1.111]**——同 grid 混跑与分区独占
  相差 ±13% 以内。**唯一系统性裂缝是 `scalar4B`（发射受限）**：凡含 `scalar` 且占可观份额的混合恒低
  **~13%**（`coal+scalar` 0.867、`scalar+l2res` 0.867），**与 `(T,O)` 正交**（扫遍 `(T,O)` 补不回）。
- **`l2res` 是不争 HBM 的「白吃者」**：`coal+l2res` **1.111（超加和）**——L2 停顿藏进 HBM 停顿；
  不含 `scalar` 的混合都 ≥1（`coal+sparse` 1.015、`sparse+l2res` 1.030）。
- **稀疏低掺杂「毒化」**（§72.6）：`coal+sparse` 扫 sparse 份额 0→100%，在 **sparse=10–30%** 时
  `meas/exp` 掉到 **0.855–0.915**（物理仅 ~2.55–2.67 TB/s，未到墙）——**少量稀疏 task 混进大量流式
  task 代价最隐蔽**；`≥50%` 回到加和（物理稳在 2.77–2.92 TB/s ≈ HBM 墙）。
- **ncu 把三堵墙分开钉死**（§72.7）：混合物理 DRAM 字节 = `Σ_p f_p·phys_p` **逐字节精确**
  （`equal4` 1.61 GB=1.50×、`coal+sparse` 2.68 GB=2.50×）——`sparse`=`物理流量`、`scalar`=发射/调度、
  `l2res`=延迟。

> **设计含义**：megakernel 里「一条 task 类型越杂越难一套参数通吃」应精确化为**「访存模式之间近似
> 可通吃；发射受限 task × 访存受限 task 的同核共驻不可通吃」**（§72.8）。

## 3. 税住在哪：SM 间（全局）而非 SM 内（§73）

§72.8 曾猜测「把发射受限 task 聚到一起 / SM 隔离」能收回税。§73（P85-1）用同一组模式把映射从
「按 block 交错」（共享 SM）换成「**按 SM 角色绑定**」（每 SM 只跑一种模式，`mode=mode_of_sm[smid]`），
**保持逻辑工作份额不变**：

- **`bind ≈ interleave` 逐行几乎重合（差 ≤1.1%）**：`coal+scalar` **0.902/0.898**、`coal+l2res`
  **1.112/1.113**、`scalar+l2res` 0.789/0.792——⇒ **共驻税与 `l2res` 超加和是全局（SM 间 / HBM /
  L2 / 全机发射）现象、不是 SM 内发射槽共享**。**证伪「SM 隔离能收回税」**。
- **ncu 逐项相同**（§73.7）：`bind` 与 `interleave` 的 DRAM 读字节、L1 sector、活跃 warp、`inst/cycle`
  完全一致——差异纯粹不在硬件计数里。
- **`bind_bal`（SM 数 ∝ 份额/每 SM 速率）反而更差**：`equal4` **0.753**、`coal+l2res` 0.854——因
  `sparse`/`l2res` **低 SM 数即饱和 HBM/L2**、每 SM 速率**非线性**，「按常数 `1/r1` 分 SM」前提不成立。

> **设计含义**：缓解共驻税**只能改 task 的访存形态（向量化 / 降发射）或份额**，**不能靠分区 / SM
> 归属**。这直接解释了为什么生产实现（MPK 去中心化 event queue / DeepGEMM 静态角色 + ring barrier）
> 走**「共享 SM + 设备内调度」**而非「离线静态 SM 分区」。

## 4. SM 分配器：从「常数速率谬误」到 in-situ 不动点（§74–§76）

既然分区收不回税，那**分区本身**还值不值得做？§74–§76 依次追问「按什么速率模型分 SM」：

| 分配器 | 速率来源 | 近线性混合 | 含 HBM 饱和模式（`sparse`） |
|---|---|---|---|
| `bind`（∝ 份额） | 无 | 基准 | 基准 |
| `bind_bal`（∝ 份额/`r1`） | 常数每 SM 速率 | 与 `bind` 同档 | 同档 |
| `bind_opt`（贪心 makespan） | **单跑速率曲线** | `coal+scalar` **0.947（反超 interleave 0.909）** | `coal+sparse` **0.664（比常数还差）** |
| `bind_insitu`（局部爬山） | **并发实测 makespan** | `coal+scalar` 0.952 | `coal+sparse` **1.024（收回）** |
| `bind_global`（多起点爬山） | 多起点并发 | `equal4` **1.039** | 追平 oracle ~1% |

- **「常数速率谬误」有两种坐标**（§74.5/§74.9）：`bind_bal` 是「每 SM 速率当常数」；`bind_opt` 是
  「**单跑**曲线把『给已饱和模式加 SM』的边际价值估高」——`coal+sparse` 被分 `[coal=9, sparse=123]`，
  123 SM 全喂给已饱和的 `sparse`、饿死 `coal`。
- **in-situ 完全收回崩盘**（§75.4）：`coal+sparse` **0.664 → 1.024**；条件 in-situ 曲线一眼看清
  「给已饱和 `sparse` 加 SM 边际价值≈0/为负」（峰位在 `n_coal≈32`，而单跑贪心选了 9）。
- **两类东西 in-situ 也修不了**（§75.4）：① `coal+scalar` 的 ~5% **全局发射税**（0.952 ≈ `bind_opt`
  0.953）；② `equal4` 的**角色绑定结构上限**（0.789 仍输 `interleave` 1.043）。
- **多起点 + oracle**（§76）：单起点爬山**不可复现**——`equal4` 收敛到双模态、`spread(max/min)=1.398`；
  多起点 `bind_global` 拉回 **1.039**、追平 oracle 到 ~1%；**评价噪声地板 ≈1.0%**（同分配重复 R=8）。
- **ncu 始终逐项相同**：所有分配器只改**并发时序**，不改 DRAM 字节/扇区/发射率——即收益/损失全在
  时序重叠，不在「多做/少做了工作」。

> **设计含义**：SM 静态分区分配器要**同时**做到 in-situ 速率、多起点、合法分配守门
> （`sum==numSM` 且活跃模式 ≥1，否则丢 work → 吞吐虚高，见 `docs/04` §76.10 / ROADMAP「已知坑」）、
> 并承认 ~1% 噪声地板——即便如此，在高度异构图只**追平**共享 SM + 交错，在发射×访存混合上**仍留
> 全局税**。**分配改变争用、争用改变速率，是一个不动点**（§74.9）：一条 task 类型的「速率 vs 给的
> SM 数」必须在别的 task 同时跑时量。

## 5. 一阶旋钮其实是「每 SM 在飞 warp」（§77–§79）

§73 说「税是全局的」，但没说完。§77–§79 用同一套装置把「每 SM 的资源量」单独扫出来：

- **每 SM block 数 `O` 不改税**（§77，固定 `O·T=1024`）：`bind ≈ interleave` 在 `O=1/2/4` 逐行不变
  （差 ≤1%），`coal+scalar` 的 ~9–13% 税在 `O=4` 下**不消失**（0.868/0.862）；ncu 硬件计数逐项相同。
- **每 SM warp 数 `Wsm=O·T` 才是一阶旋钮**（§78 headline）：`coal+scalar` 的 `bind` `meas/E`
  **0.772（Wsm=256）→ 0.825（512）→ 0.913（1024）→ 0.995（2048）**——**税随 `Wsm` 收回**；
  `Wsm=256` 时分区扫描是「两端好、中间深谷」（`sc=12` 掉到 **0.147**），`Wsm=2048` 基本压平 ~1.0。
  ncu：`O1/T256` → `O8/T256`，物理字节几乎不变，**活跃 warp 从 12.50% → 98.97%**。
- **同一 `Wsm` 内 `(T,O)` 拆分不改税**（§79 headline）：`Wsm=2048` 四拆分 `[0.978 0.969 0.987 0.987]`
  （spread ≤1.8%）；ncu `T1024/O2`、`T512/O4`、`T256/O8` 三拆分**扇区数逐字节相同**、活跃 warp 都 ~99%
  ——即 `Wsm` 一提上来就在**所有拆分上同时**收回，非单点巧合。

> **对 §3「税是全局」的精确限定**：税**不住**在块边界（§77）、也**不靠** SM 分区绕开（§73），
> 但它是**每 SM warp 预算 `Wsm` 的函数**——`Wsm` 补到满占用率（2048）即基本消失。**数据面饱和度与
> 共驻税是同一个「在飞 warp 预算」旋钮**（§78.8）。

## 6. 支配量是「每 SM 在飞 load 量 `Wsm·U`」；寄存器只经占用率（§68/§69/§80–§82）

`Wsm` 只是「在飞量」的一个因子。§80–§82（配合 §68/§69 的寄存器结论）把这一层拆开：

- **每线程 ILP `U` 是独立旋钮**（§80 headline）：固定 `Wsm=1024` 只动 `U=1→8`，`coal+scalar`
  `meas/E` **0.708→0.982**、`scalar+l2res` **0.587→0.992**。⇒ 支配量是**每 SM 在飞 load 量
  `Wsm·U`**，`Wsm` 只是其一因子。等 `Wsm·U` 的 `(Wsm,U)` 组合塌到 ±2–10%，**高 `U`、低 `O` 略优**。
- **口径警告**（§80）：`meas/E`（比值）与**绝对吞吐**是两种问题、会双向误导——`scalar+l2res`
  绝对 spread 1.084 而 `meas/E` spread 1.205（**放大**基线漂移）；反过来 `coal+scalar` 绝对 spread
  1.188 而 `meas/E` spread 仅 1.017（**掩盖**真实依赖）。**「税与拆分无关」≠「混合绝对吞吐与拆分
  无关」**，两者必须并读。
- **寄存器预算 `R` 只经占用率起作用**（§81 headline）：`__maxnreg__(R)` 是**上限不是设定值**
  （`R≥` 自然需求时用自然需求）；`numRegs` 自然需求随 `U` 增长（`U=1/2/4/8/16` = 30/28/40/54/84）。
  **抬 `R` 不变好**：`U=8` 的 `R=32` 给最高 `meas/E=1.000`，抬到 `R≥48` 掉到 ~0.96（只砍占用率）。
  **最优 = 「不 spill 的最小 `R`」**；只有 `U` 需要时才加 `R`。
- **四重占用率封顶**（§82）：H100 每 SM 占用率 = `min(线程上限 2048/T, 寄存器上限 65536/(regs·T),
  块上限 32, **SMEM 上限 SMEM_perSM/block_smem**)`。**`R≤32` 时寄存器上限恒 ≥ 线程上限**，故把
  `__maxnreg__` 压到 32 以下**买不到占用率**（只会 spill）——`R=32` 是多数数据面 task「不 spill 的
  最小预算」下界；**每块静态 SMEM 会在小 `T` 时先于线程封顶**（§82.2：8 KiB 归约数组在 `T=64` 把
  `occ` 压到 24）。
- **纯 ILP 曲线**（§82.3）：固定 `Wsm=2048` 扫 `U`，`meas/E` 0.81→≈1.00、天花板 `U≈8`；§81 报的
  `U=16` 回落主要是**占用率耦合**（`Wsm` 1024→512），税随 `U` 收回本身是纯 ILP 效应。

> **设计含义（worker 块 / 寄存器）**：**不要为保险多要寄存器**——把每 task 类型的 `R` 设成其 `U`
> 所需的自然需求（并保证 ≥32 这条「不 spill 下界」）；要收回共驻税，先补满**每 SM 在飞 warp 预算
> `Wsm`**，其次才是每线程 ILP `U`。这与 `docs/04` §8「megakernel 寄存器被固定为各 task 最大值」
> 是同一枚硬币的两面。

## 7. 块粒度 `T` 是次级量，落点在**发射侧 LSU 背压**（§83–§85）

`Wsm` 钉住后，块粒度 `T` 只剩 ~4% 的次级效应（`docs/04` §82.6），且机制一度被猜错：

- **现象**（§84.1）：固定 `Wsm=2048`，混合 `scalar+l2res` 的 `T512/T128` = **0.9586**（吞吐 **+4.3%**），
  bootstrap CI95 `[0.9528,0.9627]` **不含 1.0**；两端相反——`scalar4B` **+2.3%**、`l2res16M` **−2.6%**。
- **机制归因**（§83/§84.2）：ncu 每 warp **绝对**停顿周期分解显示——**`T` 不减轻 L2 延迟**
  （`long_scoreboard` 随 `T` **升**：混合 +6%、`scalar4B` +13%）；唯一随 `T` 单调降的是
  **`lg_throttle`（LSU 背压）**（混合 **−24%**、`scalar4B` **−43%**）。⇒ 「少而胖更好」的机制落点是
  **发射受限侧的 LSU 背压**，**不是**「减少 L2 停顿争用」（§82.6 猜测被否）。
- **是 DRAM + LSU 题**（§84.3）：混合同 `Wsm` 下 DRAM ~74%、L2 命中仅 11%、全局读 30.05/32 B/扇区。
- **跨进程 / 跨 device 稳健**（§85）：4 块卡 × 6 进程（24 进程）× 每进程 S=30，混合 `T512/T128`
  median = **0.9598**、跨进程 CI95 `[0.9574,0.9629]` 不含 1.0、**24/24 进程逐个显著**；方差分解
  显示 **betweenStd（0.33–0.63%）< withinStd（1.0–1.3%）**——换进程/换卡系统差小于同进程噪声。
- **但有两处诚实标注**（§85.3/§85.4）：`l2res16M` 单模式 betweenStd 反超 withinStd，**L2 驻留负载
  有真实卡间差**（某卡绝对值偏高 ~4%）；混合比值有小的 **per-device offset**（卡间 std ~0.4%，与
  ~1% 的绝对效应百分位差**同量级**）⇒ **比绝对效应时须固定卡**。

> **设计含义**：一阶旋钮是 `Wsm`（§5），块粒度只是 3–5% 的次级量；且对 **L2 延迟受限 task 优先
> 「少而胖」**（但机制是发射侧 LSU 背压，不是 L2 停顿）。复现这类 ~1% 量级结论必须**跨进程/跨卡**做，
> 且不能拿不同卡上的数直接相减。

## 9. 回到 MPK / DeepGEMM 的印证

- **「共享 SM + 设备内调度」不是省事，是物理结论**（部件来自 `docs/11`）：§73（税是全局的）+ §75/§76
  （分区追平即上限）证明**无论静态分区怎么调，发射×访存税与异构结构上限都收不回**。MPK 让所有
  worker SM **交错的取不同 task**（快照 §5 行 1147–1310、`docs/06` §3）、DeepGEMM mega 家族用
  **静态 warp 角色 + 设备内 ring barrier**（`docs/02` §1），正是避开「按 SM 硬分区」。
- **「少而重」而非「多而杂」是同一个选择**（对上 `docs/04` §8/§10/§14）：§72 的发射×访存不可通吃
  + 寄存器/代码足迹（§8/§10）一起说明——**DeepGEMM 只融合少数几个极重 task 类型**（MoE 的
  dispatch/GEMM/combine、Gate 的 7 段、mHC 的一整层）是方向正确的：把 task 类型数压到少数、每类都
  是重活，就绕开了「多而杂」的共驻税与足迹税。
- **生产描述符流量落在安全区**：§61 指出真峰值下描述符写开始争 HBM（读降 7–17%），但生产描述符
  流量 ~15 GB/s（~0.5%）落在读降 3–7% 档（`docs/04` §61）——即 MPK/DeepGEMM 用**极少 scheduler SM**
  推 id 而非造 payload（`docs/11` §6）把控制面流量压到不显著，与本文「控制面别和数据面抢」一致。

## 10. 局限（诚实标注）

- **全部是合成访存模式**：`coalesced/sparse8x/scalar4B/l2res16M` 是**可精确控制的画像**，不是真实
  GEMM/attention/RMSNorm；结论的形状（哪堵墙、哪个旋钮）可信，具体倍率只对本微基准成立。
- **只测目标卡 H100 / sm90、sm90a**：未与 DeepGEMM 的 SM100 专属 mega 路径对跑（每节都明记）。
- **判据普遍 C1–C5 全不满足**：§71–§85 是**纯数据面微基准**（无环协议 / 无任务描述符 / 无调度器），
  它们度量的是 megakernel **worker 侧的资源成本**，不含调度机制（调度机制由 `docs/11` 覆盖）。
- **固定配置的窄口径**：多数节固定 `U=4`（§71–§79）/ `R=32`（§71–§85）/ 单 `Wsm`；`O` 只到 16、
  `U` 只到 32、`R` 只到 128；未扫非 8 倍数 strided / 非对齐访问。
- **`meas/E` 口径 caveat**：比值会放大基线漂移（§80），判「税与某量无关」须与**绝对量**并读；
  ncu 的 `smsp__average_warp_latency` 在 application-replay 下方向可能相反，吞吐只采信无 ncu 计时
  （`docs/04` §83/§84 的踩坑）。
