=== B. make_umma_desc：K-major vs MN-major 的 stride/leading/layout 实算 ===
B1. to_umma_layout_type<kMajorMode,kSwizzleMode,kUseBase32,dtype> 映射表
   dtype  Major  swizzle  base32 -> LayoutType
   fp8    K        0      0      -> SWIZZLE_NONE
   fp8    K       16      0      -> SWIZZLE_NONE
   fp8    K       32      0      -> SWIZZLE_32B
   fp8    K       64      0      -> SWIZZLE_64B
   fp8    K      128      0      -> SWIZZLE_128B
   bf16   MN       0      0      -> SWIZZLE_NONE
   float  MN       0      1      -> SWIZZLE_128B_BASE32B
   float  MN     128      1      -> SWIZZLE_128B_BASE32B
   -> 两条「强制 BASE32」规则：(i) dtype==float 且 MN-major 必须 kUseBase32=true；
      (ii) 显式 kUseBase32 无法与 K-major/non-float 组合时 static_assert 挡下。
      故 fp8 的 K-major 128B -> SWIZZLE_128B，而 float 的 MN-major 恒 -> SWIZZLE_128B_BASE32B。

B2. K-major（fp8 e4m3, swizzle=128=BLOCK_K*sizeof(fp8)=128*1）
   mn_idx,k_idx           start(>>4) stride(>>4) lead(>>4) layout
   mn=0,k=0               4096       64         0        SWIZZLE_128B
   mn=1,k=0               4104       64         0        SWIZZLE_128B
   mn=2,k=0               4112       64         0        SWIZZLE_128B
   K-major: stride_byte_offset = num_non_contiguous(128/16=8)*BLOCK_K(128)*1B = 1024 -> >>4 = 64
            leading_byte_offset = 0；地址步进 stride_k=1 个元素；mn 每加 1 前进 BLOCK_K 元素。

B3. MN-major（bf16, swizzle=64, BLOCK_MN=64, BLOCK_K=64）
   BLOCK_MN_ATOM = swizzle/sizeof(bf16) = 64/2 = 32
   mn=0,k=0: start(>>4)=4096 stride(>>4)=32 lead(>>4)=256 layout=SWIZZLE_64B
   MN-major: num_non_contiguous=128/16=8; stride=8*32*2B=512 (>>4=32);
             leading=BLOCK_K*32*2B=4096 (>>4=256)；stride_k=BLOCK_MN_ATOM=32 元素。

B4. swizzle=16 时 MN-major 会 swap stride/leading（源码 :137-139）
   swizzle=16: stride(>>4)=32 lead(>>4)=8 （常规 MN-major 的 stride<lead，此处被交换）
   -> layout_type_=SWIZZLE_NONE（swizzle=16 映射到 SWIZZLE_NONE，与 swizzle=0 同）
