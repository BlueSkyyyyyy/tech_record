>> 读法：
>> K=1 = 每 chunk「等拷贝完再算」，两段严格串行（= kernel barrier 后的两个 kernel）；
>> K>1 = 边算 chunk s 边预取后面 K-1 段拷贝，把访存藏进计算。
>> Section A：深度 1->2 增益最大（K=1 把每段 HBM 延迟都暴露出来），随 K 加深趋饱和。
>> Section B：R=0（纯访存）时 K 也能藏「相邻拷贝之间的延迟」；R 越大访存占比越小、
>>   可重叠越多，speedup 趋近上界 (Tmem+Tcomp)/max(Tmem,Tcomp)。
>> Section C：chunks 越多越接近稳态，speedup 收敛（每 block 只剩一次首延迟）。
>> 含义：损失一（kernel barrier 挡住软件流水）在单 kernel 内**可回收**，回收比例由
>>   访存延迟/计算时长之比决定——这解释了 MPK/DeepGEMM 为何用多层 Kstages（P11）。
