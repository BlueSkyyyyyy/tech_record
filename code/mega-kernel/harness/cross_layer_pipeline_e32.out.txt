>> 读法：
>> eager  = kernel-per-operator：L 次 launch，层间由 stream 串行，SMEM 随 kernel 释放（不可预取）；
>> barrier= 单 kernel + 每层 grid.sync（集中式会合，层间串行化其上还有全图屏障）；
>> decen  = 单 kernel + 逐槽事件计数器（细粒度依赖，但不预取权重）；
>> ringK  = decen + K 页环形 SMEM 跨 task 预取（MPK §5.3 跨 task 软件流水）。
>> 预期：ring 相对 barrier/decen 把「下一层权重 tile 的 HBM 延迟」藏进「本层计算」，
>>   收益上界 ≈ (Tload+Tcomp)/max(Tload,Tcomp)，随 R（计算占比）变化。
>> 注意：R=0（纯访存、无可藏的计算）时流水反而更慢；重载 tile（-DELEM=32）才显出
>>   流水深度 K 的收益（Section B 单调到 K≈4 饱和），轻载（E=16）时事件等待已够藏访存。
