>> 读法：
>> A: 总 FMA 量恒定，唯一变量是「融合进这个 kernel 的 task 类型数 P」。P=1 是单个 task
>>    类型（未融合）；P 增大即被执行的代码工作集增大。若耗时随 P 上升，即为**代码足迹/
>>    L1 指令缓存**代价（融合的 task 类型越多，取指越容易 miss）。
>> B: 同 P、同工作量，spread(每执行流扫 P 个 body) vs sticky(每流固定 1 个 body)：
>>    两者分发表大小/间接调用数相同，差别只在**时间代码工作集**。spread/sticky 即该代价。
>> C(ncu 另跑): 对 P=1/P=256 采 instruction-fetch / branch-resolving 停顿占比归因。
